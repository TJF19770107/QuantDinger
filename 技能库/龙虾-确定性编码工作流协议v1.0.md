## 一、协议概述

本协议提取自Archon（GitHub 14k★）的YAML驱动确定性AI编码工作流引擎，核心创新：将AI编码从"黑盒随机"变为"白盒可控"——通过固定random seed + temperature=0，确保相同输入永远产出相同输出。

## 二、YAML工作流定义规范

### 2.1 节点类型

```yaml
workflow:
  name: "feature-development"
  deterministic: true  # 确定性模式开关
  seed: 42
  temperature: 0
  steps:
    - id: "plan"
      type: "ai"           # AI节点：LLM调用
      prompt: "分析需求并生成技术方案"
      
    - id: "code"
      type: "ai"
      prompt: "根据技术方案生成代码"
      depends_on: ["plan"]
      
    - id: "test"
      type: "deterministic"  # 确定性节点：脚本/命令
      command: "pytest --json-report"
      depends_on: ["code"]
      
    - id: "review"
      type: "ai"
      prompt: "审查代码变更"
      depends_on: ["code"]
      
    - id: "commit"
      type: "deterministic"
      command: "git add -A && git commit -m 'AI generated'"
      depends_on: ["test", "review"]
```

### 2.2 节点类型枚举

| 类型 | 描述 | 示例 |
|------|------|------|
| `ai` | LLM推理节点 | 规划、编码、审查 |
| `deterministic` | 确定性Shell命令 | 测试、Git操作、构建 |
| `conditional` | 条件分支 | 测试通过→合入/失败→修复 |

### 2.3 17套内置模板

1. `feature-development` — 功能开发全流程
2. `bug-fix` — Bug修复（含复现步骤）
3. `pr-review` — PR代码审查
4. `code-refactor` — 代码重构
5. `test-generation` — 测试生成
6. `documentation` — 文档生成
7. `dependency-update` — 依赖更新
8. `security-audit` — 安全审计
9. `performance-optimize` — 性能优化
10. `api-integration` — API集成
11. `database-migration` — 数据库迁移
12. `config-change` — 配置变更
13. `hotfix` — 紧急修复
14. `release-prep` — 发布准备
15. `ci-cd-setup` — CI/CD配置
16. `code-cleanup` — 代码清理
17. `custom` — 自定义模板

## 三、确定性执行保证

### 3.1 三层确定性

```
LLM层：seed=42, temperature=0, top_p=1.0
编排层：DAG拓扑固定，无随机调度
执行层：Shell命令输入固定，环境变量锁定
```

### 3.2 确定性开关

```yaml
deterministic:
  enabled: true
  llm_seed: 42
  llm_temperature: 0
  schedule_order: "topological"  # 固定拓扑序
  env_lock: ["PATH", "PYTHONPATH", "NODE_ENV"]
```

## 六、适用场景

- 需要可复现AI编码输出的CI/CD流水线
- 代码审查自动化（固定标准）
- Bug修复闭环（复现→修复→测试→验证）
- 多仓库批量重构

## 七、关键约束

- 确定性模式下seed和temperature不可运行时修改
- 环境变量锁定列表外的变量不影响输出
- 模板YAML必须通过Schema验证
- 每次执行生成trace_id用于审计
