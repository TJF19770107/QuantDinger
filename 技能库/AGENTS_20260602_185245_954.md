## 二、项目约束

### 2.1 编码规范

| 规则 | 强制要求 |
|------|---------|
| 语言 | Python 3.8+ 优先，Shell 次之 |
| 字符编码 | UTF-8，文件头 `# -*- coding: utf-8 -*-` |
| 路径格式 | Windows 绝对路径，`/` 或 `\\` 分隔，严禁单反斜杠 |
| 日期格式化 | **严禁** `strftime()` 中文字符 → 用 f-string 拼接 |
| 临时文件 | 写入 `temp/` 目录，不得写入系统临时目录 |
| 结果文件 | 写入 `output/` 或用户指定目录 |
| 空值处理 | JSON/CSV 空值统一 `""`（空字符串），不用 `null` |

### 2.2 安全分级

| 级别 | 操作 | Codex 处理 |
|------|------|-----------|
| 🟢 低 | 只读/创建非系统文件 | 直接执行 |
| 🟡 中 | 覆盖/配置变更 | 二次确认 |
| 🔴 高 | 格式化/系统路径/注册表 | **无条件拒绝，上报 Hermes** |

**禁止清单**：系统路径写入 · App Secret 明文 · 凭据编造 · 安全验证绕过 · 编码规避 · 静默覆盖

### 2.3 路径约束

| 用途 | 路径 |
|------|------|
| 技能库 | `E:\龙虾AI主控中心\我的AI分身\技能库\`（只读） |
| 知识库 | `E:\龙虾AI主控中心\我的AI分身\知识库\`（归档写入） |
| 工作目录 | 会话指定目录（动态获取） |
| 中间产物 | `<工作目录>/temp` |
| 产出物 | `<工作目录>/output` 或用户指定 |
| **绝对禁止** | `C:\Windows\` `C:\Program Files\` `C:\ProgramData\` |

### 2.4 编码特有约束

| # | 约束 |
|---|------|
| 1 | 优先使用专用工具（read_file/write_file/convert_file），禁止无谓降级到 python_executor 手搓 |
| 2 | 同类工具失败上限 2 次 → 切换策略/降级 |
| 3 | 必须基于工具真实返回结果，禁止凭文件名或经验猜测 |
| 4 | 生成文件后必须验证存在且内容正确 |
| 5 | 不硬编码凭据 → 使用环境变量或 `{{from-vault}}` 占位符 |

## 三、输入示例

### 3.1 标准 task 模板

```xml
<overall_goal>
{Hermes 层任务总目标}
</overall_goal>

<current_task>
{Codex 执行的原子任务}

【处理要求】
1. {具体操作1}
2. {具体操作2}

【约束】
- 超时：{秒}
- 输出目录：{路径}
- 安全级别：{🟢/🟡/🔴}

【输出格式】{json|markdown|file|table}
</current_task>
```

### 3.2 典型任务示例

**例1：文件处理 + CLI 自动化**
```xml
<overall_goal>读取订单 CSV，统计本月销售额，生成 Excel 报表</overall_goal>
<current_task>
读取 E:\数据\orders.csv，按以下要求处理：
1. 筛选本月订单（2026-06）
2. 按品类统计销售额
3. 生成 E:\报表\sales_report_202606.xlsx（含品类汇总表+趋势图）
【输出格式】Excel 文件 + 结构化摘要
</current_task>
```

**例2：批量格式转换**
```xml
<overall_goal>将 D:\文档\ 目录下所有 .docx 转为 PDF</overall_goal>
<current_task>
递归扫描 D:\文档\，将所有 .docx 转换为 PDF。跳过已存在同名 PDF 的文件。
【约束】超时：600s | 输出格式：json {total, converted, skipped, failed}
</current_task>
```

**例3：代码重构（有边界约束）**
```xml
<overall_goal>重构旧模块，拆分职责</overall_goal>
<current_task>
重构 E:\项目\legacy_parser.py：
- 拆分为 parser.py + validator.py + formatter.py
- 原文件保留为 legacy_parser.py.bak
- 新增单元测试 test_parser.py
- 输出重构报告到 output/refactor_report.md
</current_task>
```

## 四、错误兜底

### 4.1 自愈式执行闭环

```
代码生成 → 执行 →
  ├── [成功] → 结果验证 → 返回
  └── [失败] → 错误捕获 → 类型匹配 → 策略选择
        ├── ModuleNotFoundError → pip install → 重试（≤2次）
        ├── UnicodeEncodeError → 切换 f-string → 重试（≤1次）
        ├── FileNotFoundError → 路径修正/搜索 → 重试（≤2次）
        ├── PermissionError → 等待3s重试 → 重试（≤3次）→ 跳过
        ├── Timeout → 分块处理 → 重试（≤2次）→ 返回 partial
        └── 未知错误 → 记录日志 → 降级/返回部分结果
```

### 4.2 自愈策略速查

| 错误类型 | 自愈策略 | 最大重试 | 降级方案 |
|---------|---------|:---:|---------|
| ModuleNotFoundError | pip install 自动安装 | 2 | 替代库或纯Python实现 |
| UnicodeEncodeError | 切换 f-string | 1 | 英文标记替代 |
| FileNotFoundError | 路径修正+同类搜索 | 2 | 返回空列表+说明 |
| PermissionError | 等待3s重试 | 3 | 跳过文件+错误日志 |
| JSONDecodeError | errors='ignore' | 1 | 返回原始文本 |
| Timeout | 分块处理 | 2 | 返回部分数据+警告 |
| MemoryError | 分块≤1000行 | 1 | 输出前1000条+统计 |
| lark-cli unauthorized | — | 0 | 返回 needs_auth 状态 |

### 4.3 熔断规则（硬约束）

| 熔断条件 | 动作 |
|---------|------|
| 同一错误连续 3 次 | 终止该步骤，执行降级方案 |
| 单任务总重试 > 5 次 | 终止任务，返回已完成部分 + 错误摘要 |
| 单文件操作超 60 秒 | 超时终止，跳过该文件 |
| 内存使用 > 80% | 暂停非关键操作，释放临时变量 |
| 沙箱连续崩溃 3 次 | 终止任务，标记 `sandbox_unstable` |

### 4.4 降级矩阵

| 主方案 | 降级方案 | 最终兜底 |
|--------|---------|---------|
| `lark-cli docs create` | 生成 Markdown 本地存储 | 返回 Markdown，提示手动创建 |
| `convert_file` | Python 库手动转换 | 返回源文件，说明转换失败 |
| `search_file(query=)` | `search_file(sql=)` 属性搜索 | `fs_search_file` 兜底 / 返回空 |
| `python_executor` (大文件) | csv 标准库逐行处理 | 手动 dict 解析 / 返回原始文本 |

### 4.5 Codex-Hermes 联动故障处理

| 故障场景 | 检测方式 | 恢复策略 |
|---------|---------|---------|
| Codex app-server 不可用 | `codex --version` 失败 | 降级为 Hermes 默认运行时，上报不可用 |
| MCP 回调超时 | 响应 >30s | 重试1次（60s），仍失败则标记工具不可用 |
| 沙箱崩溃 | 子进程异常退出 | 保存快照 → 重新初始化 → Checkpoint 续跑；连续3次终止 |
| OAuth 过期 | 401/403 | 提示 `codex login`，降级为默认运行时 |

## 五、结果输出范式

### 5.1 标准返回结构

```json
{
  "status": "done | partial | failed | needs_params | handoff | needs_auth | degraded",
  "summary": "一句话执行摘要（≤50字）",
  "artifacts": [
    {"path": "E:\\绝对路径\\文件.ext", "type": "file|report|script|data", "description": "简短说明"}
  ],
  "stats": {"token_used": 0, "tool_calls": 0, "duration_ms": 0},
  "warnings": [],
  "errors": [],
  "suggestions": [],
  "gaps": []
}
```

### 5.2 状态码语义

| status | 含义 | Hermes 后续动作 |
|--------|------|----------------|
| `done` | 全部完成 | 聚合结果，呈现用户 |
| `partial` | 部分完成 | 补缺口或降级呈现 |
| `failed` | 失败 | 分析原因 → 重新派发/切换Agent |
| `needs_params` | 缺参数 | 补全后重新派发 |
| `handoff` | 需交接 | 路由到目标 Agent |
| `degraded` | 降级运行 | 标记能力降级 |
