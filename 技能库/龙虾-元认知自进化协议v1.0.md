## 一、双层架构

### 1.1 架构图

```
┌─────────────────────────────────────────┐
│              SuperAgent                   │
│                                           │
│  ┌──────────────┐  ┌──────────────┐      │
│  │  TaskAgent   │  │  MetaAgent   │      │
│  │  (解决问题)   │  │  (改进自身)   │      │
│  │              │  │              │      │
│  │ - 执行任务   │  │ - 审视Skills │      │
│  │ - 调用工具   │  │ - 提取新模式  │      │
│  │ - 生成产物   │  │ - 淘汰低效项  │      │
│  │              │  │ - 优化策略    │      │
│  └──────────────┘  └──────────────┘      │
│         │                  │              │
│         └────────┬─────────┘              │
│                  ▼                        │
│  ┌──────────────────────────────┐        │
│  │   共享知识库 (Memory + Skills) │        │
│  └──────────────────────────────┘        │
└─────────────────────────────────────────┘
```

### 1.2 SEPL (Self-Evolution Protocol Loop)

```
  Reflect ──→ Select ──→ Improve ──→ Evaluate ──→ Commit
     ↑                                                  │
     └──────────────────────────────────────────────────┘

每一步：
1. Reflect: 回顾近期任务，识别新模式/新能力
2. Select:  筛选值得固化为Skill的模式
3. Improve: 优化Skill模板（参数化、泛化、文档化）
4. Evaluate: 在新任务上验证Skill效果
5. Commit:  写入知识库，标记版本
```

## 二、SkillForge引擎（对标GenericAgent）

### 2.1 核心流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 种子代码  │ → │ 遇到新任务│ → │ 自主摸索  │ → │ 固化为   │
│ 3.3K行   │    │          │    │          │    │ Skill    │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                     │
                                                     ▼
                                              ┌──────────┐
                                              │ 写入记忆层│
                                              │ + 下次直接│
                                              │ 调用      │
                                              └──────────┘
```

### 2.2 Skill自动提取触发条件

| 触发条件 | 说明 |
|---------|------|
| 同类任务完成3次+ | 相同类型任务成功执行3次以上 |
| Token消耗降低>30% | 某类任务后续执行Token消耗显著降低 |
| 用户满意标记 | 用户对特定类型任务明确表示满意 |
| 子Agent复用 | 某类子Agent被重复创建3次以上 |

### 2.4 Skill淘汰机制

```
每周自动审计 → 检查每个Skill的：
  ├─ 最近30天调用次数（< 2 → 标记冷门）
  ├─ 最近10次成功率（< 70% → 标记低质）
  ├─ 与新增Skill的功能重叠度（> 80% → 标记冗余）
  └─ Token消耗趋势（上升 → 标记退化）

淘汰决策矩阵：
  冷门 + 冗余 → 自动淘汰
  低质 + 退化 → 进入观察期（7天），期满淘汰
  低质 + 无替代 → 触发重新训练
```

## 三、Token效率优化（对标GenericAgent 6x提升）

### 3.1 上下文信息密度最大化 (CIDM)

```
传统方式：完整上下文 → LLM → 输出
           (Token 100%)

CIDM：     完整上下文 → 压缩摘要 → LLM → 输出
           (Token 100%)   (Token 17%)  = 6x节省
```

### 3.2 实现策略

1. **增量上下文**：只发送变更部分，而非完整历史
2. **分层记忆**：热记忆(全量) → 温记忆(摘要) → 冷记忆(索引)
3. **结构化压缩**：保留关键决策+参数，丢弃冗余推理过程
4. **Schema缓存**：工具Schema预加载，不重复发送
