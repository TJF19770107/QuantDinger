# 龙虾-三层GUI感知行动协议 v1.0

> **对标来源**：GUI Agent架构设计 + Codex Appshots + Claude Computer Use + Accessibility API vs Screenshot
> **版本**：v1.0 | **创建日期**：2026-06-01 | **所属迭代**：R19
> **核心价值**：感知层→决策层→执行层三层架构，优先级元素定位策略，安全沙箱化UI操作

---

## 一、协议概述

采用"感知-决策-执行"三层架构，通过多模态感知（OCR+CV+Accessibility API）解析界面状态，由LLM推理生成操作指令，在沙箱环境中安全执行UI自动化。

---

## 二、三层架构

```
┌─────────────────────────────────────────────┐
│  感知层：OCR + CV + Accessibility API + DOM  │
│  输出：结构化界面状态（元素树+坐标+文本）     │
├─────────────────────────────────────────────┤
│  决策层：规则引擎 + LLM推理                  │
│  输出：操作指令序列                          │
├─────────────────────────────────────────────┤
│  执行层：键盘鼠标模拟 / API调用               │
│  输出：操作结果 + 状态验证                    │
└─────────────────────────────────────────────┘
```

---

## 三、元素定位优先级

| 优先级 | 策略 | 稳定性 | 示例 |
|--------|------|--------|------|
| 🥇 第1优先 | **文本匹配** | 最高 | "提交"按钮的文本内容 |
| 🥈 第2优先 | **布局路径** | 中 | "表单底部右侧按钮" |
| 🥉 第3优先 | **图像匹配** | 最低 | 图标/截图匹配 |

---

## 四、两种感知路线对比

| 维度 | Cloud+Screenshot | Local+Accessibility API |
|------|-----------------|------------------------|
| 数据隐私 | ❌ 截图上传云端 | ✅ UI数据本地 |
| 速度 | 慢（图像上传+模型推理） | 快（本地树遍历） |
| 可靠性 | 脆弱（视觉歧义） | 健壮（语义标识） |
| 跨平台 | ✅ 任何有屏幕的设备 | ❌ 操作系统特定 |
| 成本 | 高（视觉模型Token） | 低（本地处理） |
| Codex Appshots | ✅ 窗口文本+视觉 | — |

---

## 五、安全约束

| 层级 | 措施 |
|------|------|
| 权限隔离 | 沙箱环境运行Agent，限制系统文件访问 |
| 数据脱敏 | 密码/身份证号等敏感信息加密传输+临时存储 |
| 审计日志 | 全量操作轨迹记录，满足合规要求 |
| 人机闸门 | 高危操作（配置变更/删除）必须人工审批 |
| 验证循环 | 每步操作后验证预期状态变更确实发生 |

---

## 六、关键反模式（禁止）

- ❌ 无明确许可自动执行高影响操作
- ❌ 仅靠事后审计无撤销/预览机制
- ❌ 混淆模型置信度与业务规则验证
- ❌ 未经授权来源确认即提交变更
