## 一、协议概述

对标Gemini Spark的Task-Plan-Skill三元组架构，将豆包Agent的任务体系解耦为目标(Task)、触发条件(Plan)、执行能力(Skill)三个独立维度，实现15并发任务池管理。

---

## 二、Task-Plan-Skill 三元组模型

```
┌──────────────────────────────────────────────────┐
│                    Task（目标）                    │
│      "做什么" — 高层级目标、项目或对象              │
│      例：每2小时执行豆包全域迭代                    │
├──────────────────────────────────────────────────┤
│                    Plan（计划）                    │
│      "何时做" — 触发条件与调度规则                  │
│      cron时间 / 事件触发 / 条件触发                 │
├──────────────────────────────────────────────────┤
│                    Skill（技能）                   │
│      "怎么做" — 可复用指令+上下文+工具集             │
│      全网搜索 / 协议提取 / 能力融合 / 报告生成       │
└──────────────────────────────────────────────────┘
```

### 3.2 任务状态机

```
pending → running → review → done
              ↓         ↓
           failed → retry (max 3次)
              ↓
           dead (移至dead-letter队列)
```

### 3.3 优先级调度

```
P0 > P1 > P2

同优先级:
  - FIFO 基础排序
  - 等待时间超过阈值的P1任务自动提升至P0
  - P2任务在P0/P1全部空闲时执行
```

## 四、触发条件类型

| 类型 | 格式 | 示例 |
|------|------|------|
| cron定时 | 标准cron表达式 | `0 */2 * * *` |
| 事件触发 | event:事件名 | `event:咒语激活` |
| 条件触发 | condition:条件表达式 | `condition:delta>0.05` |
| 链式触发 | after:任务ID完成 | `after:T1_done` |
| 手动触发 | manual:用户指令 | `manual:立即执行全域迭代` |

## 六、任务并发控制

```
MAX_CONCURRENT = 15

约束:
  1. 同类型任务同时最多运行1个（去重）
  2. P0任务无限制
  3. P1任务在P0任务>3个时排队
  4. P2任务在P0+P1>8个时排队
  5. 单个任务超时上限：L1=5min / L2=30min / L3=2h

资源保护:
  - Token消耗超阈值 → 暂停P2任务
  - CPU/内存超80% → 暂停非P0任务
  - 网络中断 → 所有任务自动降级为本地模式
```
