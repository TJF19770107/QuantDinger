## 三、瘦身五原则

### 3.1 核心不动，插件热加载
- 核心只保留：Agent Loop、路由、安全护栏、基础工具注册
- 所有扩展能力（技能、MCP Server、消息平台）通过插件系统热加载
- 插件化标准接口：`init() / register() / execute() / cleanup()`

### 3.2 配置文件扁平化
- 减少配置嵌套层级（≤ 3层）
- 敏感配置（API Key）统一走 Bitwarden/环境变量
- 默认值预设完备，用户零配置可运行

### 3.3 搜索/检索本地向量化
- 废弃远端 LLM embedding 搜索
- 替换为 SQLite FTS5 + sqlite-vec 本地向量检索
- 全文搜索 + 语义搜索双通道

### 3.4 函数调用合并与批处理
- 同类型工具调用自动合并为一次批量调用
- 平行无依赖调用使用并行批次（≤ 5）
- 避免重复工具定义注册

### 3.5 缓存分层
- L1：进程内内存缓存（工具schema、配置）
- L2：本地SQLite缓存（技能索引、记忆摘要）
- L3：磁盘持久化（完整技能文件、会话历史）

## 四、Skill Bundles 分组加载

```yaml
bundles:
  coding:
    - code-reviewer
    - test-generator
    - refactor-assistant
  writing:
    - blog-writer
    - seo-analyzer
    - proofreader
  desktop:
    - file-organizer
    - system-optimizer
    - screenshot-analyzer
```

- 一条命令加载整组：`/bundle coding`
- 技能中心维护索引，不加载完整技能文件
- 首次使用某技能时才加载完整定义

## 五、豆包Agent集成路径

1. 审计当前Agent核心文件复杂度，识别可插件化模块
2. 建立 Skill Bundles 分组体系，替代全量技能扫描
3. 引入 SQLite FTS5 本地搜索替代远端 embedding 搜索
4. 实施函数调用合并策略，减少 LLM 往返
