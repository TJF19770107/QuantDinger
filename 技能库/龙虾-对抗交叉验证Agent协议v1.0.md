# 龙虾-对抗交叉验证Agent协议 v1.0

> **版本**：v1.0
> **对标来源**：Claude Opus 4.8 Dynamic Workflows + Hermes v0.15 Kanban Swarm
> **生效范围**：多Agent协同 / 代码质量保障
> **创建日期**：2026-06-01（R15）

---

## 一、核心定义

在多Agent协作中，引入专门的对抗Agent（Adversarial Agent）对主执行Agent的输出进行证伪和交叉验证，形成"生成→质疑→修复→收敛"闭环，直到答案信度达到阈值。

## 二、架构设计

```
主任务拆解（Planner）
    ↓
并行子Agent执行（Workers × N）
    ↓
对抗Agent证伪（Adversarial × M）
    ├── 发现漏洞 → 修复Agent介入
    ├── 发现逻辑矛盾 → 反馈Worker修正
    └── 验证通过 → 收敛标记
    ↓
合成Agent汇总（Synthesizer）
    ↓
最终审查（Reviewer）
    ↓
输出
```

## 三、关键机制

### 3.1 对抗Agent职责
- **证伪优先**：假设主Agent输出有误，主动寻找漏洞
- **逻辑一致性检查**：检测输出中的逻辑矛盾和自相冲突
- **边界条件测试**：对代码输出进行边界值/异常输入测试
- **诚实度审计**：标记Agent"不确定但未声明的部分"

### 3.2 收敛判定规则
```
收敛条件（满足任一即收敛）：
1. 对抗Agent连续2轮未发现新问题
2. 修复轮次达到上限（默认3轮）
3. 问题严重等级全部降至Low以下
4. 用户手动确认通过

不收敛处理：
→ 降级为人工审核模式
→ 标记为"需人工介入"
→ 输出已确认部分 + 争议部分
```

### 3.3 双Agent代码审查模式
- 每个文件由2个审查Agent独立审阅
- 修复循环驱动构建和测试套件
- 直到构建+测试全通过

## 四、模式选择

| 模式 | 对抗Agent数 | 适用场景 | Token消耗 |
|------|-----------|---------|----------|
| 轻量 | 1 | 日常代码审查 | 低 |
| 标准 | 2 | 重要功能开发 | 中 |
| 严格 | 3+ | 核心安全代码 | 高 |
