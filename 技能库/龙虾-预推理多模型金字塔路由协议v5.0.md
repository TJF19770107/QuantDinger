## 二、v5.0核心突破: 预推理动态路由

### 2.1 RouteMoA三步骤

```
传统MoA/Sparse MoA:
所有模型推理 → 筛选 → 融合  (成本高，先推理才能选)

RouteMoA (本协议):
① 先验筛选 → ② 后验修正 → ③ 综合排序
(不推理就判断，成本降89.8%)
```

### 2.2 三步详解

#### Step 1: 先验筛选 (Pre-Inference Scoring)

| 参数 | 说明 |
|------|------|
| 输入 | 仅用户Query |
| 方式 | 轻量级Scorer预测每个模型潜在表现 |
| 成本 | **不需要调用大模型推理** |
| 效果 | 模型池从15个缩小到3-5个潜力子集 |
| 命中率 | Top-3内命中正确模型概率≈98% |

**核心洞察**: 用Query本身的信息，提前判断模型能力匹配度。绝大多数Query上真正关键的模型只占少数。

#### Step 2: 后验修正 (Post-Inference Correction)

| 机制 | 说明 |
|------|------|
| Self-Assessment | 模型对自己的答案打分 |
| Cross-Assessment | 高质量模型评估其他模型 |
| 成本 | **只基于已生成的输出，不引入额外推理调用** |
| 目标 | 修正先验筛选的误差 |

#### Step 3: 综合排序 (Multi-Objective Ranking)

| 维度 | 权重 |
|------|------|
| 输出质量 | 高 |
| Token成本 | 中 |
| 推理延迟 | 中 |
| 模型可用性 | 动态 |

**工程最优而非单纯追求accuracy。**

### 2.3 关键数据

|------|:---:|
| 成本降低 | **-89.8%** |
| 延迟降低 | **-63.6%** |

### 2.4 重要洞察: 瓶颈正在转移

RouteMoA论文发现：
- **50%+的错误来自最终答案融合阶段（aggregation drift）**
- 真正因选错模型的比例**低得多**
- 多模型系统的瓶颈从"选谁来回答"转向"**如何整合多个答案**"

### 3.2 预推理路由决策流程

```
用户Query
  ↓
复杂度评估 (轻量Scorer)
  ↓
先验筛选 (不推理，预测3-5个候选)
  ↓
Task→层级映射
  ├─ 简单分类 → L0/L1
  ├─ 代码审查 → L3
  ├─ 复杂推理 → L4
  ├─ 多步Agent → L5/L6
  └─ 多模态 → 全模态统一框架
  ↓
候选模型并行推理 (仅Top3-5)
  ↓
后验修正 (Self+Cross Assessment)
  ↓
综合排序 → 选择最优 → 输出
```
