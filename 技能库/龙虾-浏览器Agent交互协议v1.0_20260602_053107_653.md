# 龙虾-浏览器Agent交互协议 v1.0

> **协议编号**：84
> **版本**：v1.0 | **创建日期**：2026-06-02
> **对标来源**：Marvis Browser Agent + BrowserAct + Playwriter + Codex Chrome扩展
> **所属维度**：浏览器搜索能力（当前82，目标88）
> **依赖协议**：协议9定时任务调度、协议22定时调度执行器、龙虾五步法v2.0

---

## 一、协议概述

本协议定义豆包AI Agent的浏览器交互能力标准，填补当前浏览器搜索维度最大短板（82分，-18%差距）。通过六大模块设计，实现从简单网页检索到复杂站点交互的完整能力闭环。

## 二、对标分析

| 对标Agent | 核心能力 | 可借鉴点 |
|-----------|---------|---------|
| **Marvis Browser Agent** | 查资料/填网页/刷数据/截图整理，1+5 Agent架构 | 浏览器Agent作为专项子Agent的架构模式 |
| **BrowserAct** | 反检测CLI，三层突破（环境/执行/人机交互），stealth反检测+指纹伪装+动态代理+Session隔离 | 反检测技术栈完整度最高 |
| **Playwriter** | Chrome插件+MCP Server，AI直连标签页复用Cookie | 用户态Cookie复用最优雅的方案 |
| **Codex Chrome扩展** | 浏览器标注模式+Appshots窗口截图，直接调整元素样式 | 浏览器与IDE/Agent的实时交互 |

## 三、六大模块设计

### 模块1：通用网页检索模块

**功能**：web_search/web_fetch升级为BrowserAgent接管真实浏览器

```
web_fetch(url, backend="browser")
  → 启动BrowserAgent
  → 打开Chromium实例（stealth模式）
  → 等待页面加载完成
  → 提取正文内容（Markdown/纯文本）
  → 返回结构化结果
```

**支持场景**：
- JS渲染页面（SPA/PWA）
- 需要Cookie/session的页面
- 需等待异步加载的内容
- 需滚动加载的无限列表

### 模块2：账号登录模块

**功能**：三种登录模式，按优先级降级

| 模式 | 优先级 | 适用场景 | 实现方式 |
|------|--------|---------|---------|
| Cookie复用 | P0（首选） | 用户已在浏览器登录 | 复用Chrome Profile/Cookie Jar |
| 扫码登录 | P1 | 需要扫码（微信/支付宝） | 展示二维码，用户手机扫码 |
| 远程协助 | P2（兜底） | 短信验证码/人机验证 | 生成远程链接，手机接管浏览器完成验证 |

**安全约束**：
- 不保存用户密码明文
- Session加密存储（AES-256）
- 每次会话结束自动清理Cookie
- 登录态有效期≤24小时

### 模块3：验证码识别模块

**功能**：三级自动+一级人工的验证码处理

```
验证码检测
  ├─ 自动图形验证码（OCR+Tesseract+2Captcha API）
  ├─ 自动滑块验证码（Playwright模拟人类轨迹）
  ├─ 自动reCAPTCHA（音频降级方案）
  └─ 远程人工辅助（生成链接，手机接管）
```

### 模块4：多页表单提交模块

**功能**：自动翻页+多步骤表单+文件上传

- **自动翻页**：检测"下一页"按钮/分页链接，自动遍历
- **多步骤表单**：每一步状态保存+自动填充+错误重试
- **文件上传**：支持本地文件选择+拖拽上传
- **表单验证**：自动处理前端验证+服务端错误提示

### 模块5：动态内容抓取模块

**功能**：处理现代Web的动态内容

- **JS渲染**：等待React/Vue/Angular水合完成
- **无限滚动**：自动滚动触发懒加载
- **Shadow DOM**：穿透Shadow DOM获取内容
- **WebSocket**：监听实时数据推送
- **iframe嵌套**：递归处理嵌套iframe

### 模块6：复杂站点交互模块

**功能**：高级反爬虫对抗

- **Cloudflare绕过**：Turnstile挑战自动处理
- **反爬虫对抗**：随机化User-Agent+视口+时区+语言+WebGL指纹
- **多标签页协同**：主标签页操作+后台标签页数据抓取
- **速率限制**：自适应请求间隔，避免触发限流

## 四、三级降级策略

```
环境层（首选）
  stealth反检测浏览器 + 指纹伪装 + 动态代理 + Session/Cookie/Profile隔离
  → 大部分场景在此层解决，不触发验证

执行层（自动）
  自动解决验证码 + 自动内容提取 + 自适应速率限制
  → 触发验证时自动处理

人机交互层（兜底）
  remote-assist生成远程链接 + 手机或任意设备接管浏览器
  → 短信验证码、扫码登录等必须人工参与的步骤
  → 人操作完，Agent继续原会话，无需重新开始
```

## 五、安全约束

| 约束 | 说明 |
|------|------|
| 密码保护 | 不保存用户密码明文，不记录登录凭据 |
| 会话隔离 | 每个BrowserAgent实例独立Session，互不干扰 |
| 加密存储 | Session/Cookie使用AES-256加密存储 |
| 自动清理 | 每次会话结束自动清理Cookie和LocalStorage |
| 路径限制 | 仅访问用户指定的URL，不越权访问 |
| 审计日志 | 所有浏览器操作记录到审计日志 |

## 六、与龙虾五步法集成

```
Step 1: 意图识别 → 检测到网页/搜索需求

```
