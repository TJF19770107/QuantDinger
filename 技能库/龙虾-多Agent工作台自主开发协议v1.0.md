# 多Agent工作台自主开发协议 v1.0

> **版本**: v1.0 · 2026-06-01
> **协议编号**: #82
> **对标来源**: Qoder 1.0 (阿里云 · 2026-05-15)
> **核心价值**: Agent团队自主执行/验证/交付 + 需求→代码全闭环

---

## 一、协议概述

多Agent工作台自主开发协议定义了从传统AI IDE升级为多Agent自主开发工作台的标准化流程。Agent团队不再只是被动等待指令的编码助手，而是能够自主完成需求理解→方案设计→编码实现→测试验证→交付的全流程"自动驾驶"。

---

## 二、四阶段自主开发流水线

```
需求定义 → 方案设计 → 并行开发 → 验证交付
   │          │          │          │
用户介入    Planner    Coder×N    Reviewer
(仅定义)   (自动)     (自动)     (自动)
```

### 2.1 需求定义阶段
- 用户用自然语言描述需求（功能/约束/验收标准）
- Agent自动解析需求→生成结构化需求文档
- 模糊需求自动追问澄清（最多3轮）

### 2.2 方案设计阶段
- Planner自动分析需求→拆解为子任务→分配Agent团队
- 生成技术方案文档（架构图/接口定义/数据模型）
- 方案经内部Review→自动调整→提交用户确认（可选）

### 2.3 并行开发阶段
- 多个Coder Agent并行开发不同模块
- 实时共享上下文：类型定义/接口契约/公共组件
- 冲突检测：自动感知并发修改冲突→Coordinator仲裁

### 2.4 验证交付阶段
- Reviewer自动执行测试套件→代码审查→集成测试
- 发现问题自动回退给Coder修复
- 全绿通过后生成交付包+变更日志

## 三、开发工作台能力矩阵

| 能力 | 传统AI IDE | 多Agent工作台 |
|------|-----------|-------------|
| 代码生成 | 单文件补全 | 多文件协同生成 |
| 调试 | 需人工触发 | 自动感知错误+自愈修复 |
| 测试 | 手动编写 | 自动生成+执行+修复 |
| 重构 | 单文件 | 全栈联动重构 |
| 部署 | 需人工 | Agent自主构建+部署 |
| 上下文 | 当前文件 | 全项目+跨项目知识库 |

---

## 四、Agent团队编排

### 4.1 默认团队配置
```
开发任务 → 
  Lead Developer (架构设计+关键模块)
  + Frontend Developer (前端)
  + Backend Developer (后端API)
  + Test Engineer (测试用例+自动化测试)
  + DevOps Agent (构建+部署)
```

### 4.2 动态扩缩
- 简单任务：1个全栈Agent即可
- 中等任务：3-5个Agent并行
- 复杂任务：根据Planner拆解的子任务数动态分配（上限10个）

---

## 五、执行规范

1. **需求冻结**：开发启动后，需求变更必须重新走Planner设计流程
2. **上下文共享**：所有Agent共享类型定义/接口契约/设计文档，避免信息孤岛
3. **冲突检测**：两个Agent修改同一文件时，后提交的自动Merge或请求Coordinator仲裁
4. **失败回退**：单Agent失败不影响其他Agent，Coordinator自动重新分配
5. **交付标准**：所有测试通过 + 代码审查通过 + 部署验证通过 = 交付

---

## 七、安全约束

1. Agent生成的代码必须经过安全扫描（SQL注入/XSS/硬编码密钥等）
2. 部署操作必须人工确认（🔴高风险）
3. Agent不得修改项目中的安全配置文件（.env/.gitignore/安全策略）
4. 外部依赖安装必须经Coordinator审批并记录
5. 生成的代码禁止包含后门/恶意逻辑/未经授权的网络请求
