## 一、核心定义

Dynamic Workflow（动态工作流）是一种**主Agent自主生成编排脚本、并行调动数十至数百子Agent**的极长周期执行模式。

与普通多Agent的区别：
- 普通多Agent：主Agent手写步骤 → 逐个执行
- Dynamic Workflow：主Agent写编排器 → 编排器自动生成DAG → 并行执行 → 对抗验证 → 合并

## 二、工作流四阶段

### 阶段1：编排生成（Orchestration）

```
用户目标 → 主Agent分析 → 生成编排DAG
     ↓
┌──────────────────────────────────┐
│ 编排脚本自动：                    │
│ - 任务依赖树生成                  │
│ - 并行度计算                      │
│ - 子Agent角色分配                 │
│ - 合并策略制定                    │
└──────────────────────────────────┘
```

### 阶段2：并行执行（Execution）

```
编排DAG → 扇出
    ├→ Agent_01 (file rename batch) ──┐
    ├→ Agent_02 (API migration)    ──┤
    ├→ Agent_03 (test suite)       ──┤
    ├→ Agent_04 (docs update)      ──┤
    ├→ ...                              ├→ 结果池
    ├→ Agent_N (config migration)  ──┤
    └→ Agent_N+1 (...)             ──┘
```

关键约束：
- 子Agent拥有独立上下文/工具集/迭代预算
- 子Agent不接收其他Agent的中间执行过程
- 只接收结构化结果（status + summary + diff + token_cost）

### 阶段3：对抗验证（Adversarial Validation）

```
结果池 → 独立Review Agent
         ├→ Review-A: 功能正确性审查
         ├→ Review-B: 安全/边界条件审查
         ├→ Review-C: 性能回归审查
         └→ Review-D: 代码风格/规范审查
              ↓
         多方意见收敛 → 通过/驳回
              ↓
         驳回 → 触发修复子Agent
              ↓
         第二轮审查（强制双轮）
```

### 阶段4：合并与存档（Merge & Checkpoint）

```
全部通过 → 自动merge
     ↓
增量存档：每完成N个任务自动checkpoint
     ↓
断点续传：中断后从最近checkpoint恢复
     ↓
最终产物 + 执行日志归档
```

## 三、豆包Dynamic WF实现方案

### 3.1 最小可行架构

```
                       ┌─────────────┐
                       │  Orchestrator│
                       │  (编排脚本)   │
                       └──────┬──────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐
        │ Code     │   │ Review   │   │ Test     │
        │ Agent_1  │   │ Agent_2  │   │ Agent_3  │
        └──────────┘   └──────────┘   └──────────┘
              │               │               │
              └───────────────┼───────────────┘
                              ▼
                    ┌─────────────────┐
                    │  Result Merger   │
                    │  + Checkpoint    │
                    └─────────────────┘
```

### 3.2 临时实现路径（R02可达）

1. **编排脚本生成**：主Agent分析用户目标，生成Python编排DAG
2. **并行spawn**：通过dispatch_task并行派发（受限于当前架构，先支持≤5并行）
3. **Review双审**：独立的Review Agent对产出做两轮审查
4. **Checkpoint**：使用SQLite记录进度，支持中断恢复
5. **目标规模**：初期支持10~20子Agent并行，逐步扩展至100+

### 3.3 触发条件

以下场景自动触发Dynamic Workflow：
- 涉及50+文件的代码迁移/重构
- 跨3+模块的API变更
- 全量测试套件重写
- 用户明确要求"ultracode"模式
