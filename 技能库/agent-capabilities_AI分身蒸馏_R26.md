| 超时时间 | 30分钟 | 30分钟 | — |
| 心跳间隔 | 30秒 | **15秒** | 缩短50% |
| 强制释放 | 手动命令 | 手动命令 + 自动检测残留 | 增强 |
| 心跳僵死判定 | 无 | 超15秒无心跳自动释放 | **新增** |

### 4.2 锁状态流转

```
IDLE → 步骤1启动(获取锁) → ACQUIRED
ACQUIRED → 心跳(每15秒) → ACQUIRED
ACQUIRED → 步骤完成(更新心跳) → ACQUIRED
ACQUIRED → 步骤6完成(释放锁) → IDLE
ACQUIRED → 僵死(>15秒无心跳) → TIMEOUT(自动释放) → IDLE
ACQUIRED → 超时(>30分钟) → TIMEOUT(告警) → IDLE
```

## 五、R26新增能力项详细说明

### 5.1 Goal模式持久化执行

**来源**: Claude Code Stop Hook + Codex goal模式 + Hermes五层防烂尾

**实现组件**:

| 组件 | 来源 | R26实现 | 防护目标 |
|------|------|------|------|
| 心跳检测 | Claude Code | 每15秒写入蒸馏日志 | 进程僵死 |
| 退出拦截 | Codex | 每步骤后检查产出文件IO存在 | 提前退出 |
| 幻觉拦截 | Hermes | G1门控磁盘IO验证 | 谎报完成 |
| 重试预算 | — | 单步骤最多3次，退避策略 | Token成本 |

**启用规则**: 六步全流程默认启用，可通过 `goal_mode=false` 参数关闭

### 5.2 执行可验证性

**来源**: SOUL v2.2 "不盲信"红线落地

**验证点**:
1. 每步骤产出文件须通过 `os.path.exists()` + `os.path.getsize()` IO级验证
2. MD5校验与源文件对比（G2门控）
3. 路径合规性检查（G3门控）
4. 抽查关键词验证（全域同步时）

**禁止行为**:
- ❌ 仅凭工具返回的"success"字样判断完成
- ❌ 依赖文件系统缓存而不做IO验证
- ❌ 在G5交叉验证完成前声明"全局一致"
