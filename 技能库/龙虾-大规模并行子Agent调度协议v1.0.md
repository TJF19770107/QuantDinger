## 一、协议来源

- **Claude Opus 4.8 Dynamic Workflows**：单会话内启动数十至数百并行子Agent，Bun Zig→Rust 75万行迁移11天完成，99.8%测试通过率
- **Hermes Swarm v1**：DAG拓扑自动分解 + 并行Worker + 验证器 + 合成器 + 共享黑板

---

## 二、四大核心组件

### 2.1 DAG拓扑分解器
```
复杂任务
  ├── 子任务A（可并行）
  ├── 子任务B（可并行）
  ├── 子任务C（依赖A完成）
  └── 子任务D（依赖A+B完成）
```

- 自动识别任务依赖关系
- 生成最优并行执行DAG
- 关键路径分析，预测总耗时

### 2.2 并行调度引擎
- 管理数十至数百子Agent生命周期
- 模型分层调度：轻量任务用便宜模型，复杂任务用旗舰模型
- 每个子任务独立 worktree/Git worktree 隔离
- 资源池管理：最大并行数、超时熔断

### 2.3 对抗验证Agent
- 独立Agent尝试证伪前序结论
- 交叉验证：两个Agent独立执行，结果不一致触发深度审查
- 自检闭环：Agent完成工作后自查输出

### 2.4 共享黑板（Shared Blackboard）
- 子Agent间实时通信通道
- 结构化消息：task_claim / result_post / conflict_alert / status_update
- 支持订阅模式：Agent只关注相关话题

---

## 三、执行流程

```
1. 用户任务输入
       ↓
2. Orchestrator 接收 → DAG拓扑分解
       ↓
3. 并行调度引擎分配子Agent（模型分层）
       ↓
4. 各子Agent独立执行（worktree隔离 + 共享黑板通信）
       ↓
5. 对抗Agent交叉验证 → 不通过 → 重新分配
       ↓ 通过
6. 合成器汇总结果 → 断点快照保存
       ↓
7. 用户汇报 → 断点恢复支持（中断后继续）
```

---

## 四、断点恢复机制

| 场景 | 恢复策略 |
|------|---------|
| 单个子Agent失败 | 自动重试（最多2次），失败后降级 |
| Orchestrator崩溃 | 检查点快照恢复，跳过已完成子任务 |
| 用户中断 | 保存所有子任务状态，下次继续 |
| 模型不可用 | 自动切换备用模型，延续上下文 |
