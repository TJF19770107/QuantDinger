# 文本空间技能可控优化协议 v1.0

> **版本**: v1.0 · 2026-06-01
> **协议编号**: #80
> **对标来源**: SkillOpt (ByteDance · 2026-05-25)
> **论文**: arxiv.org/abs/2605.23904
> **核心价值**: 独立优化器+文本学习率预算+拒绝编辑缓存+跨模型迁移

---

## 一、协议概述

文本空间技能可控优化协议定义了首个系统化可控的Agent技能优化框架。将Agent技能文档视为可训练的外部状态，通过独立的优化器模型生成精确的文本编辑操作，像权重空间优化一样稳定可复现，零推理开销。

---

## 二、核心三组件

### 2.1 独立优化器模型（Skill Optimizer）
- 独立的轻量模型，不增加Agent部署时的推理开销
- 输入：当前技能文档 + 执行轨迹反馈 + 得分
- 输出：精确的编辑操作（增/删/改），定位到具体行/段落

### 2.2 文本学习率预算（Textual LR Budget）
- 控制每次优化编辑的幅度，防止过度修改
- 预算单位：字符数/段落数/语义变更级别
- 初始预算较大→随迭代递减，模拟权重空间的learning rate衰减

### 2.3 拒绝编辑缓存（Rejected Edit Cache）
- 保留历史上被拒绝的编辑操作及其失败原因
- 优化器提出新编辑前先查询缓存，避免重复尝试已失败的编辑
- 缓存过期策略：相同技能+相同得分区间时保留；技能版本升级后清空

---

## 三、分阶段慢速元更新

```
Phase 1: 单技能微调 (Per-Skill Fine-tuning)
  → 独立优化每个技能文档，收集编辑模式

Phase 2: 跨技能元学习 (Cross-Skill Meta-Learning)
  → 从多个技能的编辑模式中提取通用编辑策略

Phase 3: 慢速元更新 (Slow Meta-Update)
  → 以低频率(每N轮)更新优化器自身的编辑策略
  → N ≥ 10，确保元更新稳定不震荡
```

---

## 四、执行规范

### 4.1 优化触发条件
- 技能执行后得分低于阈值（默认 <0.7）
- 同一技能连续3次执行得分下降
- 人工触发优化指令

### 4.2 编辑操作规范
| 操作 | 格式 | 约束 |
|------|------|------|
| INSERT | 在{位置}后插入{内容} | 单次≤50字 |
| DELETE | 删除{范围}的{内容} | 单次≤30字 |
| REPLACE | 将{原文}替换为{新文} | diff≤原文长度的30% |

### 4.3 验证与接受
1. 编辑后必须在验证集上测试（≥10个案例）
2. 验证集得分提升→接受编辑→写入技能文档
3. 验证集得分未提升→拒绝编辑→加入缓存
4. 连续5次拒绝触发技能版本冻结

---

## 五、跨模型迁移规范

1. 优化后的技能文档保留原始语义结构
2. 迁移到不同模型时，仅需重置文本学习率预算
3. 优化器生成的编辑操作不包含模型特定参数
4. 跨环境迁移前先执行3次验证运行确认兼容性

---

## 六、安全约束

1. 优化器不得修改技能文档中的安全约束章节
2. 涉及系统权限的编辑必须经独立审批
3. 生产环境中的技能优化必须在非高峰时段执行
4. 被拒绝的编辑不得绕过缓存机制强行提交
