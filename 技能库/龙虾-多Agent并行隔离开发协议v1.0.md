## 一、协议目标

实现多个编码 Agent 在同一项目中的并行隔离开发，互不干扰，统一 Review。

---

## 二、核心架构

```
用户
  ↕
Host（豆包Agent / 龙虾主控）
  ↕
┌──────────────────────────────────┐
│  Air ADE 调度层                   │
│  ┌────────┐ ┌────────┐ ┌───────┐ │
│  │Agent A │ │Agent B │ │Agent C│ │
│  │独立 WS │ │独立 WS │ │独立WS │ │
│  │独立diff│ │独立diff│ │独立dif│ │
│  └────────┘ └────────┘ └───────┘ │
│         ↕ 统一 Review 面板 ↕       │
└──────────────────────────────────┘
  ↕
共享项目文件系统
```

---

## 三、工作空间隔离机制

### 3.1 独立命名空间

每个 Worker Agent 分配独立的工作空间容器：
- 文件级隔离：每个 Agent 看到自己的 diff 视图
- 变量级隔离：不会因为并行改同一文件而冲突
- Git 分支隔离：可选项，每个 Agent 操作独立分支

### 3.2 冲突检测规则

当多个 Agent 修改同一文件时：
1. 自动标记 `CONFLICT_PENDING`
2. 通知 Host Agent 进行裁决
3. Host 选择保留哪个版本或合并

## 四、统一 Review 面板

### 4.1 Review 流程

```
Agent A 完成 diff → 
Agent B 完成 diff → 
Agent C 完成 diff → 
        ↓
    统一 Review 面板
        ↓
    Host 逐 diff 审查
        ↓
    通过 → 合并 / 不通过 → 退回
```

### 4.2 Review 维度

| 维度 | 检查点 |
|------|--------|
| 正确性 | 代码逻辑是否符合需求 |
| 一致性 | 与其他 Agent 的改动是否冲突 |
| 安全性 | 是否引入安全漏洞 |
| 规范 | 是否符合项目代码规范 |
