# 龙虾三方握手学习报告（豆包–Trae–Hermes）

## 1) 三方架构现状（按职责分层）

- 豆包：对话/任务入口（人机交互中枢），负责下发指令与接收结果
- Trae：执行节点（本机 IDE/脚本/文件改动与沉淀），是唯一写入共享技能库与项目文件的执行者
- Hermes：技能/UI/网关节点（HTTP 服务），承载技能调用、状态转发与多端链路（端口随栈不同：18080 或 8642）

## 2) “分布式中心化”同步原则（核心口径）

- 中心化：共享技能库作为唯一公共入口（文档/索引权威源），三方只做只读消费与按需注入
- 分布式：豆包/Hermes/Trae 平等发起握手与任务；任一方离线可降级为两方或单机继续
- 同步对象优先级：规则口径/技能版本/索引一致性 > 运行态日志 > 业务数据

## 3) 断片/不同步的根因（本次定位到的关键点）

1. 多份“技能定义”来源并存：项目内 `.trae/skills` 已更新但系统级 `C:\Users\Administrator\.trae\skills` 未同步，会导致三方读到不同口径。  
2. 握手脚本与文档口径不一致：原 PowerShell 握手脚本存在“自动生成并写入密钥到用户环境变量”的副作用，违反密钥生命周期规则；且默认把状态文件写在 `.trae` 目录下，在当前执行环境会被拦截。  
3. 编码/路径兼容问题：读取 `INDEX.jsonl` / 中文路径时需强制 UTF-8，否则解析出来的路径会乱码，导致误判“共享文档不存在”。  
4. 端口口径混用：Hermes 可能在 18080（ai-hermes-2-1）或 8642（hermes-agent/gateway）对外服务；握手默认端口必须可参数化并在报告中给出证据。
