【Trae学习笔记】2026-04-30 | 主题：FRP 穿透 + 三方前台消息互通（对标学习）

## 1) 对标基线（本项目已有实现）

- 已存在 Doubao Bridge：对外提供 `POST /bridge/doubao/webhook`，并内置 `http://127.0.0.1:18091/monitor` 前台监控页（SSE 实时日志）。
- Bridge 通过 Hermes `/v1/runs` 执行并等待终态事件返回 reply（SSE：`run.completed`/`run.failed`），以 HTTP response 回填给豆包。
- 已存在 FRP 二进制与脚本：`frpc.exe/frps.exe` 与 `frp_start_doubao_tunnel.ps1` 等，可将本机端口映射到公网 frps 的 TCP 端口。

## 2) “前台肉眼可见互通”的实现方式（最佳实践）

- 为“执行节点（Trae）”补齐一个可见的前台收件箱：最小形态为一个本机 HTTP 服务 + 网页日志窗口（不写大文件）。
- Bridge 收到 webhook 后：
  1) 记录入站日志（前台可见）；
  2) 推送消息到 Trae 收件箱并获取回复（前台可见）；
  3) 异步触发 Hermes `/v1/runs`（让 Hermes WebUI 可见链路事件）；
  4) 将 Trae 回复通过 webhook response 回填豆包窗口（肉眼可见）。

## 3) FRP 穿透的“可验收”口径

- 目标：把本机 `127.0.0.1:18091` 暴露到公网 frps 的某个 TCP 端口（建议同端口 18091），供豆包云端 webhook 回调。
- 验收最小指标：
  - 公网 `<FRP_SERVER_ADDR>:<FRP_REMOTE_PORT>/bridge/health` 返回 200
  - 公网 `<FRP_SERVER_ADDR>:<FRP_REMOTE_PORT>/monitor` 可打开并实时刷新日志
  - 豆包端 webhook 设置为 `http://<FRP_SERVER_ADDR>:<FRP_REMOTE_PORT>/bridge/doubao/webhook` 后可收到回填 reply

## 4) 安全门禁（不泄密）

- 所有密钥仅以环境变量注入；日志中只记录 SET/EMPTY，不记录值。
- 本地验收旁路（`X-Lobster-Local-Test: 1`）仍受 webhook secret 门禁约束，用于避免在前台回显 trigger token。
