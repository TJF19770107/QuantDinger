## 5. 今日踩坑点与避坑要点（按优先级）

1) 404 风暴来源
   - 表现：Bridge 日志中出现大量 404（pull_failed / hermes_failed）。
   - 根因类别：旧版 outbox 轮询路径不可用或口径不一致；或 Hermes Base URL 指向了非 Hermes API 的端口/路径。
   - 避坑：默认禁用 outbox 轮询（DOUBAO_BRIDGE_ENABLE_OUTBOX_POLL=0），以 webhook 触发为主；统一 Hermes Base URL 指向真实 API（本机为 8642）。

2) 鉴权缺失会 401，不是 404
   - 验证：无 Key 调用 `/v1/runs` 会返回 401 invalid_api_key。
   - 避坑：只允许检查“是否已设置”而不输出明文；并在 Bridge/Wechat 等调用侧统一 Bearer 口径。

3) 202 状态码导致下游误判
   - 表现：Hermes /v1/runs 常返回 202（started），如果下游硬判 200 会误判失败。
   - 避坑：在 Bridge/通用桥接层做状态码归一（202→200）或按 2xx 统一成功口径。

4) SSE events 等待超时
   - 表现：`/v1/runs/{id}/events` 可能长时间无数据，requests 默认读超时易报 ReadTimeout。
   - 避坑：区分“连接超时”和“读取超时”；拉长读取超时或实现更稳健的 SSE 消费策略（以 run_timeout_s 为总上限）。
