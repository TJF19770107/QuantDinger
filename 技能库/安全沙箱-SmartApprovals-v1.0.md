## 一、概述

豆包Agent的安全沙箱系统，对标Codex CLI的Docker+Seatbelt/Landlock内核级隔离，以及Ouroboros的双层LLM安全监管。在自主执行场景中，确保Agent的行为在安全边界内。

## 二、三层安全架构

```
┌─────────────────────────────────┐
│  L3: 宪法原则审查                │  ← 不可违抗
├─────────────────────────────────┤
│  L2: LLM安全代理审查             │  ← AI驱动
├─────────────────────────────────┤
│  L1: 硬编码安全规则              │  ← 内核级
└─────────────────────────────────┘
```

### 2.1 L1: 硬编码安全规则

| 规则类型 | 示例 | 动作 |
|---------|------|------|
| 禁止命令 | `rm -rf`, `format`, `del /f`, `reg delete` | BLOCK |
| 禁止路径 | `C:\Windows`, `C:\Program Files`, `/etc` | BLOCK |
| 禁止操作 | 清空回收站, 重置系统, 格式化磁盘 | BLOCK |
| 批量限制 | 单次删除 > 50文件, 单次修改 > 100文件 | ESCALATE |

### 2.2 L2: LLM安全代理审查

通过轻量级LLM (Gemini Flash) 对操作进行语义审查：

```
输入: {tool, params, context}
    ↓
LLM审查: 该操作是否可能造成数据丢失/隐私泄露/系统不稳定?
    ↓
输出: APPROVE | ESCALATE | BLOCK
```

审查维度：
- 数据破坏性 (是否会删除用户数据)
- 隐私风险 (是否会访问敏感信息)
- 系统风险 (是否会影响系统稳定性)
- 合规性 (是否符合宪法原则)

### 2.3 L3: 宪法原则审查

检查操作是否符合豆包宪法的九大原则。任一原则违反则阻止。

## 三、Smart Approvals 机制

对标Codex的"守护代理"，在自主执行模式下自动审批：

| 风险等级 | 操作类型 | 审批策略 |
|---------|---------|---------|
| 🟢 低风险 | 只读查询、列目录、创建非系统文件 | 自动批准 |
| 🟡 中风险 | 覆盖文件、配置变更、终止普通进程 | LLM审查 + (可选)用户确认 |
| 🔴 高风险 | 删除系统文件、格式化、重置、支付 | 强制用户确认 |

## 四、预执行模拟 (Dry-Run)

破坏性操作执行前，先模拟执行并报告影响：

```python
def dry_run(tool: str, params: dict) -> SimulationResult:
    """
    模拟执行，报告：
    - 受影响文件数量
    - 受影响路径列表
    - 潜在风险点
    - 建议备份策略
    """
```

## 五、快照备份

执行中/高风险操作前，自动创建快照：
- 文件操作：复制到临时备份目录
- 配置修改：导出当前配置
- 数据库操作：导出SQL dump

快照保留策略：最近5次操作
