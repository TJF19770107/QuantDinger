> **对标来源**：Genesis Agent（Electron + Ollama）
> **创建时间**：2026-06-01（R19）
> **版本**：v1.0

---

## 一、协议概述

本协议提取自Genesis Agent的本地自进化闭环架构：Agent在封闭沙箱内可读取、分析、递归修改自身核心指令集，每次修改自动验证，失败回滚。完全离线运行，零Token费用，代表个人AI主权方向。

---

## 二、闭环架构

```
┌─────────────────────────────────────────┐
│           Electron Desktop Shell         │
│  ┌───────────────────────────────────┐  │
│  │        Ollama Local Inference      │  │
│  │  ┌─────────────────────────────┐  │  │
│  │  │    Genesis Agent Core       │  │  │
│  │  │                             │  │  │
│  │  │  1. READ  → 读取自身指令集  │  │  │
│  │  │  2. ANALYZE → 分析改进空间  │  │  │
│  │  │  3. REWRITE → 修改指令集    │  │  │
│  │  │  4. TEST → 自动验证         │  │  │
│  │  │  5. DEPLOY or ROLLBACK      │  │  │
│  │  └─────────────────────────────┘  │  │
│  └───────────────────────────────────┘  │
│          封闭沙箱 · 无外部依赖            │
└─────────────────────────────────────────┘
```

## 三、五步自指修改循环

### Step 1: READ — 读取自身

```
Agent读取：
- core_instructions.md（核心指令集）
- skill_registry.json（技能注册表）
- memory_index.sqlite（记忆索引）
- performance_log.jsonl（性能日志）
```

### Step 2: ANALYZE — 分析改进空间

```
分析维度：
- 指令冗余度：是否存在重复/矛盾的规则
- 技能缺失：近期任务失败是否因缺少某技能
- 性能瓶颈：哪些操作耗时超出阈值
- 记忆遗忘：哪些长期记忆模式应被强化
```

### Step 3: REWRITE — 安全修改

```
修改约束：
- 每次只修改一个文件
- 修改前创建检查点快照
- 修改范围限制在 ~/.genesis/ 目录
- 禁止修改沙箱边界配置
- 禁止修改认证/安全相关规则
```

### Step 4: TEST — 自动验证

```yaml
validation_suite:
  - test: "指令集无语法冲突"
    method: "parse_and_lint"
  - test: "核心功能回归"
    method: "run_benchmark_suite"
  - test: "沙箱边界未突破"
    method: "sandbox_integrity_check"
  - test: "性能未退化>5%"
    method: "perf_regression_test"
  threshold: "all_pass"
```

### Step 5: DEPLOY / ROLLBACK

```
所有测试通过 → 部署新指令集 + 记录checkpoint
任一测试失败 → 自动回滚到上一个checkpoint
                 + 记录失败原因到 self_evolution.log
```

## 四、检查点快照机制

```
~/.genesis/
├── checkpoints/
│   ├── cp_001_20260601_120000/  # 初始状态
│   ├── cp_002_20260601_140000/  # 第1次修改
│   └── cp_003_20260601_160000/  # 第2次修改
├── current/                      # 当前活跃指令集
└── self_evolution.log            # 进化日志
```

**回滚策略**：
- 最多保留10个检查点
- 回滚时恢复完整checkpoint目录
- 进化日志追加记录回滚原因

---

## 五、安全护栏

| 护栏 | 描述 |
|------|------|
| 文件边界 | 修改限制在 `~/.genesis/` 目录 |
| 规则锁定 | `core_instructions.md` 中以 `# IMMUTABLE` 标记的段落不可修改 |
| 网络隔离 | 沙箱内禁止出站网络请求 |
| 进程隔离 | Electron主进程与Agent渲染进程分离 |
| 审查日志 | 每次修改生成diff记录 |

---

## 六、完全离线优势

- 零Token费用
- 零网络依赖
- 数据永不出本地
- 个人AI主权：Agent完全属于用户
- 可审计：所有修改有完整diff记录

---

## 七、适用场景

- 个人AI助手本地自进化
- 隐私敏感场景的Agent部署
- 研究Agent自进化行为的实验平台
- 离线环境（内网/涉密）的Agent运行

## 八、关键约束

- `# IMMUTABLE` 标记段落绝对不可修改
- 沙箱边界配置不可通过自进化突破
- 每次修改必须通过完整验证套件
- 回滚阈值：核心功能测试任一失败即回滚
