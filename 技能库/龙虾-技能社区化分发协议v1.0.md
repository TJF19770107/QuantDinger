## 一、协议概述

### 1.1 问题定义
superpowers以近20万星登顶GitHub Trending，证明市场对"Agent技能标准化"的旺盛需求。当前龙虾45项技能协议已是内部标准，但缺少：①社区化分发机制 ②即插即用的Skill文件格式 ③TDD强制化的工作流。一个Skill应该是一个自包含的、定义Agent行为准则的独立文件。

### 1.2 核心价值
Skill不是工具，不是模型，而是**行为准则**。它告诉Agent在特定场景下应该如何思考、如何拆解任务、如何验证结果。superpowers的20+ Skill经过实战检验，可以像"给Agent安装专业技能包"一样使用。

## 二、Skill文件标准格式

### 2.1 Skill结构

```yaml
# skill_name: 技能名称
# version: 1.0
# author: 作者标识
# category: [coding|review|testing|deployment|workflow]
# platforms: [claude_code|codex|cursor|all]
---
name: "TDD-driven-feature-development"
version: "1.0"
description: "强制Agent按TDD方式开发新功能"

# 阶段1：思考与提问
phase_1_think:
  rules:
    - "在写任何代码前，先向用户提出3-5个澄清问题"
    - "确认技术栈、目标平台、边界条件"
    - "生成可读的spec.md供人类审批"
  forbidden:
    - "不得跳过审批直接写代码"

# 阶段2：任务拆解
phase_2_decompose:
  rules:
    - "将spec拆解为2-5分钟可完成的小任务"
    - "每个任务有精确的文件路径"
    - "每个任务有完整的代码需求和验证步骤"
  forbidden:
    - "不得生成超过10分钟的大任务"

# 阶段3：执行（TDD）
phase_3_execute:
  rules:
    - "先写失败测试"
    - "代码最少化通过测试"
    - "重构优化"
  forbidden:
    - "不得跳过测试直接写实现"
    - "不得一次性产出>100行新代码"

# 阶段4：双轮Review
phase_4_review:
  round_1:
    checker: "spec符合性检查"
    rules: ["代码是否完全满足spec", "是否遗漏功能点"]
  round_2:
    checker: "代码质量检查"
    rules: ["命名规范", "错误处理", "性能考量", "安全审计"]
```

### 2.2 Skill包结构
```
skill-package/
├── skill.yaml          # 技能定义文件
├── templates/          # 可选模板
│   ├── spec_template.md
│   └── test_template.py
├── examples/           # 使用示例
│   └── example_task.md
└── README.md           # 文档
```

## 四、TDD强制化工作流

### 4.1 三步循环
```
失败测试 ──→ 最少代码 ──→ 重构优化
   ↑                          │
   └──────── 循环 ────────────┘
```

### 4.2 强制规则
1. 新功能必须先写测试，测试必须先失败
2. 实现代码以"刚好通过测试"为目标
3. 通过后立即重构，保持代码整洁
4. 单次循环不超过5分钟
5. 每次循环生成一个子Agent任务

## 五、Skill生命周期管理

### 5.1 五阶段
```
创建 → 评估 → 发布 → 使用 → 废弃
```

### 5.2 评估维度（继承协议#22 Hermes Curator）
| 维度 | 权重 | 说明 |
|------|------|------|
| 有效性 | 40% | 是否真实改善Agent行为 |
| 通用性 | 25% | 跨场景可复用程度 |
| 简洁性 | 20% | Skill文件复杂度 |
| 安全性 | 15% | 是否引入新风险 |

### 5.3 社区贡献流程
1. Fork技能模板 → 2. 编写skill.yaml → 3. 本地测试 → 4. 提交PR → 5. 代码Review → 6. 合并发布
