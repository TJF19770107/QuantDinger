## 一、核心问题

GUI Agent在真实场景中的两大结构性短板：

| 短板 | 表现 | 根因 |
|------|------|------|
| **记不住** | 多步骤任务中早期关键信息丢失 → 误差累积 → 连锁失败 | 上下文窗口受限，只能依赖当前截图+有限上下文做决策 |
| **学不会** | 同样的错误反复犯，无法从成功经验中迁移 | 使用固定数据集训练的静态策略，无法在线学习 |

## 二、分层记忆结构（三层抽象）

```
L1 短期轨迹缓存（Episodic Buffer）
  ↓ 关键帧抽取
L2 关键帧记忆（Keyframe Memory）
  ↓ 语义压缩
L3 语义模式库（Semantic Pattern Library）
```

### 2.1 L1 短期轨迹缓存

- 最近N步的完整交互轨迹（截图→动作→结果）
- 容量有限，遵循FIFO淘汰
- 为L2提供原始素材

### 2.2 L2 关键帧抽取

- 从L1轨迹中识别"关键帧"——导致状态转折的操作时刻
- 关键帧判定标准：动作后环境状态发生显著变化
- 关键帧包含：前置截图、执行动作、后置截图、状态变化描述

### 2.3 L3 语义模式库

- 从多次成功/失败中抽象出可复用模式
- 模式结构：`{触发条件} → {推荐动作序列} → {预期结果}`
- 跨任务迁移：模式不绑定具体App，而是绑定交互语义类型

## 三、迭代自我改进循环

```
执行任务 → 记录轨迹 → 识别失败 → 因果分析 → 提炼模板 → 注入下次执行
```

### 3.1 执行与记录

- Agent执行GUI任务，完整记录每步的截图+动作+结果

### 3.2 失败因果分析

- 任务失败时回溯轨迹，定位**根因步骤**（非最近步骤）
- 因果链分析：`步骤A的决策 → 步骤B的受限 → 步骤C的失败`
- 防止"怪罪最后一环"的归因偏差

### 3.3 模板提炼

- 从失败根因中提取"应该怎么做"的正确模式
- 从成功轨迹中提取"这样做有效"的最佳实践
- 模板格式：`{当前状态特征} → {推荐动作} → [{备选动作}]`

### 3.4 上下文注入

- 下次执行同类任务时，将L3匹配的模板注入Agent上下文
- 注入方式：System Prompt追加 + 关键帧截图参考

## 四、静态→动态范式转换

| 维度 | 传统GUI Agent（静态） | SE-GA Agent（动态） |
|------|-------------------|-------------------|
| 策略来源 | 固定训练数据集 | 在线经验积累 |
| 记忆机制 | 仅上下文窗口 | 三层分层记忆 |
| 错误处理 | 重试/放弃 | 因果分析→模板提炼→下次避免 |
| 任务适应性 | 仅训练分布 | 持续适应新环境 |
| 知识积累 | 无 | L3语义模式库持续增长 |

## 五、部署架构

```
GUI Agent Runtime
├── Perception Module（截图→语义理解）
├── Action Module（语义→坐标→键鼠操作）
├── Memory Module [本协议核心]
│   ├── L1 Episodic Buffer（短期轨迹）
│   ├── L2 Keyframe Store（关键帧持久化）
│   └── L3 Pattern Library（语义模式库，SQLite存储）
└── Self-Evolution Module
    ├── Failure Causal Analyzer（失败因果分析）
    ├── Template Extractor（模板提炼）
    └── Context Injector（上下文注入）
```
