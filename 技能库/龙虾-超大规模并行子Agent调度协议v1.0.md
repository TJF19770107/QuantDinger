# 龙虾-超大规模并行子Agent调度协议 v1.0

> **对标来源**：Google Antigravity 2.0 (93子Agent并行构建OS)
> **创建日期**：2026-06-01 (R13)
> **版本**：v1.0

---

## 一、协议概述

支持主Agent动态生成数十至上百个子Agent并并行执行，实现超大规模任务分解与异步回调汇总。引入子Agent上下文隔离、动态工作流链式传递和成本预算控制。

## 二、核心机制

### 2.1 动态子Agent生成

主Agent面对复杂任务时：
1. 自动判断是否需要分解
2. 定义专用子Agent角色和技能范围
3. 动态生成子Agent实例
4. 分配独立上下文窗口

### 2.2 并行执行模型

```
主Agent (Orchestrator)
  ├─→ 子Agent A: 前端UI (独立上下文)
  ├─→ 子Agent B: 后端API (独立上下文)
  ├─→ 子Agent C: 测试用例 (独立上下文)
  ├─→ 子Agent D: 文档编写 (独立上下文)
  └─→ ... (最多N个子Agent并行)
       ↓
  异步回调汇总 → Orchestrator合并结果
```

### 2.3 上下文隔离

- 每个子Agent拥有独立上下文窗口
- 避免主Agent上下文被无关任务信息污染
- 子Agent间通过结构化消息通信，不共享上下文

### 2.4 动态工作流链

```
Agent A 完成 → 结果传递 → Agent B 继续处理 → Agent C 最终汇总
                                  ↓
                            条件分支/异常处理
```

### 2.5 异步任务管理

| 特性 | 说明 |
|------|------|
| 非阻塞执行 | 子Agent后台运行，主Agent不等待 |
| 进度追踪 | 实时监控每个子Agent状态 |
| 超时熔断 | 单子Agent超时自动终止并上报 |
| 结果汇聚 | 所有子Agent完成后统一汇总 |

## 三、成本控制

| 策略 | 说明 |
|------|------|
| 预算上限 | 单任务设置token/成本上限 |
| 优先级排序 | 核心子Agent优先执行 |
| 动态降级 | 预算不足时自动减少子Agent数量 |
| 模型分层 | 简单任务使用轻量模型，复杂任务使用强模型 |

## 四、与现有dispatch_task的关系

| 维度 | 当前dispatch_task | 协议54升级 |
|------|------------------|-----------|
| 并行数 | 单次1个 | 单次N个（N≤100） |
| 上下文 | 共享主Agent | 子Agent独立隔离 |
| 回调 | 同步等待 | 异步回调汇总 |
| 工作流 | 无链式 | 支持A→B→C链式 |

## 五、豆包Agent适配方案

1. dispatch_task 扩展batch模式，支持一次派发多个子Agent
2. 引入子Agent上下文隔离机制
3. 实现异步回调汇总器
4. 添加预算控制和模型分层调度
