## 三、五道质量门控

### 3.1 门控定义

| 门控 | 名称 | 检查内容 | 失败动作 | 历史通过率 |
|:---:|------|------|------|:---:|
| G1 | 实事求是 | 所有产出数据可追溯到真实文件/路径/时间戳，零虚构 | 标记步骤失败，重新执行 | 100% (15/15) |
| G2 | MD5去重 | 写入前MD5校验，重复文件跳过不覆盖 | 自动跳过+日志记录 | 100% (15/15) |
| G3 | 路径合规 | 产出文件写入正确目录，中间产物写入temp目录 | 自动修正路径+告警 | 100% (15/15) |
| G4 | 对标校验 | 对标矩阵得分不得低于上轮，技能协议总数不得减少 | 标记差异项，降级为信息性产出 | 100% (15/15) |
| G5 | 全局一致性 | SOUL/USER/AGENTS/角色总说明书四文件交叉验证无冲突 | 标记冲突项，延迟门控判决 | 100% (15/15) |

### 3.2 R26新增门控检查项

| 门控 | R26新增检查 | 目的 |
|:---:|------|------|
| G1 | 执行可验证性：产出物真实落盘确认（磁盘IO验证，非文件系统缓存） | 防止Agent谎报完成 |
| G2 | 新增文件扩展名与内容类型一致性校验 | 防止格式伪装 |
| G4 | 新增协议 #88 #90 正式转化的完整schema校验 | 协议质量保证 |
| G5 | 新增SOUL v2.2 "不盲信"红线在各子Agent config中的一致性 | 红线穿透验证 |

### 3.3 门控执行策略

```
每步骤完成后 → 触发对应门控
├─ 通过 → 进入下一步骤
├─ 警告（非致命偏差）→ 记录日志 + 继续执行
└─ 失败（门控阻断）→ 本步骤重试（最多3次）
    ├─ 3次内通过 → 继续执行
    └─ 3次全失败 → 跳过本步骤 + 告警 + 全局报告中标注
```

## 四、失败恢复策略

### 4.1 恢复层级

| 层级 | 名称 | 触发条件 | 恢复动作 | 超限动作 |
|:---:|------|------|------|------|
| L1 | 本步骤重试 | 单步骤工具调用失败 / 门控阻断 | 最多重试3次，间隔5秒递增 | 进入L2 |
| L2 | 步骤降级 | L1重试3次全部失败 | 跳过本步骤，产出标注为"降级完成" | 继续后续步骤 |
| L3 | 全流程告警 | 2个及以上步骤L2降级 | 生成异常报告 + 通知用户 | 等待下个周期自动重试 |
| L4 | 人工介入 | 连续2轮全流程降级 | 暂停定时任务 + 详细错误日志 | 人工排查后恢复 |

### 4.2 R26新增Goal模式恢复机制

| 机制 | 来源 | R26实现 | 作用 |
|------|------|------|------|
| 心跳检测 | Claude Code Stop Hook | 每15秒输出执行状态到蒸馏日志 | 防止进程僵死 |
| 退出拦截 | Codex goal模式 | 每步骤完成后自动检查产出文件是否真实存在 | 防止Agent提前结束 |
| 幻觉拦截 | Hermes五层防烂尾 | G1门控新增IO验证（非缓存判断） | 防止谎报完成 |
| 重试预算 | — | 单步骤最多3次重试，含退避策略 | Token成本控制 |

### 4.3 已知故障模式与应对

| 故障 | 出现频次 | 应对 |
|------|:---:|------|
| 文件路径权限拒绝 | 0次 | 自动切换备选路径 + 权限自检 |
| 大文件读取超时 | 1次(R16) | 分页读取 + offset续读 + 超时重试 |
| MD5哈希碰撞 | 0次 | SHA-256二次校验兜底 |
| 状态锁残留 | 1次(R21) | 30分钟超时自动释放 + 强制解锁命令 |

## 五、状态锁保护机制

### 5.1 锁定义

```
锁名称: distillation_lock_R{d轮次}
锁文件: E:\龙虾AI主控中心\我的AI分身\定时任务\.distillation_lock
锁类型: 文件锁（跨进程可见）
超时时间: 30分钟（单轮蒸馏最大允许耗时）
```

### 5.2 锁生命周期

```
┌─────────────────────────────────────────────┐
│ 步骤1开始 → 获取锁                         │
│   ├─ 锁不存在 → 创建锁 + 写入PID/时间戳     │
│   └─ 锁已存在 ─→ 检查锁持有时间            │
│       ├─ <30分钟 → 退出（上一轮仍在执行）    │
│       └─ ≥30分钟 → 强制释放 + 告警 + 重新获取│
│                                             │
│ 六步全流程执行中...                          │
│   ├─ 每步骤完成后更新锁心跳时间戳            │
│   └─ 心跳超15秒未更新 → 判定僵死 → 自动释放  │
│                                             │
│ 步骤6完成 → 释放锁 + 归档执行日志            │
└─────────────────────────────────────────────┘
```

### 5.3 锁保护规则

| 规则 | 说明 |
|------|------|
| 互斥执行 | 同一时刻仅允许一轮蒸馏运行 |
| 心跳保活 | 每步骤完成/每15秒更新锁心跳时间戳 |
| 超时释放 | 超过30分钟未完成自动释放锁，下次触发时告警 |
| 强制解锁 | 提供手动强制解锁指令：`Remove-Item .distillation_lock` |
| 异常恢复 | 进程异常退出时锁文件残留，下次触发自动检测并清理 |
