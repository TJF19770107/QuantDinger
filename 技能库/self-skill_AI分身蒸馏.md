## 技能描述

基于角色总说明书和用户画像，自动执行 AI 分身全自动蒸馏六步流程（分析自己→制定计划→文件转换→构建知识库→创建self-skill→更新核心配置），实现 AI 分身从"原始数据"到"完整数字延伸"的闭环转化。

---

## 触发条件

| 触发方式 | 条件 | 说明 |
|---------|------|------|
| **定时触发** | 每 2 小时自动执行 | 经由定时任务调度器触发 |
| **手动触发** | 用户发送「蒸馏」「全域蒸馏」「嗡阿喇巴札那谛」 | 豆包Agent 识别关键词后触发 |
| **迭代触发** | R23+ 迭代完成校验后 | 智能体迭代工作流第四步自动调用 |
| **异常触发** | 角色总说明书/SOUL 检测到版本不一致 | Hermes 健康巡检检测到配置漂移时触发 |

## 六步蒸馏流程

### 步骤 1：分析自己（自我认知更新）

| 项目 | 说明 |
|------|------|
| **输入** | 角色总说明书 v1.6 + 用户历史行为日志 + 记忆库快照 |
| **处理** | 提取用户身份定位、思维模式、工作风格、技术栈、价值取向、沟通特点 |
| **产出** | `知识库/用户人格画像_[日期].md` |
| **Agent分配** | 豆包Agent 执行分析 → Hermes Agent 校验 → OpenClaw 归档 |
| **质量门控** | 与上一版人格画像对比差异率 < 5%，超过则标记待确认 |

### 步骤 2：制定计划（进化路线规划）

| 项目 | 说明 |
|------|------|
| **输入** | 用户人格画像 + 对标矩阵最新版本 + R22 全域情报库 |
| **处理** | 评估当前能力基线 → 制定 R 轮次进化方向 → 三子Agent专项计划 → 技能/工作流/记忆扩建计划 |
| **产出** | `知识库/AI分身进化规划_[日期].md` |
| **Agent分配** | Hermes Agent 执行规划 → 豆包Agent 评估可行性 → OpenClaw 落地方案 |
| **质量门控** | 对标矩阵得分必须≥上一轮，退化则自动回滚 |

### 步骤 3：文件转换（知识资产格式化）

| 项目 | 说明 |
|------|------|
| **输入** | 全目录扫描（11 个子目录） |
| **处理** | 识别非 MD 文件 → markitdown/Python 转换 → 保持原目录结构写入 → MD5 去重 |
| **产出** | 转换后 MD 文件 + `定时任务/蒸馏日志/文件转换日志_[日期].md` |
| **Agent分配** | OpenClaw 执行转换脚本 → Hermes Agent 监控失败重试 → 豆包Agent 生成日志 |
| **质量门控** | 转换成功率 ≥ 98%，低于该值暂停并报告 |

### 步骤 4：构建知识库（知识图谱化）

| 项目 | 说明 |
|------|------|
| **输入** | 全目录 MD 文件（含步骤 3 转换产物） |
| **处理** | 主题分类 → 知识图谱结构 → 关键概念词条 → 关联关系 → 统计报告 |
| **产出** | `知识库/知识库索引_[日期].md` |
| **Agent分配** | 豆包Agent 执行分类与索引 → Hermes Agent 校验完整性 → OpenClaw 写入磁盘 |
| **质量门控** | 索引覆盖的知识库 MD 文件数 ≥ 实际文件数 × 95% |

### 步骤 5：创建 self-skill（技能沉淀）

| 项目 | 说明 |
|------|------|
| **输入** | 步骤 1-4 的产出 + 技能库现有注册表 |
| **处理** | 创建专属技能文件 → MCP 工具配置 → 三子Agent 能力配置 → 注册入技能清单 |
| **产出** | `技能库/self-skill_AI分身蒸馏.md` + `技能库/mcp-tools_AI分身蒸馏.json` + `技能库/agent-capabilities_AI分身蒸馏.md` |
| **Agent分配** | 豆包Agent 设计技能协议 → Hermes Agent 编排注册 → OpenClaw 写入配置文件 |
| **质量门控** | MCP JSON 通过 JSON Schema 校验，技能文件通过模板完整性检查 |

### 步骤 6：更新核心配置（全局同步）

| 项目 | 说明 |
|------|------|
| **输入** | 步骤 1-5 的全部产出 |
| **处理** | 更新 SOUL.md → 更新 USER.md → 更新 AGENTS.md → 更新角色总说明书引用 → 同步各子Agent配置 |
| **产出** | 更新后的 SOUL.md / USER.md / AGENTS.md / 角色总说明书（版本号+1） |
| **Agent分配** | 三子Agent 同步更新各自的配置文件 → Hermes Agent 最终校验全局一致性 |
| **质量门控** | 全局配置一致性校验（SOUL ↔ USER ↔ AGENTS ↔ 角色总说明书 四文件无冲突） |

## 质量保证体系

### 五道质量门控

| 门控 | 触发点 | 检查项 | 失败处理 |
|------|--------|--------|---------|
| G1: 实事求是 | 步骤1-4 每个产出写入前 | 内容是否基于真实文件/数据，零幻觉 | 标记可疑段落，回退该步骤 |
| G2: MD5去重 | 步骤3/4/5 文件写入前 | 目标路径是否已存在同MD5文件 | 自动跳过，记录重复日志 |
| G3: 路径合规 | 所有文件操作 | 写入路径是否在授权目录内 | 拒绝写入，记录违规 |
| G4: 对标校验 | 步骤2 进化规划生成后 | 对标矩阵得分是否≥上一轮 | 退化则自动回滚至上一版本 |
| G5: 全局一致性 | 步骤6 配置更新后 | SOUL↔USER↔AGENTS↔总说明书 四文件无冲突 | 标记冲突项，通知用户手动裁决 |

### 失败恢复策略

| 失败类型 | 恢复策略 | 最大重试 |
|---------|---------|---------|
| 单个步骤失败 | 重试该步骤（最多 2 次），失败则跳过进入下一步 | 2 |
| 文件写入失败 | 换用备用路径 / 重试 3 次 / 报告 I/O 异常 | 3 |
| 依赖缺失（如 markitdown） | 自动安装依赖 / 安装失败则降级为纯 Python 方案 | 1 |
| 全局一致性校验失败 | 回滚至上一稳定检查点 / 保留冲突日志 | 1 |
