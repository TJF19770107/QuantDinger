## 一、协议概述

将任务编排逻辑外置为 JavaScript 脚本，由运行时后台执行。上下文窗口仅保留最终答案，中间结果存脚本变量。支持百级并行子 Agent + DAG 拓扑自动分解 + 断点续传。

## 二、核心架构

```
用户描述任务
    ↓
主 Agent 编写 JS 编排脚本
    ↓
运行时后台执行脚本
    ↓
┌─────────────────────────────────────┐
│  JS 编排脚本                          │
│  ├─ DAG 拓扑自动分解                  │
│  ├─ 并行子 Agent 调度（16并行/次）     │
│  ├─ 中间结果 → 脚本变量（不污染上下文） │
│  ├─ 结果聚合 + 验证                   │
│  └─ 返回最终答案 → 上下文              │
└─────────────────────────────────────┘
    ↓
用户 Session 保持响应（不被后台任务阻塞）
```

## 三、并发模型

| 参数 | 值 |
|------|-----|
| 单次并行上限 | 16 个子Agent |
| 总子Agent上限 | 1000 |
| 中间结果存储 | 脚本变量（非上下文窗口） |
| 最终答案 | 注入上下文窗口 |

## 四、DAG 拓扑分解

```
1. 任务输入 → 依赖分析
2. 构建 DAG（节点=子任务，边=依赖）
3. 按层级并行调度：
   Level 0: 无依赖节点 → 并行执行
   Level 1: 依赖 Level 0 的节点 → 并行执行
   Level N: 依此类推
4. 错误节点自动重建 + 状态恢复
```

## 五、断点续传

- 每个子Agent 完成后写入检查点
- 脚本崩溃/超时后从最近检查点恢复
- 已完成子Agent 结果不丢失
- 最大重试次数：3次/子Agent

## 六、适用场景

- 大型代码库批量重构
- 多模块并行测试
- 跨项目依赖分析
- 大规模数据采集与处理
