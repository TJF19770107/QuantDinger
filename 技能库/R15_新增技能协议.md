## 协议 #66：MCP 2026-07-28 Stateless RC 适配协议 v1.0

### 来源
MCP 2026-07-28 Release Candidate（2026-05-21锁定）· Anthropic+Google联合 · 21+ SEPs

### 核心机制

```
五大支柱适配层：
┌─────────────────────────────────────────────────────┐
│ 1. Stateless Core                                   │
│    去除initialize handshake (SEP-2575)              │
│    去除Mcp-Session-Id header (SEP-2567)             │
│    协议版本/客户端信息/能力通过_meta每请求传递        │
├─────────────────────────────────────────────────────┤
│ 2. Operability Layer                                │
│    必需header: Mcp-Method / Mcp-Name (SEP-2243)     │
│    HTTP缓存元数据 (SEP-2549)                        │
│    W3C Trace Context传播 (SEP-414)                  │
├─────────────────────────────────────────────────────┤
│ 3. Extensions Framework                             │
│    reverse-DNS标识扩展                              │
│    能力图协商                                        │
│    MCP Apps (SEP-1865) + Tasks正式发布              │
├─────────────────────────────────────────────────────┤
│ 4. Auth Hardening (6 SEPs)                          │
│    OAuth 2.1 / OpenID Connect对齐                   │
│    iss-parameter验证 (RFC 9207)                     │
│    防止issuer mix-up攻击                            │
├─────────────────────────────────────────────────────┤
│ 5. Deprecation Policy (SEP-2596)                    │
│    最低12个月弃用→移除窗口                           │
│    书面规则+公开承诺                                 │
└─────────────────────────────────────────────────────┘
```

### Stateless vs Stateful 对比

| 维度 | Stateful (pre-RC) | Stateless (2026-07-28 RC) |
|------|-------------------|--------------------------|
| 握手 | initialize handshake | 无（_meta内联） |
| 会话 | session id绑定实例 | 无会话状态 |
| 负载均衡 | 困难（粘性会话） | 天然支持（任意实例） |
| 部署 | 需状态管理 | 无状态REST服务（Cloud Run/K8s） |
| 扩展性 | 受限于单实例 | 水平扩展无限制 |
| SDK | Python SDK v1 / TS SDK v1 | Python SDK v2 / TS SDK v2（重写） |

### 豆包Agent集成方案

```
迁移路径（12个月弃用窗口内）：
Phase 1（即时）：了解RC规范，评估现有MCP集成的变更范围
Phase 2（1-3月）：SDK v2升级，_meta字段适配
Phase 3（3-6月）：Extensions Framework注册自定义扩展
Phase 4（6-12月）：MCP Apps交互式UI集成

关键变更点：
├── 现有所有MCP调用：添加_meta字段携带协议版本/客户端信息
├── 去除session id依赖：每次调用自包含
├── 路由headers：统一使用Mcp-Method/Mcp-Name
└── Auth升级：OAuth 2.1对齐，iss验证
```

### 安全评估
✅ Auth Hardening +6 SEPs | ✅ 无状态降低攻击面 | ✅ W3C Trace Context审计

## 协议 #68：AI长期记忆双系统蒸馏协议 v1.0

### 来源
微软Mnemis ACL2026 SOTA · 腾讯Hy-Memory（容量+45%/成本-35%） · PlugMem ICML2026 · δ-mem · EverMind/EverOS

### 核心机制

```
双系统记忆架构（Mnemis启发）：
┌─────────────────────────────────────────────────┐
│              输入：对话/任务/反馈                 │
│                    ↓                            │
│  ┌──────────────────────┐                       │
│  │   建构式索引(Indexing)│                       │
│  │   碎片化对话→层级图    │                       │
│  │   自适应聚类+关联发现  │                       │
│  └──────────┬───────────┘                       │
│             ↓                                    │
│  ┌──────────────────────────────────────┐       │
│  │       双系统检索 (Retrieval)          │       │
│  │  ┌─────────────┐  ┌───────────────┐ │       │
│  │  │ System 1     │  │ System 2      │ │       │
│  │  │ 快速检索     │  │ 审慎推理      │ │       │
│  │  │ 层级图索引   │  │ 知识图推理    │ │       │
│  │  │ 毫秒级关联   │  │ 跨会话模式    │ │       │
│  │  │ 高召回       │  │ 高精度        │ │       │
│  │  └─────────────┘  └───────────────┘ │       │
│  └──────────────────────────────────────┘       │
└─────────────────────────────────────────────────┘

Hy-Memory六级框架融合：
┌────────────────────────────────────────────┐
│ L1: 原始感知记忆 → L2: 事件摘要记忆        │
│ L3: 会话级记忆   → L4: 任务级记忆          │
│ L5: 用户画像记忆 → L6: 元认知策略记忆       │
│                                            │
│ 记忆压缩：信息密度+45%，Token消耗-35%      │
│ 时序感知：时间线对齐+因果链追踪             │
└────────────────────────────────────────────┘

PlugMem知识中心图：
┌────────────────────────────────────────────┐
│ 节点类型：proposition（命题）+ prescription（规则）│
│ 边类型：因果/时序/层级/类比                  │
│ 核心主张：决策信息存在于抽象知识，非冗长原始经历 │
└────────────────────────────────────────────┘
```

### 四层记忆映射

| 层级 | 对标 | 存储方案 | 检索方式 |
|------|------|---------|---------|
| L1 身份记忆 | Hy-Memory L5 | JSON配置 | 全量加载 |
| L2 会话记忆 | 现有上下文窗口 | 内存 | 直接访问 |
| L3 任务记忆 | PlugMem知识图 | SQLite FTS5 | System 1快速检索 |
| L4 长期记忆 | Mnemis双系统 | 层级图+向量库 | System 2审慎推理 |

### 豆包Agent集成方案

1. **记忆管理技能(#5)升级**：简单向量检索 → 建构式双系统
2. **Mnemi层级图索引**：替代扁平向量库，实现自适应层级聚类
3. **Hy-Memory记忆压缩**：主动标记冗余+淘汰低价值+信息密度提升
4. **PlugMem知识图**：从原始对话中提取proposition节点，构建可推理知识网络
5. **Dreaming机制**：借鉴Claude Managed Agents的后台记忆蒸馏

### 评测目标

| 基准 | 当前(向量RAG) | 目标(Mnemis双系统) | 对标 |
|------|-------------|-------------------|------|
| LongMemEval | 基线 | SOTA | Mnemis |
| PersonaMem | 基线 | 超越主流 | Hy-Memory |
| 跨会话任务连贯性 | 3-5轮 | 20+轮 | Gartner 2026预测 |
| Token消耗 | 100% | 65% | Hy-Memory -35% |

### 安全评估
🟡 中风险（记忆数据隐私）| 本地存储 + 端侧加密 + 用户可控删除

## 协议 #69：Agentic Neural Networks 自进化协议 v1.0

### 来源
Agentic Neural Networks: Textual Backpropagation (arXiv:2506.09046) · 现有自进化协议#46升级 · GEPA引擎

### 核心机制

```
文本反向传播流程：
┌─────────────────────────────────────────────────────┐
│                    Forward Pass                      │
│  任务输入 → Agent执行 → 产生输出                      │
│       ↓                                             │
│                 Loss Signal                          │
│  用户反馈 / Grader评估 / 环境奖励                     │
│  "回答不够准确，漏掉了关键数据"                       │
│  "第三步的推理有逻辑跳跃"                             │
│       ↓                                             │
│                Backward Pass                         │
│  误差信号解析 → 角色/策略梯度计算                     │
│  "搜索Agent需在第三步增加验证检索"                    │
│  "分析Agent需在输出前自检数据完整性"                  │
│       ↓                                             │
│                  Update                              │
│  补丁式增量更新Agent配置（非全量重写）                 │
│  SOUL.md / AGENTS.md 精准片段修改                    │
│  多Agent场景：各Agent独立接收梯度，协同进化            │
└─────────────────────────────────────────────────────┘

神经网络→多Agent映射：
┌────────────────────────────────────────────┐
│  传统NN              Agentic NN            │
│  ────────            ────────────          │
│  神经元      ←→      子Agent              │
│  权重        ←→      Agent策略/角色配置     │
│  激活函数    ←→      工具调用/推理链        │
│  前向传播    ←→      任务执行              │
│  损失函数    ←→      Grader评估            │
│  反向传播    ←→      文本反馈传播           │
│  梯度下降    ←→      策略精炼              │
└────────────────────────────────────────────┘
```

### 与现有Ratchet自进化对比

| 维度 | Ratchet (#46 R11) | Agentic NN (#69 R15) |
|------|-------------------|---------------------|
| 信号形式 | 行为分析（成功/失败） | 文本反向传播（精确反馈） |
| 更新粒度 | 源码级文件修改 | Agent角色+策略精炼 |
| 安全验证 | 非发散分析 | 多层梯度裁剪+沙箱测试 |
| 适用场景 | 单Agent自修改 | 多Agent系统协同进化 |
| 进化方向 | 代码质量+性能 | 策略质量+协作效率 |

### 豆包Agent集成方案

1. **现有自进化协议(#46)升级**：引入文本反向传播机制
2. **GEPA引擎增强**：交互监听器 + 文本化反馈捕获 → 角色精炼
3. **多Agent场景**：任务分解后，各子Agent独立接收文本反馈并自我优化
4. **Grader Agent**：独立评估Agent，生成文本化误差信号
5. **安全门禁**：Ratchet非发散分析 + 人工审核 → 通过后写入配置

### 安全评估
🟡 中风险（自修改配置变更）| Ratchet分析 + 人工审核门禁 + 沙箱验证

## 协议 #70：金融Agent MCP自主交易协议 v1.0

```
│  │          MCP Server 层               │         │
│  │  ┌────────────┐  ┌────────────────┐ │         │
│  │  │ Robinhood   │  │  A股/港股券商  │ │         │
│  │  │ MCP Server  │  │  MCP Server    │ │         │
│  │  └────────────┘  └────────────────┘ │         │
│  │  ┌────────────────────────────────┐ │         │

│  │  │  (25+公链，链上Agent)          │ │         │

│  └──────────────────────────────────────┘         │
│              ↓                                     │
│  ┌──────────────────────────────────────┐         │

│  └──────────────────────────────────────┘         │
└────────────────────────────────────────────────────┘
```

### 三类典型场景

| 场景 | 策略 | AI角色 | 人角色 |
|------|------|--------|--------|
| 长期投资调仓 | 分析持仓行业占比 → 建议再平衡方案 | 数据分析+建议生成 | 审核+确认执行 |
| 交易策略执行 | 基于技术指标/市场信号 → 生成买卖建议 | 信号监控+策略执行 | 设定策略参数+最终确认 |
| 理财组合管理 | 风险评估+资产配置 → 动态调整建议 | 组合优化+风险计算 | 设定目标+审批调整 |

### 三阶段验证路径

```
Phase 1: 测试网验证（链上Agent）
    BNB Chain测试网 → Trust Wallet Agent Kit → 模拟交易
    目标：验证MCP金融交易协议可用性

Phase 2: 模拟盘验证（传统金融）
    虚拟资金 → Robinhood模拟交易 / A股模拟盘
    目标：验证策略有效性+风控机制

Phase 3: 小资金实盘
    独立代理账户 + 严格限额 + 每笔人工确认
    目标：真实市场验证
```

### 豆包Agent集成方案

1. **量化交易策略资产库** → 通过MCP协议对接Robinhood/券商API
2. **风控层**：最大仓位 / 单日限额 / 止损线 / 最大回撤四重约束
3. **独立代理账户**：AI策略执行与主账户资金严格隔离（Robinhood模式）
4. **人工确认**：所有交易指令需用户approve后执行
5. **MCP协议#66适配**：Stateless模式 + Auth Hardening + OAuth 2.1

### 安全评估
🔴 高风险（真实金融交易资金安全）| 测试网→模拟盘→小资金三阶段 + 独立账户隔离 + 每笔人工确认 + OAuth 2.1
