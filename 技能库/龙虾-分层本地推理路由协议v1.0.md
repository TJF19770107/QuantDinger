# 龙虾-分层本地推理路由协议 v1.0

> **对标来源**：Ollama vs vLLM 2026全面对比 + Speculative Decoding + 量化策略
> **版本**：v1.0 | **创建日期**：2026-06-01 | **所属迭代**：R19
> **核心价值**：根据并发量/延迟/隐私需求，自动路由到最优本地推理方案

---

## 一、协议概述

根据任务场景自动选择Ollama（单用户原型）或vLLM（生产高并发），叠加量化、Speculative Decoding等优化策略，实现10x性能提升。

---

## 二、决策矩阵（10秒决策）

| 场景 | 推荐方案 | 说明 |
|------|---------|------|
| 1-4并发用户、快速迭代 | **Ollama** | 62 tok/s，Docker式模型管理 |
| 5+并发用户、生产API | **vLLM** | 920 tok/s，PagedAttention |
| 极致控制、边缘部署 | **llama.cpp** | GGUF量化，CPU友好 |
| 多GPU生产集群 | **vLLM** | Tensor Parallelism |

## 四、优化叠加策略

| 技术 | 效果 | 适用 |
|------|------|------|
| Q4_K_M量化 | 70B模型40GB→12GB | 消费级GPU |
| Speculative Decoding | 2-3x加速 | 延迟敏感 |
| Flash Attention-3 | 1.5-2x加速 | 长上下文 |
| FP8量化（Hopper） | 30%加速，近无损 | H100/B200 |
| Continuous Batching | 静态批处理→动态，23x提升 | 生产服务 |
| PagedAttention | 2-4x内存效率 | vLLM标配 |

## 五、最优配置栈（RTX 4090, Llama 3.3 70B, 32K上下文）

```
llama-server \
  --model Llama-3.3-70B-Q4_K_M.gguf \
  --model-draft Llama-3.2-1B-Q4_K_M.gguf \
  --draft 8 \
  --n-gpu-layers 99 --n-gpu-layers-draft 99 \
  --cache-type-k q8_0 --cache-type-v q8_0 \
  --flash-attn --ctx-size 32768
```

| 配置 | tok/s | 提升 |
|------|-------|------|
| 基准（F16） | 4 | — |
| +Q4_K_M量化 | 18 | 4.5x |
| +Flash Attention+KV缓存 | 19 | — |
| +Speculative Decoding | **41** | **10.3x** |
| +EAGLE-3 | ~58 | 14.5x |
