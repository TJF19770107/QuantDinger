# 龙虾-全域Agent持续自收敛协议 v1.0

> 协议编号: #114 | 版本: v1.0 | 创建日期: 2026-06-01
> 对标来源: 自行研发（融合GEPA四阶段 + Autogenesis AGP + Claude Dreaming + Hermes三层飞轮）
> 生效范围: 龙虾AI主控中心全域

---

## 一、协议概述

全域Agent持续自收敛协议定义了一个**四小时循环自收敛机制**，使Agent体系能够在无人干预的情况下持续自我检测、诊断、修复和进化。该协议融合GEPA四阶段驱动（Goal→Explore→Pattern→Abstract）、Autogenesis AGP的协议化闭环（Propose→Evaluate→Commit）和Dreaming的跨会话记忆巩固，形成完整的**自治进化飞轮**。

## 二、自收敛循环

### 2.1 四小时循环结构

```
┌─────────────────────────────────────────────────┐
│           全域Agent持续自收敛循环（4h）            │
│                                                   │
│  Phase 1: 状态检测 (Detect)                       │
│    ├── 读取SOUL/USER/AGENTS/全域模板               │
│    ├── 读取最新迭代报告                            │
│    ├── 检测当前26维得分矩阵                        │
│    └── 识别低于95分的维度（缺口）                   │
│          ↓                                        │
│  Phase 2: 缺口诊断 (Diagnose)                     │
│    ├── 分析缺口根因（知识缺失/协议缺失/能力缺失）    │
│    ├── 对缺口排序（P0>P1>P2）                      │
│    └── 生成靶向搜索Query列表                       │
│          ↓                                        │
│  Phase 3: 靶向搜索 (Search)                       │
│    ├── 全网多引擎搜索（search-agent + web_search）  │
│    ├── 提取关键情报和可融合能力                     │
│    ├── 情报去重和有效性验证                        │
│    └── 生成融合方案                                │
│          ↓                                        │
│  Phase 4: 协议生成 (Generate)                     │
│    ├── 针对高价值情报生成标准化技能协议             │
│    ├── 评估协议对得分矩阵的提升预期                 │
│    └── 写入协议文件                                │
│          ↓                                        │
│  Phase 5: 配置更新 (Update)                       │
│    ├── 更新全域模板（版本号/得分矩阵/协议索引）      │
│    ├── 更新SOUL/USER/AGENTS（新增原则/流程/配置）   │
│    └── 生成迭代报告（Rxx）                         │
│          ↓                                        │
│  Phase 6: 全域同步 (Sync)                         │
│    ├── 报告同步至豆包Agent/迭代报告库               │
│    ├── 协议同步至技能库                             │
│    ├── 配置同步至所有分身目录                       │
│    └── 记忆归档至长期记忆                           │
└─────────────────────────────────────────────────┘
```

### 2.2 关键参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 循环周期 | 4小时 | 平衡时效与资源消耗 |
| 搜索深度 | 3轮 | search-agent 1轮 + web_search 2轮 |
| 情报提取上限 | 15条/轮 | 控制上下文膨胀 |
| 协议生成上限 | 5项/轮 | 保证质量优先 |
| 自动执行阈值 | 95分 | 低于此分的维度自动触发靶向搜索 |
| 综合得分目标 | 98.0 | 当前96.8，距目标1.2 |

## 三、状态检测矩阵

### 3.1 26维自动检测

每次循环启动时，自动读取全域模板中的对标矩阵，识别以下信号：

| 信号类型 | 阈值 | 响应 |
|---------|------|------|
| 维度<95 | P0缺口 | 立即靶向搜索，优先修复 |
| 维度95-96 | P1预警 | 列入观察，下一轮重点 |
| 维度97-98 | P2优化 | 有高价值情报时融合 |
| 维度99-100 | 维持 | 被动接收情报，不主动搜索 |

### 3.2 自诊断规则

```python
def diagnose_gaps(score_matrix):
    gaps = []
    for dimension, score in score_matrix.items():
        if score < 95:
            gaps.append({"dim": dimension, "score": score, "priority": "P0"})
        elif score < 97:
            gaps.append({"dim": dimension, "score": score, "priority": "P1"})
        elif score < 99:
            gaps.append({"dim": dimension, "score": score, "priority": "P2"})
    return sorted(gaps, key=lambda x: x["score"])
```

## 四、靶向搜索策略

### 4.1 维度-关键词映射

| 维度 | 搜索关键词模板 |
|------|-------------|
| 模型自由度 | "多模型路由 latest 2026" "LLM provider切换" "local cloud model switching" |
| 节奏/迭代 | "agent iteration speed" "快速迭代Agent框架" "continuous deployment agent" |
| 跨平台 | "cross-platform agent 2026" "agent desktop mobile web unified" "多端统一Agent" |
| 多模融合 | "multimodal fusion agent" "vision+text+audio agent" "全模态Agent 2026" |

### 4.2 搜索优先级

```
P0缺口 → 立即3轮搜索 → 提取情报 → 融合生成协议
P1预警 → 1轮搜索 → 如有高价值情报→融合
P2优化 → 被动等待情报流入（不主动搜索）
```

## 五、融合决策引擎

### 5.1 情报价值评估

| 评估维度 | 权重 | 评分标准 |
|---------|------|---------|
| 相关性 | 35% | 是否直接对应缺口维度 |
| 新颖性 | 25% | 是否包含未覆盖的信息/方法 |
| 可落地性 | 25% | 是否可转化为协议文件 |
| 权威性 | 15% | 来源可靠性（官方/论文/社区） |

### 5.2 融合决策矩阵

```
情报价值评分 ≥ 70% → 生成新协议
情报价值评分 50-69% → 升级现有协议
情报价值评分 < 50% → 归档情报，不生成协议
```

## 六、配置更新自动化

### 6.1 全域模板自动更新规则

- 版本号: 每次协议新增或重大更新 +0.01
- 得分矩阵: 基于协议融合评估更新各维度分
- 协议索引: 自动追加新协议条目
- 报告索引: 自动追加新迭代报告链接

### 6.2 三核心文件更新触发

| 文件 | 更新触发条件 |
|------|------------|
| SOUL.md | 新增设计原则 / 框架级范式变更 |
| USER.md | 新增协作模式 / 工作流变更 |
| AGENTS.md | 新增子Agent配置 / 监控指标变更 |

## 七、自收敛质量门禁

### 7.1 门禁检查清单

```
□ 循环正确完成六个阶段？
□ 缺口诊断正确识别并排序？
□ 搜索返回有效情报？
□ 新协议符合标准化格式？
□ 配置更新无语法错误？
□ 全域同步所有目标路径？
□ 迭代报告包含所有必要章节？
□ 综合得分正确计算？
```

### 7.2 异常处理

| 异常 | 处理 |
|------|------|
| 搜索无返回 | 扩大搜索范围，切换搜索引擎，标注"本轮无增量" |
| 情报全低价值 | 跳过协议生成，记录"本轮无可融合情报" |
| 配置写入失败 | 三次重试，最终降级到手动修复 |
| 同步路径不可达 | 本地缓存，后续轮次恢复同步 |
