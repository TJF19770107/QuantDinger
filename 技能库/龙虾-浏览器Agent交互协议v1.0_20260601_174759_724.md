## 一、协议定位

本协议为豆包Agent的浏览器交互缺失能力建立完整技术栈：从网页检索到账号登录、验证码识别、多页表单提交、动态内容抓取、复杂站点交互，实现端到端闭环。

对标Marvis Browser Agent的架构设计——1+5智能体中Browser Agent作为网页交互专员，独立处理需要多步交互的网页场景。同时借鉴Codex Chrome Extension的直接操控已登录浏览器的能力。


## 三、五大核心能力

### 3.1 通用网页检索与内容抓取

| 能力 | 实现方式 | 对标基准 |
|------|---------|---------|
| 静态页面抓取 | Playwright page.content() + DOM解析 | web_fetch升级 |
| 动态内容抓取 | Playwright waitForSelector + 滚动加载 | Marvis Browser Agent |
| JS渲染页面 | Playwright Chromium完整浏览器引擎 | Codex Chrome |
| 多标签页并行 | Playwright BrowserContext多页面 | Codex多标签页并行 |
| iframe/Shadow DOM | Playwright frameLocator/shadowRoot | OpenClaw Browser |

**执行流程**：
1. 主Agent识别任务为网页抓取
2. Browser Agent启动Playwright实例
3. 导航到目标URL，等待关键元素渲染
4. 执行滚动/点击等操作触发动态加载
5. 提取结构化数据（表格/列表/卡片）
6. 结果整理为Markdown/JSON/CSV返回

### 3.2 账号登录与会话保持

| 场景 | 实现方式 | 安全机制 |
|------|---------|---------|
| 表单登录 | Playwright fill + click | 密码字段不记录日志 |
| Cookie持久化 | storageState存储/恢复 | 加密存储于本地 |
| OAuth/SSO | 检测跳转+自动跟随 | 用户首次需手动授权 |
| 多因素认证 | 检测MFA页面+暂停等用户 | 验证码交还用户输入 |
| 会话超时恢复 | 心跳检测+自动刷新 | 静默续期 |

**安全约束**：
- 账号密码由用户提供，Agent不自行编造
- Cookie存储使用AES-256加密
- 金融/支付页面强制用户确认后才操作
- 登录失败3次自动暂停并告警

### 3.3 验证码识别

| 验证码类型 | 识别方案 | 成功率预估 |
|-----------|---------|-----------|
| 文字验证码 | OCR（本地Tesseract + 云端AI） | 85-90% |
| 滑块验证码 | Playwright拖拽模拟 + 轨迹拟人化 | 60-75% |
| 点选验证码 | AI视觉定位 + 模拟点击 | 55-70% |
| 算术验证码 | 表达式解析 + 计算 | 95%+ |
| 图形验证码 | AI模型识别（如reCAPTCHA则暂停） | 不适用 |

**降级策略**：
- 识别失败→自动截图→发送给用户→等待手动输入→继续执行
- reCAPTCHA/高风险验证→直接暂停并请求用户协助

### 3.4 多页表单提交

| 能力 | 技术方案 |
|------|---------|
| 单页表单 | 字段检测→生成填写计划→逐字段fill→submit |
| 多步表单 | 分页检测→每页填写→检测"下一步"→循环至提交 |
| 下拉选择 | selectOption / 点击选项 |
| 日期选择器 | 解析日期→定位日历组件→点击日期 |
| 文件上传 | setInputFiles(本地文件路径) |
| 表单校验错误 | 检测错误提示→修正字段→重新提交 |

**智能填表流程**：
```
任务需求（如"帮我提交报销单，发票在D:/发票/"）
  → 解析表单字段（姓名/日期/金额/附件）
  → 从上下文/文件提取字段值
  → 逐字段填写+校验
  → 上传附件文件
  → 预览确认（截图回传用户确认）
  → 点击提交
```

### 3.5 复杂站点交互

| 场景 | 实现方案 |
|------|---------|
| 无限滚动加载 | Scroll+等待+增量提取 |
| 分页遍历 | 检测分页控件→逐页点击+提取→合并结果 |
| 弹窗处理 | 自动关闭Cookie提示/广告弹窗 |
| 条件分支 | 检测页面状态→LLM决策→选择操作路径 |
| AJAX异步等待 | waitForResponse/waitForLoadState |
| 文件下载 | 监听download事件→保存到指定目录 |

## 四、执行模式

### 4.1 三种交互模式

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| **全自动模式** | Agent完全自主执行，不中断用户 | 简单抓取、公开页面操作 |
| **半自动模式** | 关键节点（登录/支付/确认）暂停等用户 | 需要登录、涉及资金的操作 |
| **交互模式** | 每步操作前截图回传用户确认 | 高风险操作、新站点首次使用 |

### 4.2 模式选择规则

```
页面是否需要登录？
  ├── 否 → 全自动模式
  └── 是 → 是否有已保存Cookie？
           ├── 是 → 全自动模式（已有会话）
           └── 否 → 半自动模式（需要登录）
      
操作是否涉及支付/资金？
  ├── 是 → 半自动模式（确认后再提交）
  └── 否 → 继续判断
      
页面结构是否已知（有成功交互记录）？
  ├── 是 → 全自动模式
  └── 否 → 交互模式（首次探索）
```

## 五、错误处理与自愈

### 5.1 常见异常及处理

| 异常 | 检测方式 | 处理策略 |
|------|---------|---------|
| 页面加载超时 | 30s timeout | 重试2次→截图报告→升级至用户 |
| 元素未找到 | selector timeout | AI视觉定位兜底→提示用户 |
| 网络断开 | request失败 | 等待15s重连→仍失败则暂停 |
| 反爬拦截 | 状态码403/检测到验证 | 切换User-Agent→降级为截图+手工 |
| 页面结构变化 | 操作失败 | AI重新分析页面→调整选择器 |
| 会话过期 | 检测登录页跳转 | 自动恢复Cookie或提示重新登录 |

### 5.2 自愈回滚机制（联动协议24）

```
操作执行
  ├── 成功 → 记录操作快照 → 继续
  └── 失败 → 分析失败原因
            ├── 已知可自愈 → 执行修正 → 重试
            └── 未知/不可自愈 → 回滚至上一快照 → 报告用户
```

## 六、安全与隐私

| 原则 | 实现 |
|------|------|
| 最小权限 | 仅访问任务需要的URL/页面元素 |
| 数据隔离 | 浏览器会话与用户日常浏览器隔离 |
| 凭据保护 | 密码不在日志中明文出现 |
| 截图隐私 | 涉及敏感数据页面不自动截图 |
| 操作审计 | 所有浏览器操作记录审计日志 |
| 用户接管 | 用户可随时中断并接管浏览器 |
