# 龙虾-金字塔式Agent-as-Tool分解协议 v1.0

> **对标来源**：InfiAgent (ICLR 2026)
> **创建日期**：2026-06-01 (R13)
> **版本**：v1.0

---

## 一、协议概述

将多Agent系统构建为DAG金字塔拓扑，高层Agent将低层Agent视为可调用的"工具"，通过agent-as-a-tool机制实现层级化任务分解、双重审计质量保障、智能路由和自演化。

## 二、核心机制

### 2.1 DAG金字塔拓扑

```
        [Router]          ← 顶层路由，直接重定向用户查询
       /    |    \
   [A1]   [A2]   [A3]     ← 中层规划Agent，K_max ≤ 5
   /|\    /|\    /|\
  [f1..fn] ...  ...       ← 底层功能Agent，实际执行
```

- 分支因子约束 K_max = 5，单Agent协调复杂度有界
- 深度L处可达功能Agent数 N ≈ b^L（指数增长）

### 2.2 Agent-as-Tool抽象

高层Agent将低层Agent统一视为工具调用：

```
Task T₀ → Agent α
  → 识别子Agent {A₁, A₂, ..., A_k}
  → 分解子任务 {T₁, T₂, ..., T_k}
  → 调用低层Agent执行
  → 合并结果返回
```

### 2.3 四层上下文结构

| 层次 | 名称 | 内容 |
|------|------|------|
| C_sys | 系统提示上下文 | 引导行为的预定义提示 |
| C_LM | 长期记忆索引 | 压缩的文件描述符和索引 |
| C_SM | 短期共享内存 | 活跃Agent调用树 |
| C_ENV | 压缩环境交互 | 接近阈值τ时自动压缩 |

约束：|C| << |H|（H为完整历史日志），确保上下文长度有界。

### 2.4 轻量通信

Agent间仅交换 (addr, desc) 对，不传递完整内容。

### 2.5 三层自演化

| 层级 | 机制 | 说明 |
|------|------|------|
| 模型级 | Git风格merge | 多模型并行执行→Judge评估→合并到主分支 |
| Agent级 | 持续训练 | 利用主分支高质量数据持续更新并行模型 |
| 拓扑级 | DAG动态重构 | 根据性能模式和新任务需求重构拓扑 |

## 三、双重审计

- **执行级审计**：持续监控每个Agent输出，维护质量评分 Q(t+1) = α·Q(t) + (1-α)·validate(O(t))
- **系统级审计**：内置审查机制 + 回顾性摘要 + 上下文压缩

## 四、豆包Agent适配方案

1. dispatch_task 升级支持金字塔式agent-as-tool调用链
2. 高层Agent自动识别子Agent并路由
3. 引入分支因子约束，防止协调复杂度爆炸
4. 上下文压缩机制应用于长对话场景
