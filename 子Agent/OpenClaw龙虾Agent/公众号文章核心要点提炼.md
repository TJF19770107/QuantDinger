## 一、文章核心观点

**主题**：Codex 接入飞书后，AI 从"会写代码"进化到"能处理工作"。

**核心论点**：
1. Codex 接入飞书后，AI 可直接操作真实工作流（文档、Base、消息、日历、任务、知识库、会议纪要等）
2. 接入过程只需纯对话，无需写配置文件或代码
3. 飞书 CLI 的价值不是多了几个命令，而是让 AI 从工具进化为工作助手

## 二、四步接入流程（LLM/Agent提取版）

| 步骤 | 用户操作 | Codex 自动执行 | 耗时 |
|------|---------|---------------|------|
| 1 | 在 Codex 中说"请帮我安装飞书 CLI" | 自动下载安装 lark-cli | 4~5分钟 |
| 2 | "初始化配置，输出浏览器配置链接" | 执行 init 命令 → 输出配置URL → 用户在浏览器创建应用 → 将 App ID/Secret 交给 Codex | 2~3分钟 |
| 3 | "执行授权，输出授权链接" | 执行 auth 命令 → 输出授权URL → 用户在浏览器确认授权 | 1分钟 |
| 4 | "创建下周一8点的飞书日历" | 调用日历API创建事件 → 返回结果 → 验证链路贯通 | 30秒 |

**总耗时**：约 8~10 分钟，全程零代码、纯对话。

## 五、关键技术点

1. **飞书 CLI 安装**：在 Codex 对话中直接驱动 `npm install` 或二进制安装
2. **OAuth 授权流程**：CLI init → 浏览器创建应用 → App ID/Secret → CLI auth → 浏览器授权 → Token 就绪
3. **验证命令**：创建飞书日历事件（低风险、高可见性），验证全链路贯通
4. **权限最小化**：按需开通 scope，不授权不必要的业务域
