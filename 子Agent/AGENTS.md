## 一、子Agent分工体系

### 1.1 豆包Agent
- **角色**：核心交互子Agent
- **职责**：交互应答、逻辑分析、内容处理、自身版本迭代
- **能力域**：自然语言理解、多轮对话、内容生成、知识问答
- **约束**：受SOUL.md和USER.md双重约束

### 1.2 Hermes Agent
- **角色**：调度管控子Agent
- **职责**：高效调度、进程管控、高负载任务处理
- **能力域**：任务分发、并发管理、资源调度、状态监控
- **进化方向**：蜂群协同调度、Skills自演进

### 1.3 OpenClaw龙虾Agent
- **角色**：底层执行子Agent
- **职责**：底层能力支撑、插件联动、全流程落地执行
- **能力域**：API对接、外部工具集成、Skill生态扩展、流程自动化
- **进化方向**：接入更多外部API、扩展Skill生态

### 1.4 Sub-agent 运行时管理规范

#### 1.4.1 子Agent生命周期
```
创建 ──→ 执行 ──→ 验收 ──→ 销毁
  │        │        │
  │        └──→ 失败 ──→ 重试/降级/人工兜底
  │
  └── 配置（权限/工具/模型/超时）
```

- **创建**：定义子Agent的职责范围、可用工具、权限模式、超时设置
- **执行**：分发独立子任务，子Agent在隔离上下文窗口中运行
- **验收**：接收精炼结果，对照验收标准检查；不合格触发重试或降级
- **销毁**：自动释放上下文窗口和计算资源，不跨任务持久化

#### 1.4.2 上下文窗口隔离
每个子Agent拥有独立的上下文窗口，与主Agent完全隔离：
- 子Agent看不到主Agent的对话历史和推理过程
- 子Agent间不共享上下文，互不干扰
- 子Agent只返回精炼结果给主Agent，不传递中间过程
- 防止上下文污染和确认偏误

#### 1.4.3 任务粒度控制
子Agent处理有明确边界的独立子任务：
- 单一职责：一个子Agent只处理一类问题（搜索/安全审查/代码生成/文档处理）
- 输入明确：结构化输入参数，不含模糊描述
- 输出规范：标准化输出格式（JSON/Markdown + 置信度 + 来源引用）
- 可独立验证：子任务结果可脱离主Agent独立判断正确性

#### 1.4.4 并行调度策略

| 依赖关系 | 调度策略 | 示例 |
|---------|---------|------|
| 无依赖 | 并行分发，同时执行 | 多个文件的独立代码审查 |
| 数据依赖 | 串行执行，前驱完成后再启动后继 | 先搜索定位 → 再读取分析 |
| 部分依赖 | 无依赖部分并行 + 依赖部分串行 | 并行搜索+并行读取，再合并分析 |

- 并行上限：最多 5 个子Agent同时运行
- 资源感知：根据当前系统负载动态调整并行度
- 超时控制：每个子Agent设置最大执行时间，超时触发熔断

#### 1.4.5 资源回收机制
- 子Agent完成任务后**自动释放**上下文窗口和关联资源
- 失败任务的中间产物写入临时目录，不占用主工作区
- 长时间无响应的子Agent触发超时熔断，强制回收资源
- 定期清理孤立进程和僵尸会话

#### 1.4.6 Hook 注入点
四阶段 Hook 支持子Agent生命周期的关键节点注入自定义逻辑：

| Hook 阶段 | 触发时机 | 典型用途 |
|----------|---------|---------|
| **启动前** (`PreLaunch`) | 子Agent创建完成、执行前 | 权限校验、环境准备、输入验证 |
| **完成后** (`PostComplete`) | 子Agent正常返回结果 | 结果格式校验、质量评分、日志记录 |
| **失败时** (`OnFailure`) | 子Agent执行异常或超时 | 错误捕获、降级触发、告警通知 |
| **销毁时** (`OnDestroy`) | 子Agent资源回收 | 临时文件清理、统计上报、审计记录 |
