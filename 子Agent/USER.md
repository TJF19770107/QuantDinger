## 四、多Agent协作流程规范

### 4.1 任务拆解规范
根据任务特征匹配5种多Agent协作模式：

| 任务特征 | 推荐模式 | 拆解方式 |
|---------|---------|---------|
| 质量关键 + 有明确标准 | Generator-Verifier | 生成→验证→反馈→修订循环 |
| 任务可分解 + 子任务独立 | Orchestrator-Subagent | 规划→分发→执行→合成 |
| Worker需持久上下文 | Agent Teams | 分配→认领→自主执行→回报 |
| 事件驱动 + 生态系统增长 | Message Bus | 发布→路由→订阅→处理 |
| 知识发现 + 去中心化 | Shared State | 种子→探索→写入→收敛 |

### 4.2 Generator-Verifier 流程
```
产出 → 验证 → 反馈 → 修订 → 再验证 → ... → 通过 或 最大迭代次数
```
规则：
- 最多 3 轮迭代，超过则降级（人工接手或返回最佳尝试+标注）
- Verifier 必须基于明确标准评分，不是"检查好不好"
- 验证标准在任务启动前必须明确

### 4.3 Orchestrator-Subagent 流程
```
规划 → 分发（并行） → [子Agent A/B/C 独立执行] → 合成
```
规则：
- 子Agent一次性使用，完成任务即释放
- 子任务必须有明确边界和输入/输出定义
- Orchestrator 保持全局视图，不参与子任务细节

### 4.4 Agent Teams 流程
```
分配 → 认领（Worker从共享队列主动认领） → 自主执行 → 回报 → Coordinator收集
```
规则：
- Worker 持久化，跨任务积累领域上下文
- Worker 间独立性必须严格保证——不能共享中间发现
- Coordinator 只分配任务和收集结果，不重置 Worker

### 4.5 子Agent通信协议
所有子Agent产出必须遵循结构化输出标准：
- **结构化输出**：JSON/Markdown 格式，明确字段定义
- **置信度评分**：每项产出附带 0-100 置信度，低于 70 分标注不确定项
- **交叉验证**：关键结论需经至少一个独立 Agent 复核
- **溯源引用**：所有数据/结论标注来源文件和行号

### 4.6 失败处理
```
┌── 正常执行 ──→ 完成
│
├── 执行超时 ──→ 熔断：终止子Agent + 释放资源 + 记录状态
│                    ↓
│              降级：使用简化方案 / 跳过该子任务 / 返回部分结果
│
├── 执行失败 ──→ 重试（最多 1 次，调整参数/策略）
│                    ↓
│              仍失败 → 降级策略（使用缓存结果 / 切换到备选方案）
│                    ↓
│              不可降级 → 人工兜底（记录失败上下文 + 等待人工决策）
│
└── 输出异常 ──→ 置信度 < 阈值 → 触发 Generator-Verifier 验证
                     ↓
               幻觉检测 → 标记 + 回退到上一有效状态
```
