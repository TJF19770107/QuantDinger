## 二、Swarm多Agent拓扑调度强化（#42）

### 2.1 强化内容
基于R11的MetaAgent-X双层元Agent研究成果，增强Swarm拓扑的两个维度：

1. **动态DAG重组**：当执行者Agent反馈"任务拆解粒度不当"，编排者可动态重新生成子DAG
2. **跨模型Worker池**：Worker可来自不同模型（Claude/GPT/Gemini），Skill Bundles适配各平台

### 2.2 执行变更

```yaml
swarm_config:
  dag_mode: dynamic  # 从 static 升级为 dynamic
  worker_pool:
    - type: claude_opus
      skills: [coding, review, planning]
      max_parallel: 3
    - type: claude_sonnet
      skills: [testing, formatting, docs]
      max_parallel: 5
    - type: gemini_flash
      skills: [indexing, searching, monitoring]
      max_parallel: 10
  model_router: protocol_50  # 新：使用#50多模型路由
```

## 三、编排者-工作者结构化强化（#32）

### 3.1 强化内容
Hermes v0.15证明：结构化结果对象可将通信延迟降低30%。本轮强化：

1. **统一Result Schema**：所有Worker输出统一为结构化对象
2. **增量结果推送**：Worker可推送部分结果，编排者异步聚合
3. **错误上下文传播**：Worker失败时附带完整错误上下文，而非仅错误码

### 3.2 统一Result Schema

```json
{
  "task_id": "uuid",
  "status": "running|success|failed|partial",
  "progress": 0.65,
  "result": {},
  "errors": [{
    "code": "E_TIMEOUT",
    "message": "API timeout after 30s",
    "context": "calling openai.chat.completions with model=gpt-5.5",
    "recovery": "retry_with_model=claude-sonnet-4.5"
  }],
  "metrics": {
    "duration_ms": 4500,
    "tokens_used": 12500,
    "cost_estimate": 0.015
  }
}
```

### 3.3 验证清单
- [ ] 统一Result Schema兼容性测试
- [ ] 增量结果推送延迟测量（目标：<100ms）

## 四、心跳自主调度强化（#40）

### 4.1 强化内容
R11引入#50多模型无感切换后，心跳检查可以从单模型依赖中解放：

1. **双模型心跳守护**：主心跳（claude-sonnet）+ 备用心跳（gemini-flash），任一存活即认为Agent在线
2. **心跳间隔自适应**：高负载时段自动延长心跳间隔（60s→120s），低负载恢复（120s→60s）
3. **心跳失败降级链**：主模型失败→备用模型→静默模式（仅记录日志）

### 4.2 配置变更

```yaml
heartbeat:
  primary:
    model: claude-sonnet-4.5
    interval: 60s
    timeout: 10s
  backup:
    model: gemini-3.5-flash
    interval: 120s
    timeout: 5s
  adaptive: true  # 自适应间隔
  max_silent: 300s  # 5分钟无响应→告警
```

## 五、新增协议适配（#50 多模型无感切换）

### 5.1 Hermes适配要点
- 编排者Agent的路由决策集成#50的模型注册表和降级链

- 当Worker执行失败时，编排者走#50降级链切换Worker模型
