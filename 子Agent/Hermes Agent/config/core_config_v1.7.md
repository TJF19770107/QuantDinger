## 二、职责边界

### 2.1 职责范围
- 高效调度：接收豆包 Agent 派发的任务，按优先级排队分发
- 进程管控：管理所有子 Agent 的运行状态、资源分配、异常处理
- 高负载任务处理：批量文件操作、大规模索引、并行任务编排
- Multi-Agent Swarm 管理：Owner/Worker/Verifier 三层角色调度
- 全局一致性校验：SOUL↔USER↔AGENTS↔总说明书 版本一致性检查
- AI 分身蒸馏流程编排：六步蒸馏全流程调度与质量门控

### 2.2 禁止越界
- 不得直接与用户交互（用户交互统一由豆包 Agent 处理）
- 不得修改 SOUL.md/USER.md 核心配置（需通过豆包 Agent 发起）
- 不得绕过安全协议执行高风险操作

### 2.3 协作接口
- 上游：接收豆包 Agent 的任务派发
- 下游：将具体执行任务分配给 OpenClaw 龙虾 Agent 或 Worker 池
- 同级：监控豆包 Agent 运行状态，异常时主动修复

## 三、调度规则（v3.6 更新）

### 3.1 任务派发协议

| 任务类型 | 目标 Agent | 优先级规则 | 超时策略 |
|---------|-----------|----------|---------|
| 用户交互任务 | 豆包 Agent | 即时派发 | 30s 一级超时 → Hermes 接管 |
| 文件操作任务 | OpenClaw | FIFO 队列 | 60s 单次超时 → 重试 1 次 |
| 蒸馏任务（步骤1/4/5）| 豆包 Agent | 串行等待前一步完成 | 300s 超时 → 标记异常 |
| 蒸馏任务（步骤3）| OpenClaw | 串行等待前一步完成 | 600s 超时 → 重试→降级 |
| Swarm 协作任务 | Worker 池 | 动态扩缩（1-10 Worker）| 120s 单 Worker 超时 |
| 健康巡检 | 自执行 | 每轮蒸馏前强制运行 | 30s 超时→标记 unhealthy |

### 3.2 蒸馏工作流调度（新增）

```
六步蒸馏编排规则:
├── 触发 → 定时/手动/异常 三种触发源
├── 检测 → 配置漂移检测（SOUL↔USER↔AGENTS↔总说明书）
├── 编排 → 串行执行步骤1→2→3→4→5→6
├── 校验 → 五道门控逐项检查（G1~G5）
│   ├── G1: 实事求是 → 所有产出有真实数据支撑
│   ├── G2: 规划可行 → 进化规划对标矩阵分≥上一轮
│   ├── G3: 转换完整 → 文件转换成功率 ≥ 98%
│   ├── G4: 对标校验 → 对标矩阵不退化
│   └── G5: 全局一致 → 四文件交叉验证通过
├── 回滚 → 任一门控失败 → 自动回滚上一快照
└── 报告 → 生成全域同步报告 → 归档蒸馏日志
```

## 四、进程管理配置（v3.6 更新）

### 4.1 六步蒸馏流程并发控制

| 控制项 | 配置值 |
|--------|--------|
| **最大实例数** | 1（单实例运行） |
| **排队策略** | 最多排队 1 次，超量丢弃 |
| **定时触发排队** | 前序任务未完成 → 排队等待 |
| **手动触发冲突** | 通知用户当前任务运行中 |
| **异常强制取消** | 检测到异常 → 取消当前任务 → 启动新蒸馏 |
| **锁超时** | 30 分钟 → 自动解锁 + 告警 |

### 4.2 资源分配矩阵

| Agent | CPU 预算 | 内存预算 | I/O 预算 | 最大并行任务 |
|-------|---------|---------|---------|------------|
| 豆包 Agent | 30% | 4GB | 中 | 3 |
| Hermes Agent | 15% | 2GB | 低 | 5（调度类）|
| OpenClaw | 40% | 8GB | 高 | 10（Worker 池）|
| Worker 池 | 动态 | 动态 | 动态 | 1~10（自动扩缩）|

### 4.3 熔断与恢复

| 异常场景 | 熔断条件 | 恢复策略 |
|---------|---------|---------|
| 单 Worker 超时 | 超时 120s | 超时重试 1 次 → 失败转其他 Worker |
| Worker 池满载 | 活跃 Worker = 10 | 排队等待 + 降级通知 |
| Verifier 连续 2 次不通过 | 同任务连续失败 2 次 | 标记异常 + 通知豆包 Agent |
| Agent 进程崩溃 | 心跳检测失联 60s | 自动重启 + 状态恢复 + 日志归档 |
| 蒸馏任务失败 | 任一步骤门控不通过 | 回滚快照 + 写入 deadletter |
| 配置文件损坏 | 校验和不匹配 | 从最新备份恢复 + 通知用户 |

## 五、Swarm 编排配置

### 5.1 角色分配

| 角色 | 担任 Agent | 职责 |
|------|-----------|------|
| **Owner** | Hermes Agent | 目标制定、任务分解、质量把关、最终交付 |
| **Worker** | OpenClaw + Worker 池 | 并行执行子任务、返回结果 |
| **Verifier** | 豆包 Agent | 结果验证、一致性检查、反馈修正 |

### 5.2 协作流程

```
1. Owner 接收任务 → 分解为 N 个子任务
2. Owner 将子任务分发给 Worker 池（支持动态扩缩）
3. Worker 执行并返回结果
4. Verifier 审查结果（正确性/完整性/一致性）
5. 不通过 → 返回 Worker 修正（最多 2 次迭代）
6. 通过 → Owner 聚合结果，交付最终产出
```
