## 技能1：任务调度引擎

### 核心架构
```
任务池(SQLite) → 优先级排序 → SWARM协作协议 
  ├── 豆包Agent队列 (交互任务)
  ├── OpenClaw队列 (执行任务)
  └── 定时任务队列 (自动化)
```

### 调度策略
| 优先级 | 类型 | 抢占策略 | 超时(TTL) |
|--------|------|---------|-----------|
| P0 | 用户实时交互 | 立即抢占 | 30s |
| P1 | 蒸馏迭代 | 队列优先 | 300s |
| P2 | 健康巡检 | 低负载时执行 | 60s |
| P3 | 日志归档 | 空闲执行 | 600s |

### 状态管理
- 任务状态机：PENDING → CLAIMED → RUNNING → DONE / FAILED
- 原子认领机制：SWARM SQLite 原子写入防止重复执行

## 技能2：进程管控

### 监控范围
- 豆包Agent进程 (健康检测)
- OpenClaw龙虾Agent进程
- 定时任务进程 (Win cron/计划任务)
- 插件进程 (VNPY等)

### 管控动作
| 场景 | 动作 | 自动/手动 |
|------|------|----------|
| 进程僵死 | 自动重启 (最多3次) | 自动 |
| 内存超标 | 降级执行/释放缓存 | 自动 |
| CPU峰值 | 排队延迟执行 | 自动 |
| 3次失败 | 降级 → 通知用户 | 半自动 |

## 技能3：故障熔断与恢复

### 熔断策略
```
执行帧 @5分钟 
  → 健康检查(活跃/ID/响应/警告)
    → 正常: 继续
    → 异常>2帧: 自动重启Actor
      → 重启失败>3次: 暂停Actor + 通知用户 + 写CrashReport
```

### 恢复流程
1. 检测恢复信号（进程恢复/资源释放）
2. 逐步增加任务负载（半开 → 全开）
3. 3帧正常后恢复完全负载

## 技能4：SWARM协作协议

### 8种协作模式
| 模式 | 场景 | 示例 |
|------|------|------|
| 顺序 | 依赖链 | 巡检→优化→归档 |
| 并行 | 独立任务 | 多文件同时处理 |
| 轮询 | 负载均衡 | 交替处理请求 |
| 广播 | 全局通知 | 版本升级通知 |
| 竞选 | 分布式锁 | 定时任务抢占 |
| 管道 | 流水线 | 数据采集→处理→输出 |
| 扇出 | 一对多 | 主控→子Agent分发 |
| 聚合 | 多对一 | 多源结果汇总 |
