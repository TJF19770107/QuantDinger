## 一、全网感知扫描（R09 更新）

### 1.1 Marvis Workbody 深度对标 — 本轮P0发现

Marvis 是腾讯2026年5月20日上线的操作系统级AI助手，内置6 Agent协作体系（1 PM + 5专业Agent），是消费级Multi-Agent落地的标杆。

#### 1.1.1 Marvis 6 Agent 架构映射

| Marvis Agent | 技术实现 | 豆包Agent对应 | 差距 |
|-------------|---------|-------------|------|
| PM Agent | 云端混元/DeepSeek V4 意图理解+任务拆解 | 龙虾五步法 Step1-2 + 推理引擎 | ⚠️ 豆包缺少专用PM节点 |
| File Agent | 本地文件索引+语义搜索(图片文字/人脸/场景) | AutoFileScanner v1.0 | ⚠️ 豆包缺少语义图片搜索 |
| Computer Agent | Windows API直调(非模拟点击)，硬件检测走系统调用 | DesktopController v2.0 | ⚠️ 豆包依赖PowerShell，Marvis走原生API |
| App Agent | GUI视觉识别+模拟操作，支持EXE和安卓App | DesktopController v2.0 (仅Windows) | 🔴 豆包无GUI视觉识别，无安卓App操作 |
| Browser Agent | 浏览器接管+DOM解析 | 无对应模块 | 🔴 豆包无浏览器Agent |
| Search Agent | 网络搜索引擎调用 | 龙虾五步法 Step1 搜索子步骤 | ⚠️ 豆包无专用搜索Agent |

#### 1.1.2 Marvis 端云双模式对标

| 维度 | Marvis | 豆包Agent | 差距 |
|------|--------|----------|------|
| 效率模式 | 混元+DeepSeek V4(云端) | OpenAI API(云端) | 持平 |
| 隐私模式 | Qwen端侧模型，断网可用 | 无端侧模型 | 🔴 豆包无端侧推理 |
| 路由策略 | PM Agent自动判断 | 无自动路由 | 🔴 需手动切换 |
| 硬件加速 | Intel OpenVINO | 无 | 🔴 无 |

#### 1.1.3 Marvis 安全机制对标

| 安全层 | Marvis | 豆包Agent SafeGuard v3.0 | 对齐 |
|--------|--------|--------------------------|------|
| 低风险(读/搜索) | AI自主执行 | ✅ 自动执行 | ✅ |
| 中风险(删/改设置) | L2硬垂询：AI出计划→确认→执行 | ✅ 三级权限分级 | ✅ |
| 高风险(支付/微信) | 禁止AI执行，必须人工 | ✅ 永久护栏 | ✅ |

**结论**：豆包Agent在安全机制上与Marvis完全对齐。但在Agent分工粒度、端侧推理、GUI视觉识别三个维度存在明显差距。

### 1.2 Hermes Agent vs OpenClaw 深度对比 — 架构哲学差异

> 来源：OpenClaw官方博客 2026-04-11

#### 1.2.1 核心差异

| 维度 | OpenClaw | Hermes Agent | 豆包Agent对标 |
|------|----------|-------------|-------------|
| 架构哲学 | 中央网关(广度优先) | 执行循环(深度优先) | 执行循环(与Hermes一致) |
| 渠道集成 | 20+个(W/A/T/D/S/飞书/钉钉/QQ) | 6个(T/D/S/W/Signal/CLI) | 当前仅CLI |
| Skills生态 | 数十个社区Skills，开箱即用 | 内置少量，Agent自生成 | SkillForge自生成(与Hermes一致) |
| 记忆系统 | 跨渠道持久化，会话维度 | 多层：全文检索+LLM总结+用户画像 | MemoryOS v2.0三层架构(与Hermes一致) |
| 自我改进 | 社区驱动(新Skill/配置) | 内置学习闭环+强化学习 | SICA自进化协调器(与Hermes一致) |
| 执行沙箱 | 主进程内执行 | 6种沙箱(local/Docker/SSH/Daytona/Singularity/Modal) | 仅local |
| 资源消耗 | 中等(一个长期进程+DB) | 可极低($5 VPS) | 中等 |

#### 1.2.2 五类场景选型对照

| 场景 | 选OpenClaw | 选Hermes | 豆包Agent位置 |
|------|-----------|---------|-------------|
| 单人长期积累 | ❌ | ✅ | ✅ 符合 |
| 强隔离任务执行 | ❌ | ✅ | ⚠️ 无沙箱 |
| 极低预算 | ❌ | ✅ | ✅ |
| Skills自生成 | ❌ | ✅ | ✅ SkillForge |
| 持续优化型任务 | ❌ | ✅ | ✅ AutoWake |

#### 1.2.3 双栈部署启示

OpenClaw+Hermes双栈部署模式为豆包Agent提供了关键参考：

```
OpenClaw → 多渠道入口(接所有消息/意图识别/快速问答)
Hermes → 深度执行后端(长任务/学习/沙箱/持久记忆)
两者通过HTTP/消息队列/文件系统交换任务和结果
```

**豆包Agent可以借鉴此模式**：将豆包APP作为前端入口层，龙虾AI主控中心作为深度执行后端。

### 1.3 Google Antigravity — Agent-First IDE 深度解析

#### 1.3.1 核心能力

| 能力 | Antigravity | 豆包Agent对标 |
|------|-----------|-------------|
| Agent-First范式 | 描述目标→Agent规划→自主执行→审查结果 | 龙虾五步法 |
| 双界面(Editor/Manager) | VS Code fork + Mission Control | 无GUI界面 |
| 自主Agent | 规划/执行/验证/迭代/文档 | SICA自进化协调器 |
| 多模型支持 | Gemini3/Claude/GPT 6种模型 | 通过API可扩展 |
| 上下文窗口 | 100万+ token (Gemini 3) | 依赖模型API限制 |
| MCP协议 | GitHub/数据库/API集成 | 无MCP支持 |
| 终端沙箱 | macOS sandbox | SafeGuard v3.0 |
| AGENTS.md规则 | 项目级指令约束 | 龙虾全域模板 |
| Artifact系统 | 任务列表/代码Diff/截图/录制 | 无 |
| SWE-bench | 76.2% | N/A |

#### 1.3.2 关键启示

1. **Agent-First不是概念**：Antigravity证明了"描述目标→Agent执行→人类审查"范式已进入生产级
2. **多模型不是奢侈品**：Antigravity支持6种模型自由切换，豆包Agent应建立模型抽象层
3. **Artifact透明化**：让Agent的每一步产生可视化产物（Diff/截图/日志），建立信任
4. **MCP协议正在成为标准**：豆包Agent应规划MCP支持
