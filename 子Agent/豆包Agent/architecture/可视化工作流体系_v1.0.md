## 二、节点体系

### 2.1 节点类型定义

| 节点类型 | 标识 | 功能 | 示例 |
|---------|------|------|------|
| TRIGGER | 触发器 | 工作流启动入口 | 定时触发 / 事件触发 / 手动触发 |
| ACTION | 动作节点 | 执行具体操作 | 文件扫描 / 代码生成 / 桌面控制 |
| CONDITION | 条件节点 | 分支判断 | 文件类型判断 / 置信度阈值 / 用户确认 |
| AGENT | Agent节点 | 子Agent派发 | file-agent / app-agent / search-agent |
| MERGE | 汇聚节点 | 多路结果合并 | 并行结果聚合 |
| TERMINAL | 终止节点 | 工作流结束 | 成功 / 失败 / 超时终止 |

### 2.2 节点配置规范

```json
{
  "node_id": "wf_R07_001",
  "node_type": "ACTION",
  "display_name": "文件扫描",
  "config": {
    "skill": "AutoFileScanner",
    "method": "scan_directory",
    "params": {
      "path": "{{context.workspace}}",
      "recursive": true,
      "file_types": [".md", ".py", ".json"]
    },
    "timeout": 30000,
    "retry": 3,
    "retry_delay": 5000
  },
  "next": ["wf_R07_002"],
  "on_error": "wf_R07_ERR_001"
}
```

## 三、执行引擎

### 3.1 执行模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| SEQUENTIAL | 串行执行，逐节点推进 | 有数据依赖的任务链 |
| PARALLEL | 并行执行，无依赖节点同时启动 | 独立子任务批量处理 |
| CONDITIONAL | 条件分支，根据节点输出选择路径 | 需要判断的场景 |
| LOOP | 循环执行，直到条件满足 | 迭代优化 / 分页处理 |
| SUB_WORKFLOW | 子工作流嵌套 | 复杂任务模块化 |

### 3.2 并行调度规则

```
规则1：无数据依赖 → 自动并行
规则2：共享资源（文件/锁）→ 串行化
规则3：高风险操作 → 逐项确认后串行
规则4：同批次最多5个并行节点
规则5：并行失败互不影响，各自重试
```

### 3.3 条件跳转配置

```json
{
  "condition": {
    "field": "{{node_R07_001.output.file_count}}",
    "operator": "GREATER_THAN",
    "value": 100,
    "true_branch": "node_handle_large",
    "false_branch": "node_handle_small"
  }
}
```

支持操作符：`EQUALS`, `GREATER_THAN`, `LESS_THAN`, `CONTAINS`, `REGEX`, `IS_NULL`, `IN_LIST`

## 五、日志绑定

### 5.1 日志分级

```
[TRACE] 节点内部详细执行步骤（仅开发模式）
[DEBUG] 调试信息（参数/中间变量）
[INFO]  节点开始/结束/状态变更
[WARN]  重试/降级/非致命异常
[ERROR] 节点失败/异常终止
[FATAL] 工作流级致命错误
```

### 5.2 日志绑定规则

每个节点自动绑定独立日志通道：
```
logs/
├── wf_R07_claude_reasoning/
│   ├── node_001_intent_parser.log
│   ├── node_002_condition_decomposer.log
│   ├── node_003_reasoning_engine.log
│   ├── node_004_execution_orchestrator.log
│   ├── node_005_review_learner.log
│   └── workflow_aggregate.log
```

## 六、多Agent任务分发

### 6.1 分发规则

```
工作流节点类型为 AGENT 时：
  → 解析 agent_name + task 参数
  → dispatch_task 派发至对应 Sub Agent
  → 监控执行状态
  → 收集结果并传递给下游节点
```

### 6.2 Agent节点配置

```json
{
  "node_id": "wf_R07_agent_file",
  "node_type": "AGENT",
  "display_name": "文件分析Agent",
  "config": {
    "agent_name": "file-agent",
    "task": "<overall_goal>分析项目文件结构</overall_goal><current_task>扫描并分析所有Python文件的依赖关系</current_task>",
    "inherit": false,
    "timeout": 120000,
    "on_agent_error": "retry_with_fallback"
  },
  "next": ["wf_R07_merge_results"]
}
```
