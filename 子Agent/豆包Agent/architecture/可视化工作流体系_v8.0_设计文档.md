## 一、工作流核心概念

### 1.1 节点体系

| 节点类型 | 标识 | 功能 | 输入 | 输出 |
|---------|------|------|------|------|
| **Trigger** | `trigger` | 工作流启动触发 | 事件/定时/手动 | 执行上下文 |
| **FileScanner** | `file_scan` | 文件扫描与索引 | 目录路径 | 文件列表 |
| **ContentAnalyzer** | `content_analyze` | 内容分析/摘要 | 文件/文本 | 分析结果 |
| **MCP_Sandbox** | `mcp_sandbox` | 安全沙箱检测 | 工具调用 | 安全评分+结果 |
| **Reasoner** | `reasoner` | 推理决策 | 分析结果 | 决策方案 |
| **Executor** | `executor` | 方案执行 | 决策方案 | 执行结果 |
| **Validator** | `validator` | 结果验证 | 执行结果 | 验证报告 |
| **Reporter** | `reporter` | 报告生成 | 验证结果 | 产出物 |
| **Archiver** | `archiver` | 归档存储 | 产出物 | 归档确认 |
| **Router** | `router` | 条件路由 | 任意 | 分支路由 |
| **Merger** | `merger` | 合并汇总 | 多路输入 | 合并结果 |
| **Notifier** | `notifier` | 通知推送 | 消息 | 推送确认 |

## 二、执行规则体系

### 2.1 串行执行规则

```yaml
serial_execution:
  description: "节点按顺序依次执行，前置节点完成后触发后置节点"
  
  syntax:
    type: serial
    nodes: [node_id_1, node_id_2, ...]
    
  rules:
    - 前一个节点必须状态为 COMPLETED 才触发下一个
    - 任一节点 FAILED 则整个串行链中止（除非配置了 continue_on_failure）
    - 支持节点间数据传递（output → next.input）
    - 每个节点独立Durable检查点
  
  example:
    trigger → file_scan → content_analyze → reasoner → executor → reporter
    
  config:
    continue_on_failure: false   # 失败是否继续
    fail_fast: true              # 是否快速失败
    max_total_time_ms: 60000     # 总超时
```

### 2.2 并行执行规则

```yaml
parallel_execution:
  description: "多个节点同时执行，全部完成后进入下一阶段"
  
  syntax:
    type: parallel
    nodes: [node_id_1, node_id_2, ...]
    merge_strategy: [wait_all | wait_any | wait_n]
    
  rules:
    - 所有并行节点独立执行，无执行顺序依赖
    - wait_all: 所有节点完成才继续
    - wait_any: 任一节点完成即继续（其余取消）
    - wait_n(N): N个节点完成即继续
    - 并行节点间禁止数据依赖（有依赖应串行）
    - 最多同时并行10个节点（资源保护）
  
  example:
    parallel:
      - file_scan(dir=A)
      - file_scan(dir=B)  
      - file_scan(dir=C)
    merge_strategy: wait_all
    → merger: 合并三个扫描结果
    
  safety:
    max_parallel_nodes: 10
    resource_limit:
      total_tokens: 50000
      max_cost: 2.00
```

### 2.3 条件跳转规则

```yaml
conditional_execution:
  description: "根据条件表达式决定执行路径"
  
  syntax:
    type: conditional
    conditions:
      - expression: "result.score > 0.8"
        on_true: [node_id_high]
        on_false: [node_id_low]
      - expression: "result.file_count == 0"
        on_true: [node_id_empty_handler]
        
  rules:
    - 条件表达式用Python语法（沙箱执行）
    - 支持多条件链式判断（if-elif-else）
    - 每个分支可再嵌套串行/并行/条件
    - 条件评估超时200ms，超时走default分支
    
  example:
    router:
      conditions:
        - if: "complexity_score > 0.7"
          then: [deep_reasoner]     # 深度推理路径
        - elif: "complexity_score > 0.3"
          then: [hybrid_reasoner]   # 混合推理路径
        - else:
          then: [fast_reasoner]     # 快速推理路径
    
  default_branch: [fast_reasoner]   # 默认分支
```

### 2.4 复合编排示例

```yaml
# 全模态分析工作流
workflow:
  id: wf_multimodal_analysis_R54
  name: "全模态文档分析工作流"
  
  nodes:
    - id: trigger
      type: trigger
      config:
        trigger_type: manual
    
    # 并行扫描三个源
    - id: parallel_scan
      type: parallel
      nodes:
        - id: scan_docs
          type: file_scan
          config: { dir: "文档库", types: [pdf, docx, pptx] }
          model_tier: tier1
        - id: scan_images
          type: file_scan
          config: { dir: "图片库", types: [jpg, png] }
          model_tier: tier1
        - id: scan_audio
          type: file_scan
          config: { dir: "音频库", types: [mp3, wav] }
          model_tier: tier1
    
    # 合并扫描结果
    - id: merger
      type: merger
      inputs: [scan_docs.output, scan_images.output, scan_audio.output]
    
    # 条件路由：根据文件数量选择策略
    - id: strategy_router
      type: router
      conditions:
        - if: "merger.output.total_count > 100"
          then: [summary_mode]      # 摘要模式
        - else:
          then: [full_analysis]      # 全量分析
    
    - id: full_analysis
      type: serial
      nodes:
        - id: content_analyze
          type: content_analyzer
          model_tier: tier2
        - id: safety_check
          type: mcp_sandbox
        - id: reason
          type: reasoner
          model_tier: tier3
        - id: report
          type: reporter
    
    - id: summary_mode
      type: serial
      nodes:
        - id: quick_scan
          type: content_analyzer
          model_tier: tier1
        - id: smart_summary
          type: reasoner
          model_tier: tier2
        - id: summary_report
          type: reporter
    
    - id: archiver
      type: archiver
      inputs: [full_analysis.report.output, summary_mode.summary_report.output]
```

## 五、多Agent任务分发机制

### 5.1 分发架构

```
Gateway微内核中枢
       │
       ├──→ AgentPool (豆包/Claude/GPT/DeepSeek)
       │       │
       │       ├──→ Lead Agent (任务调度器)
       │       │       ├──→ Specialist Agent 1 (文件处理)
       │       │       ├──→ Specialist Agent 2 (推理分析)
       │       │       └──→ Specialist Agent 3 (报告生成)
       │       │
       │       └──→ MCP安全沙箱 (独立Agent)
       │
       └──→ 工作流引擎 (DAG编排)
               └──→ 节点 → Agent分配 → 模型路由
```

### 5.2 任务分发策略

```python
class MultiAgentDispatcher:
    """多Agent任务分发器"""
    
    AGENT_POOL = {
        'file_agent': {
            'capabilities': ['file_scan', 'file_ops', 'search'],
            'max_concurrent': 5,
            'preferred_model': 'deepseek-v3.1'
        },
        'reasoning_agent': {
            'capabilities': ['analyze', 'reason', 'plan'],
            'max_concurrent': 3,
            'preferred_model': 'claude-opus-4.8'
        },
        'execution_agent': {
            'capabilities': ['execute', 'generate', 'report'],
            'max_concurrent': 4,
            'preferred_model': 'claude-sonnet-4'
        },
        'safety_agent': {
            'capabilities': ['mcp_sandbox', 'validate'],
            'max_concurrent': 2,
            'preferred_model': 'msb-secure'
        }
    }
    
    def dispatch(self, node: WorkflowNode) -> AgentAssignment:
        """为节点分配最优Agent"""
        required_caps = self._extract_capabilities(node)
        
        # 按能力匹配+负载均衡选择
        candidates = [
            agent_id for agent_id, config in self.AGENT_POOL.items()
            if all(cap in config['capabilities'] for cap in required_caps)
        ]
        
        # 选负载最低的Agent
        selected = min(candidates, key=lambda a: self._current_load(a))
        
        return AgentAssignment(
            agent_id=selected,
            model=self.AGENT_POOL[selected]['preferred_model'],
            node_id=node.id
        )
```
