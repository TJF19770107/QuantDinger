## 二、完整自动化流水线

### 2.1 标准流水线

```
外部事件 → Trigger监听 → Agent分析 → 修复/执行 → 测试验证 → 开PR → 人工审批 → 合并
```

### 2.2 事件源

| 事件源 | 触发条件 | 动作 |
|--------|---------|------|
| GitHub Issue | 打上特定Label | 分析Bug → 修复 → 开PR |
| GitHub PR | 提交Review请求 | 自动Code Review |
| Sentry | 新错误报告 | 定位根因 → 修复 → 开PR |
| Datadog | 性能回归告警 | 定位性能瓶颈 → 优化 |
| 定时触发 | Cron表达式 | 定期维护/报告生成 |

### 2.3 三档审批模式

```
suggest    → 每步操作都需人工确认（最安全）
auto-edit  → 读操作自动，写操作确认
full-auto  → 全自动（仅限已验证的CI任务）
```

## 三、Triggers 配置模板

```yaml
# .agent/triggers.yml
triggers:
  - name: auto-fix-bug
    on:
      github:
        event: issues
        action: labeled
        label: "agent-fix"
    task: |
      分析Issue描述的Bug，定位代码根因，
      生成修复方案，编写测试用例，
      创建PR并关联此Issue。
    approval_mode: suggest
    timeout: 600s
    
  - name: auto-code-review
    on:
      github:
        event: pull_request
        action: review_requested
    task: |
      审查PR代码变更，检查：
      1. 逻辑正确性
      2. 安全漏洞
      3. 性能影响
      4. 测试覆盖
      输出结构化的Review Comments。
    approval_mode: auto-edit
    
  - name: sentry-auto-fix
    on:
      sentry:
        severity: critical
        new: true
    task: |
      读取Sentry错误报告，结合堆栈跟踪定位代码根因，
      生成修复方案，创建PR。
    approval_mode: suggest
```

## 四、SubagentStart Hook

子Agent被启动时触发自定义脚本注入，用于：
- 环境准备：安装依赖、设置环境变量
- 权限检查：验证子Agent是否有权访问目标路径
- 上下文注入：从记忆库加载关联信息

```yaml
hooks:
  subagent_start:
    - script: "./scripts/setup-env.sh"
    - script: "./scripts/check-permissions.sh"
    - script: "./scripts/load-memory-context.sh"
```
