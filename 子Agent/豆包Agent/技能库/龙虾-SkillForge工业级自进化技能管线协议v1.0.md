# 龙虾-SkillForge工业级自进化技能管线协议 v1.0

> **对标来源**：SkillForge学术论文(2026.04) + calderbuild/skillforge开源(MIT)
> **核心突破**：三阶段Pipeline自动诊断→定位→重写，演化三轮超越人类专家
> **类型**：生成层 · 技能进化
> **状态**：ACTIVE

---

## 一、协议概述

当前SkillForge v3.0（协议#5）实现了基本的技能生成能力，但存在三个短板：
1. **生成后不追踪**：技能部署后不再优化
2. **失败不诊断**：技能出错时无法自动定位缺陷
3. **无安全扫描**：生成的技能无安全审查

本协议将SkillForge从"一次性生成器"升级为"持续自进化的工业级技能管线"。

## 二、三阶段Pipeline

### 阶段1：Failure Analyzer（失败分析器）

```
输入：执行日志 + 失败案例
输出：失败类型分类 + 失败模式清单

失败类型：
├── 工具调用错误（参数错误/工具不存在/超时）
├── 逻辑错误（步骤顺序错误/条件判断遗漏）
├── 上下文错误（信息丢失/幻觉/过时信息）
└── 边界错误（未覆盖边缘情况/异常处理缺失）
```

### 阶段2：Skill Diagnostician（技能诊断器）

```
输入：失败模式 + 对应技能文件
输出：缺陷定位报告

诊断方法：
1. 回溯失败步骤 → 定位技能中的对应指令
2. 对比成功案例 → 识别差异点
3. 分析上下文 → 判断是技能缺陷还是执行环境问题
```

### 阶段3：Skill Optimizer（技能优化器）

```
输入：缺陷定位报告 + 原始技能
输出：优化后的技能文件

优化策略：
├── 补充遗漏步骤
├── 修正错误参数/条件
├── 添加异常处理
├── 更新过时信息
└── 合并冗余规则
```

## 三、安全扫描器

### 3.1 20+静态分析规则

| 严重等级 | 规则示例 | 数量 |
|---------|---------|------|
| Critical | 检测 `rm -rf` / `format` 等破坏性命令 | 5 |
| High | 检测未授权网络请求/文件访问 | 6 |
| Medium | 检测硬编码路径/缺少超时 | 6 |
| Low | 检测风格问题/缺少注释 | 4 |

### 3.2 安全评分

```
扫描完成 → 0-100 安全评分
  < 60  → 拒绝部署，需人工审查
  60-80 → 警告，建议审查后部署
  > 80  → 自动部署
```

## 四、豆包Agent集成方案

### 4.1 与SkillForge协议#5的升级关系

| 维度 | SkillForge v3.0 | 工业版增强 |
|------|----------------|-----------|
| 生成方式 | 一次性 | 持续迭代 |
| 质量保障 | 无 | 三阶段Pipeline |
| 安全审查 | 无 | 20+规则扫描+评分 |
| 失败处理 | 人工发现 | 自动诊断修复 |
| 部署方式 | 手动 | 自动校验后部署 |

### 4.2 与Curator协议#22的协同

- Curator负责"技能库级别的管理"（评分/合并/归档）
- SkillForge工业版负责"单个技能级别的进化"（诊断/修复/优化）
- Curator定期触发 → SkillForge工业版执行单技能优化

### 4.3 触发策略

```json
{
  "trigger": {
    "on_failure": "技能执行失败后自动触发",
    "on_schedule": "每48小时对所有活跃技能巡检",
    "on_demand": "用户手动触发某技能优化"
  }
}
```
