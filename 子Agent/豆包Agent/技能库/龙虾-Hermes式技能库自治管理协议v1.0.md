## 一、协议目标

赋予豆包Agent自动维护自身技能库的能力：评分、整合、清理、归档。解决技能库随迭代不断膨胀、质量下降、死技能堆积的问题，实现"越用越聪明，越用越精简"的正向飞轮。

## 三、评分体系

### 3.1 实用性评分（0-100）

```
实用性 = (最近N轮调用次数 / N) × 成功率 × 100

参数：
- N = 最近4轮迭代（16小时窗口）
- 成功率 = 调用成功次数 / 总调用次数
- 未被调用 → 实用性 = 0
```

### 3.2 质量评分（0-100）

```
质量 = (指令完整性 × 0.4) + (边界清晰度 × 0.3) + (冲突检测 × 0.3)

- 指令完整性：是否有明确的触发条件、执行步骤、输出格式
- 边界清晰度：是否明确适用范围和不适用范围
- 冲突检测：与已有技能是否存在功能重叠或冲突
```

### 3.3 综合评分

```
综合 = 实用性 × 0.6 + 质量 × 0.4

等级：
- S (>80)：核心技能，优先维护
- A (60-80)：常用技能，正常维护
- B (40-60)：辅助技能，定期检查
- C (20-40)：边缘技能，关注退化
- D (<20)：候选清理
```

## 四、整合规则

### 4.1 触发条件
- 两个及以上技能功能重叠度 > 70%
- 触发关键词交集 > 80%

### 4.2 整合流程
```
1. 识别重叠技能组
2. 提取各技能的独特功能
3. 生成合并方案
4. 执行EvoSkill Verify Agent验证
5. 验证通过 → 写入新技能文件
6. 归档旧技能文件
7. 更新能力注册表
```

### 4.3 命名规则
- 合并后技能名：`{技能1}_{技能2}_merged_v{version}`
- 保留原始技能文件到 `archive/` 目录

## 五、清理规则

### 5.1 归档条件

| 条件 | 阈值 | 动作 |
|------|------|------|
| 综合评分 < 30 | 连续2轮 | 移入 archive/ |
| 未被调用 | 超过12小时 | 移入 archive/ |
| 质量评分 < 20 | 任意轮次 | 移入 archive/ |
| 与其他技能冲突 | 持续性 | 移入 archive/，保留整合版 |

### 5.2 绝不删除
- 归档 = 移动到 `archive/` 目录，不物理删除
- 归档技能可在需要时恢复
- 保留完整历史追溯能力

## 七、Curator 报告格式

```markdown
# Curator 运行报告 — {timestamp}

| 技能 | 实用性 | 质量 | 综合 | 等级 | 动作 |
|------|--------|------|------|------|------|
| skill_1 | 85 | 90 | 87 | S | 保留 |
| skill_2 | 15 | 40 | 25 | C | 归档 |

## 整合记录
- {skill_a} + {skill_b} → {skill_merged} (重叠度: 82%)

## 清理记录
- 归档: {skill_x} (评分: 22, 未使用: 18h)
- 归档: {skill_y} (评分: 18, 质量: 15)

## 技能库健康度
- 总技能数: 24 → 22
- S级: 8 | A级: 10 | B级: 3 | C级: 1
- 归档: 2
```

## 八、执行约束

1. **Curator运行频率**：默认每4小时（对齐迭代周期），可在模板配置中调整
2. **归档安全**：归档操作不可逆但可恢复，归档目录永久保留
3. **合并验证**：合并后的技能必须通过EvoSkill Verify验证才能替代原技能
4. **人工覆盖**：用户可以手动标记技能为 `protected: true`，Curator不会触碰
5. **回滚支持**：每次Curator运行前自动创建技能库快照，异常可回滚
