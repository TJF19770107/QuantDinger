> **对标来源**：Claude Dynamic Workflows + Antigravity 2.0动态子代理 + Gemini CLI子代理
> **版本**：v1.0 · 2026-05-31
> **所属轮次**：R07

## 一、协议目标

主Agent在任务执行过程中按需动态创建、管理和销毁子Agent，通过编排脚本实现百级并行子Agent协同，突破单Agent上下文窗口限制。

---

## 二、核心机制

### 2.1 编排脚本 vs 传统子Agent调度

| 维度 | 传统子Agent | 编排脚本模式 |
|------|-----------|------------|
| 调度方式 | 主Agent逐一轮询 | 主Agent编写脚本，脚本管理并行调度 |
| 中间结果 | 堆积在主Agent上下文 | 存在脚本变量中，不占上下文 |
| 并行上限 | 几个到十几个 | 几十到几百个 |
| 最终输出 | 原始结果 | 验证+汇总后的精简结果 |

### 2.2 编排脚本模板

```javascript
// 示例：大规模代码审查工作流
async function main() {
  // 1. 拆解任务
  const repos = await scanAllRepos(); // 返回500个仓库
  
  // 2. 并行启动子Agent池（每批50个）
  const results = [];
  for (let i = 0; i < repos.length; i += 50) {
    const batch = repos.slice(i, i + 50);
    const batchResults = await Promise.all(
      batch.map(repo => spawnSubAgent("code-reviewer", { repo }))
    );
    results.push(...batchResults);
  }
  
  // 3. 双轮审查：每个结果经过2个审查Agent
  const reviewed = await Promise.all(
    results.map(r => dualReview(r))
  );
  
  // 4. 汇总：只保留审查通过的
  const final = reviewed.filter(r => r.passed);
  return final;
}
```

### 2.3 子Agent生命周期

```
  [spawn] → [initialize] → [execute] → [self-check] → [report]
                ↓                ↓            ↓
            [timeout]      [error]      [hallucination]
                ↓                ↓            ↓
            [retry]         [retry]      [reassign]
                ↓                ↓            ↓
            [exhaust]       [exhaust]    [escalate to human]
                ↓                ↓
            [destroy]       [destroy]
```

## 三、关键设计约束

### 3.1 隔离性

- 每个子Agent运行在独立工作空间（Git worktree / Docker沙箱 / 虚拟环境）
- 子Agent之间不共享内存，仅通过编排脚本变量传递数据
- 避免合并冲突：每个子Agent操作独立文件或独立分支

### 3.2 可靠性

| 机制 | 说明 |
|------|------|
| 心跳检测 | 子Agent定期发送心跳，掉线自动回收 |
| 任务超时 | 每个子Agent设硬超时，超时→重试→熔断 |
| 幻觉防护 | 子Agent必须提供完成证据，不能仅"声称完成" |
| 双轮审查 | 产出经过2个审查Agent挑刺+返工 |

### 3.3 资源控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_parallel_subagents | 50 | 单批最大并生子Agent数 |
| max_total_subagents | 500 | 单次任务总共可创建的子Agent上限 |
| subagent_timeout | 120s | 单个子Agent最大执行时间 |
| retry_limit | 2 | 单个子Agent失败重试次数 |

## 四、与豆包Agent的映射

| 子代理工厂能力 | 豆包现有能力 | 差距与动作 |
|-------------|------------|-----------|
| 编排脚本生成 | 动态工作流引擎(R06) | 已具备基础，需增加脚本变量隔离 |
| 百级并行 | dispatch_task（单次最多5并行） | 核心差距，需升级并行调度架构 |
| 双轮审查 | 无 | 新增：1执行+2审查+1返工流水线 |
| 独立工作空间 | 沙箱隔离(R04) | 已有基础，需为每子Agent分配独立空间 |
| 生命周期管理 | 子Agent生命周期钩子(R03) | 已具备，补充spawn/destroy动态管理 |
