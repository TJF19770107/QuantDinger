## 一、四层记忆架构

| 层级 | 名称 | 核心作用 | 存储内容 | 生命周期 | 存储方式 |
|------|------|---------|---------|---------|---------|
| L1 | 工作记忆 | 实时交互 | 当前会话上下文、临时数据 | 会话内有效 | 模型上下文窗口 |
| L2 | 情景记忆 | 事件回溯 | 历史对话、任务记录、时间线 | 长期存储 | SQLite+FTS5全文索引 |
| L3 | 语义记忆 | 事实沉淀 | 固定知识、用户偏好、行业规则 | 永久存储，自动更新 | 向量数据库(可选: Chroma/Pinecone/Qdrant) |
| L4 | 技能专用记忆 | 技能复用 | 自动提炼的Skill、工作流、操作步骤 | 永久存储，持续迭代 | Markdown文件 in 技能库/ |

## 二、R34升级：Dream Job异步记忆巩固引擎

### 2.1 Dream Job架构（对标Claude Dreams产品化）

```
触发条件: 会话结束 / cron定时 / 手动触发
    ↓
输入: 已有memory_store + 1~100个历史session
    ↓
Dreaming Pipeline（Claude Opus 4-8级推理）
    ├── 去重: 识别并合并重复记忆条目
    ├── 合并矛盾: 最新值覆盖旧值，保留冲突标记
    ├── 表面新洞察: 从session中挖掘模式，生成新记忆
    └── 噪声过滤: 丢弃一次性调试笔记、无关闲聊
    ↓
输出: 独立的新memory_store（不修改原始store）
    ↓
Review门控: 可选人工审核模式 → 批准/丢弃
```

### 2.2 Store版本管理

| 版本 | 内容 | 操作 |
|------|------|------|
| store_v1 (原始) | Dream前原始记忆库 | 只读保留 |
| store_v2 (候选) | Dream输出新记忆库 | Review待批准 |
| store_v3 (激活) | 批准后的活跃记忆库 | 下次会话加载 |

### 2.3 Dream Job调度配置

```yaml
dream_job:
  schedule: "0 */6 * * *"  # 每6小时
  input:
    memory_store_id: "lobster_memory_v1"
    max_sessions: 50       # 最多挖掘50个历史session
  model: "claude-opus-4-8"
  instructions: |
    聚焦: 交易策略偏好、编码风格、Agent调度模式
    忽略: 一次性调试笔记、已废弃的临时配置
  review_mode: "auto"      # auto | manual
  output_store_prefix: "lobster_curated_"
```

## 三、各层实现机制（v1.0保留+v1.1增强）

### L1 工作记忆
- 当前Marvis会话上下文窗口
- 动态压缩：去除冗余，保留核心信息
- 支持Anthropic Prompt Caching

### L2 情景记忆（v1.1增强）
- SQLite+FTS5全文检索，跨会话历史秒级查询
- 会话结束后自动压缩工作记忆→情景记忆
- **NEW**: Dream Job异步去重+合并

### L3 语义记忆（v1.1增强）
- Obsidian PARA知识库向量化索引
- 跨笔记语义检索，自动关联相关知识点
- **NEW**: Dream Job跨session模式挖掘→新语义记忆

### L4 技能专用记忆
- 技能库+全域模板
- Agent完成任务后自动提取成功路径→生成Skill文件
- 遵循协议120 Spec as Code规范

## 四、记忆压缩与注入

### 压缩策略
1. 会话结束后自动将L1→L2压缩归档
2. 去除冗余重复内容，保留核心信息
3. 关键转折点、用户偏好、成功路径优先保留
4. **NEW**: Dream Job二次压缩——跨session去重合并

### 注入策略
1. 新任务启动时检索L2+L3相关记忆
2. 摘要后注入当前L1上下文
3. 只带有用信息，不堆砌冗余
4. 避免上下文臃肿
