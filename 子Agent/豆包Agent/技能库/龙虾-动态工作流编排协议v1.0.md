# 龙虾-动态工作流编排协议 v1.0

> **对标来源**：Claude Opus 4.8 Dynamic Workflows + Hermes SWARM v2.1
> **版本**：v1.0 · 2026-05-31 · R06
> **状态**：ACTIVE

---

## 一、协议目标

将豆包Agent从"单个Agent循环执行"升级为"编排脚本 → 并行子Agent协同"的动态工作流系统。

---

## 二、核心机制

### 2.1 编排脚本引擎

主Agent在接到复杂任务时，**临时编写编排脚本**（Orchestration Script），定义：
- 任务分解树（Task Tree）
- 子Agent角色与分配
- 并行/串行执行策略
- 上下文传递规则
- 结果汇总逻辑

```
主Agent → 编写编排脚本 → 启动子Agent池 → 并行执行 → 汇总结果
```

### 2.2 并行子Agent池

- 支持百级并发子Agent
- 每个子Agent独立上下文空间
- 主Agent负责任务分配/冲突检测/结果合并
- 子Agent间可互相验证（adversarial code review）

### 2.3 Kanban看板管理

借鉴Hermes SWARM的Kanban TaskBoard：
- **待分配**（Backlog）
- **进行中**（In Progress）
- **待审核**（Review）
- **已完成**（Done）
- **阻塞**（Blocked）

每个子Agent任务状态在看板中实时更新。

### 2.4 失败熔断

- 单子Agent失败 → 自动重试最多2次
- 连续3子Agent失败 → 暂停全流程，通知主Agent
- 关键路径子Agent失败 → 立即熔断，防止级联错误

## 三、适用场景

| 场景 | 任务分解 | 子Agent数 |
|------|---------|----------|
| Service-wide Bug Hunt | 按模块/文件并行扫描 | 10-50 |
| 大型代码迁移 | 按目录拆分并行重构 | 5-20 |
| 设计压力测试 | 多方案并行生成+对比 | 3-10 |
| 内容生产流水线 | 调研→撰写→审核→排版→发布 | 4-5 |
| 竞品分析报告 | 财务/产品/技术/市场多维度并行 | 4-8 |

## 四、与现有协议的关系

- 与「多Agent协同看板协议v1.0」互补：本协议聚焦**动态生成编排脚本**和**并行执行**，看板协议聚焦**SQLite原子认领**和**协作模式**
- 与「动态工作流引擎规范v1.0」互补：引擎规范侧重**技术架构**（百级并行/双轮Review/断点续传），本协议侧重**编排脚本语法**和**看板可视化**
- 与「Arena竞技场协议v1.0」协同：设计压力测试场景可复用Arena的多方案并行+自动排序

## 五、编排脚本模板

```yaml
orchestration:
  task_id: "bug-hunt-2026"
  strategy: parallel-first
  subagents:
    - id: "scanner-auth"
      role: "扫描auth模块Bug"
      files: ["src/auth/**/*.ts"]
    - id: "scanner-api"
      role: "扫描API模块Bug"
      files: ["src/api/**/*.ts"]
    - id: "scanner-db"
      role: "扫描数据库层Bug"
      files: ["src/db/**/*.ts"]
  review:
    type: adversarial
    pairs: [["scanner-auth", "scanner-api"], ["scanner-api", "scanner-db"]]
  timeout: 300s
  on_failure: pause-and-notify
```
