> **协议编号**：#93
> **对标来源**：EvolveR (浙大+上海AI Lab, ICML 2026) + DART (语义可恢复, arXiv 2605.23311)
> **版本**：v1.0
> **创建时间**：2026-06-01 R27
> **核心价值**：Agent从"会干活"走向"越干越会干"——成功和失败都转化为可复用认知经验

---

## 一、核心问题

**传统Agent范式**：给工具+给Skill → 执行 → 成功/失败 → 结束（不沉淀）
**EvolveR范式**：执行 → 离线蒸馏 → 经验入库 → RL内化 → 下次更强

差距在于：Agent是否能在每个任务闭环中"学到东西"。

---

## 二、四步闭环生命周期

### Step 1: 在线交互 (Online Interaction)
- Agent面对任务，调用外部知识库+内部经验库
- 生成完整执行轨迹（含每一步决策+中间结果+最终结果）
- 轨迹标记：成功/失败/部分成功

### Step 2: 离线自蒸馏 (Offline Self-Distillation)
- Agent冻结参数，回看自己的成功和失败轨迹
- 从轨迹中总结出简洁的**经验策略**（经验≠原始日志）
- 示例经验：
  - "遇到比较类问题时，先分别收集两个对象的信息，再下结论"
  - "如果搜索结果不足，不要重复查询词，要改写查询角度"
  - "判断人物关系时，不要凭角色名猜测，需查证角色描述"

### Step 3: 经验库维护 (Experience Maintenance)
- 语义去重：相似经验自动合并
- 动态评分：使用次数 × 成功次数 ÷ (使用次数+1) = 经验分
- 阈值裁剪：经验分 < 0.3 → 废弃
- 环境感知：过时的经验（如API已变更）自动降权

### Step 4: 强化学习内化 (RL Internalization)
- 使用GRPO强化学习优化经验条件下的策略
- 复合奖励函数：
  - 结果奖励（Outcome）：最终答案是否正确
  - 格式奖励（Format）：思考步数合理性 + 搜索多样性
- 目标：学会"何时查经验、查什么经验、如何转化经验为行动"

## 三、认知对齐定理

**核心发现**（EvolveR实验验证）：
> 当模型≥3B参数时，Agent自己总结的原则 > 外部教师模型总结的原则

**解释**：Agent自己蒸馏的原则更符合自身能力边界和推理习惯（认知对齐），因此在执行中更容易被正确调用。

**应用**：豆包Agent的迭代经验应以"自我蒸馏"为主，"外部教师提炼"为辅。

## 四、DART语义可恢复回滚（安全增强）

### 问题场景
Agent在执行中途失败，需要回滚——但下游消费者已基于该Agent的输出做了承诺操作。

### DART方案
- 语义可恢复边界：找出哪些下游操作不受上游回滚影响
- 检查点对齐：将检查点对齐到语义可恢复边界
- 可接受恢复点选择：在恢复点回滚，保证下游承诺不丢失
- 不可恢复时：阻止回滚，改为全量重放

### 豆包Agent集成
```
SafeGuard（协议#9）← DART语义可恢复
    ↓
自愈回滚检查点协议（#24）← DART边界对齐
    ↓
豆包Agent安全护栏 → 承诺感知回滚，不破坏下游
```

## 七、执行规范

1. 每次迭代任务完成后自动触发离线自蒸馏（异步，不阻塞主流程）
2. 经验库每4小时自动维护（去重+评分+裁剪）
3. 新增经验自动检测语义重复（余弦相似度 > 0.85 → 合并）
4. 经验与MUSE技能银行双向同步：高频经验自动升级为Skill候选
5. 安全约束：涉及凭证/隐私/安全漏洞的经验单独加密存储
