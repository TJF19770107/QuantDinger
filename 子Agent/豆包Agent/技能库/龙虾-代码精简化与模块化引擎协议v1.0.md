# 龙虾-代码精简化与模块化引擎协议 v1.0

> **对标来源**：Hermes Agent v0.15.0（76%代码瘦身 + 14高内聚模块）
> **版本**：v1.0 · 2026-05-31
> **所属轮次**：R07

---

## 一、协议目标

将Agent代码库从单体巨型脚本重构为高内聚、低耦合的模块化架构，同时确保冷启动性能、函数调用延迟和内存占用达到最优水平。

---

## 二、核心原则

### 2.1 代码瘦身三法则

| 法则 | 说明 | Hermes实践 |
|------|------|-----------|
| 消除胶水代码 | 删除连接不同模块的冗余中间层代码 | 16,083行 → 3,821行（-76%） |
| 延迟加载依赖 | 非启动必需的库延迟到首次调用时加载 | OpenAI依赖延迟引入，冷启动0.8s |
| 本地替代LLM | 无需语义理解的查询使用本地过滤 | session_search从90s→20ms（4500x加速） |

### 2.2 模块分层原则

```
┌─────────────────────────────┐
│     CLI入口层 (entry)        │  ← 命令行解析、参数验证
├─────────────────────────────┤
│     核心运行层 (core)        │  ← Agent循环、任务调度、状态管理
├─────────────────────────────┤
│     工具执行层 (tools)       │  ← 文件/网络/Shell/浏览器操作
├─────────────────────────────┤
│     安全防护层 (security)    │  ← 输入过滤、流量监控、权限校验
├─────────────────────────────┤
│     生态集成层 (integrations)│  ← 第三方API、MCP、插件系统
└─────────────────────────────┘
```

## 三、性能基准

| 指标 | 目标值 | 测量方法 |
|------|--------|---------|
| 冷启动时间 | <1s | `time agent --version` |
| 高频函数延迟 | <300ms | 版本查询/会话列表 |
| 本地搜索延迟 | <50ms | 免LLM本地过滤 |
| 内存基线 | <100MB | 空载常驻内存 |

---

## 四、重构检查清单

- [ ] 核心运行文件是否超过5000行？（是→拆分）
- [ ] 是否存在"万能工具类"包含5种以上不相关功能？
- [ ] 导入依赖是否在模块顶部全量加载？（是→改为延迟加载）
- [ ] 是否存在可以用字符串匹配替代LLM调用的查询？
- [ ] 安全过滤逻辑是否集中在独立模块而非散落各处？
- [ ] 每个模块是否有明确的单一职责描述？
