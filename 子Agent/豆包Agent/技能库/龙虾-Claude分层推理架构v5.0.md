## 三、五级Effort Control体系

### 3.1 分级定义

| 级别 | Effort | Token预算 | 推理深度 | 适用场景 | 缓存策略 |
|------|--------|----------|---------|---------|---------|
| L1 | Normal | 2K | 浅层 | 简单问答、翻译、格式转换 | L1热缓存 |
| L2 | Extra | 8K | 中层 | 中等复杂度分析、对比 | L1+L2 |
| L3 | Max | 32K | 深层 | 复杂推理、代码审计、数学证明 | L1+L2+L3 |
| L4 | XHigh | 64K | 极深层 | 超大规模重构、全量审计 | 全缓存+外部文件 |
| L5 | Custom | 1~128K | 用户自定义 | 特殊场景手动指定 | 用户指定 |

### 3.2 Effort自动升级路径

```
L1 Normal → 结果置信度 < 0.7 → L2 Extra
L2 Extra  → 未解决核心问题     → L3 Max
L3 Max    → 任务规模超预算     → L4 XHigh
L4 XHigh  → 需特殊配置         → L5 Custom
```

### 3.3 成本控制

| 机制 | 说明 |
|------|------|
| 预算上限 | 单任务Token上限=当前Effort级别×2 |
| 中途降级 | 推理中间结果置信度 > 0.95时提前结束 |
| 缓存复用 | 跨任务共享三级缓存，命中率目标 > 60% |
| 并行推理调度 | L3+任务自动启用多路径并行探索 |

## 五、诚实性对齐引擎

### 5.1 核心机制

```python
# honesty_alignment.py
"""
对标 Claude Opus 4.8 Code Honesty
缺陷漏检率降至1/4的核心机制
"""

class HonestyEngine:
    """
    主动标注不确定性的诚实性引擎
    """
    
    UNCERTAINTY_LEVELS = {
        "CERTAIN":     (0.95, 1.0),   # 确定
        "CONFIDENT":   (0.85, 0.95),  # 有把握
        "LIKELY":      (0.70, 0.85),  # 很可能
        "UNCERTAIN":   (0.50, 0.70),  # 不确定
        "SPECULATIVE": (0.00, 0.50),  # 推测性
    }
    
    def check_uncertainty(self, output, context):
        """
        对输出进行不确定性检测
        返回: (confidence_score, uncertainty_flags)
        """
        flags = []
        
        # 1. 边界条件检查
        if self.has_edge_cases(context):
            flags.append("⚠️ 存在未覆盖的边界条件")
        
        # 2. 假设验证
        if self.has_unverified_assumptions(output):
            flags.append("⚠️ 包含未验证的假设")
        
        # 3. 数据完整性
        if self.has_incomplete_data(context):
            flags.append("⚠️ 输入数据可能不完整")
        
        # 4. 模型能力边界
        if self.near_capability_boundary(context):
            flags.append("⚠️ 接近模型能力边界")
        
        return self.compute_confidence(output, flags), flags
```

### 5.2 输出格式

```markdown
---

- 置信度: 87% (LIKELY)

```

```
    │
```
