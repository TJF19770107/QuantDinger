# 龙虾-长周期任务分层执行协议 v1.0

> 协议编号: 122 | 版本: v1.0 | 来源: PARC分层多Agent + Hermes委托系统
> 生效范围: 所有定时任务+长周期Agent任务 | 依赖: AgentIter + ScheduledOps + ECCFramework

---

## 一、核心理念

PARC（Plan-Act-Reflect-Correct）：分层多Agent + 自我评估 + 自我反馈。
让Agent不仅能执行长周期任务，还能在无人干预下检测并纠正战略级错误。

## 二、三层架构

### Layer 1: Orchestrator（编排层）

```
任务输入 → 目标分解 → 子目标列表
    ↓
能力匹配 → Agent选择 → 资源评估
    ↓
并行调度 → 多子Agent并行执行
    ↓
结果汇聚 → 状态汇总
```

### Layer 2: Self-Assessment（自我评估层）

```
执行结果 ← 各子Agent返回
    ↓
逐项校验 → 预期vs实际对比
    ↓
异常检测 → 错误分类(战略/战术/工具)
    ↓
评估报告 → 成功/失败/需重试
```

### Layer 3: Self-Feedback（自我反馈层）

```
评估报告 → 成功路径提取
    ↓
失败分析 → 根因追溯
    ↓
策略调整 → 重新规划→重新执行
    ↓
知识沉淀 → Skill更新
```

## 三、Marvis体系映射

| PARC组件 | Marvis对应 | 说明 |
|----------|-----------|------|
| Task Planning | Main Agent dispatch_task | 任务分解与Agent调度 |
| Execution | Sub Agent自主执行 | 各专业Agent执行子任务 |
| Self-Assessment | ECCFramework扩展 | 错误校验升级为分层评估 |
| Self-Feedback | Learning Loop协议117 | 成功/失败模式→Skill沉淀 |
| Long-horizon | ScheduledOps定时运维 | 3小时/2小时循环任务 |
| Parallel Tasks | 多dispatch_task并行 | 同时派发多个子Agent |

## 四、长周期任务类型

| 任务类型 | 周期 | 复杂度 | 示例 |
|---------|------|--------|------|
| 定时迭代 | 2h/3h | 高 | 豆包Agent全域迭代 |
| 持续监控 | 1h | 中 | 交易信号监控 |
| 批量处理 | 按需 | 低 | 知识库归档 |
| 长周期仿真 | 数小时~数天 | 极高 | PARC 43小时材料科学仿真 |

## 五、失败处理策略

### 错误分级

| 级别 | 类型 | 处理策略 |
|------|------|---------|
| L1: 工具级 | 单个工具调用失败 | 自动重试3次→降级→标记 |
| L2: 战术级 | 子任务执行策略错误 | Self-Assessment检测→重新规划子任务 |
| L3: 战略级 | 整体目标路径偏差 | Self-Feedback触发→Orchestrator重新分解目标 |

### 超时与预算管理

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_iterations | 90 | 单个Agent最大迭代次数 |
| child_timeout | 300秒 | 子Agent超时时间 |
| max_spawn_depth | 2 | 最大委托深度 |
| max_concurrent_children | 3 | 最大并行子Agent数 |

## 六、与现有定时任务体系的关系

长周期任务 ≠ 替换定时任务，而是增强：
- 定时任务负责触发（ScheduledOps）
- 分层执行负责过程管理（本协议）
- 学习循环负责经验沉淀（协议117）
- Curator负责技能策展（协议119）
