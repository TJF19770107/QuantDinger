# 龙虾-Curator技能策展协议 v1.0

> 协议编号: 119 | 版本: v1.0 | 来源: Hermes Curator v0.15.2
> 生效范围: 全域技能库 | 依赖: KBArchiving + MemoryMgr

---

## 一、核心机制

### 技能状态机

```
┌─────────┐    30天未使用     ┌────────┐    超过归档时间    ┌──────────┐
│ active  │ ────────────────→ │ stale  │ ────────────────→ │ archived │
└─────────┘                   └────────┘                   └──────────┘
     ↑                              ↑
     │ 重新使用自动恢复               │ LLM审查确认后归档
     │                              │ 或保留（有持续价值）
```

### 核心组件

| 组件 | 路径 | 职责 |
|------|------|------|
| 使用追踪 | 技能库/.usage.json | 记录每个Skill的使用次数、成功率、最后使用时间 |
| 策展引擎 | Curator.curate() | 定期扫描active→stale，触发LLM审查 |
| LLM审查 | Claude审查 | 评估stale技能是否仍有价值 |
| 备份快照 | 技能库/backups/ | 每次迭代前tar.gz备份 |
| 归档仓库 | 技能库/archived/ | 永久保留已归档技能 |

## 二、使用追踪格式

```json
{
  "技能名称": {
    "version": "1.0",
    "usage_count": 23,
    "success_rate": 0.87,
    "first_used": "2026-05-01T10:00:00Z",
    "last_used": "2026-06-01T14:22:00Z",
    "created_at": "2026-04-15T10:30:00Z",
    "times_modified": 3
  }
}
```

## 三、策展规则

### Active → Stale 触发条件
- 技能超过30天未被调用
- 技能成功率低于0.5
- 技能被新版本完全替代

### Stale → Archived 触发条件
- 技能在stale状态超过60天
- LLM审查确认无持续价值
- 手动归档（用户指令）

### Stale → Active 恢复条件
- 技能被重新调用
- 用户明确要求恢复

## 四、安全机制

1. **备份先行**：每次策展操作前自动tar.gz备份完整技能库
2. **LLM审查**：不自动删除，由LLM审查确认后才归档
3. **可逆归档**：归档=移动到archived/目录，从不真正删除
4. **人工确认**：高风险策展操作需用户确认

## 五、执行周期

| 策展动作 | 频次 | 执行时间 |
|---------|------|---------|
| 使用追踪更新 | 每次技能调用后 | 即时 |
| 状态扫描 | 每24小时 | 自动静默 |
| stalet→archived | 每7天 | 需LLM审查 |
| 备份快照 | 每次策展操作前 | 自动 |
