## 一、协议目标

赋予豆包Agent自动检测异常、自主回滚到稳定版本、优雅降级运行的能力。防止迭代过程中因错误累积导致系统性崩溃，保障"越迭代越强，不退化"的核心承诺。

## 三、检查点快照体系

### 3.1 快照时机

| 时机 | 触发条件 | 快照内容 |
|------|---------|---------|
| 迭代前 | 每轮RXX迭代开始前 | 完整快照（技能库+记忆+配置+注册表） |
| 技能变更前 | SkillForge生成新技能前 | 技能库增量快照 |
| Curator运行前 | Curator Agent评分/清理前 | 技能库快照 + 评分状态 |
| 高风险操作前 | 文件批量操作/模板更新 | 受影响目录的增量快照 |

### 3.2 快照目录结构

```
checkpoints/
└── {timestamp}_R{round}/
    ├── skills_backup/           # 技能库完整备份
    │   └── *.md
    ├── memory_snapshot.json     # 记忆状态快照
    │   {
    │     "l2_memory": {...},
    │     "recent_experiences": [...]
    │   }
    ├── config_snapshot.yaml     # 配置状态快照
    │   {
    │     "template_version": "v3.0",
    │     "matrix_version": "v3.0",
    │     "active_protocols": [1..24],
    │     "gaps": {...}
    │   }
    ├── registry_snapshot.json   # 能力注册表快照
    └── manifest.yaml            # 快照元数据
        {
          "snapshot_id": "snap_20260531_R06",
          "created_at": "2026-05-31T14:00:00Z",
          "trigger": "pre_iteration",
          "parent_snapshot": "snap_20260531_R05",
          "status": "stable"
        }
```

### 3.3 快照保留策略

```
保留规则：
- 最近 5 轮迭代：保留完整快照
- 5-20 轮：保留增量快照（仅变更文件）
- 20 轮以上：仅保留 manifest + memory_snapshot

快照大小控制：
- 单个快照上限：100MB
- 总计上限：500MB
- 超限时自动清理最旧快照（遵循保留规则）
```

## 四、回滚触发条件

### 4.1 自动回滚

| 条件 | 阈值 | 回滚目标 |
|------|------|---------|
| 迭代后技能库评分下降 | >10% | 上一轮完整快照 |
| 对标矩阵任一维度下降 | >5分 | 上一轮完整快照 |
| 连续迭代报错 | ≥3次 | 最近稳定快照 |
| Curator误删核心技能 | 核心技能评分>80被归档 | Curator运行前快照 |
| 新技能导致系统异常 | 异常率>20% | 技能变更前快照 |

### 4.2 手动回滚

```
用户指令格式：
"回滚到 R04" → 加载 R04 迭代前的完整快照
"撤销上次 Curator" → 加载 Curator 运行前快照
"恢复技能 {skill_name}" → 从 archive/ 恢复指定技能
```

### 4.3 回滚执行流程

```
1. 检测回滚触发条件
2. 确定回滚目标快照
3. 创建"回滚前"紧急快照（保存当前状态用于事后分析）
4. 执行回滚：
   ├─ 恢复技能库文件
   ├─ 恢复记忆状态（L2）
   ├─ 恢复配置
   ├─ 恢复能力注册表
   └─ 更新模板版本号（附加 -rollback 标记）
5. 验证回滚后系统健康度
6. 生成回滚报告
7. 通知用户（摘要）
```

## 五、断路器模式

```
断路器状态机：

     ┌─────────┐    连续3次失败    ┌─────────┐
     │  CLOSED │ ───────────────→ │  OPEN   │
     │  正常   │                   │  熔断   │
     └─────────┘                   └─────────┘
          ↑                              │
          │     冷却30分钟后尝试          │
          │          ↓                   ↓
          │     ┌──────────┐     ┌─────────┐
          └──── │HALF_OPEN │ ←── │ 冷却中  │
                │  半开    │     │ (30min) │
                └──────────┘     └─────────┘
                     │
              ┌──────┴──────┐
              │  测试通过?   │
              ├─────────────┤
              │ YES → CLOSED│
              │ NO  → OPEN  │
              └─────────────┘

熔断后动作：
1. 冻结当前所有迭代任务
2. 自动回滚到最近稳定快照
3. 生成熔断报告
4. 多渠道通知用户
5. 等待用户手动确认恢复
```

## 六、优雅降级策略

```
降级等级：

┌─────────────────────────────────────────────┐
│ Level 0：全功能运行（正常状态）               │
│  所有技能 + 所有协议 + 全维度对标             │
├─────────────────────────────────────────────┤
│ Level 1：部分降级（非核心功能异常）            │
│  关闭：模板美化 / 报告格式优化                │
│  保留：技能生成 / 迭代执行 / 记忆更新         │
│  告警：静默日志记录                           │
├─────────────────────────────────────────────┤
│ Level 2：核心降级（核心功能异常）              │
│  关闭：新技能生成 / Curator清理               │
│  保留：记忆读写 / Obsidian同步 / 报告生成     │
│  告警：邮件通知                               │
├─────────────────────────────────────────────┤
│ Level 3：最小运行（严重异常）                  │
│  关闭：所有迭代 / 所有写操作                  │
│  保留：心跳上报 / 记忆读取（只读）             │
│  告警：钉钉/微信/邮件全渠道                    │
├─────────────────────────────────────────────┤
│ Level 4：熔断（系统性崩溃）                    │
│  关闭：所有自主操作                           │
│  保留：进程存活                               │
│  告警：紧急通知 + 等待人工介入                 │
└─────────────────────────────────────────────┘
```

## 七、关键监控指标

| 指标 | 目标值 | 告警阈值 | 采集频率 |
|------|--------|---------|---------|
| 恢复成功率 | >95% | <90% | 每次回滚后 |
| 故障检测延迟 | <5s | >10s | 实时 |
| 优雅降级率 | <5% | >10% | 每轮迭代 |
| 检查点创建耗时 | <3s | >10s | 每次快照 |
| 快照存储大小 | <500MB | >400MB | 每轮迭代 |
| 连续成功迭代 | >10轮 | <5轮 | 每轮迭代 |

## 八、自愈执行约束

1. **回滚不可逆但可恢复**：回滚前的状态保存在紧急快照中，可手动恢复
2. **断路器需人工复位**：熔断后只能由用户手动确认恢复，防止自动反复
3. **降级不丢失数据**：任何降级级别下，记忆和日志的写入不受影响
4. **快照原子性**：快照创建为原子操作，不成功不标记为可用
5. **告警静默期**：同一类型告警30分钟内不重复发送
