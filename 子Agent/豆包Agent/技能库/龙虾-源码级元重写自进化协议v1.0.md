## 一、核心原理

MOS元级重写将Agent自进化从"Prompt调整"推进到"源码级自修改"。Agent直接读取自身Python/TypeScript源代码，发现逻辑漏洞后主动修改源文件，自动测试，重新部署。

**核心突破**：Agent不再是"提示词的奴隶"——它能读自己的代码、改自己的逻辑、测试后重新部署。这是从"工具"到"生命体"的质变。

---

## 二、四步流程

### 步骤1：源码读取（Read）
- Agent读取自身核心模块的Python/TypeScript源代码
- 白盒分析：AST解析→函数调用链→数据流→控制流
- 对目标模块建立完整理解（不是猜，是真正"读代码"）

### 步骤2：漏洞识别（Detect）
- **静态分析**：代码审查（lint/type check/security scan）
- **动态测试**：运行现有测试套件→收集覆盖率+失败用例
- **性能分析**：cProfile/py-spy定位热路径瓶颈
- **逻辑审查**：对比预期行为 vs 实际行为，识别逻辑缺陷
- 识别粒度：逻辑漏洞、性能瓶颈、边界条件缺失、安全缺陷

### 步骤3：主动修改（Rewrite）
- 直接重写源文件（不是生成Prompt补丁）
- 修改内容写入`.patches/`目录（记录diff）
- 修改策略：
  - 逻辑漏洞：重写函数体，添加guard条件
  - 性能瓶颈：算法替换/缓存引入/并行化
  - 边界条件：添加边界检查+默认值
  - 安全缺陷：添加权限检查/输入验证

### 步骤4：测试→部署（Deploy）
- 自动运行完整测试套件
- **通过**：部署新版本 + 更新.metadata.json + Git提交
- **失败**：回滚到上一版本 + 记录失败模式到.memory.md + 通知用户

## 三、安全约束（三层防护）

### 第一层：修改前检查点
```
git add -A
git commit -m "pre-mos-rewrite: {module_name} at {timestamp}"
```
保留最近N个版本（N≥10），任意版本可一键回滚。

### 第二层：测试门槛
修改后必须通过：
- 单元测试（覆盖率≥85%）
- 集成测试（关键路径全覆盖）
- 性能测试（核心操作延迟<修改前×1.1）

一项不通过→自动回滚。

### 第三层：人工审批
以下场景必须Human-in-the-loop：
- 修改涉及安全模块（SafeGuard/权限/认证）
- 修改涉及记忆系统（MemoryOS/数据持久化）
- 修改涉及核心循环（Agent Loop/五步法引擎）
- 修改量超过200行或涉及5个以上文件

## 四、集成方式（接入龙虾五步法）

### Step 1：意图识别
- 用户请求→判断是否需要自进化
- 触发条件：系统检测到重复失败模式 / 用户主动请求 / AutoWake巡检发现评分下降

### Step 2：能力映射
- 定位需要修改的模块（func→module→source_file）
- 读取模块源码+测试套件

### Step 3：方案规划
- 生成修改计划（修改哪些文件/哪些函数/预期效果）
- 创建Git检查点
- 修改计划展示给用户（关键模块需审批）

### Step 4：自主执行
- 执行源码修改→运行测试→部署或回滚
- 全部操作记录到`.patches/`目录

### Step 5：反思进化
- 成功：提取修改模式→写入.memory.md→作为未来自进化的参考
- 失败：分析失败原因→写入.memory.md→标记"不推荐此类修改"

## 五、修改范围与权限

| 模块类型 | 修改权限 | 审批要求 |
|---------|---------|---------|
| 工具实现（scripts/） | ✅ 允许 | 自动（非关键工具无需审批） |
| 配置优化（configs/） | ✅ 允许 | 自动 |
| 测试增强（tests/） | ✅ 允许 | 自动 |
| 核心循环（Agent Loop） | ⚠️ 限制 | 必须人工审批 |
| 安全模块（SafeGuard） | ⚠️ 限制 | 必须人工审批 |
| 记忆系统（MemoryOS） | ⚠️ 限制 | 必须人工审批 |
| 系统级代码（OS交互） | ❌ 禁止 | 不可修改 |
| 第三方库 | ❌ 禁止 | 仅允许版本升级 |

## 六、预期效果

| 指标 | MOS前 | MOS后 |
|------|------|------|
| 自进化粒度 | Prompt级（粗） | 源码级（细） |
| 修复速度 | 需人工介入 | 自动发现→修复→部署 |
| 性能优化 | 依赖人工profiling | 自动profiling→重写 |
| 代码质量 | 依赖Review | 自动静态分析+修复 |
| 进化可追溯 | 弱（不清楚改了什么） | 强（.patches/完整diff记录） |
