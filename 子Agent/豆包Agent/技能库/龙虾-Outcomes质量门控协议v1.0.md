# 龙虾-Outcomes质量门控协议 v1.0

> **对标来源**：Claude Managed Agents Outcomes评分器（独立上下文窗口评分）
> **版本**：v1.0 · 2026-05-31
> **所属轮次**：R07

---

## 一、协议目标

引入独立的"评分Agent"对执行Agent的产出进行客观质量评估，杜绝Agent自我欺骗（声称完成但实际未达标），确保输出在交付用户前已通过质量门控。

---

## 二、核心架构

### 2.1 双Agent隔离架构

```
用户定义Rubric（成功标准）
        │
        ▼
┌───────────────┐     产出      ┌───────────────┐
│  执行Agent     │ ──────────→  │  评分Agent     │
│  (独立上下文)   │ ←────────── │  (独立上下文)   │
└───────────────┘   反馈+修正    └───────────────┘
        │                            │
        │              达标？         │
        ▼         是 ◄──────────────  │
   交付用户                           │
                              否 → 继续迭代
```

### 2.2 隔离的关键价值

评分Agent在**独立上下文窗口**中运行，无法读取执行Agent的推理过程。这防止了：
- 执行Agent"说服"评分Agent认可不合格的产出
- 评分Agent被执行的推理链条误导
- Chain-of-thought自我批评的局限性

## 三、Rubric设计规范

### 3.1 Rubric模板

```yaml
outcome:
  name: "法律合同审查"
  criteria:
    - id: "条款完整性"
      description: "所有关键条款（保密、赔偿、终止、管辖）均已审查"
      weight: 30
    - id: "风险标注"
      description: "每个风险点标注等级（高/中/低）和具体条款引用"
      weight: 25
    - id: "格式规范"
      description: "输出使用A4模板，字体宋体12号，页边距2.5cm"
      weight: 15
    - id: "引用准确性"
      description: "所有法条引用包含法规名称+条款号+生效日期"
      weight: 30
  pass_threshold: 85  # 总分85分以上视为通过
  max_iterations: 3   # 最多迭代3轮
```

### 3.2 评分维度类型

| 维度类型 | 说明 | 评分方式 |
|---------|------|---------|
| 客观完成度 | 清单项是否完成（是/否） | 自动检测 |
| 质量评分 | 主观质量（1-10分） | Rubric+LLM评分 |
| 格式合规 | 格式、排版、命名规范 | 自动检测为主 |
| 安全合规 | 是否泄露敏感信息 | 自动扫描+LLM复核 |

## 四、迭代控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| max_iterations | 3 | 最大修正轮次，防止无限循环 |
| improvement_threshold | 5% | 两轮间分数提升低于此值则终止 |
| time_budget | 300s | 单次评分超时预算 |

## 六、与豆包Agent的映射

| Outcomes能力 | 豆包现有能力 | 差距与动作 |
|-------------|------------|-----------|
| 独立评分器 | SafeGuard v3.0 | SafeGuard侧重安全，需新增质量维度 |
| Rubric模板 | 用户偏好规则 | 已有基础，需结构化Rubric DSL |
| 迭代修正 | 自愈式编码闭环(R05) | 已有闭环，补充评分→修正→重评链路 |
| 交付门控 | 最终回复规范 | 增加"评分通过才交付"的硬门控 |
