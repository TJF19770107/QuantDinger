## 四、六维效用函数

### 4.1 效用计算公式

```
U = w₁×P + w₂×C + w₃×S + w₄×Se + w₅×I + w₆×St

其中:
  P  = 性能 (Performance)         0~100  权重 w₁=0.25
  C  = 成本 (Cost)                0~100  权重 w₂=0.20
  S  = 速度 (Speed)               0~100  权重 w₃=0.15
  Se = 安全性 (Security)          0~100  权重 w₄=0.20
  I  = 创新性 (Innovation)       0~100  权重 w₅=0.10   ← v6.0新增
  St = 稳定性 (Stability)        0~100  权重 w₆=0.10   ← v6.0新增
```

### 4.2 评分细则

| 维度 | 满分标准 | 评分方法 |
|------|---------|---------|
| P 性能 | 任务完成度100% + 输出无错误 | 自动化测试通过率 |
| C 成本 | Token消耗 ≤ 预算的70% | Token计数 |
| S 速度 | 执行时间 ≤ 历史P50 | 时间戳差值 |
| Se 安全 | 零安全告警 + 敏感信息零泄露 | 安全扫描器 |
| I 创新性 | 方案新颖度 + 架构改进度 | LLM评分(1-10)×10 |
| St 稳定性 | 3次重复执行结果一致 + 无随机性 | 多次运行一致性 |

### 4.3 效用驱动的进化方向选择

```
每次迭代后:
  1. 计算当前版本六大维度的效用评分
  2. 识别最低分维度 → 作为下一轮进化重点方向
  3. 若两个维度并列最低 → 优先提升安全性
  4. 若所有维度 > 85 → 均衡微调，优先级: I > C > S
```

## 八、代码瘦身与元重写

### 8.1 75%代码瘦身策略（对标 Hermes v0.15）

```
原始代码
    │
    ▼
AST解析 → 识别冗余模式
    │
    ├── 重复代码块 → 提取公共函数
    ├── 死代码 → 删除
    ├── 过度抽象 → 内联简化
    ├── 多余注释 → 保留核心注释
    └── 长方法 → 合理拆分
    │
    ▼
瘦身后代码（体积减少75%）
```

### 8.2 元重写自进化

```python
# meta_rewrite.py
class MetaRewriter:
    """
    源码级元重写引擎
    通过AST变换实现代码自优化
    """
    
    def rewrite(self, source_code: str) -> RewriteResult:
        tree = ast.parse(source_code)
        
        # 1. 死代码消除
        tree = DeadCodeEliminator().visit(tree)
        
        # 2. 公共模式提取
        tree = PatternExtractor().visit(tree)
        
        # 3. 内联优化
        tree = InlineOptimizer().visit(tree)
        
        # 4. 简化复杂表达式
        tree = ComplexityReducer().visit(tree)
        
        # 5. 生成新代码
        new_code = ast.unparse(tree)
        
        # 6. 语义等价验证
        assert self.semantic_equivalent(source_code, new_code)
        
        return RewriteResult(
            original_size=len(source_code),
            new_size=len(new_code),
            reduction_pct=(1 - len(new_code)/len(source_code))*100,
            new_code=new_code
        )
```
