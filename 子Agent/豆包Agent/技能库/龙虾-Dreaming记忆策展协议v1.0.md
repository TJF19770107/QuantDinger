> **对标来源**：Claude Managed Agents Dreaming (Research Preview, 2026-05-06)
> **版本**：v1.0
> **状态**：ACTIVE
> **所属模块**：深度自进化核心闭环 → MemoryOS增强
> **创建**：2026-05-31 R07

---

## 一、协议目标

将Claude Dreaming的"会话间记忆策展"模式融入豆包Agent的MemoryOS，从"仅会话内实时写入"升级为"实时写入 + 会话间提炼"双层架构。解决实时写入噪声大、信号稀疏的问题。

---

## 二、双层记忆架构

### 2.1 架构对比

```
MemoryOS v2.0 (会话内):
  会话进行中 → 实时写入记忆 → 下次会话读取
  → 问题：噪声大、碎片化、无提炼

MemoryOS v3.0 + Dreaming (R07):
  会话进行中 → 实时写入记忆 (L1热层)
       │
  会话结束后 → Dreaming策展 (Overnight/Idle)
       │         ├─ 模式提取
       │         ├─ 噪声过滤
       │         ├─ 记忆压缩
       │         └─ 高信号记忆写入 (L2精华层)
       │
  下次会话 → 读取 L1+L2 合并记忆
```

### 2.2 两层特性

| 层级 | 写入时机 | 内容 | 信号密度 | 容量 |
|------|---------|------|---------|------|
| L1 热层 | 会话中实时 | 原始事件/偏好/错误 | 低（~20%） | 大 |
| L2 精华层 | 会话间策展 | 提炼模式/收敛规则/长期偏好 | 高（~85%） | 小 |

## 三、Dreaming策展流程

### 3.1 触发条件

| 触发方式 | 条件 | 说明 |
|---------|------|------|
| Overnight | 每日凌晨3:00 | 默认策展周期 |
| Idle | 空闲 > 30分钟 | 错峰策展 |
| Threshold | L1累积 > 100条新事件 | 增量策展 |
| Manual | 用户手动触发 | 即时策展 |

### 3.2 四项策展操作

```
会话历史 + L1热层记忆
        │
        ▼
┌───────────────────────────────┐
│  1. 模式提取 (Pattern Mining)  │
│     ├─ 重复用户偏好 (>3次)     │
│     ├─ 收敛工作流 (>5次相同路径)│
│     ├─ 高频错误模式 (>2次同类)  │
│     └─ 工具使用偏好 (频率排序)  │
├───────────────────────────────┤
│  2. 噪声过滤 (Noise Filtering) │
│     ├─ 单次偶发事件             │
│     ├─ 已被覆盖的旧偏好          │
│     └─ 置信度 < 阈值            │
├───────────────────────────────┤
│  3. 冲突解决 (Conflict Resolution)│
│     ├─ 新偏好 vs 旧偏好 → 最近优先│
│     └─ 矛盾规则 → 标记待确认      │
├───────────────────────────────┤
│  4. 记忆压缩 (Compression)     │
│     ├─ 同主题合并               │
│     ├─ 结构化摘要               │
│     └─ 写入 L2 精华层           │
└───────────────────────────────┘
```

## 五、与现有组件集成

### 5.1 与MemoryOS关系

Dreaming不替代MemoryOS，而是MemoryOS的策展层：

- MemoryOS负责：实时写入 + 即时查询 + 上下文注入
- Dreaming负责：事后提炼 + 压缩 + 去噪 + 模式发现

### 5.2 与SkillForge关系

Dreaming发现的"收敛工作流"可自动触发SkillForge：

```
Dreaming发现高频工作流 (>5次)
    │
    ▼
自动提交至SkillForge候选池
    │
    ▼
SkillForge生成候选Skill
    │
    ▼
SafeGuard审查 → 入库
```

## 六、注意事项

### 6.1 Dreaming的适用前提

- 会话数量足够（>10次）才有模式可以提取
- 单用途Agent重复执行同一任务 → 几乎无Dreaming价值
- 多任务Agent处理多样化请求 → Dreaming价值高

### 6.2 当前状态参考

Claude Dreaming目前处于Research Preview阶段（非Public Beta），接口/节奏/可靠性可能变化。豆包Agent的Dreaming协议设计为独立实现，不依赖外部API。
