# 龙虾-长周期任务分层执行协议 v1.1

> 协议编号: 122 | 版本: v1.1 (R34升级) | 来源: PARC分层多Agent + Codex /goal持久化 + Hermes委托系统
> 生效范围: 所有定时任务+长周期Agent任务 | 依赖: AgentIter + ScheduledOps + ECCFramework

---

## 一、核心理念

PARC（Plan-Act-Reflect-Correct）：分层多Agent + 自我评估 + 自我反馈。
让Agent不仅能执行长周期任务，还能在无人干预下检测并纠正战略级错误。

**R34升级**: 对标Codex CLI /goal持久化工作流——增加任务暂停/恢复状态机、进度仪表盘、Token预算控制。

## 二、三层架构

### Layer 1: Orchestrator（编排层）

```
任务输入 → 目标分解 → 子目标列表
    ↓
能力匹配 → Agent选择 → 资源评估
    ↓
并行调度 → 多子Agent并行执行
    ↓
结果汇聚 → 状态汇总
```

### Layer 2: Self-Assessment（自我评估层）

```
执行结果 ← 各子Agent返回
    ↓
逐项校验 → 预期vs实际对比
    ↓
异常检测 → 错误分类(战略/战术/工具)
    ↓
评估报告 → 成功/失败/需重试
```

### Layer 3: Self-Feedback（自我反馈层）

```
评估报告 → 成功路径提取
    ↓
失败分析 → 根因追溯
    ↓
策略调整 → 重新规划→重新执行
    ↓
知识沉淀 → Skill更新
```

## 三、R34升级：Pause/Resume状态机 + Progress Dashboard

### 3.1 任务状态机（对标Codex /goal）

```
                    ┌──────────┐
           ┌───────→│  RUNNING  │←──────┐
           │        └─────┬─────┘       │
           │              │              │
      resume          pause│         error│
           │              ↓              │
           │        ┌──────────┐         │
           │        │  PAUSED   │────────┘
           │        └─────┬─────┘
           │              │
           │         stop │
           │              ↓
           │        ┌──────────┐
           └────────│  STOPPED  │
                    └──────────┘
                         │
                    ┌────┴────┐
                    ↓         ↓
              ┌──────────┐ ┌──────────┐
              │COMPLETED │ │  FAILED   │
              └──────────┘ └──────────┘
```

### 3.2 状态转换规则

| 当前状态 | 触发事件 | 目标状态 | 条件 |
|---------|---------|---------|------|
| RUNNING | pause命令 | PAUSED | 保存当前进度快照 |
| RUNNING | 错误 | FAILED | 记录错误上下文 |
| RUNNING | 所有子目标完成 | COMPLETED | 验证所有输出 |
| PAUSED | resume命令 | RUNNING | 加载进度快照恢复 |
| PAUSED | stop命令 | STOPPED | 归档中间产物 |
| RUNNING | Token预算耗尽 | PAUSED | 自动暂停，等待下一轮预算 |

## 六、失败处理策略

### 错误分级

| 级别 | 类型 | 处理策略 |
|------|------|---------|
| L1: 工具级 | 单个工具调用失败 | 自动重试3次→降级→标记 |
| L2: 战术级 | 子任务执行策略错误 | Self-Assessment检测→重新规划子任务 |
| L3: 战略级 | 整体目标路径偏差 | Self-Feedback触发→Orchestrator重新分解目标 |

## 七、与现有定时任务体系的关系

长周期任务 ≠ 替换定时任务，而是增强：
- 定时任务负责触发（ScheduledOps）
- 分层执行负责过程管理（本协议）
- 学习循环负责经验沉淀（协议117）
- Curator负责技能策展（协议119）
