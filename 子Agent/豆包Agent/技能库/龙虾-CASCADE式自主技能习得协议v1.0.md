## 一、协议目标

赋予豆包Agent自动检测能力缺口、自主习得新技能、固化沉淀为可复用技能集的完整能力。不再依赖人工编写Prompt和工具脚本，实现从"手搓Prompt"到"Skills层面自动进化"的范式跃迁。

## 二、双元技能引擎

### 2.1 Meta-Skill 1：持续学习引擎

```
输入：遇到未知工具/格式/环境/API
处理：
  1. 自动搜索相关文档（web_search / 本地检索）
  2. 从搜索结果提取代码示例
  3. 阅读目标工具的源码（如可用）
  4. 理解用法并生成操作知识
输出：工具使用知识 → 写入L1会话记忆
```

**触发条件**：
- 调用工具返回 `Unknown tool` / `Not found`
- 文件格式不支持（解析失败）
- API调用返回错误码
- 环境依赖缺失

**执行流程**：
```
检测缺口 → 搜索文档 → 提取范例 → 理解用法 → 写入记忆 → 重试任务
```

### 2.2 Meta-Skill 2：自我反省引擎

```
输入：执行报错/异常/结果不符合预期
处理：
  1. 检查运行时状态（环境变量/文件状态/依赖版本）
  2. 构建知识图谱回溯依赖关系
  3. 定位根因（而非表面错误）
  4. 生成修复方案
输出：根因分析 → 修复方案 → 写入技能库
```

**触发条件**：
- 工具调用返回 error
- 输出结果与预期不符
- 迭代后评分下降
- 异常超时

**执行流程**：
```
捕获异常 → 检查运行时 → 图谱回溯 → 定位根因 → 生成修复 → 验证修复 → 写入技能库
```

## 三、三级记忆沉淀通路

```
┌──────────────────────────────────────────────┐
│ L1 会话记忆（Session Memory）                 │
│  存储：当前任务上下文 / 即时学习成果           │
│  介质：对话上下文窗口                          │
│  生命周期：单次会话                            │
├──────────────────────────────────────────────┤
│ L2 整合记忆（Consolidated Memory）            │
│  存储：跨会话的经验教训 / 成功模式 / 失败模式   │
│  介质：MemoryOS L2 Pool (SQLite)              │
│  生命周期：跨会话持久化                        │
├──────────────────────────────────────────────┤
│ L3 技能集（Reusable Skill Set）               │
│  存储：结构化技能文件 / 模板 / 参考资料        │
│  介质：豆包Agent技能库 + Obsidian知识库        │
│  生命周期：永久 / Curator定期维护              │
└──────────────────────────────────────────────┘

沉淀规则：
- L1→L2：会话结束后，Rubric分类判断→有用经验自动写入L2
- L2→L3：跨会话累计使用>3次且成功率>80%的经验→自动提升为L3技能
- L3维护：Curator Agent每4小时评分/整合/清理
```

## 四、EvoSkill 三Agent进化循环

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────────┐
│ Execute  │ ──→ │ Propose  │ ──→ │ Verify   │ ──→ │  Implement   │
│ 执行Agent│     │ 诊断Agent│     │ 验证Agent│     │  落地Agent   │
├──────────┤     ├──────────┤     ├──────────┤     ├──────────────┤
│ 用现有   │     │ 发现能力 │     │ 验证方案 │     │ 生成结构化   │
│ 技能库   │     │ 缺口     │     │ 可行性   │     │ 技能文件夹   │
│ 处理任务 │     │ 诊断原因 │     │ 测试效果 │     │ 注册到技能库 │
│ 生成轨迹 │     │ 提出方案 │     │ 评估质量 │     │ 标记生效     │
└──────────┘     └──────────┘     └──────────┘     └──────────────┘
      ↑                                                    │
      └──────────────── 迭代循环 ──────────────────────────┘
```

### 角色分工

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| Execute (A) | 用现有技能库执行任务 | 任务描述 + 技能库 | 执行轨迹 + 结果 |
| Propose (P) | 诊断能力缺口，提出新技能方案 | 执行轨迹 + 失败信息 | 技能缺口报告 + 新技能方案 |
| Verify (V) | 验证新技能方案的可行性和质量 | 新技能方案 | 验证报告（通过/拒绝/需改进） |
| Implement | 将验证通过的方案固化为技能文件 | 验证通过的方案 | 结构化技能文件夹 + 注册 |

## 五、结构化技能文件夹格式

```
skills/
└── {skill_name}/
    ├── metadata.yaml      # 名称/版本/来源/优先级/依赖
    ├── instructions.md    # 核心指令和Prompt
    ├── script.py          # 必要的执行脚本（可选）
    ├── examples/          # 使用范例（可选）
    │   └── example_01.md
    └── test/              # 测试用例（可选）
        └── test_01.yaml
```

### metadata.yaml 模板

```yaml
skill:
  name: "skill_name"
  version: "1.0.0"
  source: "CASCADE/EvoSkill auto-generated"
  created_at: "2026-05-31T00:00:00Z"
  priority: "P0|P1|P2"
  dependencies: []
  tags: ["autonomous", "self-evolution"]
  trigger_keywords: ["关键词1", "关键词2"]
  success_rate: 0.0
  usage_count: 0
```

## 六、执行约束

1. **安全边界**：自主生成的技能默认运行在沙箱环境中，不得访问系统核心路径
2. **人工审核**：P0级别新技能生成后需标注 `review_required: true`，首次使用前人工审核
3. **回滚机制**：新技能导致评分下降>10%时，自动回滚到上一版本
4. **去重检查**：生成前检测与已有技能的功能重叠度>70%时，改为升级已有技能
5. **依赖声明**：技能依赖的外部工具/库必须在 metadata.yaml 中显式声明
