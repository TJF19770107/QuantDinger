---

## 一、协议目标

引入三档Effort模式和Token预算控制，让Agent在执行任务时主动权衡质量/速度/成本。

---

## 二、三档Effort模式

| 模式 | 速度 | Token消耗 | 适用场景 | 默认参数 |
|------|------|----------|---------|---------|
| **Low** | 快 | 低（省30-50%） | 简单查询/快速列表/单文件操作 | max_steps=5, depth=1 |
| **Medium** | 中 | 适中 | 常规任务/中等复杂度 | max_steps=15, depth=2 |
| **High** | 慢 | 高 | 深度调研/全量对比/复杂重构 | max_steps=30, depth=3+ |

### 2.1 默认行为

豆包Agent默认使用 **High Effort**，确保复杂任务不因保守而遗漏。

### 2.2 模式切换触发

- 用户主动指定："用低effort查一下"
- 任务复杂度自动判断：简单任务自动降级到Medium
- 预算不足时自动降级

### 2.3 切换命令语法

```
/effort low    # 切换到快速模式
/effort high   # 切换到深度模式
/effort auto   # 自动判断
```

## 三、Token预算控制

### 3.1 预算预估

复杂任务执行前，Agent预估算Token消耗范围：

```
预估Token: 15,000 ~ 25,000
Effort: High
步骤: 搜索(5,000) → 分析(8,000) → 生成(7,000) → 验证(5,000)
```

### 3.2 软停止机制

- 消耗达到预算80% → 发出提醒，加速收尾
- 消耗达到预算100% → 优雅降级：跳过非关键验证步骤，快速汇总
- 严禁硬中断（非关键步骤直接跳过，不抛异常）

### 3.3 成本回报率评估

对于预估Token > 50,000的任务，执行前进行成本回报率评估：

| 条件 | 行为 |
|------|------|
| 价值 >> 成本 | 直接执行 |
| 价值 ≈ 成本 | 提示用户确认 |
| 价值 << 成本 | 建议降级方案 |

## 四、Agent高消耗场景适配

Agent对Token的消耗是聊天的10-100倍。Dynamic Workflows官方提醒"powerful but expensive"。本协议通过以下机制控制消耗：

- **并行合并**：可并行的子任务合并为单轮调用
- **上下文压缩**：长程任务定期压缩中间结果
- **结果复用**：已获得的结果不重复查询
- **模型降级**：简单子任务使用更便宜的模型
