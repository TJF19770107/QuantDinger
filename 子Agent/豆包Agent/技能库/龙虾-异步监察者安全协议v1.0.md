# 龙虾-异步监察者安全协议 v1.0

> **对标来源**：SICA论文 Asynchronous Overseer 机制
> **版本**：v1.0
> **状态**：ACTIVE
> **所属模块**：深度自进化核心闭环 → SafeGuard增强
> **创建**：2026-05-31 R07

---

## 一、协议目标

将SICA论文的异步监察者（Asynchronous Overseer）机制融入豆包Agent的安全体系，为自主运行的Agent（特别是自进化模块）提供独立的、旁路的安全监察层，防止自主迭代跑偏、陷入死循环或偏离目标。

---

## 二、核心设计

### 2.1 独立旁路架构

```
┌──────────────┐         ┌──────────────────┐
│  主Agent      │ ──执行──→│  任务/自进化循环   │
│  (自进化模块)  │         │                  │
└──────┬───────┘         └────────┬─────────┘
       │                          │
       │ 状态日志                  │ 行为观测
       ▼                          ▼
┌──────────────────────────────────────────┐
│          异步监察者 (独立LLM)               │
│  ├─ 定期巡检主Agent工作状态                 │
│  ├─ 检测异常行为模式                       │
│  └─ 分级干预                               │
└──────────────────────────────────────────┘
```

### 2.2 为什么需要独立监察者

- 主Agent自我评估存在盲点（确认偏误）
- 自进化模块修改自身代码时可能引入新风险
- 长时间自主运行缺乏外部校准
- 与SafeGuard v3.0互补：SafeGuard做规则检查，监察者做行为判断

## 三、检测四类异常

### 3.1 死循环检测

| 检测指标 | 阈值 | 判定条件 |
|---------|------|---------|
| 重复操作序列 | 连续3轮相同 | 相同工具+相同参数 |
| 无进展迭代 | 连续5轮 | 状态变化 < 1% |
| 循环引用 | 节点A→B→A | 工作流图中检测环 |

### 3.2 任务偏离检测

```
初始目标: "优化文档生成性能"
    ↓
监察者定期对比当前行为与初始目标

偏离判定:
  ├─ 语义距离 > 阈值 → 轻微偏离 → 提醒
  ├─ 语义完全无关 → 严重偏离 → 建议纠正
  └─ 目标替换 → 未授权变更 → 强制取消
```

### 3.3 资源泄漏检测

| 指标 | 告警阈值 | 熔断阈值 |
|------|---------|---------|
| 内存增长 | >200MB/10min | >1GB |
| Token消耗速率 | >10K/min | >50K/min |
| 文件句柄数 | >100 | >500 |
| 并行子进程数 | >20 | >50 |

### 3.4 病态行为检测

- 自我修改频率异常（>10次/h 且无质量提升）
- 绕过SafeGuard审查的尝试
- 向非白名单路径写入
- 未经授权的外部API调用

## 四、分级干预机制

### 4.1 三级干预

```
Level 1: 观察提醒
  触发: 潜在异常，置信度 60-80%
  动作: 记录日志 + 向主Agent发送提醒消息
  用户感知: 无（后台静默）
  示例: "检测到连续3轮相同操作，请确认非死循环"

Level 2: 建议纠正
  触发: 明确异常，置信度 80-95%
  动作: 记录日志 + 暂停主Agent + 发送纠正建议 + 等待确认
  用户感知: 通知（Agent已暂停，等待监察者确认）
  示例: "当前行为与初始目标偏离35%，建议回退至Step 3"

Level 3: 强制取消
  触发: 严重异常，置信度 >95% 或 安全红线
  动作: 强制终止 + 自动回滚 + 生成事件报告 + 通知用户
  用户感知: 强制通知（Agent已终止，原因：xxx）
  示例: "检测到未经授权的系统路径写入，已强制终止"
```

### 4.2 干预决策矩阵

| 异常类型 | Level 1 | Level 2 | Level 3 |
|---------|---------|---------|---------|
| 死循环 | 3轮 | 5轮 | 10轮 |
| 任务偏离 | 偏离15% | 偏离30% | 偏离50% |
| 资源泄漏 | 黄色告警 | 橙色告警 | 红色熔断 |
| 病态行为 | — | 首次 | 重复/严重 |

## 五、实现要点

### 5.1 监察者模型选择

监察者不需要与主Agent同级别的推理能力。推荐使用轻量模型：

- 核心能力：模式匹配 + 偏离判断 + 安全规则匹配
- 不需要：深度推理、代码生成、多轮规划
- 好处：低成本、低延迟、独立运行不抢占资源

### 5.2 巡检频率

| 模式 | 频率 | 说明 |
|------|------|------|
| 主动自进化 | 每30秒 | 自进化风险高，需高频监察 |
| 普通任务执行 | 每2分钟 | 标准任务风险可控 |
| 后台运行 | 每5分钟 | 低优先级巡检 |
| 用户交互中 | 不巡检 | 用户在旁，无需监察 |

### 5.3 与SafeGuard联动

```
SafeGuard (规则层): 操作前检查
  ├─ 路径白名单
  ├─ 操作分级
  └─ 禁止操作拦截

监察者 (行为层): 运行中观察
  ├─ 模式异常
  ├─ 目标偏离
  └─ 资源异常

两者互补：SafeGuard挡在操作前，监察者看在运行中
```
