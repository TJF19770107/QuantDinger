---

## 一、架构升级：从定时到自主

### 旧架构（AutoWake v2.0 协议#7）
```
Cron定时器 → 唤醒Agent → 执行任务 → 沉睡 → 等待下次定时
```
问题：被动、时间固定、无环境感知、无优先级判断

### 新架构（Runtime Activation Layer）
```
持续感知模块 → 优先级评估器 → 激活调度器 → LLM推理 → 执行
     ↑               ↓              ↓
  环境信号        阈值判断      最小上下文构建
```

---

## 二、三层组件详解

### 组件1: 持续感知模块 (Continuous Perception)

**功能**：轻量级流式接口，接收环境信号

**信号源**：
- 文件系统变更（新增/修改/删除）— Watchdog
- 系统事件（新邮件、通知、进程状态变化）
- 时间触发器（定时任务，保留兼容）
- Webhook事件（外部系统推送）
- 数据库变更日志
- 磁盘空间/内存/CPU阈值告警

**存储**：滑动窗口缓冲区，维护近期状态压缩表示（不存完整历史）

### 组件2: 优先级评估器 (Priority Evaluator)

**功能**：小型模型（7B蒸馏版）对信号评分

**评分维度**：
- 相关性（与Agent当前目标的契合度）：0-1
- 紧迫性（时间窗口）：0-1
- 历史响应质量（同类信号之前处理得如何）：0-1

**阈值决策**：
```
综合分 = 相关性×0.4 + 紧迫性×0.3 + 历史质量×0.3
if 综合分 > 0.7 → 唤醒完整推理引擎
if 0.3-0.7 → 加入低优先级队列
if < 0.3 → 丢弃
```

**性能要求**：延迟 < 100ms，持续运行不占CPU

### 组件3: 激活调度器 (Activation Scheduler)

**功能**：构建最小上下文，分发给主LLM生成行动

**上下文构建**：
- 触发信号摘要（< 200 tokens）
- Agent持久记忆摘要（最近5条关键记忆）
- 当前活跃目标列表
- 不携带完整对话历史

**调度策略**：
- 高优先 → 立即激活主LLM
- 中优先 → 攒批，每N分钟处理一批
- 低优先 → 丢弃或归档

## 三、与OpenClaw Heartbeat v2.0融合

### 开源AgentRuntime验证指标
- GitHub组织PR自动合并率：85%自动合入，15%标记人工审查
- 误报率：< 3%（优先级评估器过滤）
- 漏报率：< 5%（关键事件必定触发）

- 无人类指令自动唤醒
- 读取近期对话日志和自身源代码

### 融合架构
```
OpenClaw Heartbeat（周期性唤醒）
    +
AgentRuntime感知层（事件驱动唤醒）

豆包Agent统一自主唤醒引擎
```

## 五、安全护栏（持久生效）

### 唤醒边界
- 系统核心路径事件：观察不干预
- 用户隐私数据变更：观察+通知用户
- 高风险操作信号：评估后**必须**向用户确认
- 未知信号类型：一律降级为低优先级

### 冷却机制
- 同一信号源30秒内最多激活1次
- 5分钟内连续3次误激活 → 该信号源暂停1小时
- 激活失败3次 → 降级为定时模式，通知用户

### 功耗控制
- 感知模块：< 1% CPU占用（常驻）
- 评估器：GPU空闲时才运行
- 调度器：仅在激活时占用资源

## 六、与龙虾定时循环的配合

```
定时循环（每2-4小时）← 保留，兼容旧模式
    +
事件驱动自主唤醒 ← 新增，感知层
    ↓
双通道唤醒体系
```

定时循环负责周期性任务（迭代、同步、整理），事件驱动负责即时响应（文件变更、系统告警、外部事件）。

---

## 七、执行规范

1. 感知层7×24小时运行（作为系统服务/守护进程）
2. 优先级评估器模型：使用豆包Agent自蒸馏的7B模型，每24小时在线更新
3. 激活日志：每次唤醒记录（信号源、评分、决策、结果）
4. 误报反馈：用户手动取消=负反馈，用于调优评估器阈值
5. 定期校准：每周自动分析激活日志，调整评分权重
