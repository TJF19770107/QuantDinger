## 二、架构对标分析

### 2.1 Claude Code — 五级工程机制金字塔

```
Level 5: Subagents + Agent Teams（多Agent协调）
    ↑
Level 4: Parallel Claude（多实例并行）
    ↑
Level 3: MCP（外部工具接入）
    ↑
Level 2: Hooks（确定性自动化）
    ↑
Level 1: CLAUDE.md（静态上下文注入）
```

**Agent Teams核心机制**:
- **Lead Agent**：全局任务分解与监控
- **Shared Task List**：优先级+依赖关系透明化
- **Mailbox**：Agent间通信中枢
- 2-16个并行Agent团队协作

**对豆包启示**：
- 当前Marvis已有Sub-Agent调度机制（dispatch_task），但与Claude Agent Teams相比，缺少Agent间直接通信通道（Mailbox）和共享任务面板
- 建议：在豆包Agent内部实现类Mailbox的Agent间消息队列

### 2.2 Hermes — 闭环学习系统

```
观察(Observe) → 执行(Execute) → 反思(Reflect) → 沉淀(Crystallize) → 复用(Reuse)
```

**三层持久记忆**：
- 短期：会话上下文窗口
- 中期：FTS5全文检索SQLite
- 长期：技能文件沉淀（兼容agentskills.io标准）

**对豆包启示**：
- 当前已有长期记忆机制（user_preference_rules），但缺少"自动从成功任务中提炼技能"的闭环
- 建议：每次任务完成后增加反思阶段，将成功工作流自动沉淀为Skill

### 2.3 OpenClaw — 多智能体网关

**核心架构**：
```
Gateway
  ├── Persistent Agent（常驻，如客服Bot）
  ├── Sub-Agent（临时并行，任务完成即归档）
  └── ACP Agent（跨平台标准化协作协议）
```

**路由机制**：bindings按 channel/accountId/peer 精确匹配路由

**对豆包启示**：
- 当前Marvis已具备多Agent调度，可借鉴OpenClaw的binding路由模式增强任务分发精准度
- OpenClaw的ACP协议可作为豆包与外部Agent通信的参考标准

### 2.4 Codex CLI — 全自动Agent范式

**核心差异化**：
- Rust实现，速度最快
- Docker + Seatbelt/Landlock 内核级安全沙箱
- Triggers：响应GitHub Issue自动修复并开PR
- Plugins：接入Sentry/Datadog等外部工具链
- 策略偏向"无人值守全自动Agent"（vs Claude Code的"开发者实时协作控制"）

**对豆包启示**：
- 自助任务触发（Triggers）是豆包应补齐的能力
- 安全沙箱在自主执行场景中至关重要

### 2.5 Gemini CLI — 多模态+大上下文

**核心优势**：
- 1M+ tokens上下文窗口
- 原生多模态（图片→代码、PDF分析、音频/视频处理）
- Gemini 3.5 Flash：价格仅GPT-5.5 Pro的1/100，速度4x

**对豆包启示**：
- 多模态输入能力是当前豆包的短板
- 超大上下文窗口对代码库整体理解至关重要

### 2.6 自进化Agent — 前沿方向

**Autogenesis 协议核心循环**：
```
执行任务 → 遇到失败/低效 → 分析根因
→ 生成改进候选（新工具/新prompt/新流程）
→ 在测试环境中验证 → 确认有效 → 集成
→ 继续执行任务...
```

**A-Evolve 五阶段框架**：
```
Solve → Observe → Evolve → Gate → Reload
```

**进化维度**：模型/记忆/工具/架构 × Intra-test-time/Inter-test-time/跨会话 × 标量奖励/文本反馈/单Agent/多Agent
