## 二、本轮新增核心知识（Anthropic最新公开内容）

### 2.1 五种多Agent协调模式（官方2026新版）

Anthropic 2026年发布《Multi-agent coordination patterns》，从1→5种模式系统梳理：

| 模式 | 核心机制 | 适用场景 | 致命缺陷 |
|------|---------|---------|---------|
| Generator-Verifier | 生成→验证→修改循环 | 代码审查、事实核查、合规审查 | 验证者形同虚设（标准不明确时） |
| Orchestrator-Subagent | 主编排→子Agent→汇总 | PR审查、客服、调研 | 编排者成信息瓶颈；串行限制吞吐 |
| Agent Teams | Worker持久化+任务队列 | 框架迁移、多服务独立部署 | 独立性硬要求，Worker间无法共享发现 |
| Message Bus | 发布/订阅事件路由 | 安全运营、事件驱动管道 | 追踪困难；路由准确性是命门 |
| Shared State | 共享存储去中心化 | 研究综合、协作调查 | 反应性循环（无限Token消耗） |

**演进决策表**：
- Orchestrator-Subagent vs Agent Teams：子任务短且有界→选前者；子任务需持续深入→选后者
- Orchestrator-Subagent vs Message Bus：步骤可预测→选前者；事件涌现→选后者
- Agent Teams vs Shared State：Worker独立不互扰→选前者；发现需实时流动→选后者

### 2.2 Claude Code七层Harness架构

Anthropic生产实践：配置生态比模型本身更重要。

```
CLAUDE.md → Hooks → Skills → Plugins → LSP → MCP Servers → Subagents
```

| 层级 | 职责 | 关键洞察 |
|------|------|---------|

### 2.3 Hooks/Skills/Agents职责三定律

> Hooks管"不能做什么"（硬约束） → Skills管"应该怎么做"（能力包） → Agents管"谁来做"（角色担当）

**Hooks核心特性**：
- 27个Hook事件，覆盖会话启动→上下文压缩全生命周期
- PreToolUse最强：可拦截并阻塞任何操作
- 写在settings.json，Claude无法跳过——是基础设施，不是建议

### 2.5 多Agent研究系统：八条提示工程原则

Anthropic Claude Research（Lead+Subagent并行架构）:
- 多Agent比单Agent强**90.2%**
- Token用量解释**80%**性能方差
- 核心洞察：多Agent架构本质是**横向扩展Token预算**的工程手段

八条原则：
1. 像你的Agent一样思考（模拟构建）
2. 教导协调器如何委派（明确目标+输出格式+边界）
3. 将规模扩展到查询复杂性（简单1Agent → 复杂10+Agent）
4. 工具设计至关重要（先检查所有工具→匹配意图）
5. 让Agent自我完善（Claude 4可以是优秀提示工程师）
6. 引文Agent确保归因准确
7. 首席Agent计划持久化到内存
8. 子Agent独立搜索+交错思考评估
