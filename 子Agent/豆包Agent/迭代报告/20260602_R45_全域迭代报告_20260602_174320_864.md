**来源**: ICLR 2026 · Baidu/ML Anthology (Jin et al., 2026)

**核心突破**:
- 解决RLVR仅依赖outcome reward的局限：生成-验证不对称
- 多轮RL框架：生成→自验证→工具评估循环
- **TAPO**(Turn-level Adaptive Policy Optimization)：轮次级信用分配
- 训练仅3轮，推理可自进化20+轮
- Pass@k显著提升，拓展基座模型推理边界

**对豆包的启示**: 现有协议#18自愈式编码闭环停留在"报错→修复"层面，ReVeal升级为"自验证先行→预防性修复"，从被动修复升级为主动验证。

**→ 生成协议 #164**: 龙虾-自验证驱动深度测试时扩展协议 v1.0

### 2.2 Advisor-Critic多层决策架构

**来源**: Anthropic Code with Claude 2026 · GitHub分享

**核心突破**:

**对豆包的启示**: 现有多Agent验证协议#128是并行对抗验证，Advisor-Critic提供了一种成本更低的串行审查模式，适合高频迭代场景。

### 2.3 Pullfrog: BYOK模型无关CI Agent

### 协议 #164: 龙虾-自验证驱动深度测试时扩展协议 v1.0

```
对标: ReVeal (ICLR 2026, Baidu/ML Anthology)
升级: 协议#18 自愈式编码闭环 v1.0 → v2.0

核心机制:
1. 自验证先行 (Verify-before-Fix)
   - 每次代码生成后，先运行自验证（self-constructed tests + tool feedback）
   - 验证通过 → 提交；验证失败 → 进入修复循环
   - 区别于旧协议"报错再修复"的被动模式

2. TAPO轮次级信用分配 (Turn-level Adaptive Policy Optimization)
   - 长周期推理分解为"生成→验证"多轮迭代
   - 每轮独立信用分配，避免长序列中的reward稀疏
   - 关键轮次（发现bug/通过edge case）获得更高权重

3. 推理时自进化 (Test-Time Evolution)
   - 训练仅需3轮基础数据
   - 推理时可自主进化20+轮
   - Pass@k持续提升，突破基座模型推理边界

4. 工具反馈闭环
   - 编译器警告/静态分析/lint结果自动注入验证循环
   - 非仅依赖模型自身判断，外部信号加权融合

状态: ✅ R45落地
文件: E:\龙虾AI主控中心\我的AI分身\技能库\龙虾-自验证驱动深度测试时扩展协议v1.0.md
```

### 协议 #165: 龙虾-Advisor-Critic多层决策与成本优化协议 v1.0

```
对标: Anthropic Advisor Pattern + Rubber Duck Critic (Code with Claude 2026)

核心机制:
1. Advisor双层模型路由 (Haiku→Opus)
   - L1执行模型(Haiku级): 处理常规任务，占比~90%
   - L2顾问模型(Opus级): 仅在L1遭遇困难时调用
   - 困难判定: 连续3次工具调用失败 / 置信度<0.7 / 任务复杂度评分>8/10
   - 成本效益: 以~Opus 10%的Token消耗获得~Opus 90%的智能

2. Rubber Duck三段Critic审查
   - Stage 1: 规划审查 → 计划合理性与完整性检查
   - Stage 2: 实现审查 → 复杂实现完成后、代码提交前
   - Stage 3: 测试审查 → 测试编写完成但尚未运行前（预测失败点）
   - Critic独立于执行Agent，防止"自我审查"盲区

3. 缓存命中率底线机制
   - 目标: ≥94% (GitHub工程标准)
   - 跌破70% → 自动告警，提示词组装缺陷检测
   - 3类缓存失效自动分类与修复建议

状态: ✅ R45落地
```
