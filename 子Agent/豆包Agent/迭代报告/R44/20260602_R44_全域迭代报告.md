## 四、P0缺口专项优化：沙箱隔离 98→99

### 4.1 缺口分析

R43遗留唯一P0缺口：沙箱隔离98分，距99分差1分。根本原因是对Windows平台Agent沙箱的落地深度不足——豆包Agent运行在Marvis框架内，依赖框架级沙箱，缺少针对Agent场景的独立沙箱策略。

### 4.2 最新情报对标

本轮搜索揭示了Windows Agent沙箱的**三条成熟路线**：

| 路线 | 代表产品 | 核心技术 | 成熟度 |
|------|---------|---------|:---:|
| **合成SID+写限制Token** | Codex Windows沙箱(Rust) | Restricted Tokens + 文件ACL + 专用沙箱用户 + CreateProcessAsUserW | GA |
| **进程级动态安全模块** | TRAE Windows沙箱 | 进程嵌入 + 底层拦截 + 零侵入系统 | GA |
| **五层同心圆模型** | Codex 内部部署 | Sandbox→Permission→Approval→Network→Telemetry | 生产验证 |

### 4.3 豆包对标优化方案

基于以上三条路线的精华，制定豆包Agent沙箱隔离升级方案：

1. **借鉴Codex三层架构**：Restricted Tokens（受限令牌）→ 文件系统ACL动态Deny-Write → 专用低权限用户执行
2. **借鉴TRAE轻量级设计**：进程级安全组件，毫秒级启动，不拖慢Agent思考-执行循环
3. **借鉴Codex五层模型**：在现有Marvis L2安全兜底基础上，增加沙箱层独立权限配置和审批策略
4. **对标AgentPatterns四要求**：开放二进制执行+宿主工作区读写+无管理员提权+进程树策略传播

### 4.4 提升验证

| 验证维度 | R43状态 | R44提升 | 对标 |
|---------|:---:|:---:|------|

### 5.1 协议#158 详细设计（Windows Agent沙箱三层隔离）

```
架构层次：
  L1: Restricted Tokens层
    - 合成SID + 写限制Token
    - CreateProcessAsUserW 启动受限进程
    - 继承策略传播至子进程

  L2: 文件系统ACL层
    - 动态Deny-Write规则（系统目录/用户配置/敏感路径）
    - Agent结束后自动回滚ACL
    - .git/.agents/.codex 目录只读保护

  L3: 专用沙箱用户层
    - 隐藏影子账户 + 独立Profile
    - 与主用户完全隔离
    - 网络防火墙规则绑定

  启动流程：
    解析安全策略 → 创建受限Token → 设置文件ACL
    → 创建I/O管道 → 启动受限进程 → 监控超时
    → 清理+回滚ACL
```
