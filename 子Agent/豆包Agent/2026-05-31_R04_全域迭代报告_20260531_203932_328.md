## 二、关键情报总结

### 2.1 JetBrains Air — Agentic Development Environment（ADE）

**来源**：今日头条/JetBrains 官方
**发布时间**：2026-05-07

**核心创新**：不造新 IDE，而在现有 IDE 之上加一层 Agent 调度层。

```
IDE（IntelliJ/VS Code/Cursor）负责人写代码
     ↕
Air ADE 负责调度 Agent 写代码
     ↕
Codex | Claude Agent | Gemini CLI | Junie
```

**关键能力**：
- 多个 code agent 在同一项目并行运行
- 每个 Agent 独立隔离的工作空间（独立 diff）
- 统一 review 面板合并所有 Agent 的改动
- 冲突检测：多 Agent 改同一文件时自动告警
- 不绑定单一模型，支持 4 类 agent 自由组合

**豆包可吸收点**：
- ADE 模式并非要求豆包自己造 IDE，而是成为"IDE 之上的 Agent 调度器"
- 豆包已有 Marvis 框架的 dispatch_task 能力，天然适配 ADE 模式
- 可扩展为：豆包作为 Host，调度 Marvis/Codex/Gemini 等子 Agent 在同一项目并行编码

### 2.2 ai-collab — Host/Worker/Knowledge Keeper 三层架构

**来源**：51CTO / GitHub (Rainbow0328)
**发布时间**：2026-05-14

**核心架构**：
```
Host（统筹全局）
├── Worker A（专注模块A）
├── Worker B（专注模块B）
└── Knowledge Keeper（维护知识库）

知识库三层：
L1-项目宪法：长期原则、技术选型、整体架构
L2-领域规则：模块边界、协议、跨模块协作原则
L3-细节对齐：接口字段、参数、返回值格式
```

**协作闭环**：
- Worker 通过 `await` 命令进入等待链，自动领取任务→执行→回报→再等待
- 超时自动续接，静默运行不打扰用户
- Host 负责构建和裁决知识库，Worker 只读并在回报中提供候选更新

**豆包可吸收点**：
- 三层知识库概念可直接集成到豆包的多 Agent 协作中
- Knowledge Keeper 可对应龙虾模板中的 MemoryOS + 自进化协调器
- 片段级引用（`l2/current#message-protocol`）避免 token 浪费

### 2.3 自进化 Agent 全景综述（TMLR 2026）

**来源**：TMLR 2026 · 77 页 · 26 位作者
**论文**：A Survey of Self-Evolving Agents

**三维框架**：

| 维度 | What（进化什么） | When（何时） | How（如何） |
|------|-----------------|-------------|------------|
| 1 | 模型参数/权重 | Intra-test-time 实时 | 标量奖励（RL风格） |
| 2 | 记忆存储/检索 | Inter-test-time 批处理 | 文本反馈（NL评价） |
| 3 | 工具创建/修改 | 跨会话长期积累 | 单 Agent 自我反思 |
| 4 | Agent 层级/通信 | — | 多 Agent 互评改进 |

**Autogenesis 协议核心循环**：
```
执行任务 → 遇失败/低效 → 分析根因
→ 生成改进候选（新工具/新prompt/新流程）
→ 测试环境验证 → 确认有效 → 集成
→ 继续执行
```

**豆包可吸收点**：
- 龙虾模板已有元认知自进化协议（R01·Skill #4），可升级为 Autogenesis 兼容版本
- 关键差异：Autogenesis 强调"在沙箱中先验证再集成"，龙虾缺少沙箱验证层
- 建议增加：沙箱验证协议（SafeEval Protocol）
