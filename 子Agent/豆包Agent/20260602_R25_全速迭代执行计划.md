## 六、风险管控措施

### 6.1 核心风险矩阵

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|
| **浏览器Agent无法实现真实浏览器接管** | 高 | 高 | 优先使用现有web_search/web_fetch增强；如不可行，降级为协议设计文档+对标分析 |
| **CI验证流水线搭建受阻（缺真实代码仓）** | 中 | 中 | 使用开源SWE-bench数据集替代；优先跑通本地脚本验证 |
| **100+并行Agent压测超出环境承载** | 中 | 中 | 采用渐进式压测（10→50→100），记录上限；如不可达，记录理论极限 |
| **协议间冲突检测复杂度爆炸** | 中 | 低 | 先用静态规则冲突检测，再逐步引入语义分析 |
| **2小时窗口不足以完成完整迭代** | 高 | 低 | 每轮产出最低可交付物（部分协议草案+简要报告），超时内容顺延至下一轮 |
| **记忆系统工程精简导致能力退化** | 低 | 高 | 精简前全量备份，每精简一项执行回归验证 |

### 6.2 熔断机制

- 单轮执行超过3小时自动截断，产出当前状态报告
- 连续3轮评分无正向提升，触发Phase重新规划
- 任何维度得分下降≥3分，触发回滚至上一稳定版本

### 6.3 备份策略

- 每轮迭代前全量备份豆包Agent目录至 `checkpoints/R25_bs/`
- 每完成一个Phase，生成Phase总结快照
- GitHub 2小时定时备份维持运行
