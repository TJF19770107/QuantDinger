## 二、功能节点拆分

### 2.1 节点类型

| 类型 | 标识 | 功能 | 输入 | 输出 |
|------|------|------|------|------|
| 触发节点 | START | 工作流入口，接收触发信号 | 用户指令/定时信号/事件 | 任务对象 |
| 意图解析节点 | PARSE | 意图识别与实体提取 | 原始输入 | TaskObject |
| 条件判断节点 | IF | 条件分支 | 任意数据 | TRUE/FALSE 分支 |
| 任务执行节点 | EXEC | 调用工具/Agent执行任务 | 任务参数 | 执行结果 |
| 数据转换节点 | TRANSFORM | 数据格式转换/清洗 | 原始数据 | 转换后数据 |
| 并行分叉节点 | FORK | 拆分为多个并行子任务 | 任务列表 | 多路并行输出 |
| 并行汇聚节点 | JOIN | 等待所有并行任务完成 | 多路结果 | 合并结果 |
| 循环节点 | LOOP | 重复执行直到条件满足 | 循环体+条件 | 最终结果 |
| 人工确认节点 | CONFIRM | 暂停等待用户确认 | 确认内容 | 确认/取消 |
| 产物输出节点 | OUTPUT | 最终产出物声明 | 产物路径 | yyb-product卡片 |
| 终止节点 | END | 工作流结束 | 最终状态 | 完成信号 |

### 2.2 节点配置格式

```json
{
  "node_id": "node_001",
  "type": "EXEC",
  "label": "读取模板文件",
  "config": {
    "tool": "read_text",
    "params": {"file_path": "E:/龙虾AI主控中心/..."},
    "timeout": 30,
    "retry": 2,
    "on_failure": "skip|abort|fallback_node_003"
  },
  "next": ["node_002"],
  "position": {"x": 100, "y": 200}
}
```

## 三、串行/并行/条件跳转规则

### 3.1 串行执行

```
触发: 节点间存在数据依赖
标识: "next": ["node_002"]
行为: 严格按顺序执行，前一节点完成后才触发下一节点
示例: 读取文件 → 分析内容 → 生成报告
```

### 3.2 并行执行

```
触发: 节点间无数据依赖，可同时执行
标识: 通过FORK节点拆分为多个并行路径
行为: 同一批次内最多5个并行任务，全部完成后汇聚到JOIN
示例: [下载图片, 下载文案, 下载视频] → JOIN
```

**并行度控制**:
| 策略 | 值 | 说明 |
|------|-----|------|
| 最大并行数 | 5 | 单批次最多5个并行任务 |
| 批次间隔 | 100ms | 批次间最小间隔 |
| 超时 | 300s | 单个并行任务超时时间 |

### 3.3 条件跳转

```
触发: IF节点根据条件判断结果路由
标识: "branches": {"true": "node_A", "false": "node_B"}
条件表达式: 支持 ==, !=, >, <, in, contains, exists
```

**条件表达式示例**:
```
result.status == "success"
file_count > 0
output.contains("error")
security_level in ["high", "medium"]
```

| 区域 | 内容 | 刷新频率 |

## 五、节点监控方案

### 5.1 监控指标

| 指标 | 采集方式 | 告警阈值 |
|------|---------|---------|
| 节点耗时 | 时间戳diff | >60s 告警 |
| 失败次数 | 状态计数 | 连续3次失败 → 熔断 |
| 内存占用 | psutil | >500MB 告警 |
| 工具调用频率 | 调用计数 | >100次/min 限流 |
| 产出物大小 | 文件大小 | >50MB 告警 |

### 5.2 熔断机制

```
连续失败3次 → 该节点自动熔断(10分钟)
熔断期间 → 跳过该节点，执行降级逻辑
10分钟后 → 半开状态，允许1次试探
试探成功 → 恢复
试探失败 → 再次熔断(30分钟)
```

## 七、多Agent任务分发

### 7.1 分发架构

```
可视化工作流引擎
    │
    ├─ 任务拆解 ──→ 子任务队列
    │
    ├─ Agent匹配 ──→ 按领域路由
    │   ├─ file-agent → 文件操作
    │   ├─ computer-agent → 系统操作
    │   ├─ app-agent → 应用操作
    │   ├─ browser → 网页交互
    │   └─ search-agent → 深度搜索
    │
    ├─ 并行调度 ──→ 无依赖任务并行派发
    │
    └─ 结果汇聚 ──→ JOIN节点合并
```

### 7.2 分发协议

```json
{
  "source": "workflow_engine",
  "target_agent": "file-agent",
  "task": "<overall_goal>...</overall_goal><current_task>...</current_task>",
  "memory_ids": ["memory_xxx"],
  "inherit_agent_id": "",
  "callback": "workflow_node_005"
}
```

### 7.3 Agent协作模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| 串行链 | Agent A → Agent B → Agent C | 有数据依赖的多域任务 |
| 并行扇出 | 同时派发给多个Agent | 独立子任务 |
| 竞争择优 | 多Agent同时执行，选最优结果 | 探索性任务 |
| Lead-Specialist | Lead分发+Specialist执行 | 复杂推理任务 |
