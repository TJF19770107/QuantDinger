## 三、关键架构提取

### 3.1 Codex应用服务器架构（JSON-RPC双向协议）

```
┌─────────────────────────────────────────┐
│              Codex 应用服务器             │
│  ┌─────────────────┐  ┌───────────────┐ │
│  │ stdio读取器      │  │ 消息处理器     │ │
│  │ (JSON-RPC→内部)  │  │ (内部→通知)    │ │
│  └─────────────────┘  └───────────────┘ │
│         ↑                      ↓         │
│  ┌─────────────────────────────────────┐ │
│  │         Codex 核心操作引擎           │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
          ↕ JSON-RPC over stdio (JSONL)
┌─────────────────────────────────────────┐
│          多客户端统一接口                 │
│  CLI | VS Code | Web | macOS |          │
│  JetBrains | Xcode | 移动端              │
└─────────────────────────────────────────┘
```

**对话原语**：
- **Item**：输入/输出原子单位，生命周期 started→delta→completed
- **Turn**：单个Agent工作单元产生的Item序列
- **Thread**：持久会话容器，支持创建/恢复/分叉/存档，保留事件历史

**豆包Agent融合价值**：Item/Turn/Thread三层抽象可适配豆包Agent的多Agent任务会话管理。

│     ↓       ↓       ↓       ↓    │

│  │   独立对抗性测试Agent        │  │
│  │   + 两轮Reviewer Agents     │  │
│  └─────────────────────────────┘  │
│              ↓                     │
│  ┌─────────────────────────────┐  │
│  │   结果收敛 → 合并             │  │

### 6.1 协议#184：源码级Harness自进化实现路径

```
实现路径（Python）：
Step 1: 失败检测 → 捕获消息路由/工具合并/hook执行/状态传递异常
Step 2: 源码定位 → AST解析定位失败点所在源码模块
Step 3: 补丁生成 → LLM生成精确修复补丁（统一diff格式）
Step 4: 沙盒测试 → 隔离环境跑回归测试套件
Step 5: 金丝雀部署 → 低流量先上线→监控→全量
Step 6: 回滚保护 → 异常自动回滚至上一稳定版本

核心模块：
- harness_diagnoser: 诊断Harness级失败
- source_locator: AST级源码定位
- patch_generator: diff精确补丁生成
- sandbox_validator: 隔离测试验证
- canary_deployer: 灰度发布控制
- rollback_guard: 秒级回滚保护

上下文信息密度最大化（GenericAgent原则）：
- 分层记忆路由：高频→热记忆/中频→温记忆/低频→冷记忆
- 匹配前过滤：相似度阈值+领域标签
- 增量学习：Δ更新而非全量重写
```
