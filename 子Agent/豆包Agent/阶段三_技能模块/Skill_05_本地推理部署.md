# Skill_05：本地推理部署

**版本号**：v1.0  
**创建日期**：2026-06-02  
**所属体系**：龙虾全域AI Agent推理基础设施层  
**挂载点**：全域调度中枢 → 本地推理引擎

---

## 一、核心能力

1. **分层推理路由**：根据任务复杂度自动选择推理后端——简单任务 → Ollama（低延迟），复杂任务 → vLLM（高吞吐），超复杂推理 → 云端API fallback
2. **14.5x加速链**：针对Llama 3.3 70B模型，组合应用AWQ 4-bit量化 + FlashAttention-2 + TensorRT-LLM编译 + vLLM PagedAttention，实测从4 tok/s优化至58 tok/s
3. **RTX 4090 24GB配置方案**：预置三档配置——经济档（Llama 3.2 3B, Ollama, ~450 tok/s）、标准档（Qwen2.5 14B, vLLM+AWQ, ~120 tok/s）、旗舰档（Llama 3.3 70B, vLLM+AWQ+FlashAttention-2, ~58 tok/s）
4. **多模型热切换**：同一推理后端支持同时加载3个模型，按请求的 `model_name` 自动路由，热切换延迟 < 2s
5. **显存OOM自动降级**：显存不足时自动切换至低精度量化配置或更小模型，保证推理服务不中断

---

## 二、输入规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `model_name` | str | 是 | 模型标识符，如 `llama3.3:70b` / `qwen2.5:14b` |
| `prompt` | str | 是 | 推理请求的提示词 |
| `backend_preference` | str | 否 | 推理后端偏好：`ollama` / `vllm` / `auto`，默认auto |
| `max_tokens` | int | 否 | 最大生成token数，默认2048 |
| `quantization` | str | 否 | 量化方案：`awq` / `gptq` / `fp16` / `auto` |

---

## 三、输出规范

| 字段 | 格式 | 说明 |
|------|------|------|
| `response` | str | 模型生成的文本 |
| `metrics` | JSON | 推理性能指标：`{backend_used, tokens_per_second, total_tokens, gpu_memory_used, latency_ms}` |
| `fallback_chain` | list | 如果发生降级，记录降级链路 |

---

## 四、执行协议

1. **模型路由**：解析 `model_name` → 查询本地已加载模型列表 → 如未加载则按显存余量决定加载方式
2. **后端选择**：`backend_preference=auto` 时，按以下规则决策——prompt长度 > 8000 → vLLM；需要流式输出 → Ollama；批量推理 → vLLM batch mode
3. **量化决策**：`quantization=auto` 时，按模型大小自动选择——≤7B → fp16；7B-30B → AWQ 4-bit；≥30B → AWQ 4-bit + FlashAttention-2
4. **推理执行**：将请求转发至选定后端，监控首token延迟与生成速度
5. **OOM处理**：捕获显存不足异常 → 卸载最久未使用的模型 → 重试 → 仍失败则降级至更小模型或更高压缩量化
6. **指标上报**：每次推理完成后记录性能指标，供后续路由决策使用

---

## 五、安全边界

- **模型来源校验**：仅加载经过SHA256校验的官方模型，拒绝未签名/未校验的GGUF文件
- **禁止暴露原始文件路径**：推理接口不返回模型文件路径、系统配置等敏感信息
- **推理内容过滤**：对生成的文本执行基础安全过滤（拒绝生成恶意代码、病毒指令等）
- **显存隔离**：推理进程运行在独立容器/虚拟环境中，与Agent主进程物理隔离
