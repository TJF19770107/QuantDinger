# Skill_01：多Agent并行调度

**版本号**：v1.0  
**创建日期**：2026-06-02  
**所属体系**：龙虾全域AI Agent调度中心  
**挂载点**：全域调度中枢 → 子Agent编排层

---

## 一、核心能力

1. **Kanban Swarm持久化看板**：基于Hermes SWARM协议的看板机制，所有子Agent状态（idle / busy / blocked / completed）实时可视化，支持拖拽式优先级重排
2. **优先级仲裁引擎**：多Agent资源冲突时，按"任务紧急度 × 依赖深度 × Agent能力匹配度"三维加权仲裁，避免死锁与饥饿
3. **并行调度策略**：同批次无依赖任务最大并行度 = min(可用Agent数, 任务数, 全局上限5)，超过则分批次流水线执行
4. **中枢调度模版**：预置"管道模式 / 扇出-扇入模式 / 竞速模式 / 流水线模式"四种调度模版，按任务特征自动匹配
5. **故障转移与重调度**：Agent超时或异常时，自动将任务重新分配给同能力等级的空闲Agent，最多重试2次后降级或交还用户

---

## 二、输入规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `task_graph` | JSON | 是 | 任务DAG图，包含节点（task_id / agent_type / priority / estimated_duration）与边（依赖关系） |
| `available_agents` | list | 是 | 当前可用的Agent列表及其能力标签 |
| `max_parallel` | int | 否 | 最大并行数，默认5 |
| `timeout_per_task` | int | 否 | 单任务超时秒数，默认600 |
| `retry_policy` | str | 否 | 重试策略：`strict`（只重试同类型Agent）/ `fallback`（可降级） |

---

## 三、输出规范

| 字段 | 格式 | 说明 |
|------|------|------|
| `execution_plan` | Markdown表格 | 分批执行计划，标注每批并行任务及Agent分配 |
| `kanban_snapshot` | JSON | 看板当前状态快照，持久化至 `temp/kanban_{timestamp}.json` |
| `execution_log` | 文本流 | 实时执行日志，含时间戳 / Agent / 状态变更 |
| `final_report` | Markdown | 汇总报告：成功/失败/跳过数量、耗时、瓶颈分析 |

---

## 四、执行协议

1. **图解析**：解析 `task_graph`，构建拓扑排序，识别独立任务组
2. **Agent匹配**：将每个任务的需求标签与 `available_agents` 的能力标签做余弦相似度匹配，取 top-3 候选
3. **优先级计算**：对每个任务计算 `priority_score = urgency × 0.4 + dependency_depth × 0.35 + match_score × 0.25`
4. **批次划分**：按优先级降序 + 无依赖约束分组，每组不超过 `max_parallel`
5. **调度执行**：逐批下发任务到对应Agent，监控心跳与超时
6. **故障处理**：超时/失败任务 → 标记为retry → 重新匹配Agent → 超过2次则置为 failed，写入异常报告
7. **状态归档**：全部批次完成后，将看板快照、执行日志、汇总报告打包写入输出目录

---

## 五、安全边界

- **不执行破坏性操作**：本Skill仅负责任务调度与状态管理，不直接操作文件系统或执行代码
- **Agent身份校验**：下发任务前校验Agent签名的有效性
- **资源上限保护**：单次调度的并行任务数上限 = 5，防止系统过载
- **敏感任务标记**：标记为 `sensitive=true` 的任务需额外人工确认后才下发
