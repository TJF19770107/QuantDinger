# Skill_08：全域对标矩阵维护

**版本号**：v1.0  
**创建日期**：2026-06-02  
**所属体系**：龙虾全域AI Agent质量保证子系统  
**挂载点**：全域调度中枢 → 对标审计层

---

## 一、核心能力

1. **26维对标矩阵框架**：覆盖 架构设计 / 安全体系 / 记忆系统 / 执行引擎 / 推理部署 / 技能管理 / 知识库 / 调度策略 / 通信协议 / 监控告警 / 日志审计 / 版本管理 / 测试验证 / 性能优化 / 容错恢复 / 扩展性 / 可维护性 / 文档完整性 / 用户交互 / 隐私保护 / 合规性 / 成本控制 / 资源管理 / 多语言 / 跨平台 / 自进化 共26个评估维度
2. **版本追踪**：每个对标维度维护「龙虾当前值 → 对标目标值 → 差距 → 追赶计划」四元组，向量化后支持相似维度聚类分析
3. **差异分析引擎**：自动计算龙虾体系与对标目标的逐维差距分数（0-100），加权汇总后生成整体对齐度报告
4. **优先级排序算法**：差距 × 业务影响权重 × 实现难度系数，输出TOP-N追赶任务清单
5. **对标源自动发现**：定期扫描技能库中的新文件，自动识别新的对标来源并更新矩阵

## 二、输入规范

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `benchmark_sources` | list | 是 | 对标来源文件路径列表 |
| `target_dimensions` | list | 否 | 指定关注的维度子集，默认全部26维 |
| `weight_config` | JSON | 否 | 维度权重配置，不传则使用默认均权 |
| `output_format` | str | 否 | 输出格式：`markdown` / `json` / `html` |

---

## 三、输出规范

| 字段 | 格式 | 说明 |
|------|------|------|
| `alignment_matrix` | Markdown表格 | 26维 × N对标源的完整对齐度矩阵 |
| `gap_analysis` | JSON | 逐维差距分析：`{dimension, current_score, target_score, gap, priority, action_plan}` |
| `top_priorities` | list | TOP-5优先追赶维度及具体行动计划 |
| `trend_report` | Markdown | 与上一版本的对比趋势：上升/下降/持平的维度 |

---

## 四、执行协议

1. **矩阵初始化**：加载 `benchmark_sources` → 解析每个对标源的核心能力声明 → 映射到26维框架中
2. **逐维评分**：对每个维度，龙虾方读取当前能力数据（从SOUL/USER/AGENTS三件套 + 技能库中提取），对标方从对标源中提取对应项，两者做语义相似度计算得出对齐分（0-100）
3. **差距计算**：`gap = 100 - alignment_score`，若 gap > 20 则标记为"显著差距"，若 gap > 40 则标记为"关键短板"
4. **优先级排序**：`priority = gap × business_impact_weight × (1 / implementation_difficulty)`，降序排列
5. **行动计划生成**：对TOP-N优先项，基于对标源的方法论生成具体的追赶计划（时间线 + 里程碑 + 所需资源）
6. **趋势对比**：加载上一版本的矩阵快照，逐维计算分数变化，标注上升（↑）/ 下降（↓）/ 持平（→）
7. **归档更新**：将本次矩阵快照写入 `temp/alignment_matrix_{timestamp}.json`，更新版本号

---

## 五、安全边界

- **只读分析**：对标矩阵维护为纯分析任务，不直接修改任何被评分的系统文件
- **来源真实性验证**：对标源文件必须为本地已验证文件，禁止引用未经验证的外部URL
- **评分透明**：所有维度评分必须附带评分依据（引用对标源的具体段落），严禁黑箱评分
- **敏感维度脱敏**：涉及安全体系、隐私保护、合规性等维度的详细评分，在对外输出时执行脱敏处理
