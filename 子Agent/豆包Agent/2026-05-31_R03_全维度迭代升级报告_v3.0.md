### 2. Hermes Agent — 自学习闭环Agent（GitHub 15万+ Stars）

**Nous Research出品，核心理念："The agent that grows with you."**

#### 六层架构骨架

```
L6 入口/UI: CLI + TUI(Ink) + Gateway + ACP适配器
L5 编排: AIAgent 同步对话循环（while + 预算）
L4 工具: 注册中心 + 自动发现
L3 推理: provider适配器 + 缓存 + 压缩 + Curator
L2 持久化: SQLite + FTS5全文索引 + 插件记忆
L1 系统: 配置 + .env + 7种执行后端
```

#### 核心差异：Curator自学习器

| 机制 | 实现 |
|------|------|
| **触发** | 后台周期运行（interval_hours），仅idle时工作 |
| **流程** | 执行→评估→提取→精炼→检索 |
| **产出** | 从复杂任务轨迹中提炼模式，写成可复用skill |
| **管理** | 自动归档过期skill、备份钩子 |
| **效果** | 持续使用数周后任务成功率提升40% |

#### Tools vs Skills 关键区分

- **Tools**：JSON Schema暴露的Python函数，确定性执行，修改需改源码
- **Skills**：Markdown文档，LLM运行时解释执行，可由Curator自动生成

#### 记忆系统

- SQLite + FTS5全文索引（毫秒级关键词召回）
- LLM摘要做语义压缩，避免上下文溢出
- 不用向量库 → $5 VPS也能跑
- 衍生记忆插件：Honcho / mem0 / supermemory

**豆包对标关键点**：
- Curator自学习闭环 → 豆包自我进化引擎
- Tools vs Skills分离 → 豆包能力层架构优化
- FTS5轻量记忆 → 本地环境记忆方案
- Agent级工具拦截路径 → 豆包主Agent特权工具

## 二、误进化警示 — 安全护栏

### 四条误进化路径（ICLR 2026）

| 路径 | 风险 |
|------|------|
| 模型误进化 | 微调或提示优化导致某些能力退化 |
| 记忆误进化 | 记忆积累导致偏见放大、信息冲突、安全对齐退化 |
| 工具误进化 | Agent自创工具含安全缺陷，漏洞随复用传播 |
| 工作流误进化 | 过度优化带来脆弱性，输出格式错误率上升 |

### 安全护栏三原则

1. **门控验证**（A-Evolve）：每个突变前在保留任务验证，回归git回滚
2. **人工审核**（SkillForge/SkillClaw）：自动进化结果需人类确认后发布
3. **进化隔离**：限定进化范围（只改prompts不改工具代码、沙箱测试）
