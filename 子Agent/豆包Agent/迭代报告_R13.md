## 第二章：多Agent协同框架对决

### 2.1 Hermes vs OpenClaw：两条路线

| 对比维度 | Hermes（爱马仕） | OpenClaw（龙虾） |
|----------|-----------------|-----------------|
| 设计哲学 | 成长进化型 | 执行至上型 |
| 技能生成 | **自动**（零感知提炼） | 手动（编写md文件） |
| 技能加载 | **四层渐进式匹配** | 全量塞入上下文 |
| 记忆机制 | **三层主动管理**（SQLite+向量库） | 文件即记忆（被动追加） |
| Token效率 | OpenClaw的1/4 | 上下文管理浪费 |
| 安全模型 | 内置沙盒+审批+扫描 | 默认无内置 |
| 代码量 | Python轻量 | TypeScript较重 |

**社区精辟总结**：
> "OpenClaw像一个听话但死板的实习生，每一步都要你写进制度手册；而Hermes像一个聪明的助理，干过一次就能举一反三。"

### 2.2 Hermes核心机制（对豆包SkillForge的启示）

**技能自动生成闭环**：
1. 执行任务→触发规则（工具调用次数/错误修复/用户纠正）
2. 静默打包为本地SKILL文件
3. GEPA算法定期优化：反思性变异 + 帕累托前沿选择 + NL反馈

**记忆主动管理**：
- Nudge机制：每15轮强制反思提炼
- 容量限制：MEMORY.md 2200字符 / USER.md 1375字符
- 策略：容量有限→只记重要的→自然淘汰低密度信息

**标准化**：遵循agentskills.io开放标准（Claude Code/Codex CLI/Cursor/Copilot等20+工具兼容）

### 2.3 Marvis 6Agent主从架构

腾讯2026年推出的OS级AI管家，出厂预置6 Agent：
- **主Agent**：意图理解+任务拆解+调度
- **5专项Agent**：File / Computer / App / Browser / Search
- 设计理念：专业的事交给专业的Agent做，装机即用零配置
- 与WorkBuddy互补：管家(Marvis) + 助理(WorkBuddy)

## 第四章：LLM推理逻辑优化

### 4.1 推理架构三阶进化

```
CoT（纯推理链） → ReAct（推理+行动循环） → Tool-Augmented Agent（选工具+执行分离）
```

### 4.2 核心设计原则

1. **CoT是工具调用的引擎**：LLM在输出JSON调用前，在隐藏CoT区推理——先想清楚再动手
2. **工具描述即产品文案**：写清楚做什么、什么场景用、返回什么、什么时候不该用
3. **循环上限是核心调参项**：建议上限5次起步，太少放弃太快，太多Token预算燃烧
4. **Context Engineering是稳定性核心**：不是塞多少的问题，而是塞什么、怎么组织

## 第五章：自进化Agent闭环系统

### 5.1 Autogenesis Protocol（NTU/Stanford/Princeton, 2026.5.30）

**双层协议架构**：

```
RSPL层（资源状态协议）：注册Prompt/Agent/Tool/Env/Memory
  → 每个资源带显式状态、生命周期、版本化接口
       ↓
SEPL层（自进化协议）：提议→评估→提交循环
  → 可审计血缘追踪 + 原子回滚
```

**核心创新**：解耦"演化的对象"(What)和"演化的机制"(How)

**实验**：LeetCode C++近满分，多项基准持续优于强基线

### 5.2 三套自进化方案对比

| 维度 | Hermes | FORGE+GEA(豆包现行) | Autogenesis |
|------|--------|---------------------|-------------|
| 粒度 | Skill级别 | 经验池+广播 | 资源级别(Prompt/Agent/Tool/Env/Memory) |
| 版本管理 | 帕累托自然淘汰 | Merkle树 | 显式版本+血缘树 |
| 回滚 | 自然淘汰 | Merkle回滚 | 原子回滚 |
| 审计 | Nudge反思日志 | 经验池记录 | 完整血缘追踪 |
| 形式化 | 工程实践 | 经验驱动 | 学术级协议 |
