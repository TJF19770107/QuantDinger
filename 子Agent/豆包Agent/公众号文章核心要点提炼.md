## 二、文章核心观点提炼

### 2.1 办公自动化的"手"终于补上了

过去的AI只能"说"（生成文本/给建议），但具体执行仍需人工操作。飞书CLI让AI可以直接"做"：发消息、写文档、建会议、更新表格——把飞书本身接入到AI的执行链路中。

**三方协作结构**：
```
用户（自然语言指令） → AI Agent（通过CLI调用飞书） → 飞书（返回执行结果）
```

### 2.2 为AI Agent原生设计

- 不是给人敲的命令行，而是给Agent调用的编程接口
- Shortcuts层带智能默认值和风险验证
- 输出格式（JSON/NDJSON/CSV/Table）对Agent友好
- 分页内置 `--page-all` 自动处理

## 三、实际案例：Codex + 飞书CLI实操

### 3.1 最小闭环验证

从零到可用仅需 5-10分钟：
1. `npm install -g @larksuite/cli`
2. `npx skills add larksuite/cli -y -g`
3. `lark-cli config init --new`（扫码授权）
4. `lark-cli auth login --recommend`
5. `lark-cli im +messages-send --content "测试消息"`

## 四、可复用的SOP模板

### 4.1 安装标准模板

```bash
# 一键安装脚本
npm install -g @larksuite/cli
npx skills add larksuite/cli -y -g
lark-cli config init --new
lark-cli auth login --recommend
```

### 4.2 文档生成→分发工作流

```bash
# 1. 创建文档
lark-cli docs +create --title "周报-20260614" --content "# 本周工作总结\n\n..."

# 2. 发送消息通知
lark-cli im +messages-send --content "周报已生成，请查收" --type text

# 3. 邮件抄送
lark-cli mail +send --to "manager@company.com" --subject "周报-20260614"
```

### 4.3 会议全流程自动化

```bash
# 1. 查询空闲时间
lark-cli calendar +freebusy --start "2026-06-14T09:00" --end "2026-06-14T18:00"

# 2. 创建会议
lark-cli calendar +meeting-create --title "项目评审" --time "2026-06-14T14:00" --duration 60

# 3. 会后读取录制转文字
lark-cli meeting +record-transcript --meeting-id "xxx"

# 4. 创建会议纪要并分配给参会人
lark-cli docs +create --title "会议纪要-项目评审" --content "..."
lark-cli task +create --title "待办项" --assignee "张三"
```
