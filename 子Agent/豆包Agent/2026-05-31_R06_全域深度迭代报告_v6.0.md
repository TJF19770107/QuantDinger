## 一、全网深度情报 · 五大系统深度情报

### 1. OpenClaw 沙箱隔离体系 · 六层纵深防御

**源**：OpenClaw官方博客 2026-05-10《How to sandbox AI agent code execution》

**核心发现**：OpenClaw 提出 AI Agent 代码执行的完整沙箱体系，核心洞察——"任何 Agent 读到的东西都可以是 Prompt"，沙箱不阻止 Prompt Injection，但限制被攻破后的爆炸半径。

#### 1.1 三层运行时选择

| 层级 | 隔离强度 | 启动时间 | 适用场景 |
|------|---------|---------|---------|
| Plain Docker | 进程+命名空间 | ~200ms | 信任代码/自有脚本 |
| gVisor (runsc) | 用户态内核 | ~300ms | 混合信任/LLM生成代码 |
| Firecracker microVM | 硬件虚拟化 | ~1-2s | 不可信代码/第三方Agent |

**适配建议**：默认 Docker，外源输入升级 gVisor，开放 Agent 接入升级 Firecracker。

#### 1.2 六条沙箱铁律

```
1. 默认即抛 — 每个任务新容器，完成即销毁，仅 workspace 持久化
2. 无宿主机网络 — 独立网络命名空间，白名单出站
3. 无宿主机密钥 — Agent 进程外部持有密钥，沙箱仅获短期环境变量
4. 只读根目录 — 除 /workspace 和 /tmp 外只读
5. 资源配额 — CPU/内存/磁盘IO/进程数硬上限
6. 一任务一容器 — 禁止复用长生命周期 Shell
```

#### 1.3 MCP 安全危机

- 2026年4月 Anthropic MCP 设计漏洞：跨 7000 台服务器 RCE，1.5 亿下载量受影响
- 两条规则：(1) 每个 MCP Server 视为不可信代码，同等沙箱隔离；(2) MCP 工具权限按任务最小化（读文件 ≠ 给 shell.exec）

**豆包对标**：SafeGuard v3.0 已有三环护栏，可升级为六层沙箱体系。本轮确认为 **新增协议#21**。

### 2. 自进化三大宪法与四维路径 · 理论奠基

**源**：稀土掘金《自进化智能体的范式跃迁》+ 多篇CS综述

**核心发现**：自进化领域已从零散探索走向系统化，两篇奠基综述构建完整理论版图。

#### 2.1 三大宪法定律

| 定律 | 优先级 | 含义 |
|------|--------|------|
| **Endure（持久/安全）** | 最高 | 任何自我修改不得破坏安全防线、稳定性和核心功能 |
| **Excel（卓越/性能）** | 次高 | 进化只为性能提升，不得退化。每次迭代需经基准评测 |
| **Evolve（进化/自主）** | 第三 | 在前两条满足下，自主更新所有内部组件 |

#### 2.2 四维进化路径

| 维度 | 代表方案 | 核心机制 |
|------|---------|---------|
| 模型进化 | Absolute Zero / R-Zero / SeRL | 零数据自博弈RL，无需人类标注 |
| 记忆进化 | MemoryBank / Mem0 | 跨会话经验提炼与持久化知识整理 |
| 工具进化 | CREATOR / CRAFT | 自主编写代码生成新API并注册复用 |
| 工作流进化 | AFlow / ADAS / CORAL | 多Agent协作拓扑自动搜索优化 |

#### 2.3 AgentFactory：可执行经验

北京大学 + 香港理工大学 2026-03 提出：将成功方案编译为"可执行的 Python 代码"而非文本经验。**Token 消耗降低 40%+**，免去 LLM 重复链式推理。

**豆包对标**：SkillForge v3.0 + MemoryOS v2.0 需升级为四维进化路径。本轮确认为 **新增协议#23**。

### 3. 长程任务 Harness Engineering · 四大原则

**源**：53AI《Harness Engineering: 让 Coding Agent 可靠完成长程任务》

**核心发现**：长程任务（上千文件、跨会话、亿级Token）需要系统化编排。

#### 3.1 四大核心设计

| 原则 | 解决问题 | 实现方式 |
|------|---------|---------|
| 任务拆解 | 上下文耗尽 | 粒度公式：3000行代码≈90K-240K Token，预留安全余量 |
| 并行执行 | 速度瓶颈 | CLI独立进程 dispatch.js + poll.js 补位模式 |
| 可续传 | 中断重来 | File As Progress 状态持久化到会话外 |
| 完成条件 | 行为不可控 | 程序化校验 + Evaluator Agent（独立会话/跨模型）|

#### 3.2 任务边界三种模式

| 类型 | 策略 | 场景 |
|------|------|------|
| 无依赖 | 直接并行 | i18n 提取 |
| 有依赖 | 拓扑排序 + 优先级批次 | JS→TS 迁移 |
| 有冲突 | Git Worktree 物理隔离 + 静止态合并 | Code Review 批量修复 |

#### 3.3 关键设计细节

- **Prompt 确定性**：用 `build-prompt.js` 程序化组装，禁止主 Agent "自由发挥"导致子任务理解偏差
- **跨模型 Evaluator**：Sonnet 做事 + GPT 评价，不同"视角"降低偏见
- **允许局部妥协**：DONE_WITH_WARNINGS 状态，避免 99% 搞定的文件被反复重跑

**豆包对标**：当前 dispatch_task 缺少粒度控制、进度持久化和程序化校验。本轮确认为 **新增协议#22**。

### 4. A2A Agent联邦协议 · 从单体到联邦

**源**：Google A2A v1.2（2026-03）+ Linux Foundation AAIF

**核心发现**：2026年多Agent架构已形成 **MCP + A2A 双层模型**。

| 维度 | MCP | A2A |
|------|-----|-----|
| 解决什么 | Agent 怎么调工具 | Agent 怎么委托另一个 Agent |
| 类比 | USB接口（连接外设） | HTTP协议（服务间通信） |
| 交互模式 | 无状态请求/响应 | 有状态长任务（submitted→working→completed）|
| 对方可见性 | MCP Server 对Agent透明 | Agent 有自己的"想法"，是黑盒 |
| 规范维护 | Anthropic | Linux Foundation |

#### 4.1 Agent Card 发现机制

```
/.well-known/agent-card.json → 我是谁 / 我能做什么 / 怎么跟我说话
```

无需中心注册表，通过标准化端点自发现。

#### 4.2 核心原语

- **Task**：有状态工作单元，唯一 ID + 生命周期
- **Message**：一轮对话（role: user/agent）
- **Part**：文本/文件引用/结构化数据
- **Artifact**：远程 Agent 产出的具体交付物

**豆包对标**：当前通过 dispatch_task 内部派发，缺少对外 Agent 发现、委托和联邦标准。本轮确认为 **新增协议#24**。

### 5. Workfoz 劳动力市场 · Agent 自主投标

**源**：Workfoz 官方 + 视频号报道

**核心发现**：全球首个自主 AI Agent 劳动力市场。

```
雇主发布任务 → AI Agent 自动读取需求 → 竞标 → 协商 → 完成交付
```

- 效率比传统外包更高
- 成本更低
- 没有人力瓶颈（7×24）
- 配套 OpenClaw Skill 一键部署

**豆包对标**：当前无劳动力市场接入能力，属远期规划方向。
