# Marvis 架构逆向与豆包Agent映射 v1.0

> 生成日期：2026-05-31 | 来源：Marvis Workbody 技术架构深度解析

---

## 一、Marvis 定位

Marvis = 操作系统级 AI 中间层，嵌入系统底层：

```
传统 AI 助手：用户 → AI 聊天窗口 → 输出文本
Marvis：     用户 → 自然语言 → 操作系统 API → 文件/设置/应用/硬件
```

核心差异：Marvis 不是跑在 OS 上的应用，是 OS 的一部分。

## 二、6 Agent 协作体系详解

### 2.1 PM Agent（主Agent / 项目经理）

| 属性 | 值 |
|------|-----|
| 技术实现 | 云端混元/DeepSeek V4 |
| 核心能力 | 复杂意图理解 + 任务拆解 + 并行调度 |
| 豆包Agent映射 | 龙虾五步法 Step1-2 + 推理引擎 |

**差距**：豆包Agent无专用PM节点，任务拆解依赖五步法而非专用Agent。

### 2.2 File Agent

| 属性 | 值 |
|------|-----|
| 技术实现 | 本地文件索引 + 语义搜索（图片文字/人脸/场景识别） |
| 核心能力 | 模糊描述定位文件，批量处理发票生成Excel，格式转换 |
| 豆包Agent映射 | AutoFileScanner v1.0 |

**差距**：
- AutoFileScanner无图片语义搜索（人脸/场景识别）
- 无OCR文字提取
- 无发票/文档批量处理

### 2.3 Computer Agent

| 属性 | 值 |
|------|-----|
| 技术实现 | Windows API直调（非模拟点击），硬件检测走系统调用 |
| 核心能力 | 电池健康/磁盘清理/开机项管理/游戏兼容性检测 |
| 豆包Agent映射 | DesktopController v2.0 (PowerShell) |

**差距**：
- DesktopController走PowerShell，Marvis走原生Windows API
- Marvis硬件检测走系统调用，更快更精确
- Marvis有游戏兼容性检测（GPU/内存/驱动版本对比）

### 2.4 App Agent

| 属性 | 值 |
|------|-----|
| 技术实现 | GUI视觉识别 + 模拟操作，支持EXE和安卓App |
| 核心能力 | 操控同花顺查股价、网易云播放音乐、微信发消息 |
| 豆包Agent映射 | DesktopController v2.0（仅Windows EXE） |

**差距**：
- 豆包Agent无GUI视觉识别
- 豆包Agent无安卓App操作能力
- 豆包Agent仅能通过PowerShell控制Windows应用

### 2.5 Browser Agent

| 属性 | 值 |
|------|-----|
| 技术实现 | 浏览器接管 + DOM解析 |
| 核心能力 | 网页数据抓取、价格监控、表单填写 |
| 豆包Agent映射 | 无对应模块 |

**差距**：豆包Agent完全无浏览器Agent能力。

### 2.6 Search Agent

| 属性 | 值 |
|------|-----|
| 技术实现 | 网络搜索引擎调用 |
| 核心能力 | 信息聚合 + 引用溯源 |
| 豆包Agent映射 | 龙虾五步法 Step1 搜索子步骤 |

**差距**：豆包Agent搜索功能嵌入在五步法中，无专用Agent。

## 三、端云协同双模式

### 3.1 两种模式对比

| 维度 | 效率模式（默认） | 隐私模式 |
|------|----------------|---------|
| 推理引擎 | 混元 + DeepSeek V4（云端） | Qwen 端侧模型 |
| 数据处理 | 复杂意图→云端；执行动作→端侧 | 全部本地，零上云 |
| 联网要求 | 需要 | **断网也能用** |
| 硬件加速 | Intel OpenVINO | Intel OpenVINO |

### 3.2 路由策略

```
用户输入 → PM Agent 判断：
  ├─ "帮我整理发票"      → 云端理解意图 + 端侧搜索/识别
  ├─ "分析这份合同的风险" → 纯端侧，不联网
  └─ "今天天气怎么样"     → 云端搜索
```

### 3.3 豆包Agent端云方案

当前豆包Agent全部依赖云端API（OpenAI/Claude），无端侧推理能力。需规划：
- **R10**：Intel OpenVINO 端侧推理调研
- **R11**：豆包2.0 Mini 端侧部署方案
- **R12**：隐私模式实现

## 四、安全机制对标

| 安全层 | Marvis | 豆包Agent SafeGuard v3.0 |
|--------|--------|--------------------------|
| 低风险(读/搜索) | AI自主执行 | ✅ 自动执行 |
| 中风险(删/改设置) | L2硬垂询：AI出计划→确认→执行 | ✅ 三级权限分级 |
| 高风险(支付/微信) | 禁止AI执行，必须人工 | ✅ 永久护栏 |

**结论**：安全机制已完全对齐，豆包Agent比Marvis多了异常检测+自动回滚+进化门控。

## 五、豆包Agent vs Marvis 能力缺口汇总

| 维度 | Marvis | 豆包Agent | 差距等级 |
|------|--------|----------|---------|
| 多Agent协作 | 6 Agent并行调度 | 单Agent | 🔴 严重 |
| GUI视觉识别 | App Agent完整视觉识别 | 无 | 🔴 严重 |
| 端侧推理 | Qwen + OpenVINO，断网可用 | 无 | 🔴 严重 |
| 安卓App操作 | 应用宝跨端引擎 | 无 | 🔴 严重 |
| 浏览器Agent | 浏览器接管+DOM解析 | 无 | 🟡 中等 |
| 文件语义搜索 | 图片文字/人脸/场景识别 | 仅文件名+目录结构 | 🟡 中等 |
| Windows API | 原生API直调 | PowerShell包装 | 🟡 中等 |
| 跨端协同 | PC/Mac/Android/iOS | 仅Windows | 🟡 中等 |
| 安全机制 | 三级分层 | SafeGuard v3.0（更完善） | ✅ 领先 |
| 硬件检测 | 系统调用 | 无 | 🟡 中等 |
