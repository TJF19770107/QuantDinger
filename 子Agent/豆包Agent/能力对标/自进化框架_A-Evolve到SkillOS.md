## 二、A-Evolve — "Agentic AI的PyTorch"

### 五阶段进化循环

```
Solve ──→ Observe ──→ Evolve ──→ Gate ──→ Reload
 执行       记录       改配置      验证      加载
                                    │
                               git回滚(安全阀)
```

### 关键设计

| 设计 | 说明 |
|------|------|
| Git标签 | 每个接受的突变有evo-1/evo-2标签，可复现可回溯 |
| 安全阀 | 进化退步就git回滚 |
| 只改配置 | 不微调模型，只进化prompts/skills/tools/memory |
| 进化-缩放假说 | 适应能力 ∝ 分配给进化的计算量 |

### 实测成绩

| 基准 | 排名 | 分数 |
|------|:---:|:---:|
| MCP-Atlas | 第1名 | 79.4% |
| SWE-bench Verified | ~第5名 | 76.8% |

## 三、SkillX — 三层技能层次

```
战略计划（Strategic Plans）
  │  高层策略："先收集信息，再制定方案，最后执行"
  ▼
功能技能（Functional Skills）
  │  可复用能力："调用API获取数据"、"解析JSON响应"
  ▼
原子技能（Atomic Skills）
    基础操作："发送HTTP请求"、"写入文件"
```

### 跨Agent迁移

GPT-4级别Agent产生的技能库 → 显著提升GPT-3.5级别Agent表现。
**强Agent的技能可以赋能弱Agent。**

## 四、SkillClaw — 双循环集体进化

### 双循环架构

```
Agent任务循环（同步）: 用户任务 → 执行 → 返回结果
        ↕
SkillClaw演化循环（异步）: 分析会话 → 创建/优化技能 → 验证 → 发布
```

### 三层部署

| 层 | 作用 |
|----|------|
| Client Proxy | 本地API代理，拦截请求记录会话，管理本地技能库 |
| Evolve Server | 后台服务，从共享存储读会话数据，自主演化技能 |
| 共享存储 | 阿里云OSS/AWS S3/本地FS，跨设备跨用户同步 |

### 跨Agent交叉授粉

前端Agent使用React积累的模式识别经验 → 改善后端Agent处理API设计的决策。
**这在单体进化中不可能发生。**

## 五、SkillForge — 工业级闭环进化

### 三阶段循环

```
故障分析器 → 批量诊断失败案例，分类归纳失败模式
    ↓
技能诊断器 → 将失败模式定位到具体技能缺陷
    ↓
进化优化器 → 生成改进方案，审核后部署
```

### 关键结论

在5个真实云支持场景、1883张工单、3737个任务上：
**自动化进化可以超越人工策划的专家知识。**

## 六、SkillOS范式

### 核心理念

**技能应该是活的、有生命周期的、可进化的实体，不是静态的配置文件。**

### 两种实践

| 项目 | 星数 | 特点 |
|------|:---:|------|
| EvolvingAgentsLabs/skillos | 12 | 纯Markdown定义一切，14种压缩方言 |
| dudusoar/skillOS | 2 | 元技能+合约+渐进式披露 |

### 14种压缩方言

skillos提供针对不同领域的压缩格式，token减少50-99%：
- `strict-patch` 压缩率 ~98%
- `roclaw-bytecode` 压缩率 ~99%

## 七、误进化 — 四条风险路径

| 路径 | 风险描述 |
|------|---------|
| **模型误进化** | 微调或提示优化导致某些能力退化 |
| **记忆误进化** | 记忆积累→偏见放大→信息冲突→安全对齐退化 |
| **工具误进化** | Agent自创工具含安全缺陷，漏洞随复用传播 |
| **工作流误进化** | 过度优化→脆弱性，输出格式错误率上升 |

> **即使使用Gemini-2.5-Pro这样的顶级模型，误进化也会发生。**

### 安全护栏三原则

| 原则 | 实现 | 代价 |
|------|------|------|
| 门控验证 | 突变前跑保留任务验证，回归git回滚 | 计算开销 |
| 人工审核 | 自动进化结果需人类确认 | 速度换质量 |
| 进化隔离 | 限定可进化范围（只改prompts不改工具） | 限制进化自由度 |

## 八、豆包自进化方案建议

### 阶段一：基础设施

1. 记忆系统（SQLite+FTS5）→ 记录所有任务轨迹
2. 技能目录结构（三层层次）→ 战略/功能/原子
3. 评估基准（保留任务集）→ Gate验证

### 阶段二：单Agent自进化

1. Curator后台学习器 → 从轨迹提炼技能
2. 五阶段循环 → Solve→Observe→Evolve→Gate→Reload
3. Git版本控制 → 可回溯可回滚

### 阶段三：多Agent集体进化

1. SkillClaw双循环 → Agent任务+演化异步并行
2. 跨Agent交叉授粉 → 技能在不同子Agent间迁移
3. 共享技能库 → 多用户/多Agent技能同步
