## 三、豆包Agent对标差距与优化方向

### 3.1 P0 — 自进化闭环（对标 Hermes）
**差距**：豆包当前无经验沉淀→Skill生成→复用机制
**优化方案**：
- 实现"任务执行→关键步骤提取→结构化Skill文件写入→下次加载"闭环
- Skill格式：Markdown，含触发条件/执行步骤/注意事项
- 引入 git 版本标记，确保可回滚

### 3.2 P0 — 长时域持久目标（对标 Codex /goal）
**差距**：豆包缺乏持久化目标追踪与断点续传
**优化方案**：
- 引入持久Goal体系：目标入库→状态追踪→断点恢复
- 支持 /goal 命令：一次性设定目标，自主拆解子任务并持续执行

### 3.3 P1 — 并行子Agent调度（对标 Claude Dynamic Workflows）
**差距**：豆包多Agent协作为串行派发
**优化方案**：
- 实现并行子Agent调度器：无依赖任务同一批次并行派发
- 引入子Agent线程池，支持同时运行多个子Agent

### 3.4 P1 — 消息网关多平台统一（对标 Hermes/OpenClaw）
**差距**：当前仅电脑端+移动端
**优化方案**：
- 扩展Gateway架构，适配更多消息渠道
- 统一会话ID映射，跨平台上下文保持

### 3.5 P2 — 超大上下文窗口适配（对标 Gemini）
**差距**：Token限制影响长文档处理
**优化方案**：
- 优化memory_ids机制，支持更大上下文注入
- 分层摘要策略：长文档先摘要再按需展开

### 3.6 P2 — 端侧自主操作用（对标 Project Mariner）
**差距**：App操作依赖Android模拟器中介
**优化方案**：
- 探索原生GUI Agent能力
- 优化模拟器操作延迟与稳定性
