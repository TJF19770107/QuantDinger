## 二、R12 新增技能协议

### 技能 #51：GitHub Skills 生态集成协议
- **来源**：mattpocock/skills + andrej-karpathy-skills + obra/superpowers
- **定义**：将AI Agent能力模块化为可插拔的Skills文件（单文件配置），实现"一次编写、多Agent复用"
- **核心原则**：
  1. 先理解再修改（分析代码逻辑→最小变更）
  2. 始终先写测试（TDD强制约束）
  3. 单文件配置（CLAUDE.md / CODE.md 即技能）
  4. 社区驱动迭代（吸收开发者实践反馈）
- **适用Agent**：豆包Agent、Hermes Agent、OpenClaw龙虾Agent
- **落地路径**：在技能库新增 `skills-registry.md`，登记所有可复用Skills

### 技能 #52：数字分身蒸馏协议
- **来源**：疯狂的豇豆教程体系
- **定义**：通过MBTI人格测试+AI对话记录分析，将用户三观/人格/习惯/思维蒸馏为AI可理解的核心配置文件
- **六步流程**：
  1. 分析自己（MBTI + 豆包分析三观）
  2. 制定计划（结合十五五规划做个人五年规划）
  3. 转换文件（聊天记录/简历→MD格式）
  4. 分析文件（LLM深度提炼）
  5. 建立第一个SKILL（个性化技能）
  6. 更新配置（SOUL.md / USER.md / AGENTS.md）
- **核心文件**：
  - SOUL.md：人格宪法（性格/语气/边界/三观）
  - USER.md：用户信息（背景/偏好/习惯）
  - AGENTS.md：工作方式（决策流程/任务处理规则）
- **适用Agent**：豆包Agent（交互层）、Hermes Agent（调度层）
- **落地路径**：在子Agent目录下同步创建SOUL.md/USER.md/AGENTS.md模板

### 技能 #53：多Agent编排与Swarm协作协议
- **来源**：ruvnet/ruflo + MiniMax Mavis + CrewAI + AutoGen Studio
- **定义**：将多个专业Agent组织为团队，按Owner→Worker→Verifier三层角色协作
- **架构模式**：
  - Owner（目标制定+质量把关）→ 分配任务
  - Worker（多执行者并行）→ 提交结果
  - Verifier（结果验证）→ 反馈修正
- **关键能力**：多Agent Swarm、RAG集成、Claude Code原生对接、Human Feedback介入
- **适用Agent**：Hermes Agent（调度）+ OpenClaw龙虾Agent（执行）
- **落地路径**：在工作流库新增 `swarm-orchestration.md`，定义多Agent协作标准流程

### 技能 #54：长期记忆持久化协议
- **来源**：Letta/Mem0/Zep + GraphRAG + Agentic RAG
- **定义**：将Agent记忆从"会话级"升级为"持久化级"，支持跨会话知识积累与经验复用
- **四阶段演进**：
  - 1.0 全量上下文注入（token受限）
  - 2.0 RAG检索增强（语义碎片化）
  - 3.0 Agentic RAG + GraphRAG（主动检索+知识图谱）
  - 4.0 长期记忆产品化（Letta/Mem0/Zep）
- **核心洞察**：记忆不是"存更多数据"，而是"知道什么时候该想起什么"
- **适用Agent**：全部子Agent
- **落地路径**：在记忆库新增 `memory-strategy.md`，定义记忆分层策略

### 技能 #55：AI编程Agent协同工作协议
- **来源**：Claude Code 54%份额 + Codex CLI + OpenClaw + Gemini CLI
- **定义**：在生产环境中组合多个AI编程Agent，各司其职形成流水线
- **生产组合模式**：
  - Claude Code：本地精雕（craftsmanship）
  - Codex CLI：独立Shell耐久任务（endurance）
  - Cursor Background Agents：云端并行扇出（fan-out，最多8并行）
  - OpenClaw：底层能力支撑+插件联动
- **统一路由**：单一API网关 → 统一计费 + 模型目录
- **适用Agent**：豆包Agent（代码生成）、OpenClaw龙虾Agent（执行验证）
- **落地路径**：在工作流库新增 `coding-pipeline.md`
