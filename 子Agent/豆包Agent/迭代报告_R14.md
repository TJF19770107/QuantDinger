## 第二章：自进化Agent工程化突破

### 2.1 Autogenesis Protocol (AGP) — 2026.5.30 重大更新

**来源**：NTU/Stanford/Princeton联合团队，论文 arXiv:2604.15034

**双层协议架构**：

```
RSPL层（Resource Substrate Protocol Layer）
  五类可演化资源：Prompt / Agent / Tool / Environment / Memory
  → 每资源：显式状态 + 生命周期 + 版本接口 + 可演化标记

SEPL层（Self-Evolution Protocol Layer）
  闭环操作：Reflect → Select → Improve → Evaluate → Commit
  → 可审计血缘追踪 + 原子回滚 + 不绑定特定优化方法
```

**关键设计洞察**：
- **解耦是核心**：把"什么能进化"（RSPL资源）与"如何进化"（SEPL流程）彻底解耦
- **不是代码工程，是资源治理**：所有智能体组件进入可管理、可复用、可回滚状态
- **优化方法无关**：Reflection Optimizer/TextGrad/Reinforce++/GRPO均可映射到同一个SEPL接口

**性能验证**：
- GAIA Validation: 93.33%（Agent-Evo），Test: 89.04%（+12.61% vs baseline）
- HLE全量: 59.6%，仅次于Claude Mythos Preview
- LeetCode C++: 近满分，五语言全面提升

### 2.2 EvolveR（ICML 2026收录）

**来源**：浙江大学+上海AI Lab，论文 arXiv:2510.16079

**核心创新**：经验检索动作——Agent不仅可以调用外部知识库，还可以调用自身经验库。经验库保存的不是具体答案，而是从过去任务中总结的**策略原则**（如"比较类问题应先分别收集双方信息再进行结论判断"）。

**闭环流程**：在线交互 → 离线自蒸馏 → 经验库维护 → 强化学习更新

### 2.3 MiniMax M2.7 自主进化验证

**实测数据**：
- 100+轮自主迭代，发现采样参数最优组合
- MLE Bench Lite: 9金5银1铜（24小时自主进化）
- 生产故障恢复时间缩短至3分钟以内
- SWE-Pro: 56.22%追平GPT-5.3-Codex
- Terminal Bench 2: 57.0%

## 第四章：Agent安全沙箱四层体系

### 4.1 五级隔离层次（2026年标准）

| 级别 | 技术 | 启动延迟 | 内存开销 | 安全边界 | 适用场景 |
|------|------|---------|---------|---------|---------|
| L1 容器 | Docker/Podman | <1s | 0 | 共享内核 | 内部可信代码 |
| L2 用户态内核 | gVisor | ~100ms | ~20MB | 拦截syscall | Agent中等风险代码 |
| L3 MicroVM | Firecracker | ~125ms | ~5MB | 硬件虚拟化 | **LLM生成代码金标准** |
| L4 库OS | LiteBox(实验) | — | — | 最小原语 | 前沿研究 |
| L5 机密计算 | AMD SEV/Intel TDX | — | — | 硬件加密内存 | 金融/医疗/合规 |

**行业共识**：AWS Lambda(Firecracker)、Google(GKE+gVisor)、Azure(Hyper-V)全部选择最强隔离原语指向AI Agent，无一选择容器。

### 4.2 三层市场格局

| 层级 | 代表 | 适用场景 |
|------|------|---------|
| **原语层** | Firecracker/gVisor/LiteBox | 自建调度，最大控制，合规需求 |
| **嵌入式运行时** | E2B(托管API)/microsandbox(自托管) | 快速接入，强隔离，低运维 |
| **托管平台** | Daytona/Modal/Northflank | GPU场景，零运维，数据密集 |
| **混合方案** | Google Agent Sandbox(K8s) | 已有K8s团队，开源，温池 |

### 4.3 豆包沙箱安全升级路线

| 当前状态 | 升级方向 | 来源 |
|---------|---------|------|
| D09=4分，基础隔离 | **引入Firecracker MicroVM**作代码执行隔离层 | E2B/Firecracker |
| 内核级共享 | 用户态syscall拦截（gVisor对标） | Google Agent Sandbox |

## 第五章：Marvis 1+5 架构深度对标

### 5.1 架构全景

```
MainAgent (PM)
  ├─ File Agent      → 文件全生命周期
  ├─ Computer Agent  → OS底层操控
  ├─ App Agent       → 应用操作（桌面+安卓）
  ├─ Browser Agent   → 网页交互
  └─ Search Agent    → 信息检索
```

### 5.2 关键设计原则（豆包可直接复用）

1. **不越级执行**：Agent不直接调用底层工具，必须通过框架层安全路由
2. **并行调度**：复合指令同时调度多个Agent并行执行，而非串行排队
3. **强制确认**：敏感操作L2级硬垂询，Agent必须先给出执行计划
4. **双模切换**：效率模式(端云协同) + 隐私模式(完全本地)，用户按需切换
5. **出厂预置**：6 Agent装好即用，零配置零技能编写

### 5.3 豆包与Marvis差距分析

| 维度 | Marvis | 豆包 | 差距 |
|------|--------|------|------|
| Agent分工 | 出厂预置5专项Agent | 自主定义Agent | Marvis更"开箱即用" |
| 并行调度 | ✅原生 | D07=3 | 需强化并行执行引擎 |
| 双模切换 | ✅端云双模 | 端侧为主 | 可补充云端模式 |
| OS级权限 | ✅Windows底层 | DesktopController | 接近，需深度 |
| 跨端协同 | ✅手机↔电脑 | — | 新能力方向 |
