## 一、GEPA循环定义

```
 ┌──────────────────────────────────────────────┐
 │                  GEPA 循环                    │
 │                                              │
 │   Goal ──────→ Execution ──────→ Performance │
 │    ↑                              │          │
 │    │                              ↓          │
 │   Adaptation ←────────────────── 评估        │
 │                                              │
 └──────────────────────────────────────────────┘
```

### 四阶段详解

| 阶段 | 英文 | 输入 | 输出 | 核心动作 |
|------|------|------|------|---------|
| G | Goal | 用户需求 | 结构化任务模型 | 意图识别、需求拆解、依赖分析 |
| E | Execution | 任务模型 | 执行结果 | 多Agent并行、工具调用链、实时监控 |
| P | Performance | 执行结果+用户反馈 | 多维度评分 | 正确性/效率/完整性/满意度评估 |
| A | Adaptation | 评分+历史数据 | 优化策略+新技能 | 策略调整、技能沉淀、记忆更新 |

## 二、Performance评估体系

### 2.1 评分维度

```
总体评分 = 正确性×0.35 + 效率×0.20 + 完整性×0.20 + 用户满意度×0.25

正确性 (0.35):
├── 功能正确: 代码能否编译/运行通过
├── 逻辑正确: 是否符合业务逻辑
├── 边界处理: 异常情况是否覆盖
└── 安全合规: 无注入/泄露风险

效率 (0.20):
├── Token消耗: 输入+输出Token总量
├── 执行耗时: 端到端完成时间
├── 调用次数: 工具/API调用次数
└── 资源占用: 内存/CPU使用率

完整性 (0.20):
├── 需求覆盖: 所有子任务是否完成
├── 文档配套: 是否生成必要说明
├── 测试覆盖: 是否有测试代码
└── 错误处理: 是否有异常处理

用户满意度 (0.25):
├── 直接反馈: 用户明确评价
├── 修改频率: 用户要求修改的次数
├── 采纳率: 生成内容的采纳比例
└── 复用意願: 用户是否复用结果
```

### 2.2 评分等级

| 等级 | 分数 | 含义 | 后续动作 |
|------|------|------|---------|
| S | 90-100 | 卓越 - 一次性完美完成 | 技能沉淀 + 优先复用 |
| A | 80-89 | 优秀 - 小修即可用 | 策略记录 + 部分沉淀 |
| B | 70-79 | 良好 - 需要中等修改 | 策略微调 |
| C | 60-69 | 及格 - 需要大幅修改 | 策略审视 + 根因分析 |
| D | <60 | 不合格 - 需要重做 | 策略重构 + 报警 |

## 三、Adaptation适应机制

### 3.1 技能自动沉淀流程

```
任务完成 → Performance评分 ≥ 80分
  → 提取任务模式: 输入→步骤→工具→输出
  → 泛化: 去具体化参数，保留流程骨架
  → 验证: 用相似任务测试可复用性
  → 注册: 写入技能库 + 更新索引
  → 版本: 记录创建时间+来源任务+评分
```

### 3.2 策略优化机制

```
策略 = {模型选择, Prompt模板, 工具配置, 子Agent编排}

低分任务 → 根因分析:
├── 模型问题 → 升级模型或调整推理强度
├── Prompt问题 → Prompt自动优化(尝试变体)
├── 工具问题 → 替换或增强工具
├── 编排问题 → 调整Agent分工或并行度
└── 知识不足 → 触发联网学习

A/B测试:
- 对同类任务尝试不同策略组合
- 对比Performance评分
- 选择最优策略并固化
```

### 3.3 三层记忆架构（参考Hermes）

```
Layer 1: 会话记忆 (Session Context)
- 存储: 当前对话历史（压缩表示）
- 容量: 最近N轮对话
- 用途: 即时上下文理解

Layer 2: 任务记忆 (SQLite Task Memory)
- 存储: 结构化任务记录+评分+策略
- 容量: 全量历史任务
- 用途: 相似任务检索+策略复用

Layer 3: 持久记忆 (MEMORY.md)
- 存储: 用户偏好、项目背景、长期知识
- 容量: 无限（文件系统）
- 用途: 跨会话身份一致性+个性化

检索策略:
当前任务 → Layer 1 初步匹配 → Layer 2 相似任务检索 → Layer 3 身份补充
         → 融合上下文 → 注入Agent
```

## 四、推理强度可调（参考Claude）

```
用户可选模式:
├── ⚡ 快速模式: mini模型 + 低推理深度 + 适合简单问答
├── 📝 标准模式: 默认模型 + 中等推理 + 日常任务
├── 🧠 深度模式: Pro模型 + 高推理深度 + 复杂分析
└── 🔬 极限模式: 旗舰模型 + xhigh推理 + 编码/数学/科学

自动切换:
- 简单任务（问候/常识）→ 快速模式
- 标准任务（写作/翻译）→ 标准模式
- 复杂任务（编码/分析/规划）→ 深度模式
- 竞赛级任务（IMO/ICPC）→ 极限模式
```

## 五、与龙虾五步法的融合

```
龙虾五步法               →  GEPA映射
─────────────────────────────────────
Step 1: 意图识别          →  Goal (G)
Step 2: 能力映射          →  Goal (G) - 策略选择
Step 3: 方案规划          →  Goal (G) - Planner
Step 4: 自主执行          →  Execution (E)
Step 5: 反思进化          →  Performance + Adaptation (P+A)
```
