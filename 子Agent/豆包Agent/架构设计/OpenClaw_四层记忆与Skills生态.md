# OpenClaw 四层记忆与Skills生态 — 架构深度分析
## 来源：全网调研 2026-05-31

---

## 一、定义

OpenClaw是一个**自托管、开源、本地优先**的AI Agent执行网关。核心定位："AI世界的通用桥梁"——一端打通所有主流LLM，另一端连接本地系统工具与第三方API。

- 创建者：Peter Steinberger（PSPDFKit创始人）
- 发布时间：2025年11月（历经 ClawdBot → Moltbot → OpenClaw）
- GitHub Stars：20万+
- 协议：MIT

---

## 二、四层记忆架构

```
L4 向量检索 — 语义搜索，跨会话知识发现
L3 长期记忆 — 结构化持久化，跨session保留偏好与知识
L2 日志 — 操作记录、工具调用链、执行轨迹
L1 会话上下文 — 当前对话的完整上下文窗口
```

### 关键设计

1. **记忆是黑盒**：用户不需要知道记忆内部结构
2. **跨项目污染风险**：不同项目的记忆可能交叉，需项目隔离
3. **飞轮效应**：记忆带来数据复利，越多用越懂你

## 三、Skills体系

### 三部分构成

| 部分 | 作用 |
|------|------|
| **Instructions（指令）** | 精准引导LLM完成特定任务 |
| **Code（可执行代码）** | 工程规范性封装 |
| **Resources（资源）** | 辅助数据、模板、配置 |

### 生态规模

- 25,000+ 技能可组合
- AI能自己写新技能
- 12%第三方技能含恶意代码（需安全审核）

### Skills vs MCP的关系

- **MCP**：能力提供层，解决"连接"问题
- **Skills**：能力封装层，解决"如何组织能力"问题
- **AI**：流程编排层

---

## 四、核心架构模块

### Gateway 网关模块（神经中枢）

- 单端口复用WebSocket+HTTP
- 统一管理模型接入、渠道对接、工具权限、消息流转
- 支持50+通讯渠道（Telegram/微信/飞书/iMessage/WhatsApp等）

### Agent 智能体模块（决策大脑）

- OPA循环：观察(Observe) → 计划(Plan) → 行动(Act)
- 自主拆解步骤→选择工具→链式执行
- 基于LLM的动态规划能力

### Commander-Worker 多Agent编排

- Commander负责任务分发
- Workers执行具体子任务
- 支持A2A通信

### 持久化存储

- 7×24小时后台运行
- cron+HEARTBEAT.md自主心跳
- 长期记忆+向量检索

## 五、设计决策

| 决策 | 为什么有效 | Trade-off |
|------|-----------|-----------|
| 聊天界面作为入口 | 复用现有习惯，学习成本零 | 线性对话，过程不可观测 |
| 统一上下文+持久化记忆 | 跨平台跨会话记住一切 | 记忆黑盒，跨项目易污染 |
| 丰富Skills生态 | 25000+可组合，AI自生成 | 12%第三方含恶意代码 |
