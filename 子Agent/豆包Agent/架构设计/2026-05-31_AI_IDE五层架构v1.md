# 豆包 AI IDE 五层架构 v1.0 设计

> **日期**: 2026-05-31 | **状态**: 草案
> **融合来源**: Codex五层架构 + Gemini Antigravity 2.0 + 豆包AI编程现有能力

---

## 一、五层架构总览

```
Layer 5: 验证与反馈层  ←── 测试运行 · LSP诊断 · 代码审查 · 性能分析
Layer 4: 工具与沙箱层  ←── 隔离执行 · 文件操作 · 命令执行 · 包管理
Layer 3: 静态分析层    ←── Tree-sitter依赖图 · RAG索引 · 符号解析
Layer 2: Agent编排层   ←── 任务拆解 · 多Agent调度 · 结果整合
Layer 1: 用户交互层    ←── 多面板IDE · 对话 · 代码 · 预览 · 终端
```

## 二、逐层设计

### Layer 1: 用户交互层

```
┌─────────────────────────────────────────────┐
│ [文件树]  │  [代码编辑器]  │  [对话面板]     │
│           │                │                 │
│ src/      │  main.py       │  豆包: 我来     │
│  app/     │  def main():   │  帮你重构这个   │
│  utils/   │    ...         │  函数...        │
│           │                │                 │
│           ├────────────────┤                 │
│           │  [终端面板]    │  [预览面板]      │
│           │  $ python main │  [WebView]      │
│           │  Hello World   │                 │
└─────────────────────────────────────────────┘

面板布局:
- 左: 文件树（项目结构浏览）
- 中上: 代码编辑器（语法高亮+自动补全+Agent建议）
- 右上: AI对话（自然语言交互）
- 中下: 终端（命令执行输出）
- 右下: 预览（网页/图表/UI实时渲染）
```

### Layer 2: Agent编排层

```
Planner Agent工作流:
用户输入 "给这个项目加用户登录功能"
  → 意图识别: 功能开发
  → 项目分析: 读取现有结构（Layer 3）
  → 任务拆解: [创建User模型, 添加登录路由, 编写登录表单, 添加认证中间件, 写测试]
  → Agent分配: Coder×2 + Filer×1 + Terminal×1
  → 并行执行: 4个子Agent同时工作
  → 结果整合: 代码合并+测试验证
  → 用户确认: 展示变更diff+测试结果
```

### Layer 3: 静态分析层

```
核心能力:
1. Tree-sitter符号依赖图
   - 支持: Python/JS/TS/Go/Java/Rust/C++/...
   - 构建: 类→方法→变量→引用的完整依赖图
   - 用途: 跨文件重构时精确定位影响范围

2. RAG项目索引
   - 向量化: 所有代码文件+文档嵌入
   - 检索: 语义相似度搜索相关代码片段
   - 上下文: 自动注入相关文件到Agent上下文

3. 代码质量分析
   - LSP诊断: 语法错误+类型错误实时提示
   - 静态检查: ESLint/Pylint/Rustfmt集成
   - 复杂度: 圈复杂度+依赖深度分析
```

### Layer 4: 工具与沙箱层

```
隔离执行环境:
- Docker/MicroVM: 每个Agent在独立沙箱中运行
- 文件系统: 写时复制(COW)，原始文件不受影响
- 网络: 按需开放，默认隔离
- 系统调用: Seccomp过滤，禁止危险操作

工具清单:
├── 文件操作: read/write/copy/move/delete
├── 命令执行: shell/bash（在沙箱内）
├── 包管理: pip/npm/cargo/go mod
├── 测试运行: pytest/jest/go test
├── Git操作: commit/branch/merge/push
├── 数据库: SQLite/PostgreSQL临时实例
└── 浏览器: Playwright自动化测试
```

### Layer 5: 验证与反馈层

```
验证流程:
代码生成 → 语法检查(LSP) → 静态分析(ESLint/Pylint)
         → 单元测试运行 → 集成测试 → 性能基准测试
         → 安全扫描 → 代码审查报告 → 用户确认

反馈机制:
- 即时: LSP实时红线提示
- 快速: 测试结果<3秒返回
- 深度: 完整CI流程<30秒
- 学习: 错误模式记录 → 预防同类问题
```

## 三、与豆包现有AI编程的升级路径

```
现有: 对话式AI编程（文本输入→代码输出）
  ↓
Phase 1: 代码面板 + 文件树
        - 在豆包对话界面旁增加代码展示面板
        - 支持语法高亮+行号+复制
        - 文件树展示项目结构
  ↓
Phase 2: 终端嵌入 + 实时预览
        - 内嵌Web终端运行命令
        - HTML/网页实时预览
  ↓
Phase 3: 项目级理解 + 跨文件操作
        - Tree-sitter分析项目结构
        - 跨文件重构支持
        - Git集成
  ↓
Phase 4: 沙箱隔离 + 自动测试
        - 安全执行环境
        - 自动生成并运行测试
        - CI/CD集成
  ↓
Phase 5: 全功能AI IDE
        - 对标Codex+Antigravity
        - 完整五层架构
```

## 四、关键技术选型

| 组件 | 推荐方案 | 备选 |
|------|---------|------|
| 代码编辑器 | Monaco Editor (VS Code内核) | CodeMirror 6 |

| 终端模拟 | xterm.js | 原生WebView |
| 文件监听 | Chokidar (Node.js) | watchdog (Python) |
| 向量检索 | LanceDB | Chroma |
| LSP | language-server-protocol | 自定义 |
