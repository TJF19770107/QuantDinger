## 二、核心机制

### 2.1 任务路由（参考Hermes Gateway）

```
用户输入 → 主控Agent意图分类 → 路由规则
├── 代码类  → 编码Agent (+ 终端Agent + 文件Agent)
├── 搜索类  → 搜索Agent (+ 记忆Agent)
├── 操作类  → UI Agent (+ 安全Agent)
├── 复合类  → Planner拆解 → 多Agent并行 → 评估Agent汇总
└── 学习类  → GEPA引擎启动 → 技能沉淀
```

### 2.2 多Agent并行（参考Codex隔离工作树）

```
隔离机制:
- 每个子Agent在独立上下文中运行
- 文件操作先写临时工作树 → 评估通过后合并
- 无合并冲突设计（类似git worktree）
- 最大并行数: 6个子Agent（Codex已验证可行）

协同协议:
- 消息总线: Agent间通过标准化JSON消息通信
- 状态共享: 记忆Agent提供全局上下文
- 冲突解决: 评估Agent仲裁
```

### 2.3 评估与进化（参考Hermes GEPA）

```
Goal: 用户需求 → Planner拆解为原子任务
Execution: 子Agent池并行执行
Performance: 评估Agent多维度评分
  ├── 正确性: 结果是否符合预期
  ├── 效率: Token消耗/执行时间
  ├── 完整性: 是否覆盖所有子任务
  └── 用户反馈: 满意度指标
Adaptation: 评分 → 策略调整 → 技能沉淀 → 记忆更新
```

### 2.4 可视化面板（参考Marvis虚拟办公室）

```
Agent状态面板:
- 主控Agent: 🟢 调度中
- 规划Agent: 🟡 拆解任务中 (2/5)
- 编码Agent: 🟢 生成代码中 (app.py: 156行)
- 搜索Agent: ⚪ 空闲
- 评估Agent: ⚪ 等待结果
- 文件Agent: 🟢 写入中
```

## 四、与豆包APP现有架构的融合路径

```
现有: 豆包单线程对话模型
  ↓
Step 1: 在主对话模型内部增加意图路由器（透明升级）
  ↓
Step 2: 编码/搜索等高频场景启用专门子Agent
  ↓
Step 3: 复合任务自动启动Planner拆解
  ↓
Step 4: 全部子Agent就绪，进入全多Agent模式
```
