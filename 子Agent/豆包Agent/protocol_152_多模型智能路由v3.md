## 一、协议目标

构建企业级多模型智能路由层，实现Agent执行链中每一步任务的"最优模型自动匹配"，消除单一模型依赖瓶颈，将 **模型自由度得分从96提升至≥98**。

## 二、技术架构

### 2.1 模型金字塔（Model Pyramid）

```
┌─────────────────────────────────────────────┐
│  战略层 (Strategic): Claude Opus / GPT-5.4 Pro  │
│  → 复杂推理、深度规划、多步编排、创意生成        │
├─────────────────────────────────────────────┤
│  战术层 (Tactical): Claude Sonnet / GPT-4o      │
│  → 代码编写、工具调用、中等文本分析、格式转换     │
├─────────────────────────────────────────────┤
│  执行层 (Executor): Claude Haiku / GPT-5.4 Nano │
│  → 意图分类、实体提取、JSON格式化、条件判断      │
└─────────────────────────────────────────────┘
```

### 2.2 阶段分离路由（Stage-Separated Routing）

Agentic Loop 各阶段能力需求与模型匹配：

| 阶段 | 能力需求 | 路由模型 | 成本等级 |
|------|---------|---------|---------|
| 感知 (Perception) | 多模态理解/OCR | Gemini Flash / Haiku | $ |
| 规划 (Planning) | 强推理+指令跟随 | Opus / GPT-5.4 | $$$ |
| 工具选择 (Tool Select) | 工具调用精确 | Sonnet / GPT-4o | $$ |
| 执行 (Execution) | 视任务类型定 | 代码→专用Code模型 | $$ |
| 反思 (Reflection) | 质量评估 | Opus / GPT-5.4 | $$$ |

### 2.3 Router-R1 原生路由决策

路由决策本身作为一个CoT推理过程：

```
1. THINK → 分析任务复杂度、领域特征、输出要求
2. ROUTE → 选择最优专业模型执行
3. COLLECT → 收集响应，更新上下文
4. DECIDE → 判断是否需要更高级模型重试
```

### 2.4 置信度升级路由（Confidence-Based Escalation）

```
初始路由 → 低成本模型
   ↓
置信度<0.9 → 自动升级到更强模型
   ↓
最终模型仍低于阈值 → 多模型并行集成决策
```

### 2.5 成本感知预算

| 策略 | 描述 |
|------|------|
| Per-query预算上限 | 每查询最大token成本约束 |
| 95%任务走执行层 | 仅5%升级到战术层 |
| 0.5%走战略层 | 仅最复杂推理调用最强模型 |
| 成本节省目标 | 相比全量走Opus节省60-85% |

## 三、生产基础设施

### 3.1 路由平台选型

| 平台 | 策略 | 集成方式 |
|------|------|---------|
| LiteLLM | 自动分类+fallback链 | Proxy模式，多模型统一接口 |
| OpenRouter | 按cost/latency/质量 | floor model后缀 |
| OpenClaw原生 | 模型无关设计 | 运行时抽象层，分离workflow与模型选择 |

### 3.2 路由观测性

每条路由决策记录：
- query_hash / routed_model / router_confidence
- actual_latency_ms / quality_score (事后评估)
- cost_saved_vs_baseline
