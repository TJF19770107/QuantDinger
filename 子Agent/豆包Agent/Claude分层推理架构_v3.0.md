## 一、五层推理全链路

```
┌─────────────────────────────────────────────────────┐
│  用户输入 / 定时唤醒 / 事件触发                      │
└──────────────────┬──────────────────────────────────┘
                   ▼
  ┌──────────────────────────────────────┐
  │ Layer 1: 问题解析 (Problem Parsing)   │
  │ · 意图识别 · 实体提取 · 约束解析     │
  │ · 输入：自然语言 / 结构化指令        │
  │ · 输出：结构化任务对象               │
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │ Layer 2: 条件拆解 (Condition Decomp)  │
  │ · 前置条件枚举 · 分支路径展开        │
  │ · 输入：任务对象                     │
  │ · 输出：条件树 + 能力匹配表          │
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │ Layer 3: 逻辑推演 (Logic Reasoning)   │
  │ · 因果链推演 · 约束求解 · 风险预估   │
  │ · 输入：条件树                       │
  │ · 输出：推理路径DAG + 置信度评分      │
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │ Layer 4: 方案执行 (Plan Execution)    │
  │ · 工具调度 · Agent委派 · 并行编排    │
  │ · 输入：推理路径DAG                  │
  │ · 输出：执行日志 + 产物清单           │
  └──────────────────┬───────────────────┘
                     ▼
  ┌──────────────────────────────────────┐
  │ Layer 5: 结果复盘 (Outcome Review)    │
  │ · 期望vs实际对比 · 回溯修正          │
  │ · Rubric自评分 · 经验沉淀入库        │
  │ · 输入：执行日志 + 产物              │
  │ · 输出：复盘报告 + 进化增量           │
  └──────────────────────────────────────┘
```

## 二、各层详细设计

### Layer 1: 问题解析

| 组件 | 功能 | 实现策略 |
|------|------|---------|
| 意图分类器 | 识别任务域（文件/系统/App/搜索/编码） | 关键词匹配 + 上下文推断 + 模板五步法Step1 |
| 实体提取器 | 提取路径/文件名/App名/URL/时间/数量 | 正则 + NER + 上下文指代消解 |
| 约束解析器 | 安全约束/路径约束/时间约束/格式约束 | 规则引擎 + 安全护栏SafeGuard |
| 任务对象构造 | 组装标准TaskObject | JSON Schema标准化输出 |

**TaskObject Schema**:
```json
{
  "task_id": "uuid",
  "domain": "file|system|app|search|code",
  "intent": "create|read|update|delete|query|execute",
  "entities": {"paths":[], "apps":[], "keywords":[]},
  "constraints": {"security_level":"low|medium|high", "timeout":300},
  "context_refs": ["memory_id_xxx"],
  "priority": "P0|P1|P2"
}
```

### Layer 2: 条件拆解

| 组件 | 功能 | 实现策略 |
|------|------|---------|
| 前置条件枚举 | 列出所有需要满足的条件 | 知识库规则 + 历史经验池 |
| 分支路径展开 | 每个条件的true/false分支 | 决策树自动生成 |
| 能力匹配表 | 条件→所需Skill/Agent/工具映射 | 能力注册表查询 |
| 缺口识别 | 检测无匹配能力的条件 | GAP_BACKLOG自动登记 |

**条件树示例**:
```
任务: 写一份周报
├─ 条件1: 原始数据是否已存在?
│   ├─ TRUE → 读取已有数据文件
│   └─ FALSE → 需要收集数据 (缺口: 需用户提供或联网搜索)
├─ 条件2: 目标格式?
│   ├─ PDF → 需要PDF生成能力
│   ├─ DOCX → 需要Word生成能力
│   └─ MD → 直接使用write_file
└─ 条件3: 是否需要图表?
    ├─ TRUE → 需要可视化工具
    └─ FALSE → 纯文本即可
```

### Layer 3: 逻辑推演

| 组件 | 功能 | 实现策略 |
|------|------|---------|
| 因果链推演 | 步骤间依赖关系分析 | DAG拓扑排序 |
| 约束求解 | 路径合法性/安全等级/超时 | SafeGuard + 路径验证 |
| 风险预估 | 评估每步风险等级 | 三级风险定级(🔴🟡🟢) |
| 推理回溯 | 执行失败时回溯到上一个安全节点 | Checkpoint快照 + 分支回退 |
| 置信度评分 | 每步推理的确定性评级 | 0.0-1.0浮点 + 低置信度自动确认 |

**推理DAG**:
```
  [解析] → [读取数据] → [分析汇总] → [生成报告] → [保存]
                ↓(失败)
           [回溯: 请求用户提供数据]
```

### Layer 4: 方案执行

| 组件 | 功能 | 实现策略 |
|------|------|---------|
| 工具调度器 | 按DAG顺序调用工具 | dispatch_task / shell_executor / python_executor |
| Agent委派 | 跨域任务分发给Sub Agent | file-agent / computer-agent / app-agent / browser / search-agent |
| 并行编排 | 无依赖任务并行执行 | 同批最多5个并行调用 |
| 执行监控 | 实时状态跟踪 | 心跳检测 + 超时熔断 |
| 中间产物管理 | 临时文件写入temp目录 | 会话工作目录规范 |

**执行流控制**:
```
串行: A → B → C (有数据依赖)
并行: [A, B, C] (无依赖，同时发起)
条件: A → if result=X then B else C
循环: repeat A until condition_met (最多3次)
```

### Layer 5: 结果复盘

| 组件 | 功能 | 实现策略 |
|------|------|---------|
| 期望对比 | 任务目标 vs 实际产出 | 结构化diff |
| Rubric自评分 | 多维度自动评分 | 协议26 Rubric自纠正复盘 |
| 回溯修正 | 不达标则回溯重试 | 最多2次同类重试 |
| 经验沉淀 | 成功模式/失败模式入库 | 经验池持久记忆协议19 |
| 进化增量 | 生成Skill或更新规则 | SkillForge v3.0 自动萃取 |

**Rubric评分维度**:
| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 完成度 | 30% | 是否达成所有子目标 |
| 准确性 | 25% | 输出内容是否正确 |
| 效率 | 15% | 调用次数/耗时 |
| 安全性 | 20% | 是否触发安全护栏 |
| 可复用性 | 10% | 是否产出可复用Skill |

## 三、长上下文加载策略

### 3.1 分层加载

| 层级 | 内容 | 加载策略 |
|------|------|---------|
| L1 热缓存 | 当前会话上下文、最近5轮对话 | 始终加载 |
| L2 温缓存 | 当前任务相关文档、Skill定义 | 按需加载（memory_id） |
| L3 冷存储 | 历史迭代日志、经验池 | 关键词检索后加载 |

### 3.2 上下文窗口管理

| 策略 | 方法 |
|------|------|
| 压缩 | 历史轮次摘要压缩，保留关键决策点和产物路径 |
| 分片 | 大文件分段读取，配合offset+limit |
| 过期 | 超过24h的非关键对话自动归档到memory |
| 优先级 | 安全规则 > 技能定义 > 任务上下文 > 对话历史 |

## 四、推理回溯机制

### 4.1 回溯触发条件

| 条件 | 动作 |
|------|------|
| 工具调用失败 | 回溯到上一个安全节点，切换参数/路径/工具重新执行 |
| 结果不满足Rubric阈值(总分<60) | 回溯到Layer 3重新推演 |
| 用户否定/修正 | 继承agent_id继续上下文，修正方案后重新执行 |
| 安全护栏拦截 | 立即停止，通知用户并等待授权 |

### 4.2 Checkpoint快照

```
每完成一个Layer → 自动保存Checkpoint
执行失败 → 加载最近Checkpoint → 跳过失败步骤重试
最多回溯3次 → 第4次失败则降级为人工确认
```

## 五、工具联动推理

### 5.1 工具选择决策矩阵

| 任务特征 | 工具选择 | 推理依据 |
|---------|---------|---------|
| 文件操作 | file-agent | 涉及本地文件读写/搜索/整理 |
| 系统配置 | computer-agent | Windows系统设置/管理 |
| 应用操作 | app-agent | App安装/打开/操作 |
| 网页内容 | web_fetch / web_search | 无交互的网页抓取 |
| 网页交互 | browser | 需要登录/点击/多页跳转 |
| 深度搜索 | search-agent | 需要RAG总结的复杂搜索 |

### 5.2 降级链

```
专用Sub Agent → 专用Skill → 通用Tool → python/shell executor
```
