## 三、技术要点提炼

### 3.1 内置 Subagent 关键设计
| Agent | Model | Tools | 加载 CLAUDE.md? | 加载 Git Status? |
|-------|-------|-------|----------------|-----------------|
| **Explore** | Haiku | 只读 (Read/Grep/Glob) | ❌ | ❌ |
| **Plan** | 继承 | 只读 | ❌ | ❌ |
| **General-purpose** | 继承 | 全工具 | ✅ | ✅ |

**设计意图**：Explore 和 Plan 跳过项目配置，保持研究快速且成本低廉。

### 3.2 不可用于 Subagent 的内置工具
- `Agent`（防止无限嵌套）
- `AskUserQuestion`
- `EnterPlanMode`
- `ExitPlanMode`（除非子代理的 permissionMode 为 plan）
- `ScheduleWakeup`
- `WaitForMcpServers`

### 3.3 Plugin 子代理特殊限制（安全原因）
- ❌ 不支持 `hooks` frontmatter
- ❌ 不支持 `mcpServers` frontmatter
- ❌ 不支持 `permissionMode` frontmatter

**解决方案**：复制到 `.claude/agents/` 或 `~/.claude/agents/`

### 3.4 模型解析优先级（从高到低）
1. `CLAUDE_CODE_SUBAGENT_MODEL` 环境变量
2. 每次调用的 `model` 参数
3. Subagent 定义的 `model` frontmatter
4. 主对话的模型

3. **成本优化铁律**：能用 Haiku 不用 Sonnet，能用 Sonnet 不用 Opus
4. **从临时到固化**：对话式 → 自定义 → CLAUDE.md → Skills → Hooks
5. **文件交接机制**：管道工作流中，文件（非对话历史）作为阶段间交接物

### 4.3 反模式警示（新增）
| 场景 | 不要用 Subagent | 原因 | 替代方案 |
|------|----------------|------|---------|
| 简单单步任务 | ❌ | 开销超过任务本身 | 主对话直接执行 |
| 需要实时交互 | ❌ | 不能调用 AskUserQuestion | 主对话处理 |
| 强依赖共享上下文 | ❌ | 独立上下文导致信息割裂 | 保留在主对话 |
| 结果每次可预测 | ❌ | 隔离收益不大 | Skills 模板 |
| 跨代理状态持久 | ❌ | 完成后不保留状态 | Agent Teams + memory |
