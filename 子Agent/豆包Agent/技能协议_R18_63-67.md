## 协议63：GEPA运行时自进化闭环协议 v1.0

### 协议元数据

| 字段 | 内容 |
|------|------|
| **协议编号** | 63 |
| **协议名称** | GEPA运行时自进化闭环协议 v1.0 |
| **对标来源** | Hermes Agent v0.8.0 (Nous Research) |
| **情报触发** | 情报B — GEPA四阶段循环：Execute→Evaluate→Abstract→Refine |
| **核心机制** | 运行时四阶段自进化闭环 + 多目标帕累托优化 + 无人工干预技能自主重写 |
| **难度评估** | ⭐⭐⭐⭐（高）— 涉及遗传算法、帕累托前沿、多目标优化 |

### 协议内容

**四阶段循环**：

```
Execute（执行）：使用40+内置工具完成任务，记录完整执行轨迹
    ↓
Evaluate（评估）：分析任务完成质量
    - 显式反馈（用户评分/确认/拒绝）
    - 隐式接受信号（结果被引用/文件被打开/后续任务引用）
    ↓
Abstract（抽象）：将成功经验转为结构化Skill文档
    - Markdown格式存储于技能库
    - 包含：触发条件 / 执行步骤 / 工具调用序列 / 参数模板 / 注意事项
    ↓
Refine（精炼）：后续使用中持续优化Skill
    - 10-20次相似任务后执行速度提升2-3倍
    - 自主重写工具定义，无需人工干预
```

**多目标帕累托优化**：

| 目标维度 | 权重 | 约束条件 |
|---------|------|---------|
| 执行成功率 | 0.35 | ≥95% |
| 响应延迟 | 0.25 | ≤3s |
| Token效率 | 0.25 | Skill文档≤15KB |
| 用户满意度 | 0.15 | 语义不偏离原始意图 |

**遗传算子**：
- 交叉：合并两个Skill的优点（如A的触发条件 + B的执行步骤）
- 变异：随机扰动参数（温度/超时/重试次数 ±20%）
- 精英保留：每代保留Top-3不参与变异

**约束门控**（GEPA核心创新）：
- 测试100%通过才可发布
- Skill文档≤15KB防止膨胀
- 语义嵌入余弦相似度≥0.85防止偏离

### 落地路径

1. **Phase 1**：在自进化引擎v4.0中实现Execute→Evaluate基础循环（基于R17 DESIGNED方案）
2. **Phase 2**：集成Abstract模块，自动生成结构化Skill Markdown
3. **Phase 3**：实现Refine + 多目标帕累托优化器
4. **Phase 4**：接入治理审计追踪（GAP-053），防止Reward Hacking

### 与其他协议关系

- 协议28（SICA元Agent编程）→ GEPA替代SICA作为进化引擎
- 协议38（技能全生命周期管理）→ GEPA提供自动化Refine能力
- 协议41（协议化闭环自进化）→ GEPA提供运行时维度的补充

## 协议64：超图多层记忆引擎协议 v1.0

### 协议元数据

| 字段 | 内容 |
|------|------|
| **协议编号** | 64 |
| **协议名称** | 超图多层记忆引擎协议 v1.0 |
| **对标来源** | EverOS HyperMem (EverMind实验室, ACL 2026) |
| **情报触发** | 情报G — 三层超图：主题超边缘 + 事件超边缘 + 事实超边缘 |
| **核心机制** | 从线性向量存储升级为超图结构 + 自组织记忆OS + mRAG三模融合检索 |
| **难度评估** | ⭐⭐⭐⭐⭐（极高）— 涉及超图理论、自组织系统、多模态检索 |

### 协议内容

**三层超图结构**：

```
主题超边缘（Topic Hyperedge）
    ├── 连接相关主题节点（如"自进化"→"GEPA"→"记忆系统"→"技能协议"）
    ├── 权重基于共现频率 + 时间衰减
    └── 支持跨领域知识发现

事件超边缘（Event Hyperedge）
    ├── 连接同一任务/会话中的所有节点（文件/工具调用/Agent/结果）
    ├── 保留完整时间线和因果链
    └── 支持失败轨迹回溯和成功模式提取

事实超边缘（Fact Hyperedge）
    ├── 连接已验证的事实三元组（主体-关系-客体）
    ├── 带置信度评分
    └── 支持逻辑推理链
```

**mRAG三模融合检索器**：

| 模态 | 实现 | 适用场景 |
|------|------|---------|
| 稠密向量 | Embedding + 余弦相似度 | 语义相近的概念检索 |
| 稀疏关键字 | BM25 + TF-IDF | 精确术语/代码/ID匹配 |
| 多模态信号 | 时间戳/文件类型/来源Agent | 时序过滤 + 来源可信度加权 |

**自组织记忆OS (EverCore)**：
- 自动从任务执行历程提炼技能与模式
- 复杂任务成功率提升234.8%
- 支持跨会话无限期记忆与推理

### 落地路径

1. **Phase 1**：在MemoryOS v3.0基础上引入超图数据结构（节点+超边缘）
2. **Phase 2**：实现mRAG三模融合检索（稠密向量已就绪，增加稀疏+多模态信号）
3. **Phase 3**：集成自组织技能提炼（与协议63 GEPA Refine协同）
4. **Phase 4**：建立EverMemBench三层评估体系验证效果

### 与其他协议关系

- 协议14（分层记忆架构）→ 超图替代线性分层
- 协议44（无损层次记忆MemPalace）→ 超图提供图结构补充
- 协议63（GEPA自进化）→ 记忆引擎为进化提供经验基础

## 协议65：原生多Agent编排引擎协议 v1.0

| 字段 | 内容 |
|------|------|
| **协议编号** | 65 |
| **协议名称** | 原生多Agent编排引擎协议 v1.0 |
| **对标来源** | Gemini 2.5 Pro (Google I/O 2026) |
| **情报触发** | 情报D — 原生多Agent编排 + 200万Token上下文 + Vertex AI Agent Builder |
| **核心机制** | 任务自动分解→专项Agent实例化→中央编排器协调→结果合成，无需手动管理编排逻辑 |
| **难度评估** | ⭐⭐⭐⭐（高）— 涉及分布式Agent调度、状态持久化、Agent间通信协议 |

### 协议内容

**编排架构**：

```
用户任务
    ↓
中央编排器（Orchestrator）
    ├── 任务分析：识别子任务类型和依赖关系
    ├── Agent实例化：根据子任务类型创建对应专项Agent
    ├── 并行调度：无依赖子任务并行执行
    ├── 状态管理：持久化中间结果和Agent状态
    └── 结果合成：汇总子Agent输出→一致性校验→生成最终结果

专项Agent池：
    ├── 编码Agent（Codex模式）
    ├── 文件Agent（File Agent）
    ├── 搜索Agent（Search Agent）
    ├── 分析Agent（Analysis Agent）
    └── 执行Agent（Execution Agent）
```

**关键特性**：

| 特性 | 实现 |
|------|------|
| 任务分解 | 基于任务类型的自动DAG分解，识别并行/串行依赖 |
| Agent实例化 | 模板化Agent创建，共享系统提示词缓存（Fork优化） |
| 状态持久化 | 检查点快照 + 断点续传，Agent崩溃后自动恢复 |
| 通信协议 | 结构化结果对象 + 4种模式（同步/异步/广播/订阅） |
| 200万Token管理 | 上下文分层：核心上下文(50K) + 扩展上下文(200K) + 外部存储(无限) |

### 落地路径

1. **Phase 1**：在工作流引擎v3.0中实现基于DAG的任务自动分解
2. **Phase 2**：集成专项Agent模板化创建（对接豆包现有6大专项Agent）
3. **Phase 3**：实现状态持久化和断点续传
4. **Phase 4**：引入上下文分层管理，支持超长任务

## 协议66：MCP安全纵深防御协议 v1.0

### 协议元数据

| 字段 | 内容 |
|------|------|
| **协议编号** | 66 |
| **协议名称** | MCP安全纵深防御协议 v1.0 |
| **对标来源** | Hermes Agent v0.8.0 MCP安全层 |
| **情报触发** | 情报B — MCP OAuth 2.1 + 恶意软件扫描 + 凭证池轮换 |
| **核心机制** | 在MCP协议集成之上叠加三层安全防御：认证层(OAuth 2.1) + 扫描层(恶意检测) + 运营层(凭证管理) |
| **难度评估** | ⭐⭐⭐（中高）— OAuth 2.1为标准协议，恶意扫描和凭证池需自研 |

### 协议内容

**三层防御体系**：

```
第一层 — 认证层（MCP OAuth 2.1）
    ├── 标准OAuth 2.1授权码流程 + PKCE
    ├── MCP Server注册时强制OAuth认证
    ├── Token自动刷新 + 过期撤销
    └── 权限最小化：Server仅获取声明需要的scope

第二层 — 扫描层（恶意软件检测）
    ├── MCP插件安装前自动沙盒扫描
    ├── 静态分析：AST解析 + 危险API调用检测
    ├── 动态分析：沙盒执行 + 行为监控
    └── 社区信誉评分集成

第三层 — 运营层（凭证池轮换）
    ├── 多API Key负载均衡（防限速）
    ├── 自动轮换策略（定时/用量触发）
    ├── 异常检测：单一Key用量突增自动切换
    └── 凭证加密存储（AES-256-GCM）
```

**安全等级映射**：

| MCP操作 | 风险等级 | 防御措施 |
|---------|---------|---------|
| 读取资源 | 🟢 低 | OAuth认证 |
| 调用工具 | 🟡 中 | OAuth + 沙盒扫描 |
| 修改文件 | 🔴 高 | OAuth + 沙盒 + 用户确认 |
| 安装新Server | 🔴 高 | 全三层防御 + 用户确认 |

### 落地路径

1. **Phase 1**：在MCP桥接集成协议(协议17)基础上增加OAuth 2.1认证层
2. **Phase 2**：实现MCP插件安装前恶意扫描
3. **Phase 3**：构建凭证池轮换系统
4. **Phase 4**：集成到SafeGuard安全子系统作为MCP专属防御模块

### 与其他协议关系

- 协议17（MCP桥接集成协议）→ 本协议提供安全层补充

## 协议67：双记忆协同进化协议 v1.0

### 协议元数据

| 字段 | 内容 |
|------|------|
| **协议编号** | 67 |
| **协议名称** | 双记忆协同进化协议 v1.0 |
| **对标来源** | MIA框架 (中国教育新闻网 / DAIR.AI推荐) |
| **情报触发** | 情报F — 非参数记忆+参数记忆双向转化 + Manager-Planner-Executor + 交替强化学习 |
| **核心机制** | 将记忆系统与进化引擎打通：非参数记忆(经验)↔参数记忆(能力)双向转化，失败轨迹作为约束 |
| **难度评估** | ⭐⭐⭐⭐（高）— 涉及双记忆架构重构、交替强化学习、Planner-Executor对齐 |

### 协议内容

**双记忆架构**：

```
非参数记忆（经验沉淀）
    ├── 结构化经验库：任务轨迹→成功模式提取→失败轨迹标记
    ├── 三维检索：语义相似度 + 价值奖励 + 频率奖励
    ├── 存储形式：向量嵌入 + 结构化JSON元数据
    └── 作用：为Planner提供历史参考，为Executor提供操作模板

参数记忆（能力吸收）
    ├── Planner参数：在线RL更新，从经验中学习更好的规划策略
    ├── Executor参数：RL更新，学会更准确地执行Planner指令
    └── 作用：将经验内化为模型能力，实现"越用越聪明"
```

**双向转化机制**：

```
非参数 → 参数（内化）
    ├── 触发：某项经验被成功复用N次(N≥10)
    ├── 过程：提取经验模式→生成RL训练样本→微调Planner/Executor参数
    └── 效果：从"查经验"变为"本能反应"

参数 → 非参数（外化）
    ├── 触发：Planner生成新的、未被经验库覆盖的成功策略
    ├── 过程：轨迹压缩→结构化提取→存入非参数记忆
    └── 效果：新能力沉淀为可检索的经验
```

**Manager–Planner–Executor 三层结构**：

| 角色 | 职责 | 对应的豆包模块 |
|------|------|-------------|
| Manager | 记忆管理：三维检索 + 记忆更新 + 质量评估 | MemoryOS v3.0 |
| Planner | 策略规划：任务分解 + 经验注入 + Reflect-Replan | 龙虾五步法 Step 1-3 |
| Executor | 任务执行：按步骤执行 + 结果反馈 + 失败上报 | 子Agent体系 |

**Reflect–Replan 反馈闭环**：
- Executor执行受阻→上报失败轨迹
- Planner接收失败轨迹→Reflect分析原因→Replan生成替代方案
- 失败轨迹标记为约束→后续规划自动避开相同错误

**交替强化学习**：
- 阶段一：固定Planner，训练Executor学会理解并严格执行规划
- 阶段二：固定Executor，训练Planner生成更易执行的规划
- 测试时：两者持续在线学习，边做边进化

### 落地路径

1. **Phase 1**：解耦当前MemoryOS和自进化引擎，明确非参数/参数边界
2. **Phase 2**：实现非参数→参数内化管道（经验→训练样本→微调）
3. **Phase 3**：实现Manager-Planner-Executor三层结构
4. **Phase 4**：引入交替强化学习和Reflect-Replan闭环

### 与其他协议关系

- 协议63（GEPA自进化闭环）→ 双记忆为GEPA提供经验基础和参数化目标
- 协议64（超图记忆引擎）→ 非参数记忆底层存储升级为超图
