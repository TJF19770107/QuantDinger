## 一、五层架构

```
┌─────────────────────────────────────────┐
│          桌面超级应用 (SuperApp)          │
│  ChatGPT + Codex + Atlas 统一入口        │
├─────────────────────────────────────────┤
│          技能层 (Skills)                 │
│  SKILL.md 可复用工作流 · 上下文自动加载    │
├─────────────────────────────────────────┤
│         Hooks 引擎                       │
│  Pre-submit 审计 · PostToolUse 自动触发  │
├─────────────────────────────────────────┤
│        安全守护层                         │
│  Smart Approvals · Codex Security(Aardvark) │
├─────────────────────────────────────────┤
│        多代理执行层                       │
│  6个子代理并行 · 隔离git worktree         │
├─────────────────────────────────────────┤
│        模型路由层                         │
│  GPT-5.4(1M) / GPT-5.4-mini(30%) / Spark │
└─────────────────────────────────────────┘
```

## 二、模型双层路由

| 模型 | 上下文 | 定位 | 特色 |
|------|--------|------|------|
| GPT-5.4 | 100万token | 旗舰推理 | 跨大型代码库复杂任务 |
| GPT-5.4-mini | 同上 | 子代理专用 | 配额消耗仅旗舰30% |
| GPT-5.3-Codex-Spark | — | 实时协作 | Cerebras WSE-3, 1000+ token/s |

## 三、子代理角色模板

| 角色 | 权限 | 用途 |
|------|------|------|
| explorer | 只读 | 扫描代码库、搜索、分析 |
| worker | 读写 | 执行批量编码任务 |
| reviewer | 审查 | 运行测试、代码审查 |
| 自定义 | 自定义 | 测试分析员等专用角色 |

## 四、智能审批三级决策

```
Agent动作 → 守护代理审查 →
  ├─ 可信操作 → 静默批准
  ├─ 低风险操作 → 升级给用户确认
  └─ 高风险操作 → 直接拦截
```

## 五、可融合要点

1. **角色模板体系**：定义explorer(只读搜索)、worker(读写执行)、reviewer(审查测试)、architect(架构设计)
2. **三级审批逻辑**：可信→自动 / 低风险→确认 / 高危→拦截
3. **技能自动加载**：SKILL.md基于任务上下文自动匹配
4. **Hooks管道**：Pre-submit拦截无效请求，PostToolUse自动触发验证
5. **Computer Use**：跨应用操作扩展AI Agent的能力边界
