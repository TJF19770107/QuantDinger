## 三、R13 六大升级项

### 3.1 🔺 GUI-Tool 混合动作空间路径编排 (NEW)

> **对标来源**：ToolCUA (复旦大学 × 通义 MobileAgent)

**核心突破**：
- Computer Use Agent 从纯 GUI 操作升级为 GUI + Tool 混合动作空间
- 模型学习在正确时机在 GUI 和 Tool Call 之间切换——「路径编排」
- Tool-Efficient Path Reward：不是工具越多越好，而是用得合适+路径更短

**技术要点**：
- Interleaved GUI-Tool Trajectory Scaling Pipeline：从GUI轨迹合成~4k工具库
- Tool-Bootstrapped GUI RFT：离线SFT学习工具知识 + Single-turn RL校准切换点
- Online Agentic RL：真实环境长程rollout + group-relative path efficiency reward
- 关键指标：OSWorld-MCP 46.85% accuracy，ACS仅14.93步，TIR 24.32%

**豆包Agent映射**：
- 当前豆包 Agent 通过 computer-agent 执行桌面操作，应引入 Tool 层作为 GUI 操作的快速通道
- 对于结构化操作（表格/文件/设置），优先使用结构化 API/工具调用替代 GUI 导航序列
- 在 Agent 的 Plan 阶段注入 Tool-Efficient 路径偏好

---

### 3.2 🔺 MetaAgent-X 端到端RL多Agent进化 (NEW)

> **对标来源**：MetaAgent-X (Oregon State/UCSD/Amazon AGI/PSU)

**核心突破**：
- Designer + Executor 双层端到端RL训练：设计和执行同时进化
- Stagewise Co-evolution：交替30步阶段训练，避免同时训练的模型崩溃
- Executor-Designer Hierarchical Rollout (M=4, N=4)：多次执行平均评估设计质量
- 共享策略优于分离策略：设计者和执行者共享参数，知识双向流动

**实验结果**：
- Qwen3 8B: 六项平均38.33% (+11.17 pct vs 单智能体基线)
- 超过已有自动多Agent基线 MaAS (+6.11 pct)
- Designer根据任务难度自适应选择结构（reflection/single/ensemble）

**豆包Agent映射**：
- 豆包的双层元Agent解冻协议(协议48)与MetaAgent-X高度对齐
- 引入阶段式共同进化训练节奏，避免元Agent和执行Agent同时更新导致的崩溃
- 借鉴Hierarchical Rollout信用分配机制，稳定评估设计质量

**豆包Agent升级方向**：

- Goal Mode → 增强长时域Goal追踪协议(协议3)，加入自动核对与推进循环
