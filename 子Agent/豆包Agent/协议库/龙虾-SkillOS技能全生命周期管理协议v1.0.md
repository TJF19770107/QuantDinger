# 龙虾-SkillOS技能全生命周期管理协议 v1.0

> **协议编号**: 119 | **生效范围**: 全域 / 永久 / 永恒
> **版本**: v1.0 | **依赖**: 协议117 L3馆长引擎 + 协议118安全复盘 + 协议113知识图谱协同 + 协议115知识蒸馏v3
> **对标**: SkillOS范式 + Hermes Curator v0.12.0 + SkillX三层蒸馏 + SkillClaw集体演化 + SkillForge工业闭环 + ICLR 2026误进化

## 一、设计哲学

技能不是静态配置文件，而是活的、有生命周期的、可进化的实体。像操作系统管理进程一样，Agent管理自己的技能生命周期。

---

## 二、五态生命周期

```
  ┌─────────┐    使用    ┌─────────┐   30天未用   ┌──────────┐   60天未用   ┌───────────┐
  │  NEW    │ ────────→ │ ACTIVE  │ ───────────→ │ DORMANT  │ ───────────→ │ ARCHIVED  │
  │  新生   │           │  活跃   │              │  休眠    │              │  归档     │
  └─────────┘           └─────────┘              └──────────┘              └───────────┘
                             ↑                         │                        │
                             │      再次使用             │     外部引用触发        │
                             └─────────────────────────┘ ←──────────────────────┘
                                                        复活(REVIVE)
```

| 状态 | 定义 | 触发条件 | 读写权限 |
|------|------|---------|---------|
| NEW | 新创建，未使用 | 协议117 L1复盘生成 | 可读/可写/可删除 |
| ACTIVE | 正在使用 | 首次被Agent调用 | 可读/可(谨慎)写 |
| DORMANT | 进入休眠 | 30天未使用 | 只读/可复活 |
| ARCHIVED | 归档 | 60天未使用+Curator确认 | 只读/可手动恢复 |
| REVIVE | 复活 | 外部Agent引用 | 转回DORMANT→ACTIVE |

## 三、三层技能蒸馏（对标SkillX）

```
┌─────────────────────────────────┐
│  L3 战略计划 (Strategic Plan)    │ ← 高层策略模板
│  "先收集信息→制定方案→执行"       │
├─────────────────────────────────┤
│  L2 功能技能 (Functional Skill)  │ ← 可复用中层能力
│  "调用API" "解析JSON" "查搜索"   │
├─────────────────────────────────┤
│  L1 原子技能 (Atomic Skill)      │ ← 基础操作单元
│  "HTTP请求" "文件写入" "正则匹配"  │
└─────────────────────────────────┘
```

**跨层组合**：L3调用L2，L2组合L1。技能库可跨Agent、跨环境复用。

**跨Agent迁移**：强Agent(GPT-4级)产生的技能库可显著提升弱Agent(GPT-3.5级)的表现。交叉授粉机制。

## 四、伞状合并算法

当Curator检测到同一场景出现≥3个碎片化窄技能时，触发合并：

```
碎片A (pdf发票提取)  ─┐
碎片B (pdf合同提取)  ─┼→ 主技能 (PDF文档结构化提取)
碎片C (pdf表格提取)  ─┘   ├─ references/发票提取.md
                          ├─ references/合同提取.md
                          └─ references/表格提取.md
```

| 合并条件 | 阈值 |
|---------|------|
| 语义相似度 | >0.75 |
| 技能数量 | ≥3个碎片 |
| 场景重叠率 | >60% |
| 同域确认 | 同一功能域 |

## 五、7天自动策展周期

### 评分公式

```
Score = 模型评分×0.4 + 使用热度×0.3 + 场景覆盖率×0.3
```

| 模型评分(0.4) | 使用热度(0.3) | 场景覆盖率(0.3) |
|-------------|-------------|---------------|
| 技能描述清晰度 | 30天内调用次数 | 覆盖任务类型数 |
| 步骤完整性 | 成功率 | 复用频率 |
| 参数规范性 | Agent评分 | 跨Agent引用数 |

### 策展动作

| 分数范围 | 动作 |
|---------|------|
| ≥80 | 标记为"推荐"，排序优先 |
| 60-79 | 维持现状 |
| 30-59 | 标记"需优化"，下次优先合并 |
| <30 + 60天未用 | → ARCHIVED |
| 任意分 + pin标记 | 永久保护 |

### 保护机制

| 类型 | 策略 |
|------|------|
| pin固定 | 用户手动固定，永不归档 |
| bundled捆绑 | 系统核心技能，不可删除 |
| hub源 | 来自Hub的第三方技能，不可修改内容 |
| 协议级 | 协议库技能，Curator可评分但不可存档 |

## 六、跨Agent交叉授粉

对标 SkillClaw 双循环模型：

```
┌─────────────────┐     ┌─────────────────┐
│  File Agent     │     │  App Agent      │
│  模式识别经验    │ ←→  │  API设计决策     │
│  (文件操作)      │     │  (应用调用)      │
└─────────────────┘     └─────────────────┘
         ↘           ↙
    ┌──────────────────┐
    │  共享技能池       │
    │  SkillClaw协议    │
    └──────────────────┘
```

| 机制 | 实现 |
|------|------|
| 跨Agent技能发现 | 知识图谱协同(协议113)自动关联 |
| 技能质量共享 | 一个Agent验证过的技能，其他Agent直接信任 |
| 失败经验共享 | 一个人踩过的坑，其他人不必再踩 |
| 交叉验证 | 新技能需经≥2个Agent验证才入共享池 |
