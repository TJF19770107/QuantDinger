# 龙虾-三层自进化引擎协议 v1.0

> **协议编号**: 117 | **生效范围**: 全域 / 永久 / 永恒
> **版本**: v1.0 | **依赖**: Ouroboros v1.1 + SafeGuard v3.0 + MemoryOS v2.0 + 协议112集群进化 + 协议114全域自收敛
> **对标**: Hermes Curator v0.12.0三层架构 + 龙虾自进化闭环

---

## 一、设计哲学

三层解耦、双向联动、数据闭环。L1解决"经验有无沉淀"、L2解决"技能活性存续"、L3解决"技能质量优劣"。

---

## 二、三层架构

### L1 实时反思引擎

| 属性 | 值 |
|------|-----|
| 触发条件 | 脏计数器：工具迭代≥8次/会话 |
| 执行模式 | fork影子Agent异步复盘 |
| 复盘对象 | 全量对话交互、工具调用、问题排查、方案落地 |
| 产出物 | 技能、记忆、模板、参考资料 |
| 阻断条件 | Agent主动调skill_manage时自动重置计数器 |
| 超时 | 120秒无进展→放弃本轮复盘 |
| 计算成本 | 复用父进程缓存，降低Token消耗 |

**分类优先**：先判断内容类型（技能/记忆/模板/参考资料），再决定写入形式。

**偏向更新**：优先更新本次使用的已有技能，而非创建新技能。

### L2 延迟统计引擎

| 属性 | 值 |
|------|-----|
| 存储方式 | 边车文件（独立于技能正文）|
| 数据粒度 | 使用/查看/修改/复用，毫秒级埋点 |
| 状态流转 | 活跃(USED)→陈旧(STALE)→归档(ARCHIVED) |
| 活性判定 | 30天未使用→陈旧标记 |
| 复活条件 | 归档技能被外部引用→自动复活 |
| 数据驱动 | 规则驱动非LLM驱动，避免主观偏差 |

```yaml
状态机:
  NEW → ACTIVE: 首次使用
  ACTIVE → STALE: 30天未使用
  STALE → ARCHIVED: 60天未使用
  STALE → ACTIVE: 再次使用
  ARCHIVED → STALE: 外部引用触发
```

### L3 定期合并引擎（Curator馆长）

| 属性 | 值 |
|------|-----|
| 触发周期 | 7天自动执行 |
| 评分维度 | 模型评分(40%) + 使用热度(30%) + 场景覆盖率(30%) |
| 核心动作 | 评分→合并→清理 |
| 合并策略 | 伞状合并：碎片化窄技能→通用主技能 |
| 碎片去向 | 细分为主技能的子文档(references/) |
| 归档标准 | 综合分<30且60天无使用 |
| 保护机制 | pin固定/bundled受保护/hub源只读 |
| 输出报告 | curator_report.json + REPORT.md |

## 三、双向联动机制

```
正向链路: L1生成 → L2统计 → L3聚合优化
反向链路: L3回写L2状态 ↔ L2制约L3优先级 ↔ L2重置L1脏计数
```

| 联动 | 方向 | 机制 |
|------|------|------|
| 单向蒸馏 | L1→L2→L3 | 经验逐层结构化 |
| 回写修正 | L3→L2 | 合并操作同步更新使用数据 |
| 优先级约束 | L2→L3 | 热度数据决定合并优先级 |
| 触发重置 | L2→L1 | 主动技能操作重置复盘阈值 |

## 四、安全护栏

| 层级 | 措施 |
|------|------|
| L1 | 影子Agent六层舱壁隔离（见协议118） |
| L2 | 只读边车文件，无写权限 |
| L3 | 合并前dry-run预览，变更git打tag |
| 通用 | 所有操作可回滚可审计 |

## 六、性能指标

| 指标 | 目标值 |
|------|--------|
| 复盘延迟 | <5秒启动影子Agent |
| 复盘成功率 | >85%有效产出 |

| 冗余复盘避免率 | >90%（脏计数器+主动重置） |
