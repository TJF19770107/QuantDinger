## 二、豆包APP七维升级架构

### 2.1 维度一：思考架构 → 对标 Claude Code ReAct + Hermes 自学习 + Gemini 反思

```
当前豆包：用户输入 → LLM推理 → 文本回复（单轮线性）

升级后 - 三环思考架构：
┌─────────────────────────────────────┐
│         外环：反思循环 (Gemini)        │
│  知识缺口检测 → 追加搜索 → 来源验证     │
│  ┌───────────────────────────────┐   │
│  │    中环：规划执行 (Claude)      │   │
│  │  意图理解 → 任务拆解 → 工具调用  │   │
│  │  ┌─────────────────────────┐ │   │
│  │  │ 内环：自学习 (Hermes)    │ │   │
│  │  │ 执行轨迹分析 → 技能提取  │ │   │
│  │  │ → 经验固化 → 复用调用   │ │   │
│  │  └─────────────────────────┘ │   │
│  └───────────────────────────────┘   │
└─────────────────────────────────────┘
```

**实现方案**：
- 外环：每次复杂回答后自动触发"我是否完全回答了问题？还有哪些信息缺口？"反思
- 中环：对标 Claude Code ReAct 模式：Thought → Action → Observation → Response
- 内环：对标 Hermes Skill 自学习：多步骤操作完成后自动询问"是否保存为快捷技能？"

### 2.3 维度三：自主规划 → 对标 Marvis PM Agent + Hermes 任务拆解

```
规划架构：
用户输入 → PM Agent（对标Marvis主Agent）
              ├─ 意图分类器 → 识别任务类型(编码/搜索/文件/系统/对话)
              ├─ 复杂度评估器 → 决定单Agent/多Agent协作
              ├─ 任务拆解器 → 对标Claude Code plan mode
              ├─ 并行调度器 → 对标Codex 原生并行
              └─ 执行监控器 → 对标Hermes Agent迭代优化
```

**关键技术**：
- 意图分类：7类任务自动路由（编码/搜索/创作/分析/操作/问答/系统）
- 复杂度评分：1-10分，>5分自动启动plan mode先规划再执行
- 拆解粒度：对标 Marvis PM Agent "一个子任务一个专业Agent完成"
