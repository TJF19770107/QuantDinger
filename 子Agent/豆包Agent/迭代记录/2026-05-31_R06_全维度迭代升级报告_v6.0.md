## 二、检查点体系初始化

### 2.1 体系架构

```
豆包Agent/checkpoints/
├── stable_checkpoint.json            ← 当前稳定版本指针
│   {
│     "current_stable": "checkpoint_R06_20260531_033000",
│     "last_rollback": null,
│     "total_checkpoints": 1,
│     "total_rollbacks": 0
│   }
│
├── rollback_history.json             ← 回滚历史
│   {
│     "history": []
│   }
│
└── checkpoint_R06_20260531_033000.json  ← R06初始检查点
    {
      "checkpoint_id": "R06_20260531_033000",
      "status": "stable",
      "snapshot": { 全部文件MD5映射 },
      "diff_summary": "R06工程落地：6模块代码骨架+检查点体系+任务队列",
      "validation": { "smoke_test": "pending" },
      "rollback_cmd": "从快照还原文件"
    }
```

### 2.2 检查点触发规则

| 触发条件 | 检查点类型 | 保留策略 |
|---------|-----------|---------|
| 迭代开始时 | PRE_ITER | 保留最近5个 |
| 迭代成功 | STABLE | 保留最近3个 |
| 迭代失败 | FAILED | 保留最近5个 |
| 手动触发 | MANUAL | 永久保留 |
| 高危操作前 | PRECAUTION | 保留最近3个 |

### 2.3 回滚协议

```
1. 异常检测 → SafeGuard 自动识别
2. 定位stable_checkpoint → 上一稳定版本
3. 对比Diff → 确定变更范围
4. 用户确认 → 展示回滚清单
5. 执行回滚 → 文件逐项还原
6. 冒烟测试 → 验证核心功能
7. 记录日志 → rollback_history.json
```

### 3.2 PES任务拆分

每个任务采用 LoongFlow Plan-Execute-Summarize 范式：
- **Plan**: 分析依赖 → 拆分子任务 → 分配优先级 → 设置超时
- **Execute**: 无依赖并行 → 有依赖串行 → 实时监控 → 异常熔断
- **Summarize**: 聚合结果 → 提取模式 → SkillForge → MemoryOS
