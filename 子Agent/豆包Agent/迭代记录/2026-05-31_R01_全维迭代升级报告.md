### 3.2 P0 升级方案详情

#### P0-1: 多Agent协同框架
```
架构: 主控Agent → 规划Agent → 执行Agent池（编码/搜索/文件/UI/测试）
       ↑              ↓
    记忆Agent ←── 评估Agent

关键机制:
- Codex式隔离工作树：每个子Agent在独立沙箱中运行
- Hermes式Gateway路由：统一消息入口，分发到对应Agent
- Marvis式可视化：Agent状态面板，实时查看各Agent工作进度
```

#### P0-2: AI IDE完整功能
```
五层架构映射到豆包APP:
L1 用户交互层: 豆包对话界面 → 升级为多面板IDE布局（对话+代码+预览+终端）
L2 Agent编排层: 任务拆解→Agent调度→结果整合
L3 静态分析层: Tree-sitter符号依赖图 + RAG项目索引
L4 工具与沙箱层: 隔离执行环境 + 文件操作 + 命令执行
L5 验证与反馈层: 测试运行 + LSP诊断 + 代码审查

里程碑:
Phase 1: 代码面板 + 文件树 + 终端嵌入
Phase 2: 项目级理解 + 跨文件重构
Phase 3: 沙箱隔离执行 + 自动测试
Phase 4: 多Agent并行编码 + Git集成
```

### 3.3 P1 升级方案详情

#### P1-1: GEPA自进化闭环
```
Goal（目标）: 用户需求解析 + 任务建模
Execution（执行）: 多Agent并行 + 工具调用链
Performance（评估）: 结果验证 + 用户反馈 + 自动评分
Adaptation（适应）: 技能沉淀 + 策略优化 + 记忆更新

循环周期: 每轮任务 → 即时评估 → 技能库更新
```

#### P1-2: 工具调用增强
```
- 统一Tool Gateway（参考Hermes）：web_search / code_exec / file_ops / browser / image_gen / tts / asr
- Claude式推理强度可调：用户可选择"快速/标准/深度/xhigh"
- Prompt Caching：高频System Prompt缓存，降低80-90%成本
```
