### 1.2 关键发现

1. **Harness框架与模型同等重要**：Claude Code 的实际表现由七层配置质量决定，其影响超过模型本身
2. **从简单开始逐步演进**：绝大多数用例从 Orchestrator-Subagent 起步即可，无需过早引入复杂模式
3. **渐进式披露是核心设计哲学**：Skills 通过 description 匹配按需加载，避免上下文膨胀
4. **Hooks 执行率 100% vs Prompt 遵从率 20%**：确定性检查必须用 Hooks，不能依赖 Prompt
5. **CLAUDE.md 应 ≤200行**：超过后 Claude 开始忽略一半内容，重要规则淹没在噪声中
6. **Agent Manager 是新兴角色**：混合 PM 和工程师职能，专门管理 Claude Code 生态

### 1.3 15条核心实践提炼

| # | 原则 | 关键洞察 |
|---|------|---------|
| 1 | 从简单开始逐步演进 | Orchestrator-Subagent → 观察痛点 → 定向演进 |
| 2 | 探索与编辑分离 | 只读Subagent搜索 + 主Agent编辑 |
| 3 | 渐进式披露 | 不把所有知识常驻上下文 |
| 4 | 上下文即资产 | CLAUDE.md ≤200行，分层管理 |
| 5 | Hooks > Prompts | 确定性检查用脚本而非自然语言指令 |
| 6 | Plugin化分发 | 好配置打包为可安装单元 |
| 7 | 子目录初始化 | 作用域限定，减少噪声 |
| 8 | 权限最小化 | 每个Agent只授予必需权限 |
| 9 | 独立上下文窗口 | Subagent不污染主会话 |
| 10 | 设计终止条件 | 自主Agent必须有限制 |
| 11 | 模型进化同步配置 | 每3-6月审查，移除过时规则 |
| 12 | LSP精准导航 | 符号级追踪优于文本grep |
| 13 | 可组合可移植 | Skills跨平台统一运行 |
| 14 | 信息不中转多轮 | 关键细节经Orchestrator多轮传递后丢失 |
| 15 | 分配责任人 | 设立Agent Manager角色 |
