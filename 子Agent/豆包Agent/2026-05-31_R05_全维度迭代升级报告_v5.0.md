### 1. Claude Code 50万行源码 · 五层工程护城河（核心勒索）

**源**：2026-03-31 源码泄露事件 + arXiv 系统分析论文

**核心发现**：Claude Code 的 while-loop 只有 20 行代码，但 50 万行 TypeScript 构建了五大护城河：

#### 1.1 七级权限系统

| 层级 | 机制 | 触发条件 |
|------|------|----------|
| L1 Always Allow | 只读操作默认放行 | read / search / list |
| L2 Auto Allow | 白名单写操作 | git commit / lint |
| L3 ML Classifier Gate | 训练分类器判断危险度 | 非白名单命令 |
| L4 Per-Session Allow | 会话内授权记忆 | 用户曾允许 |
| L5 Explicit Confirm | 高危强制确认 | rm -rf / 网络请求 |
| L6 Directory Scoped | 目录边界超限拦截 | 越界文件访问 |
| L7 Global Deny | 硬编码全局禁止 | 永不允许 |

**ML 分类器核心**：轻量模型，输入 = bash命令+上下文，输出 = 风险分。训练数据来自真实用户日志的反向标注。

**豆包对标**：SafeGuard 现有的三环护栏（用户授权→命令审批→沙箱隔离）可以升级为七层体系。**本轮的 AutoAllow + MLClassifier + DirectoryScoped 为 R05 新增。**

#### 1.2 五层上下文压缩管线

| 层级 | 机制 | 压缩率 |
|------|------|--------|
| L1 Tool Output Truncation | 工具输出超阈值→头尾+摘要 | 60-80% |
| L2 Message Pruning | 最近N条完整 + 早期只留标题 | 30-50% |
| L3 Conversation Summary | 每N轮生成摘要替换历史 | 70-90% |
| L4 Context Window Sliding | token 接近上限→滑动裁剪 | 边界保护 |
| L5 Semantic Dedup | 语义相似调用去重 | 10-20% |

**关键洞察**：不是所有历史信息权重相等。用户原始需求、最近操作结果、报错信息 = 高权重。中间工具调用结果 = 可压缩。

**豆包对标**：MemoryOS 三层压缩（即时摘要→语义索引→知识图谱）可升级为五层管线。L4+L5 为本轮新增观察。

#### 1.3 四种扩展机制

```
MCP (外部工具协议) → Skills (项目知识注入) → Hooks (生命周期钩子) → Plugins (实验性自定义)
```

**Hooks 亮点**：afterToolCall / onSessionEnd 等生命周期钩子，可插入自定义逻辑。

**豆包对标**：已有 MCP 协议集成 + Skill 生态，缺少 Hooks 机制。**本轮确认为 GAP-007。**

#### 1.4 Git Worktree 子代理编排

每个子代理在独立 worktree 工作 → 互不干扰 → 主代理审查 diff → 合并成功 / 丢弃失败。

**豆包对标**：当前多 Agent 通过 dispatch_task 串行/并行派发，可通过 worktree 实现文件级别隔离。**本轮确认为 GAP-008。**

#### 1.5 技术栈亮点

- Runtime: **Bun**（启动速度 + TS 原生支持）
- UI: **React + Ink**（终端里用 React 渲染）
- 状态管理: **Zustand-like Store**
- Schema: **Zod**

**豆包对标**：桌面端可参考 Ink 类终端 UI 方案。

### 2. Hermes Agent v0.15.1 · 自学习 Skill 机制（核心升级点）

**源**：CSDN 实测 + Nous Research 官方文档

**里程碑**：Hermes 以 6:5 在 11 项 CLI 基准测试中击败 Codex，GitHub 10.1 万 Star。

#### 2.1 核心能力

| 特性 | 详情 |
|------|------|
| 自学习闭环 | 完成复杂任务→自动生成Skill→下次复用 |
| 跨会话记忆 | SQLite + FTS5 全文检索，历史永不丢失 |
| 40+ 内置工具 | 网页搜索、文件操作、终端、代码执行 |
| 15+ 平台接入 | CLI/Telegram/Discord/Slack/WhatsApp |
| 6 种运行后端 | 本地/Docker/SSH/Daytona/Singularity/Modal |
| 200+ 模型支持 | 任意 OpenAI 兼容端点 |
| 硬件需求 | **6GB 显卡可跑**（Q4_K_M 量化） |

#### 2.2 Skill 自学习流程

```
用户发出复杂任务
  → Hermes 执行多步骤序列
  → 检测到复杂任务序列（≥5步）
  → 询问用户是否保存为Skill
  → 生成 .md Skill 文件 → ~/.hermes/skills/
  → 下次同类任务自动调用
  → 多次调用后分析成功率 → 自动优化执行步骤
```

**实测数据**：重复任务时间减少 40%（TokenMix.ai benchmark）。

#### 2.3 Skill 进化机制

- 同一 Skill 被多次调用 → Agent 分析成功率
- 自动优化 Skill 执行步骤
- 社区证实：**技能越多，加载越快，Token 消耗反而下降**

**豆包对标**：SkillForge 技能已落地此机制基础版。升级方向：
- ⬆ 成功率跟踪 + 自动优化（R05 新增）
- ⬆ FTS5 全文检索替代文件扫描（R05 新增）
- ⬆ Skill 性能降级检测 + 自动下架（R05 新增）
