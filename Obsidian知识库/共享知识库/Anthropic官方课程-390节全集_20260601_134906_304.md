## 七、子代理（Subagents）专题 — Anthropic 核心方法论提炼

### 7.1 子代理定义

子代理是把整体任务拆成能独立运行的小单元，适用于：
- 并行处理场景
- 上下文窗口受限场景
- 需要专业化处理的子任务

**核心区别**：

| | 主代理 (Main Agent) | 子代理 (Subagent) |
|------|------|------|
| 职责 | 统筹调度、复杂逻辑 | 短时、明确输入输出工作 |
| 上下文 | 完整对话上下文 | 独立上下文窗口（隔离） |
| 输出 | 最终结果聚合 | 仅返回摘要/摘录 |
| 复用性 | 任务级 | Spec 级（可复用的 spec 模板） |

### 7.2 子代理 Spec 设计模板

```
输入字段：项目名 / 目标平台 / 字数上限 / 风格约束
输出要求：JSON 格式（含 title / intro / steps）
失败返回：{"error": "描述"}
超时策略：30s
重试阈值：3次
```

### 7.3 子代理五级范围体系

| 优先级 | 范围 | 路径 | 用途 |
|--------|------|------|------|
| 1 (最高) | Managed | 组织部署 | 全组织统一 Subagent |
| 2 | CLI Flag | `--agents` JSON | 当前会话临时定义 |
| 3 | Project | `.claude/agents/` | 项目级共享 Subagent |
| 4 | User | `~/.claude/agents/` | 个人跨项目 Subagent |
| 5 (最低) | Plugin | Plugin `agents/` 目录 | 第三方 Subagent 分发 |

### 7.4 子代理并行执行模式

```
主代理分解任务
    ├── Subagent A：搜索关键词 X → 返回相关摘录
    ├── Subagent B：搜索关键词 Y → 返回相关摘录
    ├── Subagent C：搜索关键词 Z → 返回相关摘录
    └── Subagent D：代码生成任务 → 返回代码片段

主代理收集结果 → 去冲突 → 合并 → 统一输出
```

### 7.5 常见问题与应对

| 问题 | 应对策略 |
|------|---------|
| 空响应 | 增加重试、检查输入格式 |
| 输出格式错位 | spec 中强制 JSON 模式、加入示例 |
| 并行结果冲突 | 优先级规则或合并模板调和 |
| 超时 | 设置合理超时阈值、降级方案 |

## 八、多 Agent 协作最佳实践（Anthropic 验证）

### 8.1 Agent Teams 四种模式

| 模式 | 描述 | 适用场景 |
|------|------|---------|
| **Orchestrator-Worker** | 一个主 Agent 调度多个 Worker | 龙虾当前模式 |
| **Peer-to-Peer** | Agent 之间平等通信 | 同等能力 Agent 协同 |
| **Hierarchical** | 多层 Agent 树状结构 | 大规模复杂任务 |
| **Dynamic Re-planning** | 根据执行反馈动态重组 | 不确定性高的任务 |

### 8.2 Agent Loop 标准循环

```
Gather Context ──→ Take Action
      ↑                │
      │                ▼
      └────── Verify Work

工具链：
- Agentic Search + File System
- Semantic Search（按需）
- Subagents（并行化 + 上下文隔离）
- Compaction（自动上下文压缩）
```

### 8.3 验证三策略

| 策略 | 适用场景 | 可靠性 | 延迟 |
|------|---------|--------|------|
| Rules-based (Linting) | 代码/格式/规则校验 | 高 | 低 |
| Visual Feedback (Screenshot) | UI生成/视觉任务 | 中 | 中 |
| LLM-as-Judge | 模糊规则/语气/风格 | 低 | 高 |

## 九、Claude Agent SDK 核心设计原则

### 9.1 "给 Claude 一台电脑" 哲学

Agent 拥有与人类相同的计算机访问权限（终端、文件系统、Bash），像人类程序员一样工作——不仅能编码，还能进行深度研究、视频创作、笔记整理等非编码任务。

### 9.2 工具设计四原则

| 原则 | 说明 |
|------|------|
| **主要动作** | 工具是 Agent 上下文中最突出的元素，应设计为"主要动作" |
| **代码优先** | 代码是精确、可组合、无限复用的 Agent 输出 |
| **Bash 兜底** | Bash 作为通用工具，处理专用工具未覆盖的场景 |
| **MCP 标准化** | 外部服务集成走 MCP 协议，避免自定义集成代码 |

### 9.3 Compaction 策略

| 机制 | 触发条件 | 行为 |
|------|---------|------|
| Compact | 接近 Context Limit | 自动摘要压缩历史消息 |
| Subagent Isolation | 大量信息筛选 | 独立 Context Window，仅返回摘要 |
| Agentic Search | 大文件处理 | grep/tail 逐步加载，非全量读入 |
