## 一、文章主题

**通过 Codex CLI（及同类 AI Agent 工具）用自然语言对话直接操作飞书**，实现消息、文档、日历、多维表格、任务、知识库、邮箱等全业务域的自动化操作。

飞书官方开源了 `lark-cli` 命令行工具（MIT协议），专门为 AI Agent 设计。用户只需完成一次安装和授权，之后即可用自然语言向AI下达飞书操作指令。

## 二、核心要点提炼

### 2.1 飞书CLI是什么

- **定位**：飞书开放平台官方命令行工具，Go 语言编写，MIT 协议开源
- **目标用户**：使用 Claude Code / Codex / Cursor / Trae / Windsurf 等 AI Agent 工具的用户
- **核心价值**：让 AI 代理你操作飞书——一句话总结昨日工作、整理群聊消息、批量更新多维表格数据
- **开源地址**：https://github.com/larksuite/cli

### 2.2 为什么需要它

- 此前 AI 操作飞书依赖非官方插件或自定义 Skills，能力碎片化、维护成本高
- 飞书官方 CLI 一次性覆盖消息/文档/日历/邮件/任务/知识库/多维表格/通讯录/云空间/视频会议/搜索12大业务域
- 支持用户身份与应用身份两种模式，可直接集成进自定义 AI Agent

### 2.3 安装四步法

| 步骤 | 命令 | 说明 |
|------|------|------|
| 1 | `npm install -g @larksuite/cli` | 全局安装CLI |
| 2 | `npx skills add https://github.com/larksuite/cli -y -g` | 注册Skills |
| 3 | `lark-cli config init --new` | 初始化应用配置 |
| 4 | `lark-cli auth login --recommend` | 用户授权 |

### 2.4 授权流程关键点

- 第3步和第4步各输出一个授权链接，需在浏览器中打开、飞书扫码、同意授权
- 建议选择"仅个人使用"以避免权限过大
- 授权完成后需重启 AI Agent 工具确保 Skills 完整加载

### 2.5 Skill 体系

飞书CLI 通过 Skills 机制集成到 Codex 等 AI Agent 中：

- **自动安装**：`npx skills add` 命令将飞书 CLI 注册为一组 Skills
- **自动触发**：Agent 根据用户自然语言描述自动匹配并调用对应 Skill
- **手动干预**：用户可通过 `$skill-name` 精确指定使用哪个 Skill
- **自定义扩展**：用户可创建自己的飞书操作 Skill（如周报生成器、会议安排器）

## 三、可复用的SOP模板

### 3.1 标准安装SOP

```
1. 确认环境：Node.js >= 16, Codex 已安装
2. 终端执行：npm install -g @larksuite/cli
3. 终端执行：npx skills add https://github.com/larksuite/cli -y -g
4. 终端执行：lark-cli config init --new → 浏览器扫码授权
5. 终端执行：lark-cli auth login --recommend → 浏览器扫码授权
6. 验证：lark-cli --version && lark-cli auth status
7. 重启 Codex 终端
8. 测试：在 Codex 中输入"帮我在飞书文档里创建一个测试文档"
```

### 3.2 日常操作SOP

```
1. 打开 Codex 终端
2. 用自然语言描述你要做的飞书操作，例如：
   - "帮我在飞书查一下明后两天的日程"
   - "帮我在飞书「项目组」群发一条消息"
   - "帮我在飞书多维表格更新所有待办状态"
3. Codex 自动识别意图 → 调用飞书CLI Skill → 返回结果
```

### 3.3 Skill创建SOP

```
1. 在 Codex 中输入：$skill-creator
2. 按提示输入：
   - Skill名称：描述性名称（如 feishu-weekly-report）
   - 触发描述：什么情况下自动激活
   - 执行指令：具体调用哪些 lark-cli 命令
3. 重启 Codex
4. 测试：用自然语言触发刚创建的 Skill
```

## 四、关键命令速查表

### 4.1 安装与配置

| 命令 | 用途 |
|------|------|
| `npm install -g @larksuite/cli` | 安装飞书CLI |

| `lark-cli --version` | 查看版本 |
| `lark-cli auth status` | 查看授权状态 |

### 4.2 业务操作速查

| 业务域 | 核心能力 | 典型自然语言指令 |
|--------|---------|----------------|

| 云文档 | 创建/读取/更新/评论 | "帮我在飞书写一份周报" |
| 云空间 | 上传/下载/权限管理 | "把这个文件上传到飞书云空间" |
| 电子表格 | 创建/读写/批量更新 | "帮我在飞书表格填数据" |
| 多维表格 | 表/字段/记录/视图/仪表盘 | "更新多维表格所有待办状态" |
| 日历 | 查询/创建/忙闲/推荐时间 | "帮我查一下明天下午有没有空" |
| 视频会议 | 搜索/纪要/逐字稿 | "帮我找上次产品评审的会议纪要" |
| 邮箱 | 搜索/读取/起草/发送/归档 | "帮我查收件箱最新3封未读邮件" |
| 任务 | 创建/更新/清单管理 | "帮我创建一个Q2复盘任务" |
| 知识库 | 查询空间/节点/文档层级 | "帮我在知识库搜OKR指南" |
| 通讯录 | 查用户/搜同事/看部门 | "帮我找一下张三的直属上级" |
| 搜索 | 跨域搜索 | "帮我搜飞书里所有关于AI Agent的文档" |

### 4.3 Codex Skill 管理

| 命令/操作 | 用途 |
|-----------|------|
| `/skills` 或 `$` | 查看已安装Skills列表 |
| `$skill-creator` | 进入Skill Creator创建新Skill |
| `npx skills add <仓库地址>` | 安装新Skill |
| 编辑 `~/.codex/config.toml` | 禁用/启用指定Skill |
| 重启 `codex` | 使Skills变更生效 |

## 五、与龙虾AI主控中心的集成建议

### 5.1 战略定位

飞书CLI作为龙虾AI主控中心的**飞书接入标准通道**，取代此前碎片化的飞书操作Skills，实现统一的飞书操作能力层。

### 5.2 分阶段集成路线

| 阶段 | 动作 | 产出 |
|------|------|------|
| **Phase 1** | 在子Agent中完成飞书CLI安装与基础验证 | 安装确认报告 |
| **Phase 2** | 消息/文档核心能力接入，替代现有 feishu-send 等自定义 Skill | 统一飞书操作通道 |
| **Phase 3** | 日历/任务/多维表格能力接入 | 全域飞书覆盖 |
| **Phase 4** | 知识库/邮件/通讯录接入 | 全业务域闭环 |

### 5.3 对标矩阵赋能

| 维度 | 赋能方向 | 预期提升 |
|------|---------|---------|
| 工具调用 | 通过飞书CLI扩展飞书12域操作能力 | +2 |
| 跨平台 | 飞书作为跨团队协作平台深度接入 | +1 |
| Skills生态 | 飞书CLI Skills与龙虾技能库双向桥接 | +1 |

### 5.4 关键注意事项

1. **授权模式**：子Agent建议使用应用身份模式（App ID + App Secret），避免依赖个人用户授权
2. **凭证管理**：App Secret 纳入龙虾安全体系（SafeGuard v3.0）统一管理，禁止明文存储
3. **错误降级**：飞书CLI调用失败时，需触发龙虾自愈回滚协议（协议#24），自动重试或降级到备用通道
4. **审计追溯**：所有飞书操作纳入龙虾操作审计链，与桌面Agent协议（协议#23）审计日志打通
