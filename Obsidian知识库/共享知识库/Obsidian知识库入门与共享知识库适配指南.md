## 二、基础改造（立即执行，15 分钟完成）

### 2.1 建立目录结构（PARA + MOC）

在共享知识库根目录下创建以下子目录：

```
共享知识库/
├── 0-Inbox/            ← 新采集内容的临时入口
├── 1-AI-Agent/         ← AI Agent 生态所有笔记
├── 2-协议与架构/        ← MCP/协议/架构设计
├── 3-工具与平台/        ← 具体工具平台（Marvis/OpenClaw/本地部署）
├── 4-业务场景/          ← 量化交易/网文创作/营收方案
├── 5-知识管理/          ← Obsidian 使用技巧/公众号订阅等方法论
├── 6-MOC/              ← 各主题的 Map of Content 索引笔记
├── 7-执行报告/          ← 龙虾五步法报告/校验报告
└── 8-归档/             ← 已过时但保留的笔记
```

**操作步骤**：
1. 在 Obsidian 左侧文件列表中，右键空白处 → "新建文件夹"，逐个创建上述 9 个文件夹
2. 将现有 18 个 .md 文件拖入对应文件夹（按主题分类）

### 2.2 统一文件命名规范

**新规则（立即执行）**：


示例：
- `2026-05-29_AI-Agent生态全景_知识库.md`
- `2026-05-28_三源模板校验_执行报告.md`

**旧文件需要重命名**：

## 三、核心功能启用（30 分钟完成）

### 3.1 给每篇笔记添加 YAML Frontmatter

在每篇 .md 文件开头插入以下元数据块。以 `AI智能体与生产力工具链` 为例：

```yaml
---
title: AI智能体与生产力工具链全景
date: 2026-05-29
tags:
  - AI-Agent
  - 生产力工具
  - 生态全景
category: 4-业务场景
source: 多源聚合
status: 活跃
---
```

**操作步骤**：
1. 打开笔记，在文件最开头（第一行之前）输入 `---` 并回车
2. 按上面格式填写元数据，注意 `tags` 使用 YAML 列表格式（每行 `  - tag名`）
3. 末尾再输入 `---` 并回车
4. 对 18 个文件全部执行此操作

**标签体系建议**（统一标签分类）：

| 标签 | 用途 |
|------|------|
| `#AI-Agent` | AI Agent 生态相关 |
| `#MCP` | 模型上下文协议 |
| `#本地部署` | 本地大模型/量化技术 |
| `#工具` | 具体工具平台 |
| `#业务` | 营收/商业化场景 |
| `#知识管理` | 知识库方法论 |
| `#报告` | 执行报告/校验报告 |
| `#待归档` | 标记即将归档的内容 |

### 3.2 建立双向链接网络

在笔记正文中，用 `[[笔记名]]` 链接到相关笔记。

**示例**：在 `AI智能体与生产力工具链` 中插入：

```markdown
## 相关笔记
- 核心协议：[[2026-05-28_AI-Agent-MCP多智能体_知识库]]
- 具体平台：[[2026-05-28_腾讯Marvis系统级AI助手_知识库]]
- 本地部署：[[2026-05-28_本地大模型部署与量化技术_知识库]]
- 业务场景：[[2026-05-28_量化交易与营收业务技术方案_知识库]]
```

操作步骤：
1. 在笔记末尾添加 `## 相关笔记` 章节
2. 输入 `[[`，Obsidian 会自动弹出文件列表供选择
3. 选择相关笔记，完成链接创建
4. 打开被链接的笔记，右侧"反向链接"面板会自动显示谁链接了它

### 4.2 必装插件推荐（按优先级）

| 优先级 | 插件 | 用途 | 对你当前库的价值 |
|--------|------|------|-----------------|
| ★★★★★ | **Dataview** | 把库当数据库查询 | 自动汇总所有标签、按日期排序展示、生成动态目录 |
| ★★★★★ | **Templater** | 高级模板引擎 | 一键生成标准化知识库笔记（带 frontmatter + 来源区块） |
| ★★★★ | **Tag Wrangler** | 批量管理标签 | 清理/合并混乱标签，统一标签体系 |
| ★★★★ | **Linter** | 自动格式化 | 统一 frontmatter 格式、空行、标题层级 |
| ★★★ | **Calendar** | 日历视图 | 按日期浏览笔记，适合日报/执行报告 |
| ★★★ | **Obsidian Git** | Git 版本控制 | 知识库版本历史 + 备份，匹配龙虾迭代规则 |
| ★★ | **Kanban** | 看板视图 | 管理知识库建设任务（补 frontmatter、建链接等） |
| ★★ | **Excalidraw** | 手绘图表 | 画 Agent 架构图、协议流程图 |

**安装步骤**：
1. 设置 → 第三方插件 → 关闭安全模式
2. 点击"浏览" → 搜索插件名 → 安装 → 启用

### 4.3 Dataview 实用查询（针对你的库）

安装 Dataview 后，创建 `6-MOC/数据仪表盘.md`，粘贴以下查询块：

**查询 1：所有知识库笔记按日期排列**
```dataview
TABLE date, tags, category
FROM "1-AI-Agent" OR "2-协议与架构" OR "3-工具与平台" OR "4-业务场景"
SORT date DESC
```

**查询 2：统计标签使用频率**
```dataview
LIST
FROM ""
FLATTEN file.tags AS tag
GROUP BY tag
SORT rows.length DESC
```

**查询 3：待归档笔记**
```dataview
LIST
FROM ""
WHERE contains(tags, "待归档")
```

**查询 4：孤岛笔记（零链接笔记）**
```dataview
LIST
FROM ""
WHERE length(file.inlinks) = 0 AND length(file.outlinks) = 0
```

## 五、适配龙虾全域模板的维护 SOP

### 5.1 新知识入库流程

```
外部内容（B站/GitHub/公众号）
    ↓ Marvis Agent 采集
生成 _知识库.md 文件
    ↓ 存入 0-Inbox/
人工/Agent 审核
    ↓ 补全 frontmatter + 标签 + [[]]链接
移入对应分类目录
    ↓ 更新相关 MOC 笔记
Dataview 自动索引生效
    ↓ 月度归档（DirOps MD5去重）
移入 8-归档/ 或保留活跃状态
```

### 5.2 定期维护任务

| 频率 | 任务 | 使用技能 |
|------|------|----------|
| 每次入库 | 补 frontmatter + 标签 + 双向链接 | 手动或 Agent |
| 每周 | 检查孤岛笔记、标签一致性 | Tag Wrangler |
| 每月 | MD5 去重、归档过期内容 | DirOps |
| 每季度 | 图谱健康巡检、MOC 更新 | HealthCheck |

### 5.3 Agent 自动生成笔记的模板标准

将以下模板配置到 Templater 插件中，让 Agent 生成的笔记直接符合 Obsidian 标准：

```markdown
---
title: {{title}}
date: {{date:YYYY-MM-DD}}
tags:
  - {{tag1}}
  - {{tag2}}
category: {{category}}
source: {{source}}
status: 活跃
---

# {{title}}

> **版本**: v1.0 | **生成日期**: {{date:YYYY-MM-DD}} | **来源平台**: {{source}}

## 学习来源
- **URL**: {{url}}
- **平台**: {{source}}

## 核心知识点总结
<!-- 内容区 -->

## 相关笔记
<!-- [[链接]] -->
```
