## 5. 多智能体通信：Hermes HIACP协议与架构

### 5.1 核心理念："AI团队"范式

单一全能Agent（Monolithic Agent）存在瓶颈：上下文切换成本高、任务模式间"精神分裂"、无法达到专家水平。

**解决方案**: 多专业化Agent协作 → 项目经理 + 研究员 + 程序员 + 作家

### 5.2 三大核心组件

#### (1) Agent Registry（代理注册中心）

服务发现组件，Agent启动时注册信息：

```json
{
  "agent_id": "researcher-01",
  "address": "127.0.0.1:8001",
  "capabilities": ["web_search", "summarize_text"]
}
```

#### (2) HIACP（Hermes Inter-Agent Communication Protocol）

标准化JSON消息格式，灵感源自FIPA-ACL：

| 字段 | 说明 |
|------|------|
| message_id | 消息唯一标识符 |
| conversation_id | 追踪完整对话/任务流程 |
| sender_id / receiver_id | 发送/接收Agent ID |
| performative | 消息意图（核心） |
| content | 消息内容 |

**performative类型**: REQUEST / INFORM / QUERY_REF / DELEGATE_TASK / ACCEPT / REFUSE / FAILURE

#### (3) 内部消息总线（Internal Message Bus）

基于ZeroMQ的轻量级异步消息总线，处理网络连接、序列化、超时、重试。目标Agent离线时缓存消息，上线后再次投递。

### 5.3 多Agent协作模式

| 模式 | 描述 | 适用场景 |
|------|------|----------|
| 编排器/委派模式 | 主Agent拆解任务→分发给专业子Agent→汇总 | 复杂多步骤项目 |
| 分层协作 | PM→研究员/程序员→作家 | 调研+编码+报告 |
| 并行协作 | 多个Agent同时执行独立子任务 | 并发处理 |
| 服务发现 | Registry动态查找能力匹配Agent | 动态扩展 |

### 5.4 企业协作优势

- **专业化**: 每个Agent使用最优化模型/Prompt/Skills
- **可扩展性**: 轻松增加新专家Agent
- **鲁棒性**: 单Agent失败不导致系统崩溃
- **并发性**: 多任务并行执行

## 6. 本地大模型部署：Ollama + GGUF量化方案

### 6.1 GGUF量化级别速查表

| 量化级别 | 体积vs原始 | 质量损失 | 推荐场景 |
|----------|-----------|----------|----------|
| **Q8_0** | ~50% | 最小 | 质量优先设置 |
| **Q6_K** | ~40% | 极轻微 | 质量/速度均衡 |
| **Q4_K_M** | ~30% | 轻微 | **推荐大多数用户** |
| **Q3_K_M** | ~22% | 明显 | 低VRAM设备 |
| **Q2_K** | ~15% | 显著 | 仅紧急情况下使用 |

### 6.2 导入自定义GGUF模型流程

```bash
# 1. 下载指定量化GGUF
wget https://huggingface.co/Qwen/Qwen2.5-7B-GGUF/resolve/main/qwen2.5-7b-q4_k_m.gguf

# 2. 创建Modelfile
cat > Modelfile << 'EOF'
FROM ./qwen2.5-7b-q4_k_m.gguf
PARAMETER temperature 0.7
PARAMETER num_ctx 32768
EOF

# 3. 导入Ollama
ollama create my-custom-qwen -f Modelfile

# 4. 运行
ollama run my-custom-qwen
```

### 6.3 Web界面部署

```bash
docker run -d -p 3000:8080 \
  -v open-webui:/app/backend/data \
  -e OLLAMA_BASE_URL=http://host.docker.internal:11434 \
  --name open-webui --restart always \
  ghcr.io/open-webui/open-webui:main
```

### 6.4 推荐工具栈

| 层级 | 工具 | 说明 |
|------|------|------|
| 模型运行 | Ollama | 本地模型管理引擎 |
| 量化格式 | GGUF | 标准量化格式 |
| 模型仓库 | HuggingFace | GGUF模型下载 |
| Web界面 | Open WebUI | ChatGPT式交互界面 |
| 工作流 | ComfyUI / LangChain | 复杂流程编排 |

### 6.5 生产部署注意事项

- 始终检查chat template正确性
- 生产环境建议Q4_K_M或Q6_K
- 关键场景（合同审查、财务分析）数据不离开本地
- 支持Ollama + 云端API混合部署（自动故障转移）
