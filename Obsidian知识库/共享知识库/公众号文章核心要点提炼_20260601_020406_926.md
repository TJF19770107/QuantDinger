## 2. 核心流程

```
环境准备 → 安装CLI → 初始化认证 → 重启Codex → 验证 → 开始使用
```

| 步骤 | 操作 | 关键命令 |
|------|------|---------|
| 1. 环境准备 | 确认 Codex CLI / Node.js / 飞书账号就绪 | `codex --version` |
| 2. 安装CLI | 安装 lark-cli 并注册为 Codex Skill | `npm install -g @larksuite/cli`；`npx skills add larksuite/cli -y -g` |
| 3. 初始化认证 | 创建应用配置并授权 | `lark-cli config init --new`；`lark-cli auth login --recommend` |
| 4. 重启Codex | **关键步骤**，否则CLI不生效 | `exit` → `codex` |
| 5. 验证 | 确认授权状态 | `lark-cli auth status` |
| 6. 开始使用 | 自然语言操作飞书 | "帮我创建一个飞书文档..." |

## 3. 关键命令速查表

### 安装与认证

| 命令 | 用途 |
|------|------|
| `npm install -g @larksuite/cli` | 安装飞书CLI |
| `npx skills add larksuite/cli -y -g` | 注册为 Codex Skill |
| `lark-cli config init --new` | 创建新应用配置 |
| `lark-cli auth login --recommend` | 推荐权限登录 |
| `lark-cli auth status` | 查看认证状态 |
| `lark-cli help` | 查看全部可用命令 |

### 文档操作

| 命令 | 用途 |
|------|------|
| `lark-cli docs +create --title "标题" --markdown "内容"` | 创建文档 |
| `lark-cli docs +create --folder "fld_xxx"` | 指定文件夹创建 |
| `lark-cli docs +read` | 读取文档 |
| `lark-cli docs +update` | 更新文档 |

### 其他业务域

| 命令 | 用途 |
|------|------|
| `lark-cli drive +search --query "关键词"` | 搜索云盘文件/文件夹 |
| `lark-cli drive +list` | 列出云空间文件 |
| `lark-cli im +messages-send` | 发送消息 |
| `lark-cli im +messages-list` | 列出消息 |
| `lark-cli calendar +agenda` | 查看日程 |
| `lark-cli calendar +create` | 创建日程 |
| `lark-cli mail +send` | 发送邮件 |
| `lark-cli base +records` | 操作多维表格 |

### Skill 管理

| 命令 | 用途 |
|------|------|
| `$skill-creator` | 启动内置 Skill 创建向导 |
| `/skills` 或 `$` | 查看已安装 Skill 列表 |
| `npx skills add <仓库地址>` | 安装新 Skill |
| `$skill-name` | 手动指定调用某个 Skill |

## 4. 踩坑记录汇总

| 序号 | 问题 | 原因 | 解决方案 |
|------|------|------|---------|
| 1 | 安装后 CLI 无反应 | **未重启 Codex**（最高频踩坑点） | `exit` 退出后重新 `codex` 进入 |
| 2 | 授权失效 | Token 过期 | 重新执行 `lark-cli auth login --recommend` |
| 3 | 操作被拒 / 返回权限错误 | 飞书应用权限不足 | 去飞书开放平台后台补充对应 Scope 权限 |
| 4 | 生图要求提供 API Key | Codex 未识别已有订阅 | 直接反驳：已订阅 Codex + ChatGPT Plus，可直接用 GPT-Image-2，无需额外 Key |
| 5 | 创建文档失败 | 未授权文档相关权限 | 检查应用权限中"云文档"相关 Scope |
| 6 | 不知道有哪些命令 | - | 执行 `lark-cli help` 或直接问 Codex |

## 6. 学习结论

### 核心洞察

这套方案的本质是：
```
飞书 = API 能力层（数据存储 + 业务逻辑）
Codex = Agent 调度层（自然语言理解 + 任务编排）
```

### 接入评估

- **上手门槛**：极低，10分钟内可从零到创建第一篇飞书文档
- **核心依赖**：Codex CLI + Node.js + 飞书账号
- **价值密度**：高。一次安装后，所有飞书操作均可自然语言化
- **扩展空间**：通过 Skill 机制可无限扩展自动化场景（周报、监控、纪要沉淀等）

### 推荐路径

1. **轻度使用**：直接用自然语言操作文档，效率已明显提升
2. **中度整合**：创建专属 Skill（如周报生成），固化高频场景
3. **深度基建**：通过 cc-connect 桥接到飞书群，成为内部办公自动化基座
