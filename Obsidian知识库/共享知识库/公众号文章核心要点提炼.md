## 一、核心事件

OpenAI 于 2026 年 6 月宣布 **Codex+ChatGPT 史诗级合体**（"Intelligence at Work"），近 10 亿用户获得 Agent 能力。Codex 作为执行层与 ChatGPT 思考层统一入口，通过 Agent Plugins（6角色110技能，后扩展至8角色146技能+80企业应用）实现全链路自动化。

飞书 lark-cli 作为 Agent Plugin 接入 Codex，将飞书全系办公能力（11域200+命令19 Agent Skills）纳入自然语言调度范围。

## 三、飞书 CLI 自动化流程

### 3.1 四步接入 SOP

```
安装CLI → 配置应用 → OAuth授权 → 验证接入
```

1. `npm install -g @larksuite/cli --registry=https://registry.npmmirror.com`
2. 飞书开放平台创建企业自建应用
3. `lark-cli auth login --recommend`（OAuth 2.0 设备流）
4. `lark-cli doctor` 诊断验证

### 3.2 三层命令体系

| 层级 | 说明 |
|------|------|
| 快捷命令（+前缀） | 自然语言风格，适合对话式交互 |
| API命令 | 直接映射飞书开放平台API |
| 通用API | 调用任意飞书API端点 |

### 3.3 11大业务域覆盖

云文档 · 多维表格(Base) · 消息与群组 · 日历 · 视频会议 · 邮件 · 知识库 · 云盘 · 任务 · 审批 · 通讯录

### 3.4 19个 Agent Skills

飞书CLI内置19个业务Skills（lark-doc/lark-base/lark-im/lark-calendar/lark-vc/lark-mins/lark-mail/lark-wiki/lark-drive/lark-task/lark-approval/lark-event/lark-whiteboard/lark-search/lark-shared/lark-okr/lark-attendance/lark-contact）

### 3.5 三种接入模式

| 模式 | 适用场景 |
|------|---------|
| 不授权 | 仅查看公开文档 |
| 应用身份 | 生产环境（create_application OAuth） |
| 用户身份 | 需用户授权（request_user OAuth） |

## 六、安全权限配置

- 最小权限原则：按场景14项Scope按需授权
- `--dry-run` 强制预览所有写操作
- 凭据管理：环境变量 + OS原生密钥链
- Codex 权限模式：生产环境推荐 `auto-edit`

## 七、关键洞察

1. **"思考+执行"统一入口**是 Agent 从开发者工具走向全民基础设施的关键——Codex+ChatGPT合体覆盖近10亿用户，飞书CLI作为标准插件接入，实现零代码办公自动化
2. **三层命令体系**（快捷/API/通用API）满足从"对话式探索"到"生产级CI"的全场景覆盖
3. **Agent Plugins 生态**从6角色110技能扩展到8角色146技能，企业应用从62扩展到80+，证明"开放插件"是Agent平台的核心竞争壁垒
4. **安全从设计开始**——`--dry-run` + 最小权限 + 审计日志 + Codex四级权限模式，构建纵深防御
5. **双Agent生态协作**（Claude Code ↔ Codex异步交接）开启"Agent-to-Agent"编排新范式，共享层设计是关键基础设施
6. **飞书CLI的19个Agent Skills**覆盖办公全链路，对标龙虾协议#201，可作为企业Agent自动化的标准化底座
