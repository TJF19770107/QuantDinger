## Claude Code Harness 五大扩展点（2026年最佳实践）

Anthropic 2026年5月分享了Claude Code Harness落地最佳实践，提炼出五大扩展点：

### E1. CLAUDE.md — 项目记忆文件
- **原则**：精简分层，根目录只放指针和关键坑点(gotcha)
- **配置**：子目录初始化而非仓库根目录（Claude自动向上遍历加载所有层级CLAUDE.md）
- **反模式**：把本应放进Skill的可复用专长塞进CLAUDE.md

### E2. Hooks — 生命周期钩子
- **配置自我进化**：Stop hook在会话结束时自动反思并建议更新CLAUDE.md；Start hook按模块动态加载上下文
- **类型**：PreToolUse / PostToolUse / SubagentStart / SubagentStop / SessionStart / SessionStop
- **反模式**：用prompt处理本该自动运行的事情

### E3. Skills — 按需加载专业知识
- **路径绑定**：Skills绑定到特定路径（如支付团队的deploy skill只在支付目录激活）
- **按需触发**：安全审查skill在评估漏洞时才加载，不膨胀每次会话
- **反模式**：把一切塞进CLAUDE.md而不是建Skill

### E4. Plugins — 把好经验打包分发
- **定义**：Skills + Hooks + MCP配置打包为一个可安装组件
- **价值**：新工程师第一天装上就能拥有和老员工相同的能力
- **反模式**：让好的setup停留在小圈子里（部落知识）

### E5. MCP Servers — 连接外部工具
- **连接对象**：内部文档、工单系统、分析平台、设计工具、数据库
- **最佳实践**：暴露"结构化搜索"作为Claude可直接调用的工具
- **反模式**：在基础都没跑通时就先建MCP连接

## Claude Code 三大配置模式（生产验证）

### 模式一：让代码库可导航
1. CLAUDE.md 精简分层
2. 子目录初始化（Claude自动向上遍历加载）
3. 按子目录范围跑测试和lint
4. 用 .ignore 排除生成文件和构建产物
5. 目录结构不清晰时建"代码地图"
6. 启用 LSP 按符号搜索（而非字符串匹配）

### 模式二：配置随模型进化而维护
为旧模型写的指令可能在新模型上变成约束，需持续迭代配置

### 模式三：Subagents 探索与编辑分离
只读 subagent 先 map 子系统 → 写发现到文件 → 主 agent 带完整信息编辑。避免同一实例既探索又修改时的上下文混乱

## Anthropic Agent 设计核心原则

### 1. "给 Claude 一台电脑"原则
给 Agent 与人类相同的计算机访问权限（终端、文件系统、Bash），让 Agent 像人类一样工作。

### 2. Agent Loop: Gather → Act → Verify
- **Gather Context**：Agentic Search + 文件系统 + Semantic Search + Subagents + Compaction
- **Take Action**：Tools + Bash/Scripts + Code Generation + MCP 集成
- **Verify Work**：Rules-based(Linting) + Visual Feedback(Screenshot) + LLM-as-Judge

### 3. Subagent 两大价值
- **并行化**：多个 Subagent 同时处理不同任务
- **上下文隔离**：Subagent 在自己的 Context Window 中工作，只返回摘要

### 4. Skills-as-Configuration
Subagent = YAML Frontmatter(配置) + Markdown Body(系统提示)，即插即用、跨项目复用、版本可控。

### 5. 五级 Subagent 范围
managed(组织级) > CLI flag(会话级) > project(`.claude/agents/`) > user(`~/.claude/agents/`) > plugin

### 6. 工具设计原则
- 工具是 Agent 上下文中**最突出的元素** → 直接影响 Agent 决策
- 工具应是 Agent 的"主要动作"（Primary Actions）
- 通用工具（Bash）+ 专用工具（自定义函数）组合

### 7. 简单优先原则
能不用 Agent 就不用 Agent。Workflow 能解决的不用 Agent 系统。保持简单是最高的设计原则。
