## 一、文章核心主题

**一句话总结**：飞书 CLI 开源后，Codex（或其他 AI Agent）可通过自然语言直接操作飞书全生态（文档/多维表格/消息/日历/会议），将"照着文档一步步敲命令"的繁琐流程转变为"一句话让 AI 完成"的自动化体验。

## 二、核心流程拆解（5步法）

### 第1步：安装飞书 CLI

```bash
npm install -g @larksuite/cli
# 验证
lark-cli --version
```

### 第2步：初始化并登录授权

```bash
lark-cli config init --new --brand feishu --lang zh
lark-cli auth login --recommend
lark-cli auth status --verify  # 验证
```

### 第3步：安装飞书 Agent Skills

飞书官方提供 Agent Skills 包，安装后 Codex 自动具备飞书操作能力。

### 第4步：重启 Codex

Skills 安装后需重启 Codex 以加载新能力。

### 第5步：用自然语言操作飞书

Codex 将自然语言指令自动翻译为 CLI 命令并执行。

## 三、关键技术要点

### 3.1 飞书 CLI 是什么

飞书官方的命令行工具，开源在 GitHub（仓库 `larksuite/cli`），Star 数 10.7K+。支持：
- 云文档 CRUD
- 多维表格(Base) 完整操作
- 消息发送与群聊管理
- 日历日程管理
- 视频会议创建

### 3.2 cc-connect 桥接方案

**核心价值**：让飞书成为 Codex 的远程交互入口。在飞书里发一句话，驱动本地 Codex 执行。

**关键特点**：
- WebSocket 长连接，不需要公网 IP/域名/HTTPS
- 不需要 ngrok/frp 反向代理
- 办公室内网、家里 NAS、个人笔记本都能跑

**配置流程**：
1. `npm install -g cc-connect`
2. `cc-connect feishu setup --project my-codex`
3. 编辑 `~/.cc-connect/config.toml` 配置 Agent 类型和飞书应用凭据
4. `cc-connect` 启动服务

### 3.3 权限模式（Codex）

| 模式 | 说明 | 建议场景 |
|------|------|---------|
| `suggest` | 仅受信命令自动执行，其他需确认 | 开发调试 |
| `auto-edit` | 模型自行决定是否执行 | 日常使用 |
| `full-auto` | 自动执行 + 沙箱保护 | 自动化流水线 |
| `yolo` | 跳过所有确认，全自动 | **生产慎用** |

### 3.4 飞书开放平台最小权限集

- `im:message` / `im:message:send_as_bot` — 消息收发
- `docx:document` / `drive:drive` — 文档操作
- `bitable:app` — 多维表格
- `calendar:calendar` — 日历
- `contact:user` — 通讯录（可选）

## 四、可复用 SOP 模板

### 4.1 日报自动生成流水线

```
触发：每日18:00（定时任务）
  → Step1: 从多维表格提取当日数据
  → Step2: 生成日报文档（Markdown格式）
  → Step3: 存入指定知识库目录
  → Step4: 发送到团队群聊
```

### 4.2 客户数据同步流水线

```
触发：外部CRM Webhook
  → Step1: Codex 解析Webhook数据
  → Step2: 匹配飞书多维表格记录
  → Step3: 批量更新字段
  → Step4: 异常记录推送告警消息
```

### 4.3 知识库智能问答

```
触发：飞书消息 @机器人 提问
  → Step1: Codex 解析问题意图
  → Step2: lark-cli docx search 检索知识库
  → Step3: RAG 二次排序最相关文档
  → Step4: 拼接上下文 + LLM 生成回答
  → Step5: 飞书消息回复
```
