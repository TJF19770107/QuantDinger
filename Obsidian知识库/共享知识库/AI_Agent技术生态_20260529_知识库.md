## 一、核心AI Agent平台与技术

### 1.1 Marvis（腾讯马维斯）
**发布时间**：2026年5月20日  
**核心定位**：操作系统级AI助手，用自然语言操控整台电脑/手机  
**架构特点**：1主Agent + 5副Agent多智能体协作架构
- **主Agent**：任务调度、理解用户意图、拆解任务
- **File Agent**：文件管理、搜索、整理、转格式、内容理解
- **Computer Agent**：系统运维、配置查询、设置修改、优化
- **App Agent**：应用操控、自动化流程
- **Browser Agent**：网页交互、数据采集
- **Search Agent**：信息检索、整理摘要

**核心能力**：
- 系统级操控：查配置、改设置、清垃圾、优化启动项
- 文件深度智能：按内容/场景/人像分类、批量转格式
- 办公自动化：写周报、做PPT、整理会议纪要
- 跨端协同：手机远程控制电脑、跨设备接力任务
- 隐私保护：端侧模式（基于腾讯自研Qwen端侧模型）

**技术亮点**：
- 支持Windows/Mac/Android，iOS即将上线
- 每天免费提供1000万Token
- 直接调用系统API实现真正系统级操作

### 1.2 OpenClaw
**定位**：个人AI助手，基础设施可控的开源方案  
**核心特点**：
- 非企业级、非托管，基础设施用户自控
- 支持多智能体协同
- 可处理WhatsApp等即时通讯数据源
- "Hackable"安装选项，高度可定制

**技术生态**：
- 支持Minimax M2.5作为主要驱动模型
- 平台/操作系统无关
- 社区活跃，开发者评价极高

### 1.3 Gemini多模态Agent
**技术特点**：
- 原生多模态：理解PDF/视频/音频
- 通过function calling调用图像、语音生成模型
- 支持长达9小时音频处理
- Nano Banana原生图像生成支持世界理解
- 实时音频模型实现单架构audio-in/out

**应用场景**：
- 图像识别+提问
- 图表解读
- OCR+问题回答
- 屏幕共享分析代码/文档

**开发实战**：
- 使用Gemini Pro Vision或更新的多模态版本
- 构建图文混合输入结构，Base64编码嵌入图片
- 图像建议不超过2048x2048像素

### 1.4 Echo Agent
**GitHub项目**：

## 二、多智能体通信协议

### 2.1 MCP（Model Context Protocol）
**发布时间**：2024年11月（Anthropic发布）  
**当前状态**：2026年4月，每月SDK下载量超过9700万（Python+TypeScript）

**核心价值**：
- 解决"N×M"集成问题：N个Agent × M个工具 → N+M问题
- 标准化Agent与工具间的通信
- 动态工具发现与使用，无需重新编程

**采用时间线**：
- 2024年11月：Anthropic发布MCP规范
- 2025年：社区驱动增长，服务器数量突破10,000
- 2026年Q1：OpenAI、Google、Microsoft、Amazon全部支持
- 2025年11月：移交至Linux Foundation Agentic AI Foundation治理

**技术架构**：
- **MCP Server**：工具提供者，暴露标准化接口
- **MCP Client**：Agent端，调用工具服务
- **标准化接口**：任何支持MCP的Agent可使用任何MCP工具

**2026年路线图重点**：
1. **有状态会话**：支持在多次调用间保持上下文
2. **资源生命周期管理**：引入resources/release端点
3. **扩展认证框架**：OAuth 2.0、mTLS客户端证书支持
4. **批量调用提案**：单个请求打包多个工具调用

**主流客户端支持**：
- Claude Desktop/Code：原生支持
- ChatGPT：2026年1月原生支持
- VS Code：通过Cline等扩展
- Cursor：原生集成
- Zed Editor：通过context_servers配置

### 2.2 A2A协议（Agent-to-Agent）
**技术特点**：
- 与MCP完美对齐，专注于Agent间通信
- 支持跨Agent工具调用
- 标准化接口，Linux Foundation主导

**应用场景**：
- 一个Agent通过MCP调用另一个Agent的能力
- 多智能体系统协同工作
- 状态修改Agent的安全隔离

## 三、本地大模型部署技术

### 3.1 Ollama
**核心优势**：CPU玩转大模型部署，轻量级本地化方案  
**技术特点**：
- 支持从GGUF格式导入模型
- 提供REST API（Python、Java、JavaScript、C++等）
- 集成LangChain
- 可视化界面部署

**部署流程**：
1. 安装Ollama：`curl -fsSL https://ollama.com/install.sh | sh`
2. 拉取模型：`ollama pull liquidai/lfm2-2.6b-gguf:q4_k_m`
3. 运行模型：`ollama run lfm2-2.6b-gguf`

**自定义模型导入**：
```bash
# 1. 下载GGUF文件
wget https://huggingface.co/Qwen/Qwen2.5-7B-GGUF/resolve/main/qwen2.5-7b-q4_k_m.gguf

# 2. 创建Modelfile
cat > Modelfile << 'EOF'
FROM ./qwen2.5-7b-q4_k_m.gguf
PARAMETER temperature 0.7
PARAMETER num_ctx 32768
EOF

# 3. 导入到Ollama
ollama create my-custom-qwen -f Modelfile

# 4. 运行
ollama run my-custom-qwen
```

### 3.2 GGUF格式
**技术特点**：
- 专门为机器学习设计的张量库格式
- 单文件共享，易于在不同架构的GPU/CPU上推理
- 支持多种量化级别

**量化级别对比**：
| 量化级别 | 大小 vs 原始 | 质量损失 | 适用场景 |
|----------|--------------|----------|----------|
| Q8_0 | ~50% | 最小 | 质量最大化设置 |
| Q6_K | ~40% | 非常轻微 | 平衡质量/速度 |
| Q4_K_M | ~30% | 轻微 | 🟢 推荐大多数用户 |
| Q3_K_M | ~22% | 明显 | 低VRAM环境 |
| Q2_K | ~15% | 显著 | 仅限紧急情况 |

**模型转换流程**：
1. 克隆llama.cpp：`git clone https://github.com/ggerganov/llama.cpp.git`
2. 创建虚拟环境
3. 安装依赖：`pip install -r requirements.txt`
4. 转换模型：`python convert_hf_to_gguf.py`

### 3.3 轻量级模型案例：LFM2-2.6B-GGUF
**核心参数**：
- 参数量：2.6B
- 量化后大小：约1.5GB（INT4量化）
- 内存需求：最低4GB，推荐8GB+
- 推理速度：CPU推理比同规模模型快2-3倍

**部署方式**：
- llama.cpp
- Ollama
- LM Studio

**Web界面搭建**：
```python
import gradio as gr
import requests

def chat(message, history):
    # 调用Ollama API
    response = requests.post(
        "http://localhost:11434/api/generate",
        json={"model": "lfm2-2.6b-gguf", "prompt": message}
    )
    return response.json()["response"]

gr.ChatInterface(chat).launch()
```
