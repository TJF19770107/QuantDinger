## 二、Claude Code 核心架构 · 官方文档深度提炼

### 2.1 Subagents（子代理）体系

#### 2.1.1 核心概念

Subagents 是处理特定类型任务的专门 AI 助手。每个 subagent 在独立的 context window 中运行，拥有自定义系统提示、特定工具访问权限和独立权限。

**使用场景**：
- 辅助任务会充斥主对话（搜索结果、日志、文件内容）
- 需要保持主对话上下文干净
- 需要限制工具访问权限
- 需要跨项目复用配置
- 需要将任务路由到更快/更便宜的模型（如 Haiku）

#### 2.1.2 内置 Subagents

| Agent | 模型 | 工具 | 用途 |
|-------|------|------|------|
| **Explore** | Haiku | 只读工具 | 快速代码库搜索和分析 |
| **Plan** | 继承主对话 | 只读工具 | Plan Mode 下的代码库研究 |
| **General-purpose** | 继承主对话 | 全部工具 | 复杂多步骤任务 |
| **statusline-setup** | Sonnet | - | 状态栏配置 |
| **claude-code-guide** | Haiku | - | Claude Code 功能问答 |

#### 2.1.3 自定义 Subagent 配置

```yaml
---
name: code-reviewer
description: Reviews code for quality and best practices
tools: Read, Glob, Grep
model: sonnet
permissionMode: acceptEdits
maxTurns: 20
skills: [code-review-checklist]
memory: project
isolation: worktree
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
```

**关键配置字段**：

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | 是 | 唯一标识符，小写字母+连字符 |
| `description` | 是 | Claude 何时委托任务给此 subagent |
| `tools` | 否 | 可用工具白名单 |
| `disallowedTools` | 否 | 禁用工具黑名单 |
| `model` | 否 | sonnet/opus/haiku/完整模型ID/inherit |
| `permissionMode` | 否 | default/acceptEdits/auto/dontAsk/bypassPermissions/plan |
| `maxTurns` | 否 | 最大 agentic 轮次 |
| `skills` | 否 | 预加载到上下文的 Skills |
| `mcpServers` | 否 | 可用的 MCP 服务器 |
| `hooks` | 否 | 生命周期钩子 |
| `memory` | 否 | 持久记忆范围：user/project/local |
| `background` | 否 | 设为 true 始终后台运行 |
| `effort` | 否 | 努力级别：low/medium/high/xhigh/max |
| `isolation` | 否 | worktree 隔离模式 |
| `color` | 否 | 显示颜色 |
| `initialPrompt` | 否 | 作为主会话 agent 时的初始提示 |

#### 2.1.4 Subagent 作用域优先级

| 优先级 | 位置 | 作用域 |
|--------|------|--------|
| 1 (最高) | Managed settings | 组织级 |
| 2 | `--agents` CLI flag | 当前会话 |
| 3 | `.claude/agents/` | 当前项目 |
| 4 | `~/.claude/agents/` | 所有项目 |
| 5 (最低) | Plugin `agents/` | 插件启用处 |

#### 2.1.5 Subagent 工具控制

- **白名单模式**：`tools: Read, Grep, Glob, Bash`
- **黑名单模式**：`disallowedTools: Write, Edit`
- **Agent 类型限制**：`tools: Agent(worker, researcher), Read, Bash`
- **不可用工具**：Agent, AskUserQuestion, EnterPlanMode, ExitPlanMode, ScheduleWakeup, WaitForMcpServers

### 2.2 Agent Teams（多 Agent 团队协作）

#### 2.2.1 核心概念

Agent Teams 允许多个 Claude Code 实例协同工作。一个会话作为 Team Lead，协调工作、分配任务、综合结果。队友独立工作，各自拥有独立上下文窗口，可直接相互通信。

**与 Subagents 的关键区别**：
- Subagents 在单个会话内运行，只能向主 Agent 报告
- Agent Teams 中每个队友是独立会话，可直接交互

#### 2.2.2 启用方式

```json
// settings.json
{
  "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": true
}
```

#### 2.2.3 协作模式

| 模式 | 协调者 | 通信方式 | 适用场景 |
|------|--------|---------|---------|
| Subagents | 主 Agent | 单向报告 | 单会话内委托 |
| Agent View | 用户 | 用户监控 | 多个独立任务 |
| Agent Teams | Team Lead | 双向消息 | 复杂项目分解 |
| Dynamic Workflows | 脚本 | 脚本编排 | 大规模并行 |

---

### 2.3 Dynamic Workflows（动态工作流）

#### 2.3.1 核心概念

Dynamic Workflow 是 JavaScript 脚本，用于大规模编排 subagents。Claude 根据任务描述编写脚本，运行时在后台执行，会话保持响应。

**适用场景**：
- 代码库级 Bug 扫描
- 500 文件迁移
- 需要交叉验证的研究
- 从多个角度起草计划

#### 2.3.2 四种并行方式的对比

| 方式 | 协调者 | 通信 | 文件隔离 | 规模 |
|------|--------|------|---------|------|
| Subagents | Claude | 单向报告 | 可选 worktree | 每轮几个 |
| Agent View | 用户 | 用户监控 | 自动 worktree | 多个独立会话 |
| Agent Teams | Team Lead | 双向消息 | 手动分区 | 团队协作 |
| Dynamic Workflows | 脚本 | 脚本变量 | 脚本控制 | 数十到数百 |

#### 2.3.3 运行时约束

| 约束 | 原因 |
|------|------|
| 无中途用户输入 | 只有权限提示可暂停 |
| 无直接文件系统/Shell 访问 | Agent 执行读写，脚本协调 |
| 最多 16 并发 Agent | 限制本地资源 |
| 单次运行最多 1000 Agent | 防止失控循环 |

#### 2.3.4 内置 Workflow

| 命令 | 功能 |
|------|------|
| `/deep-research <question>` | 多角度网络搜索 → 交叉验证 → 引用报告 |

### 2.4 Skills（技能扩展）

#### 2.4.1 核心概念

Skills 通过 `SKILL.md` 文件扩展 Claude 的能力。与 CLAUDE.md 不同，Skill 的主体内容仅在调用时加载，长参考材料几乎零成本。

#### 2.4.2 创建 Skill

```
.claude/skills/
├── deploy/
│   └── SKILL.md
├── code-review/
│   ├── SKILL.md
│   └── checklist.md
```

```markdown
---
name: deploy
description: Deploy the current project to production
---

# Deploy Skill

1. Run tests: `npm test`
2. Build: `npm run build`
3. Deploy: `npm run deploy`
4. Verify: Check health endpoint
```

#### 2.4.3 Skills vs Commands

- 自定义 Commands 已合并到 Skills
- `.claude/commands/deploy.md` 和 `.claude/skills/deploy/SKILL.md` 效果相同
- Skills 额外支持：辅助文件目录、条件加载、元数据

### 2.5 Hooks（生命周期钩子）

#### 2.5.1 事件类型

| 事件 | 触发时机 | 频率 |
|------|---------|------|
| `SessionStart` | 会话启动 | 每会话一次 |
| `SessionEnd` | 会话结束 | 每会话一次 |
| `UserPromptSubmit` | 用户提交提示 | 每轮一次 |
| `Stop` | Agent 完成 | 每轮一次 |
| `StopFailure` | Agent 失败 | 每轮一次 |
| `PreToolUse` | 工具调用前 | 每次工具调用 |
| `PostToolUse` | 工具调用后 | 每次工具调用 |
| `SubagentStart` | Subagent 启动 | 每次启动 |
| `SubagentStop` | Subagent 完成 | 每次完成 |
| `SubagentStopFailure` | Subagent 失败 | 每次失败 |

#### 2.5.2 Hook 类型

| 类型 | 说明 |
|------|------|
| Shell Command | 执行本地命令，stdin 接收 JSON 上下文 |
| HTTP Endpoint | POST 请求到指定 URL |
| LLM Prompt | 调用 LLM 处理事件 |

### 2.6 MCP（Model Context Protocol）

#### 2.6.1 核心概念

MCP 是 AI-工具集成的开源标准。Claude Code 通过 MCP 服务器连接外部工具、数据库和 API。

#### 2.6.2 三大原语

| 原语 | 说明 |
|------|------|
| **Tools** | 模型可调用的函数（LLM 控制） |
| **Resources** | 应用控制的数据暴露（类似 GET 端点） |
| **Prompts** | 预定义提示模板（用户控制） |

#### 2.6.3 MCP 服务器配置

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "your-token"
      }
    }
  }
}
```

### 2.7 Context Engineering（上下文工程）

#### 2.7.1 核心原则

Anthropic 明确指出：**上下文是有限资源**。随着上下文增长，模型会出现注意力稀释和信息相关性下降。

**关键策略**：
1. **Subagent 隔离**：将辅助任务委托给独立上下文的 subagent
2. **Skills 延迟加载**：仅在需要时加载详细指令
3. **Worktree 隔离**：并行会话使用独立 git 工作树
4. **上下文窗口可视化**：监控上下文使用情况

#### 2.7.2 CLAUDE.md 最佳实践

- 项目级 `.claude/CLAUDE.md`：项目约定、架构、构建命令
- 用户级 `~/.claude/CLAUDE.md`：个人偏好
- 保持简洁：只包含 Claude 需要知道的关键信息
- 过程性内容放入 Skills，事实性内容放入 CLAUDE.md

### 2.8 Agent 模式设计原则

#### 2.8.1 Workflow vs Agent

| 维度 | Workflow | Agent |
|------|----------|-------|
| 控制流 | 预定义代码路径 | LLM 动态决定 |
| 适用场景 | 可预测的重复任务 | 需要灵活决策的开放任务 |
| 可靠性 | 高（确定性） | 中（需要验证） |
| 复杂度 | 低-中 | 中-高 |

#### 2.8.2 Building Effective Agents 核心原则

1. **简单优先**：能用单次 LLM 调用解决的不用 agent
2. **透明性**：让用户看到 agent 在做什么
3. **精心设计工具**：工具文档质量决定 agent 表现
4. **充分测试**：agent 系统需要比传统软件更全面的测试

## 四、多 Agent 协作最佳实践

### 4.1 任务分解原则

1. **单一职责**：每个 subagent 只处理一类任务
2. **明确输入输出**：定义清晰的接口契约
3. **独立可测试**：每个 subagent 可独立验证
4. **失败隔离**：一个 subagent 失败不影响其他

### 4.2 上下文管理策略

| 策略 | 说明 |
|------|------|
| Subagent 委托 | 辅助任务在独立上下文完成，仅返回摘要 |
| Worktree 隔离 | 并行会话使用独立 git 工作树 |
| Skills 延迟加载 | 详细指令仅在调用时加载 |
| Forked Subagent | 继承完整对话上下文的 subagent |

### 4.3 权限与安全

| 层级 | 说明 |
|------|------|
| 工具白名单 | 限制 subagent 可用的工具 |
| 权限模式 | default/acceptEdits/auto/bypassPermissions/plan |
| 组织级管理 | Managed settings 统一管控 |
| 插件安全 | 插件 subagent 不支持 hooks/mcpServers/permissionMode |

### 4.4 成本优化

| 策略 | 说明 |
|------|------|
| 模型分层 | 简单任务用 Haiku，复杂任务用 Sonnet/Opus |
| Prompt Caching | 缓存重复前缀 |
| 上下文隔离 | Subagent 避免主对话上下文膨胀 |
| 批量处理 | Message Batches API 降低请求成本 |
