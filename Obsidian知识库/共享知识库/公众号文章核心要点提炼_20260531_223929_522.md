## 二、关键发现

### 2.1 飞书CLI的本质

不是传统的REST API，而是为AI Agent专门设计的命令行工具。AI可以像操作电脑一样直接执行命令——发消息、写文档、查日历、建表格、发邮件、管任务。

### 2.2 与传统API的根本区别

| 维度 | 传统API | 飞书CLI |
|------|---------|---------|
| 使用方式 | 需要写代码调用 | Agent直接执行命令 |
| 接入难度 | 需要开发集成 | 一行命令安装 |
| 适用对象 | 开发者 | AI Agent（Codex/Cursor/Claude Code等） |
| 交互模式 | 程序化调用 | 自然语言对话 |

### 2.3 支持的主流AI Agent工具

Claude Code / Codex / Cursor / Trae / GitHub Copilot / Windsurf / OpenClaw

## 五、关键技术点

### 5.1 Codex权限模式选择

- **建议入门前**：`suggest` 或 `auto-edit`
- **熟练后**：`full-auto`
- **全自动化**：`yolo`（需谨慎评估）

### 5.2 安全注意事项

- App Secret 不入全局配置（使用 `.env.personal`）
- 最小权限原则（按需开通）
- 定期轮换凭据
- 关注API调用审计日志

### 5.3 常见问题

- 命令不存在 → 检查PATH或重启终端
- 授权过期 → 重新 `lark-cli config init`
- 权限不足 → 检查飞书开放平台权限并重新发布
