## 一、Agent 内核设计原则

### 1.1 Agentic Loop 黄金闭环
```
收集上下文 → 执行操作 → 验证结果 → 反馈修正
```
- 每个操作后必须验证，形成感知-行动-验证的完整闭环
- 失败时自动回溯，不盲目前进
- **Approval Mode / Auto-Accept / Plan Mode** 三模式策略：复杂任务用 Plan Mode 先生成计划再执行

### 1.2 上下文窗口隔离原则
- **子代理隔离**：每个子代理拥有独立上下文窗口，主Agent只接收精炼结果
- **渐进式披露**：按需加载信息，避免一次性塞入全部上下文
- **精准回报**：子代理只返回关键信息，不返回完整执行过程
- **上下文管理三命令**：`/compact`（压缩）/ `/clear`（清空）/ `/context`（查看）
- **脚本执行不消耗上下文**：Skills可通过脚本执行复杂任务，不占用上下文窗口

### 1.3 工具与权限分层
| 层级 | 范围 | 权限 |
|------|------|------|
| 核心层 | 读文件、搜索、基础执行 | 默认开启 |
| 扩展层 | 写文件、网络请求、MCP工具 | 按需授权 |
| 特权层 | 系统配置、删除、支付 | 显式确认 |

### 1.4 Chat 与 Cowork 的本质区分（新增）
| 模式 | 类型 | 产物 | 循环 |
|------|------|------|------|
| Chat | 对话 | 文本回复 | 一问一答 |
| Cowork | 工作会话 | 真实文件结果 | 描述→计划→执行→引导 |

> Cowork 是 Claude 直接操作文件系统——读取、编辑、产出真实文件。用户描述任务，Claude 规划并执行，用户全程引导。

## 二、多Agent协作设计原则

### 2.1 Lead-Specialist 模式
- **Lead Agent**：负责任务分解、路由、结果汇总
- **Specialist Agent**：专注单一领域，独立上下文执行
- **共享文件系统**：通过文件传递中间结果，避免上下文污染

### 2.2 Agent 通信模式
| 模式 | 适用场景 | 特点 |
|------|---------|------|
| 并行执行 | 无依赖子任务 | 最大效率 |
| 链式调用 | 有先后依赖 | 结果传递 |
| 条件路由 | 动态决策 | 基于中间结果分支 |
| 竞争模式 | 多方案择优 | 并行生成+自动排序 |

### 2.3 委派判断标准
- **可独立完成**：任务不需要与其他任务实时协调
- **结果可验证**：产出有明确的质量标准
- **值得开销**：委派的开销小于直接执行的收益
- **反模式识别**：非所有任务都适合子代理——需判断是否"值得"

### 2.4 子代理设计模式（R17新增）
- **结构化输出格式**：要求子代理以固定格式返回结果，确保可解析
- **障碍报告机制**：遇到无法解决的问题时主动报告，避免静默失败
- **allowed-tools 限制**：通过配置限制子代理工具访问，建立安全边界
- **`/agents` 命令**：Claude Code 中快速创建自定义子代理

## 三、Skills 设计原则

### 3.1 原子化与可组合
- 每个Skill仅做一件事，做好一件事
- Skills之间通过标准化接口组合
- SKILL.md 使用 frontmatter 声明触发条件和优先级

### 3.2 渐进式披露
```
SKILL.md (入口) → 详细指令文件 → 示例/模板 → 参考文档
```
- Level 1: 名称+描述+触发条件（始终加载）
- Level 2: 详细步骤（触发时加载）
- Level 3: 参考资料（按需加载）

### 3.3 高级配置（R17新增）
- **allowed-tools**：限制工具访问，既是权限边界也是安全边界
- **脚本执行不消耗上下文**：Skills通过脚本完成复杂任务，不占用上下文窗口
- **条件触发与优先级管理**：精确控制Skills何时触发

### 3.4 团队分发
- 通过Git仓库管理Skills版本
- 通过plugins实现跨团队分发
- 企业托管设置实现组织级部署
- 与子代理集成实现专家级任务委派

### 3.5 Skills 生命周期
```
创建 → 测试 → 评估 → 精炼 → 分发 → 废弃
```

## 四、安全设计原则

### 4.1 纵深防御
| 层级 | 机制 |
|------|------|
| 输入层 | 指令审计、注入检测 |
| 执行层 | 沙箱隔离、权限最小化、allowed-tools限制 |
| 输出层 | 结果审查、敏感信息过滤 |
| 审计层 | 全链路日志、异常告警 |

### 4.2 异步监察者
- 独立LLM对每次操作进行安全评估
- 四级异常检测：正常/警告/危险/致命
- 三级分级干预：日志/确认/阻断

### 4.3 MCP 安全（R17新增）
- **Sampling 成本转移**：AI 调用成本从服务器转移到客户端
- **Roots 文件权限**：特定目录授权 + 安全边界 + 用户友好文件发现
- **传输安全**：Stdio(本地) vs StreamableHTTP(远程+SSE) 按场景选择

## 五、记忆与进化原则

### 5.1 双层记忆架构
- **会话记忆**：当前对话上下文，自动管理
- **持久记忆**：跨会话的模式、经验、偏好，结构化存储
- **CLAUDE.md**：项目级持久记忆，Claude跨会话记住约定

### 5.2 Dreaming 策展
- 会话间自动提取模式
- 噪声过滤 + 原则蒸馏
- 自动记忆重构

### 5.3 自进化闭环
```
执行 → 评估 → 反思 → 改进 → 验证 → 沉淀
```
- 每次失败都是进化机会
- 成功模式自动沉淀为Skills
- 错误模式记录到经验池

### 5.4 生产级扩展（R17新增）
- **无状态 HTTP + 负载均衡器**：MCP服务器水平扩展
- **Prompt Caching**：缓存优化减少延迟和成本
- **Extended Thinking**：深度推理模式用于复杂任务

## 六、API 设计原则（R17新增）

### 6.1 提示工程
- XML 标签结构化指令
- 示例驱动学习（few-shot）
- 清晰指令优于模糊描述
- 评估工作流：测试数据集生成 + 自动评分

### 6.2 多模态能力
- 图像分析
- PDF 处理
- 引用生成（Citation Generation）
- Extended Thinking 深度推理
