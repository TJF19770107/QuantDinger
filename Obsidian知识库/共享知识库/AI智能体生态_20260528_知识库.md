# AI智能体生态知识库（2026.05.28）

## 一、核心框架与协议

### 1.1 MCP（Model Context Protocol）
- **定义**：Anthropic主导的开源标准协议，AI应用的"USB-C接口"，标准化连接外部系统
- **核心架构**：客户端-服务器模型，使用HTTP+SSE实现流式通信
- **关键特性**：
  - 上下文交换：标准化格式共享短期/长期记忆
  - 动态工具注册：运行时工具出现/消失
  - 多代理协调：解决AI代理间上下文共享、知识交换

### 1.2 A2A（Agent-to-Agent）协议
- **定义**：谷歌推出的智能体间通信开放标准，基于HTTP上的JSON-RPC 2.0
- **发展历程**：
  - 2025年4月9日：Google Cloud Next宣布
  - 2025年6月23日：贡献给Linux基金会
  - 2026年初：接近1.0版本，150+组织支持
- **核心机制**：
  - 智能体名片：能力发现
  - 任务生命周期管理
  - 多模态消息交互

### 1.3 ACP（Agent Communication Protocol）
- **定义**：专注于智能体如何通信的协议
- **特点**：基于HTTP/2，支持文本、图像、JSON数据等富通信

## 二、主流AI智能体框架

### 2.1 OpenClaw
- **定位**：自托管、开源、本地优先的AI Agent框架
- **核心特性**：
  - 自主执行：基于cron定时任务和HEARTBEAT.md机制
  - 四层记忆架构：会话上下文→日志→长期记忆→向量检索
  - 多平台通信：支持20+消息渠道
  - 多Agent协作：Commander-Worker模式
- **技术栈**：
  - 内置15+种工具（Shell、文件操作、浏览器自动化、Docker等）
  - 支持Claude、GPT、Gemini、DeepSeek及本地模型
- **部署**：Docker、本地服务器、PC

### 2.2 Hermes Agent
- **开发方**：Nous Research
- **核心突破**：内置完整学习闭环
- **关键特性**：
  - 技能自动创建与优化：从经验中创造可复用技能
  - 跨会话记忆：MEMORY.md（环境+教训）+ USER.md（偏好+风格）
  - 自我进化：发现更好方法时技能自动升级
- **架构**：
  - 入口层：CLI/消息网关/ACP编辑器集成
  - 核心引擎：Prompt Builder + Provider Resolution + Tool Dispatch
  - 持久化层：SQLite会话存储 + Skills技能库
- **部署**：6种后端（本地、Docker、SSH、Daytona、Singularity、Modal）

### 2.3 Echo Agent
- **定位**：基于对话记忆的自进化智能体系统
- **核心概念**：Interface-Aware Cognition（界面感知认知）
- **三视图架构**：
  - Chat（交互）：流式对话体验
  - Memory（认知）：碎片化信息沉淀为结构化长期记忆
  - Evolve（进化）：AI代码级自我重构权限
- **自我进化流程**：
  1. 深度洞察
  2. 架构设计
  3. 全栈实现
  4. 自我反思
- **部署**：一键安装脚本，支持systemd服务注册

### 2.4 Project NOVA
- **定位**：自托管的AI助手生态系统
- **架构**：中心化AI助手中心，连接25+专业Agent
- **核心组件**：
  - OpenWebUI前端：现代聊天界面
  - n8n工作流引擎：处理请求和编排Agent通信
  - 智能路由Agent：分析请求和对话上下文
  - 25+专业Agent：知识管理、开发工具、媒体制作等
- **特点**：容器化架构，易于部署

## 四、本地模型部署

### 4.1 Ollama + GGUF
- **GGUF格式**：2026年量化模型标准格式
1. **量化级别与质量**：
   - Q8_0：~50%大小，最小质量损失
   - Q6_K：~40%大小，非常轻微损失
   - Q4_K_M：~30%大小，轻微损失（推荐大多数用户）
   - Q3_K_M：~22%大小，明显损失
   - Q2_K：~15%大小，显著损失（仅限紧急情况）

2. **自定义模型导入流程**：
   ```bash
   # 1. 下载GGUF文件
   wget https://huggingface.co/Qwen/Qwen2.5-7B-GGUF/resolve/main/qwen2.5-7b-q4_k_m.gguf
   
   # 2. 创建Modelfile
   cat > Modelfile << 'EOF'
   FROM ./qwen2.5-7b-q4_k_m.gguf
   PARAMETER temperature 0.7
   PARAMETER num_ctx 32768
   EOF
   
   # 3. 导入Ollama
   ollama create my-custom-qwen -f Modelfile
   
   # 4. 运行
   ollama run my-custom-qwen
   ```

3. **离线部署要点**：
   - Linux环境：解压ollama-linux-amd64.tgz到/usr/bin
   - 启动服务：`ollama serve`
   - 模型存储：`~/.ollama/models/`

### 4.2 模型选择建议
- **平衡质量/速度**：Q4_K_M
- **质量优先**：Q8_0或Q6_K
- **低VRAM环境**：Q3_K_M
- **关键**：始终检查聊天模板兼容性

   - 专业摄影术语识别

   - 节点式自动化管道
   - 可发布为共享App
   - 适合生产团队重复流程

## 七、AI漫剧制作

### 7.1 四步工作流
1. **剧本与分镜**：
   - 工具：豆包、文心一言
   - 关键：结构化分镜脚本（场景描述+角色对白+画面提示词）
   - 格式：景别+场景+角色+动作+表情+风格+画质

2. **角色与场景生成**：
   - 工具：即梦AI、可灵AI
   - 核心：角色一致性（三视图基准图）
   - 风格统一：国漫风、古风、Q版、写实

3. **动态化**：
   - 方法A：AI直接生成短视频（即梦AI、可灵AI、Vidu AI）
   - 方法B：静态图+剪映动态特效
   - 时长：单段3-8秒，越短越稳定

4. **配音与剪辑**：
   - 配音：剪映智能配音、讯飞配音
   - 剪辑：剪映（一站式）
   - 输出：1080P、30fps、MP4

### 7.2 新手避坑要点
- **角色统一**：全程用同一张角色基准图
- **提示词精准**：写清景别、动作、表情、风格
- **时长控制**：单集1-3分钟，单镜3-5秒
- **风格统一**：从头到尾不换画风、不换工具
