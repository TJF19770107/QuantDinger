**课程摘要**：MCP架构全解。Host/Server/Client/Transport四层模型、JSON-RPC协议、Python SDK构建MCP服务器。三大核心原语：tools（模型控制的动作）、resources（只读应用数据）、prompts（预定义指令模板）。MCP Inspector测试与调试。

**MCP三层架构设计思想**：

| 层 | 角色 | 职责 |
|---|------|------|
| Host | 宿主应用 | 发起连接、管理MCP客户端生命周期 |
| Client | 协议客户端 | 与Server建立1:1连接、收发JSON-RPC |
| Server | 服务端 | 暴露tools/resources/prompts、处理请求 |

**核心技能提炼**：
- 三大原语（tools/resources/prompts）的设计与实现
- MCP Server注册与发现
- JSON-RPC 2.0协议
- MCP Inspector调试
- 传输机制选择

### 课程13：Introduction to Subagents ⭐⭐⭐
| 属性 | 内容 |
|------|------|
| 编号 | AC-207 |
| 难度 | 中级-高级 |
| 时长 | ~2小时（含4个短视频+实操） |
| 证书 | 有 |
| 推荐度 | ★★★★★ |

**课程摘要**：在Claude Code中使用和创建Subagents。上下文管理、任务委派、Skills协同、构建专业化工作流。

**Subagent上下文隔离原则（重点）**：

| 原则 | 说明 | 重要性 |
|------|------|--------|
| 一代理一职责 | 每个子代理只做好一件事 | ★★★★★ |
| 探索与编辑分离 | 只读子代理先map→写发现文件→主代理带信息编辑 | ★★★★ |
| 上下文隔离 | 独立Context Window，只返回摘要 | ★★★★★ |
| 工具最小化 | 只给完成任务所需的最小工具集 | ★★★★ |
| 专业化命名 | code-reviewer/test-runner（非模糊的"engineer"） | ★★★ |

**Subagent Spec模板设计**：
```yaml
输入字段: 项目名 / 目标平台 / 字数上限
输出要求: JSON格式 {title, intro, install_steps}
失败返回: {"error": "描述"}
超时策略: 30s / 重试3次
```

**核心技能提炼**：
- 创建带Skills的Subagents
- 构建多Agent系统
- 管理隔离上下文
- 并行子代理编排
- Spec模板设计

**最佳实践**：
- 主代理负责统筹+复杂逻辑，子代理适合短时明确任务
- 拆分好的子任务显著降低主代理上下文占用
- 并行启动子代理时需设置超时与重试阈值
- 主代理统一收集结果、格式化和冲突解决

**🟢 龙虾映射**：协议#13 子Agent生命周期钩子、协议#25 Lead-Specialist推理分发、协议#42 Swarm多Agent拓扑调度、协议#54 百级并行子Agent调度、协议#90 并行子Agent自动分解调度、协议#111 Agent技能四件套、协议#155 Kanban多Agent任务看板、协议#160 去中心化自组织Agent团队

### 课程16：AI Capabilities and Limitations
| 属性 | 内容 |
|------|------|
| 编号 | AC-303 |
| 难度 | 初级 |
| 时长 | ~30分钟 |
| 证书 | 有 |
| 无需技术背景 | 是 |

**课程摘要**：AI行为心理模型。四大核心属性：Next Token Prediction（下一个Token预测）、Knowledge（知识）、Working Memory（工作记忆）、Steerability（可操控性）。每项通过简短讲解+实操练习探索。

**四大核心属性详解**：

| 属性 | 说明 | 设计启示 |
|------|------|---------|
| Next Token Prediction | AI本质是统计预测，不是理解 | 输出需要验证，不可盲信 |
| Knowledge | 训练数据截止，有知识盲区 | 提供上下文补充知识缺口 |
| Working Memory | 上下文窗口有限 | 信息密度管理，分层压缩 |
| Steerability | 可被引导但可能偏离 | System Prompt + 约束设计 |

**核心技能提炼**：
- AI能力边界的理性认知
- 避免过度信任或过度怀疑两个极端
- 设计时考虑AI固有的局限性

**🟢 龙虾映射**：协议#167 诚实性自检与抗过度自信协议、SOUL.md"不盲信原则"

```

    ├── Subagent B: 单一职责 + 最小工具集 + 独立上下文
    └── Subagent C: 单一职责 + 最小工具集 + 独立上下文

### 6.4 MCP三层架构设计思想

**来源课程**：AC-203 MCP入门 / AC-204 MCP高级

```
Host（宿主应用）
  └── Client（协议客户端，1:1连接）
        └── Server（暴露 tools/resources/prompts）
              ├── tools: 模型控制的动作
              ├── resources: 只读应用数据
              └── prompts: 预定义指令模板

**设计原则**：

- 连接失败优雅降级
