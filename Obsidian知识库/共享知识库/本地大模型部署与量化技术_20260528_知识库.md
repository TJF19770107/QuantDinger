## 核心知识点总结

### 1. 硬件配置速查表

### 2. 量化技术详解
**GGUF格式**：当前最主流的消费级量化格式，Ollama和llama.cpp的通用标准

**量化版本选择原则**：
- **Q4_K_M**：通用首选，平衡效果和速度
- **Q5_K_M**：质量略高，占用略大
- **Q3_K_M**：显存吃紧，极致节省
- **Q2_K**：极限硬件，质量下降明显

**量化压缩比**：
- FP32 → 4字节/参数
- FP16/BF16 → 2字节/参数
- Q4 → 0.5字节/参数（8倍压缩比）
- 7B模型从14GB降到4GB以下

### 3. Ollama部署流程
**三步走完**：
1. **安装**：一键安装，支持Linux/macOS/Windows
2. **拉模型**：`ollama pull qwen3.5:7b-q4_K_M`
3. **运行**：`ollama run qwen3.5:7b-q4_K_M`

**关键参数**：
- `--num-ctx 2048`：限制上下文长度，节省1–2GB显存
- `--num-threads`：限流并行请求
- `OLLAMA_DEBUG=1`：查看详细显存占用

### 4. llama.cpp精细控制
**编译配置（CUDA）**：
```bash
cmake -B build \
  -DGGML_CUDA=ON \
  -DGGML_CUDA_FA=ON \
  -DGGML_CUDA_F16=ON \
  -DGGML_CUDA_GRAPHS=ON \
  -DCMAKE_BUILD_TYPE=Release
```

**运行参数**：
- `-m models/model.gguf`：模型文件路径
- `-c 4096`：上下文长度
- `-ngl 33`：offload到GPU的层数（7B模型共33层）
- `-t 8`：CPU线程数

**API服务**：
```bash
./build/bin/llama-server -m models/model.gguf --host 0.0.0.0 --port 8080
```

### 5. 性能优化与调试
**常见问题及解决方案**：
1. **模型一直在CPU跑**：检查驱动，`ollama ps`查看GPU识别
2. **跑着跑着卡死/闪退**：降低上下文长度，`--num-ctx 2048`
3. **推理速度太慢**：增加batch size，确保CUDA编译
4. **卡在loading model不动**：检查文件完整性，重拉模型

**显存占用公式**：
```
参数规模 × 量化位数/8字节 × 1.2（覆盖KV Cache和框架开销）
```
示例：7B Q4模型 ≈ 7×10⁹ × 4/8 × 1.2 ≈ 4.2GB

### 6. 芯片阵营支持
| 芯片类型 | 支持方案 | 特点 |
|----------|----------|------|
| NVIDIA CUDA | 原生支持 | 驱动安装完即用，RTX 20/30/40/50系通用 |
| AMD ROCm | ROCm原生或Vulkan | Linux下apt安装，较复杂但性能提升 |
| Apple Silicon Metal | 统一内存架构 | 系统内存即显存，`-ngl 99`全量使用GPU |
| 纯CPU | 全量CPU推理 | 7B模型约3–5 token/s，适合离线处理 |

## 技术方案与参数

### 1. 极限配置案例
**设备**：RTX 4060 8GB笔记本电脑
**目标**：运行Qwen2.5-32B-Q4_K_M模型
**方案**：通过partial offload把部分层放到CPU+DDR5内存
**结果**：10.8 token/s速度，32B模型在8GB显存上可用

### 2. 上下文窗口影响
| 上下文长度 | KV Cache占用 | 显存需求 |
|------------|--------------|----------|
| 2048 | 约1–2GB | 基础+1-2GB |
| 4096 | 约2–4GB | 基础+2-4GB |
| 8192 | 约4–8GB | 基础+4-8GB |

### 3. 速度分级参考
| 速度范围 | 典型配置 | 适用场景 |

| 30–50 token/s | 6–8GB显存跑7B Q4_K_M | 流畅对话 |
