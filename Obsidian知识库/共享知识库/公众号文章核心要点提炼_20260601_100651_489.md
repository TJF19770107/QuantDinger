## 一、文章核心价值

**飞书 CLI 让 AI Agent 可直接通过命令行操作飞书全系产品**——不再是传统 API 开发模式，而是 Agent Native 模式：AI 收到自然语言指令 → 自动编排 CLI 命令 → 直接操作飞书数据。

核心突破：
- 从"写代码调 API"变为"说人话驱动飞书"
- 无需公网 IP、无需域名、无需服务器部署
- 10 分钟即可完成从安装到首条指令的全流程

## 二、关键知识点清单

| # | 知识点 | 要点 |
|---|--------|------|
| 1 | CLI 本质 | Go 语言编写、MIT 协议、命令行界面而非 GUI，专为 AI Agent 设计 |
| 2 | 覆盖范围 | 11 大业务域：IM / 文档 / 多维表格 / 日历 / 会议 / 邮箱 / 任务 / VC / 文件 / 知识库 / 通讯录 |
| 3 | 命令规模 | 200+ 命令 + 19 个 Agent Skills |
| 4 | 兼容工具 | Codex / Claude Code / Cursor / OpenCode / Trae / Windsurf |
| 5 | 安装命令 | `npm install -g @larksuite/cli` + `npx skills add larksuite/cli -y -g` |
| 6 | 关键状态 | `lark-cli auth status` 返回 `identity: user` + `tokenStatus: valid` |
| 7 | 两种模式 | 个人使用（基础权限） vs 团队应用（管理员审批） |
| 8 | 核心闭环 | 安装 CLI → 安装 Skills → 初始化应用 → 登录授权 → 重启 Agent → 自然语言驱动 |
| 9 | cc-connect | 桥接 Codex 到飞书群聊，群内 @机器人 直接对话 |
| 10 | Codex Pets | 桌面悬浮伴侣可视化 Agent 任务状态，结合飞书 CLI 实现进度可见 |

## 五、学习建议

1. **先跑通最小闭环**：安装 → 创建第一个文档 → 验证成功
2. **逐个场景击穿**：从文档自动化开始，逐步扩展到日程/消息/多维表格
3. **团队推广路径**：个人跑通 → 演示效果 → 申请团队应用 → 群聊机器人部署
4. **与龙虾技能体系融合**：将飞书 CLI 能力纳入 AutoWake 定时任务、Hermes 编排工作流、SICA 自进化循环
