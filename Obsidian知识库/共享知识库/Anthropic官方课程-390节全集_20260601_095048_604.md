## 重点专题深度提炼

### 一、子代理 (Subagents) 深度解析

#### Introduction to subagents（完整学习目标 ★★★）

> 子代理是延长 Claude Code 会话最实用的方式。将任务委派给隔离助手，助手独立工作并仅返回你需要的信息——保持主上下文窗口干净、对话聚焦。

**四大学习模块**:

1. **子代理如何工作** — Claude Code 启动独立上下文窗口时的内部机制：输入如何流入、摘要如何返回
2. **创建自定义子代理** — 使用 `/agents` 命令构建适配工作流的子代理：代码审查者、文档生成器等
3. **设计有效的子代理** — 让子代理可靠的模式：
   - **结构化输出格式**：要求子代理以固定格式返回结果
   - **障碍报告**：遇到无法解决的问题时主动报告而非静默失败
   - **限制工具访问**：通过 `allowed-tools` 配置限制子代理权限
4. **何时使用（及何时不使用）** — 子代理最有帮助的场景 + 常见反模式的实用指导

**核心洞察**:
- 委派=「拆分为聚焦任务 → 隔离执行 → 精准回报」
- 子代理不是万能药：有明确的反模式需要避免
- 结构化输出 + 障碍报告 = 可靠的子代理设计模式

### 二、Skills 体系深度解析

#### Introduction to agent skills（完整课程 ★★★）

> 停止重复自己，开始一次性教会 Claude。Skills 是可复用的 Markdown 指令，Claude 在合适的任务时自动应用。

**五大学习模块**:

1. **理解 Skills** — Skills 与 CLAUDE.md、hooks、subagents 的区别和定位
2. **创建第一个 Skill**：
   - 编写 SKILL.md frontmatter
   - 设计能可靠触发匹配的描述
   - 渐进式披露组织目录结构
3. **高级配置**：
   - `allowed-tools` 限制工具访问
   - 使用脚本执行（**不消耗上下文窗口**）
   - 条件触发与优先级管理
4. **团队分发**：
   - 提交到 Git 仓库
   - 通过 plugins 分发
   - 企业级托管设置组织部署
5. **与 Subagents 集成**：
   - 将 Skills 接入自定义子代理
   - 实现隔离式专家任务委派
6. **故障排除**：
   - Skills 不触发的诊断
   - 优先级冲突
   - 运行时错误

**核心洞察**:
- `allowed-tools` + 脚本执行 = Skills 可在不消耗上下文的情况下完成复杂任务
- Skills 不只是指令模板，更是「行为准则」和「权限边界」

### 五、MCP (Model Context Protocol) 完整学习路径

#### Introduction to MCP（★★★ 11项学习目标）

1. MCP 架构原理：工具定义和执行负担从你的服务器转移到专业 MCP 服务器
2. 传输无关通信系统 + 客户端-服务器消息类型
3. 完整请求-响应流：用户查询 → MCP 客户端 → 外部服务 → Claude
4. **Python SDK + 装饰器**定义工具（替代手写 JSON schema）
5. 文档管理实战：Field descriptions + type hints
6. **内置 MCP Server Inspector**：浏览器端测试调试
7. Resources：静态 URI + 参数化模板资源
8. **MIME 类型处理**：JSON 和文本的 proper handling
9. Prompts：预构建高质量指令模板
10. 三原语选择原则：tools（模型控制）/ resources（应用控制）/ prompts（用户控制）
11. 实用集成模式：**autocomplete + context injection**

#### MCP Advanced Topics（★★★ 9项学习目标）

1. **Sampling 实现**：MCP 服务器通过连接客户端请求 LLM 调用，AI 成本从服务器转移到客户端
2. **进度和日志通知**：context 对象 + logging callbacks + 长时操作进度报告
3. **Roots 文件访问**：权限系统（特定目录授权 + 安全边界 + 用户友好文件发现）
4. **JSON 消息架构**：request-result vs notification，双向通信模式
5. **Stdio 传输**：标准输入/输出流通信 + 初始化握手序列
6. **StreamableHTTP 传输**：SSE 实现服务器→客户端通信 + session 管理 + 双连接架构
7. HTTP 传输限制：配置标志对功能的影响（服务器发起的请求/流式传输）
8. **生产扩展**：无状态 HTTP + 负载均衡器水平扩展 + 状态管理权衡
9. **传输选择标准**：部署需求 / 功能需求 / 扩展约束

## 关键洞察总结（R17深度增量）

### 子代理 (Subagents) 最佳实践
1. **隔离上下文**: 每个子代理拥有独立上下文窗口，避免主对话膨胀
2. **明确委派标准**: 任务可独立完成、结果可验证、值得开销
3. **精准回报**: 子代理只返回关键信息，不返回完整执行过程
4. **结构化输出 + 障碍报告**: 要求子代理以固定格式返回 + 遇到问题主动报告
5. **allowed-tools 限制**: 通过配置限制子代理工具访问，建立安全边界
6. **反模式识别**: 不是所有任务都适合委派——需要判断"是否值得"

### Claude Code 核心工作流
- **Explore → Plan → Code → Commit** 节奏是日常开发的黄金模式
- **CLAUDE.md** 是项目级记忆，让 Claude 跨会话记住约定
- **五大定制手段**: CLAUDE.md + Subagents + Skills + MCP + Hooks
- **上下文管理三命令**: `/compact`(压缩) / `/clear`(清空) / `/context`(查看)
- **三模式策略**: approval mode(审查) / auto-accept(信任) / Plan Mode(规划)

### MCP 三层架构
- **Tools**: 让 Claude 执行操作（函数调用，模型控制）
- **Resources**: 让 Claude 读取数据（文件/API/数据库，应用控制）
- **Prompts**: 预构建的指令模板（用户控制）
- **进阶特性**: Sampling(成本转移) / SSE(服务器推送) / Roots(文件权限) / 无状态HTTP(水平扩展)

### Agent 设计模式
- **确定性工作流**: 适合步骤固定、结果可预测的场景
- **灵活 Agent 系统**: 适合需要自主决策的复杂任务
- **并行 vs 链式**: 根据任务依赖关系选择执行模式
- **条件路由**: 基于中间结果动态决策下一步

### Skills 工程化
- **渐进式披露**: SKILL.md(入口)→详细指令→示例→参考文档
- **allowed-tools**: 限制工具访问 = 安全边界
- **脚本执行不消耗上下文**: 关键性能优化手段
- **企业级分发**: Git仓库→plugins→企业托管设置

### Cowork 与 Chat 的本质区别
- **Chat** = 对话（信息交换）
- **Cowork** = 工作会话（描述→计划→执行→引导，产出真实文件）
- **关键**: Cowork 是 Claude 直接操作文件系统，而非仅生成文本

### API 扩展能力（新增洞察）
- **Extended Thinking**: 深度推理模式
- **Prompt Caching**: 缓存优化减少延迟和成本
- **Citation Generation**: 自动生成引用来源
- **PDF Processing + Image Analysis**: 多模态处理能力
