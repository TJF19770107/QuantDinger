```

└─────────────────────────────────────────────────────────────┘
```

### 1.2 各层定位与核心能力

| 层级 | 名称 | 定位 | 核心能力 | 关键约束 |
|------|------|------|----------|----------|
| L1 | 交互层 | 用户界面与服务入口 | Marvis PC端对话、Obsidian 知识图谱浏览、Trae（已退役，Hermes接管） | 不直接执行量化操作，只发起请求 |

| L3 | 中枢层 | 唯一跨模块路由与学习中枢 | Hermes网关：双向同步、规范学习、迭代闭环、链路隔离 | 唯一有权跨模块调度的中枢，其他服务禁止互调 |
| L4 | 执行层 | 量化策略实际运行 | VeighNa引擎（CTA回测/实盘）、DOGE策略矩阵、技术指标计算 | 仅响应L3调度，不主动跨模块通信 |
| L5 | 监控层 | 全局可视化和告警 | N8N工作流自动化、Obsidian Dataview动态仪表盘、定时报告生成 | 仅读取不写入，数据来自L4产出归档 |

```

    ↓

    ↓ MCP/A2A 协议
OpenClaw 多Agent协同：双模型路由、技能调用 (L2)
    ↓ 需要跨模块时
Hermes 网关路由：双向同步、规范学习、状态中转 (L3)
    ↓ 定量化任务
VeighNa 引擎执行：数据拉取→指标计算→策略回测→信号输出 (L4)
    ↓ 结果归档
Obsidian 知识库 + quant_data 目录 + 腾讯云 COS (L5)
```

## 第五章：Hermes 中枢模块

### 5.1 定位与配置原则

Hermes 是全链路中**唯一有权跨模块路由调度的中枢节点**，执行以下配置原则：

| 原则 | 说明 |
|------|------|
| **环境变量注入** | 所有配置通过环境变量注入，机密不入仓库 |
| **最小权限** | Hermes 只有必要接口暴露 |
| **唯一迭代权** | 仅 Hermes 执行规范学习、策略迭代、日志沉淀 |
| **网络隔离** | 其他模块（Marvis/OpenClaw/Obsidian/VeighNa）禁止直接互调 |

### 5.2 四层内部架构

```
Hermes 系统架构
├── 主链路层：双向同步、检索学习、回执生成、规范演进
├── 服务层：Flask HTTP API（健康/学习/检索/迭代）
├── 存储层：SQLite3（hermes_store.sqlite3）+ 日志文件系统
└── 数据源层：豆包云端规范 → from_doubao 队列 / to_doubao 队列
```

### 5.3 核心接口

| 接口 | 路径 | 功能 |
|------|------|------|
