## Anthropic Agent 设计核心原则（提炼）

### 1. "给 Claude 一台电脑"原则
Claude Agent SDK 核心理念：给 Agent 与人类相同的计算机访问权限（终端、文件系统、Bash），让 Agent 像人类一样工作。

### 2. Agent Loop: Gather → Act → Verify
每个可靠的 Agent 都应遵循三阶段循环：
- **Gather Context**：Agentic Search + 文件系统 + Semantic Search + Subagents + Compaction
- **Take Action**：Tools + Bash/Scripts + Code Generation + MCP 集成
- **Verify Work**：Rules-based (Linting) + Visual Feedback (Screenshot) + LLM-as-Judge

### 3. Subagent 两大价值
- **上下文隔离（首要）**：Subagent 在自己的 Context Window 中工作，只返回摘要。中间噪音留在子代理上下文，主代理只拿到信号。
- **并行化**：多个 Subagent 同时处理不同任务，最多 10 个并行。

### 4. Skills-as-Configuration
Subagent = YAML Frontmatter (配置) + Markdown Body (系统提示)，即插即用、跨项目复用、版本可控。

### 5. 渐进式揭露 (Progressive Disclosure)
Agent 初始仅看到 Skills 的名称和描述，仅在任务触发时才加载完整指令。大幅节省 Context Window 消耗。

### 6. 五级 Subagent 范围
managed (组织级) > CLI flag (会话级) > project (`.claude/agents/`) > user (`~/.claude/agents/`) > plugin

### 7. Agent Teams 通信机制
- 共享任务列表：所有代理可见、可认领、可更新
- 消息邮箱：代理之间互相通信
- Team Lead 分配任务和汇总结果
- 直接消息 + 广播（广播成本随团队规模翻倍）

### 8. 工具设计原则
- 工具是 Agent 上下文中最突出的元素 → 直接影响 Agent 决策
- 工具应是 Agent 的"主要动作"（Primary Actions）
- 通用工具（Bash） + 专用工具（自定义函数）组合

### 9. 决策框架：子代理 vs Agent Teams
| 场景 | 子代理 | Agent Teams |
|------|--------|-------------|
| 通信模式 | 只跟主代理通信 | 代理间互相通信 |
| 协作方式 | 完成后交付结果 | 持续协作，共享任务 |
| 适用场景 | 独立并行任务 | 需要协调的复杂项目 |
| Token 成本 | 4-7x | ~15x |
| 选择信号 | 任务可完全独立完成 | 任务间有依赖/需互相验证 |

### 10. 实务建议
- 先建 Skills，再建 Agent——高质量 Skill 比多加三个 Agent 更有效
- 每周做两次以上的事封装成子代理
- CLAUDE.md 是一切的基础——修上下文，而非修对话
- 大多数时候从子代理开始，需要频繁同步时再升级到 Agent Teams
