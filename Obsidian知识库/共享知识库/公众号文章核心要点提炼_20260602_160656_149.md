## 二、核心要点提炼

### 要点 1：Codex CLI 基础准备

| 步骤 | 操作 | 说明 |
|------|------|------|
| 1 | 安装 Node.js ≥ 18 | Codex CLI 运行环境 |
| 2 | `npm install -g @anthropic-ai/codex` | 安装 Codex CLI |
| 3 | 配置 `ANTHROPIC_API_KEY` | 认证凭证 |
| 4 | `codex --version` 验证 | 确认安装成功 |

**关键命令**：
```bash
codex "你的问题"                    # 基础对话
codex --model claude-opus-4 "问题"  # 指定模型
codex --format json "问题"           # JSON 格式输出
```

---

### 要点 2：飞书应用创建与权限配置

**创建应用步骤**：
1. 访问 [飞书开放平台](https://open.feishu.cn/) → 创建企业自建应用
2. 记录 `App ID` 和 `App Secret`
3. 开通权限（核心必选）：
   - `im:message`（收发消息）
   - `docx:document`（读写云文档）
   - `bitable:app` + `bitable:record`（多维表格）
   - `calendar:calendar`（日历）
4. **发布应用版本**（权限开通后必须发布才生效）
5. 管理员在后台启用应用

**获取访问凭证**：
```bash
curl -X POST "https://open.feishu.cn/open-apis/auth/v3/tenant_access_token/internal" \
  -H "Content-Type: application/json" \
  -d '{"app_id": "cli_xxx", "app_secret": "xxx"}'
```

### 要点 3：Codex 对话接入飞书的三种方式

#### 方式 A：Webhook 事件订阅（推荐，实时响应）

```
用户发消息 → 飞书事件订阅 → Webhook → 中间件服务 → Codex CLI → 回复消息 → 飞书 → 用户
```

**核心步骤**：
1. 搭建中间件服务（Python Flask / Node.js）
2. 配置飞书「事件订阅」Webhook URL
3. 订阅 `im.message.receive_v1` 事件
4. 中间件收到消息 → 调用 `codex` 命令 → 将回复通过飞书 API 发回

#### 方式 B：飞书 CLI（lark-cli）联动（轻量级）

```bash
# 安装飞书 CLI
npm install -g @larksuiteoauth/lark-cli
lark-cli auth login

# Codex + lark-cli 联动
lark-cli docs +get --doc-id "YxWxxx" | codex "分析此文档内容"
codex "生成周报" | lark-cli docs +create --title "本周周报"
```

#### 方式 C：OAuth 完整授权流程（生产级）

- 用户首次使用 → 跳转飞书 OAuth 授权页面
- 授权后获取 `access_token` + `refresh_token`
- 后续请求携带 `access_token` 调用飞书 API

### 要点 4：飞书 CLI（lark-cli）核心命令

| 功能域 | 命令 | 说明 |
|--------|------|------|
| 认证 | `lark-cli auth login` | OAuth 登录 |
| 消息 | `lark-cli im +messages-send` | 发送消息到群/个人 |
| 文档 | `lark-cli docs +create` | 创建云文档 |
| 文档 | `lark-cli docs +get` | 读取文档内容 |
| 多维表格 | `lark-cli base record-create` | 创建记录 |
| 日历 | `lark-cli calendar +create` | 创建日程 |
| 搜索 | `lark-cli search +search` | 跨域搜索 |

### 要点 5：自动化场景 SOP

#### SOP 1：AI 生成内容 → 自动写入飞书文档

```
触发（定时/事件）→ Codex 生成内容 → lark-cli docs +create → 发送文档链接到群
```

#### SOP 2：飞书群消息智能总结

```
定时触发 → lark-cli im +messages-list 获取消息 → Codex 总结 → 发送总结到群 / 写入文档
```

#### SOP 3：外部数据 → 飞书多维表格

```
定时拉取 API 数据 → Codex 清洗结构化 → lark-cli base record-create 批量写入
```

#### SOP 4：代码审查 → 飞书卡片通知

```
GitHub PR 事件 → Webhook → Codex 代码审查 → 飞书卡片消息（含审查结论）发送到群
```

## 四、风险点与注意事项

### 风险点清单

| 风险 | 等级 | 说明 | 规避措施 |
|------|------|------|---------|
| 飞书应用权限未发布 | 🟡 中 | 权限开通后未发布版本，接口调用失败 | 每次开通权限后务必发布新版本 |
| Token 过期 | 🟡 中 | `tenant_access_token` 有效期 2 小时 | 实现自动刷新逻辑 |
| 消息频率限制 | 🟡 中 | 飞书 API 有 QPS 限制 | 添加重试 + 指数退避 |
| Webhook 伪造请求 | 🔴 高 | 攻击者伪造飞书回调 | 验证 `header.token` 签名 |
| API Key 泄露 | 🔴 高 | `ANTHROPIC_API_KEY` 硬编码风险 | 使用环境变量，加入 `.gitignore` |
| Prompt 注入 | 🟡 中 | 用户消息中包含系统指令 | 对用户输入做过滤和长度限制 |

### 注意事项

1. **飞书应用需要管理员审核**：企业自建应用需要管理员在后台审核通过后才能正常使用
2. **`tenant_access_token` 有效期 2 小时**：生产环境需要实现自动刷新机制
3. **Webhook 必须可公网访问**：本地开发可使用 `ngrok` 等工具暴露本地服务
4. **飞书 CLI 与 Codex CLI 是两个独立工具**：`lark-cli` 负责飞书操作，`codex` 负责 AI 对话
5. **事件订阅的 Verify Token 需校验**：服务端必须校验请求中的 Token，防止伪造请求
6. **Codex CLI 输出可能包含换行/特殊字符**：发送到飞书消息时需做转义处理
