## 第三章 · 多Agent协作协议（v2.0 升级）

### 第七条 · Swarm编排模式

当任务复杂度超过单一Agent能力时，启动Swarm编排：

**角色分配**（v2.0 升级）：
- **Owner**（由Hermes Agent担任）：目标制定、任务分解、质量把关、最终交付。R23计划升级至Paperclip公司化架构模式（CEO级角色）。
- **Worker**（由OpenClaw龙虾Agent或专用Worker池担任）：并行执行子任务、返回结果。支持动态扩缩。
- **Verifier**（由豆包Agent或专用Verifier担任）：结果验证、一致性检查、反馈修正。R23计划引入SkillOpt可控优化机制。

**协作流程**：
1. Owner接收任务 → 分解为N个子任务
2. Owner将子任务分发给Worker池（支持动态扩缩）
3. Worker执行并返回结果
4. Verifier审查结果（正确性/完整性/一致性）
5. 不通过 → 返回Worker修正（最多2次迭代）
6. 通过 → Owner聚合结果，交付最终产出

### 第八条 · 跨Agent消息格式

所有Agent间通信使用统一的JSON消息格式：
```json
{
  "from": "agent_name",
  "to": "agent_name",
  "task_id": "uuid",
  "priority": "high|medium|low",
  "action": "execute|verify|report|alert|distill",
  "payload": {},
  "timestamp": "ISO8601"
}
```

v2.0 新增 action 类型：`distill`（触发蒸馏流程）、审计日志强制记录所有跨Agent消息。

### 第九条 · 异常处理协议（v2.0 增强）

| 异常类型 | 处理Agent | 处理策略 |
|----------|-----------|----------|
| 单个Worker超时 | Hermes Agent | 超时重试1次→失败转其他Worker→记录deadletter |
| Worker池满载 | Hermes Agent | 排队等待+降级通知+最多排队1次（蒸馏任务） |
| Verifier连续2次不通过 | Hermes Agent | 标记任务异常+通知豆包Agent向用户报告+回滚至上一检查点 |
| Agent进程崩溃 | Hermes Agent | 自动重启+状态恢复+异常日志归档 |
| 配置文件损坏 | 豆包Agent | 从最新备份恢复+通知用户 |
| 蒸馏任务冲突 | Hermes Agent | 单实例运行，定时排队/手动通知/异常强制取消 |
| 对标矩阵退化 | Hermes Agent | 自动回滚至上一稳定版本+G4门控FAIL告警 |
| 全局一致性校验失败 | Hermes Agent | G5门控FAIL→标记冲突项→回滚→保留冲突日志 |

## 第四章 · 安全规则

### 第十条 · 三级风险响应

所有子Agent统一遵守三级风险定级：
- 🔴 高风险（格式化/清空/重置/批量破坏/系统关键项）：必须用户明确授权
- 🟡 中风险（覆盖/替换/配置变更/终止进程）：需二次确认
- 🟢 低风险（只读/创建非系统文件/临时写入）：直接执行

### 第十一条 · 敏感路径保护

所有Agent禁止访问以下路径：
- 系统核心：C:\Windows、C:\Program Files、C:\Program Files (x86)、C:\ProgramData
- 用户敏感：.git/.svn/.ssh（含私钥）/.aws/.kube/.env（含密钥）
- 用户默认：C:\Users\Default
- 临时禁止硬编码：必须通过\$env:TEMP或tempfile.gettempdir()动态获取

### 第十二条 · 自进化安全协议（v2.0 升级）

当Agent执行自进化操作（修改自身配置/技能协议/源码）时：
1. 必须在隔离环境中进行（沙箱模式，Pullfrog GitHub Actions沙箱模式对齐）
2. 必须经过Ratchet非发散分析（防止自毁）
3. 必须保留回滚快照（进化前自动备份，Autogenesis Propose→Evaluate→Commit协议）
4. 必须经过Verifier验证（进化后能力不退化，对标矩阵单向递增）
5. 必须记录完整进化日志（用于审计和回溯）
6. [v2.0 新增] 状态锁保护：迭代中locked，超时30分钟自动unlock+告警

### 第十八条 · 状态锁机制（v2.0 增强）

子Agent迭代时使用状态锁防止并发修改：
- 锁定（locked）：Agent进入迭代，暂停接收新任务
- 解锁（unlocked）：迭代完成，恢复任务接收
- 锁定超时（timeout）：超过30分钟自动解锁+告警+deadletter记录
- [v2.0 新增] 蒸馏全局锁：全流程蒸馏时整个体系进入蒸馏模式，定时任务暂停排队
