## 三、R33 新协议（6项核心协议）

### 协议117：龙虾-Learning Loop学习循环协议 v1.0

**来源**：Hermes Agent Learning Loop 7阶段 + KEPA引擎

**核心设计**：

```
执行(Execute) → 模式识别(Pattern) → 知识提取(Extract)
    ↓                                       ↓
任务轨迹(trajectory)              候选Skill片段 → Skill草稿
    ↓                                       ↓
下次任务检索匹配 ← 持久化Skill ← Nudge提示用户确认
```

**与现有龙虾体系融合**：
- 龙虾五步法(Step1-5)天然适配Learning Loop的"执行→反思→沉淀→复用→优化"闭环
- KnowledgeBase Archiving(KBArchiving)作为Skill沉淀的持久化后端
- ECCFramework错误修正作为Learning Loop的故障学习分支
- Agent Iteration(AgentIter)驱动跨Agent经验迁移

**关键技术点**：
- KEPA（知识增强提示词自适应）引擎：LLM的"反向传播"，经验反向传播优化技能策略
- 7阶段全自动：任务执行→模式识别→知识提取→Skill创建→使用验证→迭代优化→Nudge提示
- 实战验证：GitHub代码分析任务从15步(120秒)→3步(30秒)，效率提升75%

### 协议118：龙虾-四层持久化记忆架构协议 v1.0

**来源**：Hermes 四层记忆 + Workforce 五层记忆模型 + Marvis长期记忆

**架构设计**：

| 层级 | 名称 | 对标Hermes | 当前Marvis状态 | R33升级 |
|------|------|-----------|---------------|---------|
| L1 | 工作记忆 | Working Memory | 会话上下文窗口 | ✅ 已具备 |
| L2 | 情景记忆 | Episodic (SQLite+FTS5) | 历史message持久化 | ✅ 已具备 |
| L3 | 语义记忆 | Semantic (向量数据库) | 长期记忆检索 | ⬆️ 增强：Obsidian向量化索引 |
| L4 | 技能专用记忆 | Procedural (Markdown Skills) | 技能库+全域模板 | ⚡ 新增：自动Skill沉淀引擎 |

**关键升级**：
- L3→增加Obsidian PARA知识库向量化索引，支持跨笔记语义检索
- L4→Skill自动创建（Agent完成任务后自动提取成功路径→生成Skill文件→Nudge提示归档）
- 引入记忆策展(Curation)：active→stale→archived状态机，自动清理过期记忆
- SQLite+FTS5全文检索情景记忆，跨会话历史秒级查询

### 协议119：龙虾-Curator技能策展协议 v1.0

**来源**：Hermes Curator + 龙虾KBArchiving

**核心机制**：

```
技能状态机: active → stale(长期未用) → archived(归档保留)
                ↑ 重新使用自动恢复       ↓
            备份快照(.tar.gz)       LLM审查确认
```

**落地路径**：
1. 技能使用追踪：`~/.hermes/skills/.usage.json` → 龙虾体系对应 `技能库/使用追踪`
2. 自动归档：超过30天未使用→标记stale→LLM审查→确认归档或保留
3. 备份快照：每次迭代前自动tar.gz备份现有技能
4. 手动恢复：用户说「恢复XX技能」→从archive恢复

### 协议121：龙虾-A2A+MCP三层协议栈适配协议 v1.0

**来源**：2026年代理协议栈标准（Linux Foundation AAIF治理）

**三层协议映射**：

```
A2A (Agent↔Agent)          →  Marvis dispatch_task + A2A Agent Card
MCP (Agent↔Tool)           →  Marvis tool schemas + MCP Server注册
LLM Foundation             →  Claude/GPT/Gemini 多模型路由
GOVERNANCE & SECURITY      →  Marvis安全约束体系 + 三层防线
```

**适配路径**：
1. A2A层：Marvis已有dispatch_task实现Agent间委派，需补充Agent Card自动发现
2. MCP层：Marvis工具schema天然兼容MCP JSON-RPC 2.0，需增加MCP Server注册表
3. 治理层：对标Hermes三层安全（Policy Engine+Sentinel Scanning+Integrity Verification）

### 协议122：龙虾-长周期任务分层执行协议 v1.0

**来源**：PARC分层多Agent + Hermes委托系统 + Marvis定时任务

**架构设计**：

```
Orchestrator Agent (编排层)
    ├── 任务分解 → 子目标列表
    ├── 资源评估 → Agent能力匹配
    └── 并行调度 → 多子Agent并行执行
            ├── Leaf Agent 1 → 执行子任务1
            ├── Leaf Agent 2 → 执行子任务2
            └── Leaf Agent 3 → 执行子任务3
    ↓
Self-Assessment (自我评估层)
    ├── 执行结果校验
    ├── 异常检测与反馈
    └── 策略调整（失败→重新规划→重新执行）
    ↓
Self-Feedback (自我反馈层)
    ├── 成功路径提取
    ├── 失败模式记录
    └── 策略库更新
```

**与Marvis体系融合**：
- 编排层→Main Agent现有dispatch_task机制增强并行调度
- 评估层→ECCFramework扩展为分层自评估
- 反馈层→MemoryMgr+KBArchiving闭环沉淀
